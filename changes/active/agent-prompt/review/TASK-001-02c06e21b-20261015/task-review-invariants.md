## Findings

### INV-REV-001 — INCORRECT: reapplying an existing pinned Agent reselects its inline Prompt against the newest line

- **Severity:** Important.
- **Violated obligation:** REQ-003 independent versioning and immutable Agent pinning; REQ-005 preservation of idempotent Card writes and stable conflict semantics; task scenario 2 and registration replay acceptance.
- **Changed location:** `crates/wyrd/wyrd-server/src/components/cards/service.rs:1130–1134`.
- **Producer-to-sink evidence:** The writer always synthesizes a Prompt submission with `version: None` (`:1574`) and persists it before persisting the Agent (`:1130–1140`). `persist_node` calls existing `resolve_existing`; its auto path uses `resolve_version`. `crates/wyrd/wyrd-sql/src/queries/cards/version_resolve.rs:83,103–119` deduplicates only against the latest stable Prompt in the line. The Agent's pinned-version path in `service.rs:1410–1426` compares the normalized spec hash, including the newly selected Prompt ref, against the immutable old Agent row. The shared SDK registration saga mints a fresh operation key per invocation (`crates/shared/wyrd-client/src/cards/saga/mod.rs:60`), so ordinary `Cards::register_from_path` / CLI apply is not protected by replay of the first operation key.
- **Reachable scenario and consequence:** Register Agent `a@1.0.0` with inline Prompt A; register `a@2.0.0` with inline Prompt B; reapply the original `a@1.0.0` file unchanged. The generated Prompt line is now B, so A selects a fresh third Prompt version. The unchanged old Agent consequently hashes differently and is rejected with spec drift. The transaction rolls back, so this is a false conflict/reapply failure, not a claim of committed orphan data. The existing journey only immediately repeats A before writing B and later reads A, so it cannot detect this path. Independently changing the authored `<agent>-prompt` line makes the same failure reachable.
- **Sibling consumers/authority:** Direct HTTP, Rust/Python/TS `Cards`, and CLI share this server writer. Ref/path authored Prompt version intent remains explicit and must not be altered. Ordinary Prompt version resolution deliberately considers only the latest row; globally changing its dedup policy would violate the reuse/non-goal boundary.
- **Smallest testable correction:** Keep correction in the existing registration owner. When an exact Agent version already exists, validate an unchanged inline submission against that Agent's already pinned registered Prompt and reuse the existing exact relationship; do not reselect a child version from the latest line before deciding whether this is an identical pinned-parent registration. Continue rejecting genuine parent/inline content drift and keep fresh Agent versions on the normal Prompt version resolver. Use the existing exact Card lookup/version-lock/transaction mechanisms, without another version store or a changed global Prompt policy.
- **Closure proof:** Extend the existing real-server registration proof with pinned Agent A@1 → B@2 → unchanged A@1 reapply under a fresh operation key. Assert successful noop/exact original Agent and Prompt UID, unchanged old relationship, and no extra Prompt version. Also assert changed inline content under the existing Agent pin still conflicts atomically.
