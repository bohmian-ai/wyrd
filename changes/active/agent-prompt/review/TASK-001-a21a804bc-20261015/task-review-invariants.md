## Producer-to-sink and shared-owner audit

1. **Registration state.** Public HTTP authorization and request validation precede RegistrationWriter. Typed inline content becomes an ordinary Prompt CardSubmission, with derived validated name and Agent space. Both authored siblings and generated children call the same persist_node. Canonical hashes and artifact identity remain computed in that owner; the generated Prompt has no artifacts. Its exact returned ref is installed before submission_card recomputes parent relationships and hash. Thus the normal canonical reference-slot inventory observes the selected child, and downstream registry hydration has an ordinary relationship to follow.

2. **Version selection and sibling writers.** Searched all SubmittedCardIdentity/resolve_version/persist_node callers. resolve_existing is the sole resolve_version caller; persist_node has the two intentional writer calls (generated child and normal topo node). The fix extends that shared version authority instead of introducing a Prompt cache or searching historical hashes. A current-operation stable Pending child participates in normal latest-line dedup/advance, while other operations' Pending rows remain excluded. Explicit pins still compare exact content and artifact hash. Topological order's canonical kind ordering places authored Prompt leaves before inline Agent leaves; generated-child UID suppression preserves one selected child outcome when that same child was authored explicitly. Generated children cannot create a cycle because the native Prompt body does not add a registration graph dependency.

3. **Transaction and lifecycle.** New children remain Pending with their parent in the one tenant transaction, using existing version-line locks and operation identity. Any child/parent/version error drops the transaction before the operation seed commits. The seed retains generated outcomes even though they have no authored artifact manifests. Existing bounded upload initialization, completion, abort and replay handle those ordinary rows; no early activation or additional commit was added. Existing post-commit failure/recovery behavior is retained. The accepted deletion interleaving is not made a remediation demand.

4. **Hydration and consumers.** Existing GraphTraversal reads and validates exact UID-bearing relationship targets, assigns normal aliases and publishes through CardGraphHydrator. State's existing typed map is populated once, then each Agent is checked against the Prompt map. HydratedAgent borrows both holders, so prompt() itself is infallible and local. Run.invoke reads that same Prompt. Python builds Prompt holders first, attaches those holders to Agent wrappers, and generic/typed aliases access the same retained maps; GC visits and clears the new retained Prompt reference. TypeScript's native wrapper resolves through shared state, and its public wrapper merely projects that resolved pair. No per-language reference traversal or version selection was introduced.

5. **Whole-workflow alternatives.** Existing transaction/lifecycle, exact lookup/version resolution, canonical slots, loader, graph hydrator and alias index already supply all durable workflow steps. The implementation extends each at the missing seam. The only new retained view is justified by the declarative Agent holder lacking a reference to its hydrated Prompt; it retains no IO dependency. The Python union is a single pure-Python typing owner, re-exported without new native machinery. No replacement workflow, dependency or optional configuration requires deletion.
