The locked tracing-subscriber implementation documents that operation's panic when a global subscriber was already installed (`tracing-subscriber-0.3.23/src/fmt/mod.rs:515–521`). The binary's one-call convention is described, but the public function still has that precondition/failure mode and §16 requires documenting it. No behavior change or new subscriber abstraction is needed.

Consequence: the explicit rustdoc merge gate is still red, and the test/helper contracts now misidentify which operation decodes and returns failures. This is not a claim that comments themselves corrupt runtime streams.

Smallest correction: put each helper's existing, accurate purpose/operation/Errors/Panics documentation on the item it describes; remove the inapplicable returned-error text from `run_cli_logged`; document the one-time global-subscriber panic on `install_tracing`. Preserve executable logic and assertions. Include these edits with bounded behavior remediation; do not start a standalone style-only round, sweep unchanged helpers/tests or mechanically renamed items, add a checker, or suppress a gate.
