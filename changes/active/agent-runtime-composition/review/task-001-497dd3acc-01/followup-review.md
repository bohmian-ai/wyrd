## Authority resolution

The original task is unambiguous: its approach at base lines 70–71 says to preserve coverage of surviving behavior and remove tests solely for the retired API; its verification section at 138–141 says, “Retire tests only when their sole contract is the intentionally deleted API.” The reuse map explicitly lists Prompt/live-smoke consumers at line 56. REQ-013 requires actual-consumer inspection and meaningful coverage retention; the revision 3 non-goals expressly exclude removing Prompt authoring/loading. Design authority `architecture/wyrd-design.md:416–439` retains both authored portable compilation and native pass-through forms.

Revision 3 replaces the revision 2 expansion objective and excludes its unified lifecycle/Jev work. That does not retroactively make existing compiler acceptance tests runtime-exclusive. Migrating these existing tests to application-owned requests follows the current doctrine (user code owns inference) and task lines 40–43; it needs no SDK API, executor, provider compiler, new harness, or product decision. There is no obligation here to reintroduce revision 2 sweep hardening, new providers, Vertex, streaming/tools, broader settings, or runtime lifecycle checks.

Thus the maintainer's blanket description of all deleted smoke tests as removed execution-vehicle tests is too broad. The SDK review's distinction between retained local lowering proof and lost live acceptance is accurate, but recording it solely as a verification limit does not close the explicit test-retirement obligation. INVREV-004's core claim survives, with the runtime-only assertions and actual scope narrowed as above.
