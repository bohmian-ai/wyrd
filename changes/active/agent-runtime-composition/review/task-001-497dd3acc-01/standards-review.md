## Finding

### REPO-001 — VIOLATION — document interruption and partial progress of the migrated Rust model-call workflows

- **Rule:** `AGENTS.md:742–748` requires fallible-function error docs and relevant cancellation, partial-progress or retry documentation for async/durable operations; missing/incomplete changed-item rustdoc remains a hard blocker. `architecture/references/languages/rust-core.md`, Documentation, requires the same operational contract.
- **Locations:** `examples/support-desk/rust/support_desk.rs:169–181` (`answer`) and `:209–216` (`serve`); `examples/support-desk-app/rust/lib.rs:109–120` (`SupportDesk::answer`), `:251–262` (`ask`), and `:303–313` (`review`). One documentation correction boundary covers the migrated workflow.
- **Evidence:** The new `answer` sends a model POST at Rust example lines 190–197, then waits for/decodes the body at 198–205. Dropping that future after dispatch cannot establish that no model execution occurred. `serve` only records/submits evidence after `answer` returns (225–240), and exits early through `?`; its docs currently say telemetry/tickets are flushed “on return.” The HTTP app dispatches the model at 136–144, reads the reply at 145–155, and only then records the ticket at 157–162. `ask`/`review` perform verification/submission afterward. Their docs contain no interruption/partial-progress contract; `ask`/`review` still describe only “the Wyrd error” despite the new render/transport/malformed-response `ApiError::internal` paths.
- **Consequence:** A maintainer or user copying the documented application cannot tell that cancellation or a lost/malformed response can leave a completed gateway call without the ticket/check that follows, that early exit does not guarantee the documented flush, or that retrying the whole operation may invoke the model again. This is an omitted side-effect contract in materially changed Rust, not a request to add retries or stronger durability.
- **Smallest correction:** Update rustdoc on the two `answer` implementations and their changed callers to state the actual cancellation/partial-progress behavior, that a sent model call is not rolled back or proven unexecuted by losing the local response, and that the application does not automatically replay it. Qualify `serve`'s flush promise to successful completion and describe early-exit effects. Correct app handler `# Errors` to include new application failures. Reuse the source's current behavior; add no runtime machinery, API, wrapper or test harness.
- **Focused closure proof:** Source review of the complete affected docs against operation order; verify all new/materially changed Rust items remain documented. This is documentation-only proof; no behavioral test is required solely for this correction.
