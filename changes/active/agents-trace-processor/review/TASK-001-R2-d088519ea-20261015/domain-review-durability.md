## Material proposal DUR-R2-001

Classification: **REGRESSION** at the imported attribution/OTLP-ingress seam. Suggested next stable ID is `FIND-TASK-001-9` if independently confirmed; no final ID is assigned here.

**Obligation.** Bifrost design requires persisted rows to record their verified subject/current actor. The existing OTLP derived-identity owner explicitly binds authenticated publisher attribution so two authorized callers cannot collapse identical payload onto one fence and lose the second caller's attribution (`gate/mod.rs:110-119`, `:2890-2898`). This is batch identity, not a request to introduce row identity or lossless client delivery.

**Location.** `crates/vala/vala-bifrost-redux/src/gate/mod.rs:131-146` (`otlp_batch_id`) and `:975-988` (`dispatch_canonical`). Imported main materially changes `ScribeIngressFrame.attribution` and the stamps consumed at this unchanged derived-identity boundary.

**Reachable path.** A subject S exports a canonical OTLP batch directly, then an authorized delegated actor A exports the same batch for S (or actors A and B do so). `caller_auth_context` retains the verified chain; `delegated_attribution` returns `(S,S)` versus `(S,A)` while `auth.principal.id` stays S. `dispatch_canonical` hashes only that subject id plus the same tenant/table/pre-stamp logical and correlation content. Its frame nevertheless carries the different pair. The canonical projections have no server-stamped actor yet, so the correlation digest cannot distinguish these requests. Both exports receive the same batch id.

Scribe stamps the pair in `execution_lanes.rs::stamp_correlation_columns/managed_arrays`, but `preprocess.rs::logical_data_identity` deliberately excludes all managed columns, including both principal columns. Shard retained-batch lookup and the durable commit fence identify this as a replay rather than preserving the new publisher: `shards.rs::write_group`, `commit_batch_control_fences`; `vala-sql/src/queries/scribe_batch_commits.rs::ExistingScribeBatchCommit::matches_logical`, `ScribeBatchCommitResolution::AlreadyCommitted`. The first actor's rows remain, and the second export can be acknowledged without the second verified actor appearing in retained telemetry. This is first-publisher attribution winning, not cross-tenant access.

**Sibling coverage and smallest correction.** All three canonical OTLP signals use `dispatch_canonical`, over both HTTP and gRPC. Native inserts use caller-provided batch ids and must keep their existing retry semantics. Server-internal Scribe outbox frames already hash both attribution members in `scribe_outbox.rs::identify` (lines 799-803); they do not need another mechanism. Extend the existing OTLP-derived identity to bind the server-verified `Attribution` pair, reusing `auth.attribution()` rather than adding a second actor resolver, extra queue, retry system, registry lookup, or identity at Scribe consumers. Preserve same-pair replay convergence, request-id independence, tenant/table/correlation separation, and client-controlled native identities.

**Focused closure.** Extend the existing derived-OTLP-identity test to distinguish direct `(S,S)`, delegated `(S,A)`, and delegated `(S,B)` with otherwise identical batch inputs, while repeats for the same pair converge. Add one existing OTLP ingress journey case exporting identical canonical content with two authorized same-subject actor pairs, confirming each pair is retained once and replay of either adds nothing. The source cause is shared; separate trace/log/metric implementations or a broad suite are unnecessary.
