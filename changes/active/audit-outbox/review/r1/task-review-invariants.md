# Invariant review: audit outbox revision 1

## Review Findings

### Important

- **INV-REV-001 — INCORRECT** — [`crates/vala/vala-sql/src/audit_outbox.rs:296`](../../../../../crates/vala/vala-sql/src/audit_outbox.rs) violates the user-approved outbox recovery principle. `commit_tenant` treats every acquire, append, or commit error as permanent loss (`record_commit_failure` for each event), and [`AuditOutboxWriter::settle`](../../../../../crates/vala/vala-sql/src/audit_outbox.rs) then removes the entire batch from `pending`. The same non-replay behavior is made operational policy in [`architecture/operations/runbooks.md:120`](../../../../../architecture/operations/runbooks.md) and [`architecture/wyrd-security-posture.md:358`](../../../../../architecture/wyrd-security-posture.md). A transient Postgres restart, pool-acquire timeout, or temporary tenant-connection failure therefore creates a permanent audit gap even when the dependency recovers seconds later; graceful shutdown has nothing left to flush. The approved repository principle permits receipt acknowledgements and hard-kill loss, but requires batched server-owned outboxes to retain and retry work on dependency slowness. Preserve the failed per-tenant batch and its order, retry it with bounded backoff through the existing writer and connection ceiling, keep later events for that tenant behind it, and let graceful shutdown continue those retries until its deadline. Add a focused Postgres test that fails the first append attempt(s), restores the dependency, and proves the original events commit once in a gap-free chain without changing the request result; also prove shutdown drains the recovered batch before its deadline. Align the security authority and runbook with retry-on-transient-failure while retaining the accepted hard-kill window.

- **INV-REV-002 — MISSING** — Live contract and maintainer documentation still says audit persistence is transactional or can refuse operations, contrary to REQ-003 and the implemented public behavior. Examples include the served OpenAPI descriptions and rustdoc in [`crates/wyrd/wyrd-server/src/components/platform/credentials.rs:56`](../../../../../crates/wyrd/wyrd-server/src/components/platform/credentials.rs), [`crates/wyrd/wyrd-server/src/components/auth/routes.rs:333`](../../../../../crates/wyrd/wyrd-server/src/components/auth/routes.rs), [`crates/wyrd/wyrd-server/src/components/principals/routes.rs:402`](../../../../../crates/wyrd/wyrd-server/src/components/principals/routes.rs), and the authorization-code contract in [`crates/wyrd/wyrd-auth/src/callback.rs:65`](../../../../../crates/wyrd/wyrd-auth/src/callback.rs). Public Bifrost documentation still states that allowed decisions commit atomically with effects and an append failure refuses the operation at [`docs/src/content/docs/bifrost/architecture.svx:313`](../../../../../docs/src/content/docs/bifrost/architecture.svx). Repository references retain the removed “named exceptions” model at [`architecture/references/architecture/patterns.md:243`](../../../../../architecture/references/architecture/patterns.md) and [`architecture/references/doctrine/architecture-constraints.md:106`](../../../../../architecture/references/doctrine/architecture-constraints.md). Callers and maintainers are therefore told that audit failure can produce a 500 or roll back a credential/grant even though the outbox cannot return such an error. Remove the stale audit-failure/atomicity claims from the affected rustdoc, Utoipa response descriptions, public docs, and live architecture references, replacing them with the one-outbox non-blocking contract. Extend the served OpenAPI contract proof to reject audit-failure response language on the migrated routes, and run `docs:check` plus `codegen:check`.

- **INV-REV-003 — MISSING** — AC-002 explicitly requires an injected audit commit failure for the Oracle surface, but the evidence claimed at [`changes/active/audit-outbox/tasks/02-one-outbox.md:120`](../../tasks/02-one-outbox.md) cites `oracle_peer_postgres_audit_routes_security_identity_and_detail`. That test only stages two healthy events and asserts their rows at [`crates/wyrd/wyrd-server/src/oracle/peer_audit.rs:115`](../../../../../crates/wyrd/wyrd-server/src/oracle/peer_audit.rs); it injects no commit failure, does not exercise a served Oracle request, and does not assert the `bifrost` failure counter. The Gate/run journey covers Gate and verification only. Consequently the required family-specific proof that an Oracle request remains successful and observable when its audit commit fails is absent. Add the smallest existing-harness Oracle query or peer-boundary test that injects staging failure, proves the Oracle operation/result is unchanged, and observes `audit_outbox_commit_failures_total{surface="bifrost"}`. Under INV-REV-001's correction, restore the dependency and prove the retained event subsequently commits rather than asserting permanent loss.

- **INV-REV-004 — MISSING** — AC-005 requires `mise run bench:capacity` to meet every judged saturation SLO and pass the two-replica scale-out step, but neither the T02 evidence matrix nor its command record includes that lane ([`changes/active/audit-outbox/tasks/02-one-outbox.md:113`](../../tasks/02-one-outbox.md), [`changes/active/audit-outbox/tasks/02-one-outbox.md:169`](../../tasks/02-one-outbox.md)). Repository search found no candidate evidence for `bench:capacity` or AC-005. The change was motivated by a two-replica throughput regression, so unit, integration, and journey greens do not establish its scale acceptance criterion. Run the existing canonical capacity lane against this candidate, preserve the judged-step and scale-out result in task evidence, and correct any failure at the outbox owner before re-review.

## Invariant Trace Summary

- **Producer to sink:** permission owners construct `AuditEvent` values, pass an authoritative `DataTenantId` to `AuditOutbox::stage`, the single writer groups by that tenant, `tenant_conn` installs the RLS binding, and the private canonical append assigns sequence/hash state before commit.
- **Lifecycle:** receipt is immediate; pending work is bounded by event count; one tenant has at most one batch in flight; server shutdown runs after request/Bifrost drain and reports remaining pending work. The recovery break is at `commit_tenant`: a dependency error is converted to irreversible loss rather than retained retry state.
- **Publication:** freeze persists or reuses one per-tenant upper bound independently of the append head; readers project the exact range; settle monotonically advances the watermark, conditionally clears the matching bound, and deletes through the watermark in one tenant transaction.
- **Sibling consumers:** Gate, Oracle, gateway, verification, Card/admin/platform routes, and `wyrd-auth` all receive the shared process outbox in production composition. Test-only direct append helpers remain feature-gated.
- **Tenant isolation:** data-plane calls use caller/context tenant; platform-plane and unverified peer decisions use the fixed seeded `SYSTEM_OWNER`; every append transaction is opened through the corresponding `TenantConn`.
