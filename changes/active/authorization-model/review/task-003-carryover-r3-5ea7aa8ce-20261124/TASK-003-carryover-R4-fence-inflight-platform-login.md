# Keep removed platform OIDC authority invalid during an in-flight callback

After this correction, an old platform OIDC callback cannot create a browser session if its connection was removed/reinstalled while the provider was answering. Password sessions, separate API access and fresh sign-in remain available.

Reviewed prior candidate `dfb3599d5fbfb3d863ecb68382257cb30abfd79b`; R3 candidate `5ea7aa8ce310b33dc8cebb139aa5202c7b67b5a4`; cumulative base `63ee31a0205c9b59a11877d5cf571d7bd0632cd6`. Original task is TASK-003-carryover cycles12–16 under approved authorization-model revision11. Retain the original task, R3 packet, prior verdicts and [current verdict](verdict.md). Only FIND-003-carryover-12 remains open; -13 through -17 are closed.

## Diagnosed incomplete correction

REQ-018/AC-013 and security posture “Platform console browser sessions” require original connection invalidation on removal/replacement. R3S1 already includes unfinished login invalidation. The new SQL deletion correctly revokes sessions and deletes pending rows, but the callback removes its pending row before remote code redemption. While that remote wait is in progress, an operator can remove/reinstall the connection, restoring revision1. Completion then inserts a fresh session because current numeric revision1 matches the in-memory old revision1. The row deletion/revocation transaction cannot invalidate state already in memory or a session not yet created.

[Independent focused validation](oidc-closure-validation.md) traces the full path: `PlatformLogin::verify_return` / `complete_browser`, SQL `take_platform_login_state`, connection-removal owner, `PlatformSessions::browser_federated` / `create_browser` and SQL session insert. Current console regression invokes callbacks only after removal/reinstall; its valid GREEN does not cover a callback already awaiting its token response. This is incomplete closure of the existing finding, not a new finding, migration issue or requirement.

## Correction boundary

Use existing platform login/session/connection SQL ownership. Final session issuance must atomically depend on durable validity of the original login/connection so removal permanently invalidates a callback already exchanging its code. Retaining existing login-state ownership until atomic final consumption/issuance is one available existing-store approach; equivalent complete fencing is acceptable. Do not rely on an unprotected recheck or reused numeric revision alone. Leave helpers, signatures and control flow to the implementer.

Preserve browser binding, purpose, nonce/state/PKCE/issuer/subject validation, one-use callback consumption, current sequential session/pending-state invalidation, password sessions, separate CLI/API break-glass access and nonblocking audit. Do not hold database transactions or locks across remote provider IO. No new migration, persistence purpose, service or authentication engine is authorized or needed by this packet; a newly necessary material schema boundary returns SPEC_REVISION_REQUIRED.
