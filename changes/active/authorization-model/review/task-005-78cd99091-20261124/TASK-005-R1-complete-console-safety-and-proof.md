   Staging-refusal 504 diagnosis:
   - **Symptom:** inside the full `test:wyrd` lane, `pg_verification_routes::staging_refusal_recovers_the_same_enqueue_identity` panicked at `:610`. The keyed request got `WYRD_SERVER_504_REQUEST_TIMEOUT` instead of 429, and a fill also returned 504 after 30001 ms.
   - **Evidence:** the trace showed `wyrd_runtime::outbox: outbox is full; staged items were shed outbox="scribe" shed=1 max_items=3`, followed by two `/v1/verification/enqueue` responses with `http.response.status_code=504 latency=30001 ms`.
   - **Cause (test synchronization; no production defect):**
     - With capacity 3, reservations hold 2 slots and unreserved staging holds 1 (`crates/shared/wyrd-runtime/src/outbox.rs:421-423`, `:581`).
     - After its awaited target read (`crates/wyrd/wyrd-server/src/components/verification/service.rs:827`), each enqueue stages an unreserved permission audit (`:846`), reserves one slot, and stages its inputs (`:894-903`).
     - The test's gate was `outbox.pending() < 2`. `pending()` counts every unwritten item (`outbox.rs:648`), audits included, so fill A's audit plus its inputs opened the gate while fill B's target read was still pending.
     - The keyed request then took the last reserved slot instead of being refused, and fill B was refused with 429.
     - The test releases the stall only after the keyed request returns, and the keyed request waits for its acknowledgement until the stall is released. So the keyed request and fill A both hit the 30 s handler timeout.
     - This race does not need host load; load only widens the window. Reservation and shedding behave as designed.
   - **Fix site:** the test's gate (`crates/wyrd/wyrd-server/tests/integration/pg_verification_routes.rs:602`). It now waits until a probe `outbox.reserve(1)` is refused, which happens exactly when both fills hold their slots. The probe is taken and returned with no await in between, on a `current_thread` runtime, so it never holds a slot a fill needs. The doc comment records why `pending()` is the wrong signal. The other `pending()` callers in `outbox.rs` (settle, shutdown) mean "unwritten items" and are correct as they are; no other test gates this way.
   - **Diagnostician:** a read-only diagnostician was given the failing command, the trace and the diff. It independently reported the same cause, fix site and affected callers.
   - **The assertions are unchanged:** typed 429 `WYRD_VERIFICATION_429_STAGING_FULL` with `retry_after_seconds` 1, recovery under the same key, the same execution on replay, and the queue and inputs counts.
   - **Command:** `mise exec -- scripts/postgres/with-test-postgres.sh -- bash -lc "mise run db:migrate:inner && WYRD_LOG=info,wyrd_runtime::outbox=debug mise exec -- cargo nextest run --locked -p wyrd-server --test integration --run-ignored=all -E 'test(=pg_verification_routes::staging_refusal_recovers_the_same_enqueue_identity)'"`, run 5 times → 5/5 passed.
   - **Limitation:** an isolated pass cannot reproduce the original lane interleaving. The proof is the removal of the race by construction.
