## Proposed finding

### SYS-001 — MISSING: orderly deployed shutdown never reaches the SDK lifetime-drop report or final flush

**Obligation:** approved revision 8 REQ-018 and task Scenario 3 require retention/proof of the exact lifetime drop total at orderly shutdown and bounded flush/shutdown/interruption. Changed architecture text now explicitly promises it at `architecture/wyrd-design.md:1032–1035`; operations instructions tell operators to expect the total at shutdown.

**Locations:** `crates/shared/wyrd-telemetry/src/lib.rs:431–468` (production installation/ownership), `lib.rs:100–109` and `300–310` (guard lifetime), `crates/wyrd/wyrd-server/src/app/mod.rs:103–104` (actual deployed release), and newly added V3 `lib.rs:1013–1025` (proof bypass).

**Source-proven path:** configure an operator endpoint, let collector unavailability fill the stock bounded queue, then perform an ordinary graceful server shutdown or the documented diagnostic restart. `app::run` waits for serving/role drain and then executes `drop(telemetry)` and `drop(telemetry_runtime)`. `TelemetryGuard` has no `Drop` implementation. Dropping its `SdkTracerProvider` field only decrements an Arc; it does not call its explicit `shutdown(self)` method. The global subscriber installed by `init` still owns the SDK tracer. In installed `opentelemetry_sdk-0.31.0/src/trace/tracer.rs:26–28`, `SdkTracer` holds a strong `SdkTracerProvider`; `provider.rs:158–160` holds an Arc. SDK `TracerProviderInner::Drop` (`137–147`) only runs after the final reference, which the global subscriber retains through process exit. There is no other production telemetry shutdown caller in the server. Rust process exit does not drop that global subscriber. Therefore `BatchSpanProcessor::shutdown_with_timeout` is never entered and its `SpansDropped` lifetime-total log (`span_processor.rs:633–642`) never appears. Pending operator batches are also not deliberately flushed before the process exits.

**Observable consequence/materiality:** ordinary rolling replacement or the newly documented investigation/restart workflow silently omits the promised final loss accounting after real collector failure or saturation; buffered diagnostics may disappear even on healthy orderly exits. Request availability and tenant outbox behavior remain intact, but the explicit operational recovery/evidence guarantee fails. Although the latent guard behavior predates this diff, it is directly in scope because this task newly requires and asserts deployed shutdown reporting and supplies a test that bypasses the failing lifecycle owner. This is not unrelated hardening.

**Smallest testable correction and burden:** make the existing `TelemetryGuard` drop behavior honor its existing documented contract: shut down its retained SDK provider exactly once using the existing stock provider shutdown path, preserving explicit `shutdown` and no-provider behavior. Keep the application's current ordering after role/outbox drain and retain SDK timeout/error handling. This is a small local lifecycle correction, not a new runtime manager, process-kill policy, queue or retry implementation. Explicit shutdown must avoid double invocation after the guard gains drop behavior. No public policy or architecture revision is needed. Calling shutdown only from one downstream serving path is insufficient because the shared guard already promises drop cleanup and both production target modes retain it.

**Focused closure proof:** retain a tracer/subscriber reference as production does; drive a stock processor through saturation with a controlled exporter; release the guard through the production lifecycle action rather than directly shutting down a test-local provider; assert SDK first warning and exact shutdown total, buffered export/exporter shutdown when available, and bounded return when exporter remains stalled. Preserve explicit guard shutdown/no-provider behavior and tenant-drain ordering. Reuse the existing controlled exporter and SDK, without a new harness or live-drop metric. The test must fail before the correction despite the retained tracer reference.
