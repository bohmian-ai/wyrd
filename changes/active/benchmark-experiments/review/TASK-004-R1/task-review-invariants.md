## Proposed findings

### INV4-01 — MISSING: engine clocks still include request drain as measured work

**Obligation.** REQ-006/007 and TASK-004 Scenario 5 explicitly require a fixed measurement CPU/work window ending at admission stop, with later completions counted only in cohort latency and separate drain accounting.

**Locations and value flow.**

- Verification `run.rs:270` (`Bench::closed`) opens `Window`, awaits `drive`, then closes it. `drive` at line 942 stops *starting* requests at a deadline but awaits every request and `JoinSet` result; its `Measured::record` call at line 954 unconditionally passes `late = false`. All acknowledged calls become `verifications` at line 340.
- Gateway `run.rs:553` opens `Window`, awaits closed-loop `drive` (line 656), then closes it. That driver also waits for every task. `Observed::repetition` credits every answered request; only later capture settlement is called drain.
- Bifrost `query/isolated.rs:123` opens the window, awaits `Bench::drive/drive_with` or `Sender::closed_loop`, then closes it at line 176. Those drivers await outstanding requests (`query/run.rs:244`, `373`, `574`) and count all successful queries/rows/bytes.
- Gateway L2 `capacity.rs:947` opens the window; `Driver::drive` awaits `open_loop`, whose final `slots.acquire_many(cap).await` at line 351 waits until every sent call finishes. The resource window closes only at line 975. `Observed::repetition` at line 642 credits every answered call and records no after-window count.
- Shared `Window::close` (`capacity.rs:348`) additionally reads CPU after awaiting the final metrics scrape, despite recording wall seconds before that scrape. `ResourceWindow::freeze` already exists, but these paths do not call it at their declared admission stop.

**Reachable failure.** A 10-second closed-loop measurement sends a request at 9.9 seconds whose server execution completes at 12 seconds. The current L1 path reports approximately 12 seconds and includes that request and its CPU in throughput/efficiency. It records neither the 10-second completed-work value nor the 2-second request drain. The same occurs routinely for Gateway L2's paced streams started near the end of its fixed schedule. A slower tail changes the measured denominator and work population instead of remaining cohort latency outside that denominator. This is ordinary boundary-crossing work, not adversarial load or an exotic duration.

**Consequence/materiality.** The required W/T/P, W/C and C/W values do not describe the approved fixed measurement interval, and records cannot distinguish late work. This directly invalidates the purpose of TASK-004's accounting conversion. Including both late CPU and late work does not satisfy the requirement; it silently changes the experiment window.

**Minimum correction.** Reuse existing `Window`/`ResourceWindow` and owned driver task sets. Freeze resource/work readings at the declared stop instant independently of awaiting outstanding calls. Keep later successes/bytes/rows apart, finish the already-admitted cohort under the existing bounded lifecycle, and record its drain duration and counts. Preserve latency for those calls and existing cancellation/cleanup ownership. Do not add a clock service or another measurement harness. Fix the shared close ordering where its final scrape extends CPU past wall time. This necessarily reaches each driver's result accounting because the current result types discard late/in-window distinction; a downstream denominator adjustment cannot recover it.

**Focused proof.** At a real driver/measurement seam with a controlled slow final request, assert CPU/work freeze at admission stop, the final completion increments only drain work, cohort latency includes it, and no request is admitted afterward. Exercise representative read/write and streamed Gateway callers plus the shared window close ordering. The current V4 synthetic histogram test alone cannot close this finding.

### INV4-02 — INCORRECT: phase and offered-work identity disappear before collection

**Obligation.** REQ-007 and TASK-004 Scenarios 1/5 require closed case/repetition/phase/outcome populations, complete measured cohorts including their late final outcomes, matching scan facts, and counts that incidental work cannot satisfy.

**Producer-to-consumer evidence.**

1. `wyrd-client/src/transport/trace.rs:35` defines only BENCHMARK_CASE, `with_benchmark_case` at line 66 scopes only that value, and `headers` at line 124 emits only the case header. No benchmark caller sends `x-wyrd-benchmark-phase`. Verification and Gateway workload calls do not attach a benchmark case either. Bifrost mixed queries alone use a case helper (`query/competing.rs:535`); native writes/OTLP `Sender::send` and `authorized` (`query/run.rs:191`, `590`) attach no benchmark classification.
2. The receiving owner correctly supports case and phase (`timing.rs::label_request`), but absent values become `none`. The histogram is therefore unable to distinguish capacity-admitted work from overload-admitted work after either finishes.
3. Verification `Ended::between/overhead_p99` (`verification/run.rs:733`, `752`) judges observations *recorded* between phase snapshots. Gateway `Capacity::step` (`gateway/capacity.rs:966`, `1030`) does the same for capacity/recovery. Bifrost `Competing::competing` (`query/competing.rs:358`) builds completion-time slices and `server_percentile` (line 555) explicitly selects phase `none`.
4. `Population::collect/expect/count` (`capacity.rs:534`, `591`, `664`) checks only boundary + case, merges phases/outcomes, and can accept a lower bound. Bifrost L2 `expected` (`query/competing.rs:428`) intentionally uses unlabelled native/OTLP counts and lower-bound collection at line 342 because lane traffic reaches the same boundaries. Task execution evidence acknowledges this limitation rather than closing the explicit constraint.
5. Oracle `QueryTelemetryGuard::finish` (`oracle/mod.rs:571`) records scan facts at Oracle completion; public `QueryTiming` records timing later at body handoff/drop (`query/routes.rs:130`, `513`). `Population::scanned_per_query` (`capacity.rs:780`) averages whichever scan records fell in the interval, without requiring their count to match successful public query timings for the same population. Bifrost L2 takes scans from the window-end slice, even though the final drained population is separately read and then discarded for judgment.

**Realistic failing scenario.** During Bifrost's 150-second L2 capacity phase, the last 20 point queries queue or stall until just after capacity ends. The capacity snapshot contains the earlier fast requests, so its p99 can pass. The slow admitted queries land in overload, where the capacity SLO does not judge them. Once they finish, whole-window lower-bound reconciliation succeeds: there is no missing evidence reason. Identical phase-crossing exists in Verification and Gateway. At final window end, Bifrost recovery's slow outstanding requests can fall outside every judged latency slice even though collection later sees them. With native writes, independent client-queue activity is guaranteed to share the same unlabelled distribution and can mask a missing offered-work count; no per-cohort expected check can distinguish them. Scan facts may also straddle a snapshot earlier than the corresponding public handoff, so even correctly labelled query classes do not ensure matching phase populations.

**Consequence/materiality.** Tail work can move out of the phase that offered it, allowing favorable latency evidence and unreconciled class/phase/scan counts without INVALID. This is exactly the interleaving and boundary-crossing case explicitly requested by the task, and occurs with the supported L2 schedule; it is not a request for general tracing or per-request identities.

**Minimum correction.** Use the already approved closed benchmark metadata from actual producers through their existing authenticated request context, including finite repetition/phase and offered-vs-incidental identity. Preserve the existing long-lived native transport's durability/ownership while making the classified cohorts distinguishable; do not merely loosen counts because its stream currently lacks classification. Reconcile expected final outcomes and scan populations against the same finite class/phase cohort, then judge that cohort after bounded drain. Retain snapshot times for resource windows, but do not substitute completion-time slices for admission identity. Keep probe/lane observations in separate closed populations. This is one missing upstream population authority, not a reason to add request IDs, a trace collector or separate per-engine guards. Extending only `expect` cannot recover identity that producers never sent.

**Focused proof.** Drive interleaved classes with a slow capacity-admitted request completing in overload and a recovery-admitted request completing after stop. Assert each remains in its admitted cohort's latency and exact outcome/count reconciliation while only early completions contribute work. Include unrelated native/lane activity and scan-vs-handoff delay; neither unrelated work nor another phase can close an expected-count gap. Exercise real outbound metadata construction and receiving context, not only hand-labelled spans as V1 currently does.

### INV4-03 — MISSING: server distributions and their reconciliation evidence are discarded

**Obligation.** REQ-007 requires full interval distributions under target for percentile regeneration, recorded percentile rank/value bounds, outcome populations and maximum; TASK-004 requires v2 method, boundaries and count reconciliation and both measurement/drain windows.

**Source evidence.** `Distribution::buckets` (`timing.rs:727`) exposes a complete interval representation, but has no caller in wyrd-testing. `Population` contains in-memory series/scans only (`capacity.rs:519`); `validate` (`capacity.rs:736`) transfers just invalid strings and a human-readable total-count health string. `percentiles` transfers selected summary readings. `Reading::quantile` (`experiment.rs:1117`) drops `Quantile::rank`, and `Repetition` (`experiment.rs:1247`) stores only scalar readings, CPU/resource fields, arrivals and prose. It has no timing snapshot, process/generation, interval distribution, per-outcome reconciliation or measured/cohort window record. `Artifacts` (`experiment.rs:1541`) stores only a directory and profile note; no code writes histogram artifacts. Server shutdown therefore destroys the only complete evidence. No engine records a maximum distribution value.

**Observable consequence.** After any successful benchmark exits, the stored p99 can be reread and printed, but it cannot be independently regenerated from retained interval buckets as AC-001 requires. Neither a missing failure-duration series nor an incorrect cohort association can be audited from the retained record: only selected successful percentiles and aggregate prose survive. Reading v2 does not recover discarded information. V5's fabricated scalar-bound round trip proves presentation stability, not the required evidence retention.

**Materiality.** Auditable timing evidence is the stated outcome of this task, and full-distribution retention is an explicit acceptance requirement. This fails on every successful run, independent of rare failures, clock resolution or measurement length.

**Minimum correction.** Extend the existing shared population-to-record/artifact handoff, using the already available bucket representation and existing experiment artifact directory/publication handling. Persist the complete selected interval timing/scan distributions with finite population keys, method/process identity, actual window boundaries and reconciled admitted/completed/drain/outcome counts. Keep percentile rank and exact inclusive value bounds plus required maximum in the machine-readable evidence. Preserve v1 reader/report behavior and stored-summary report regeneration without requiring raw artifacts. No second report framework, collector, baseline migration or new dependency is needed. A health string or more percentiles cannot replace the omitted distribution and counters.

**Focused proof.** Run a representative real collection through the shared persistence path, terminate the server, rebuild p50/p95/p99/max and ranks from its retained buckets, and match stored bounds and per-outcome/cohort counts. Include zero and a late/failure outcome, and prove write failure cannot yield a successful completed record. Reuse existing record publication tests for atomicity rather than inventing another publication owner.
