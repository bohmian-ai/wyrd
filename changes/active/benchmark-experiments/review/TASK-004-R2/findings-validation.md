- **Discovery IDs / status / classification:** prior B-001 and INV4-01; current INV4-R2-01; **REVISED**, INCORRECT/MISSING. This is incomplete closure of the existing stop boundary, not a new clock requirement.
- **Violated obligation:** original TASK-004 same measurement clock and Scenario 5; REQ-006/007 same-window work/CPU/T, separate drain and final cohort. Required work includes retained Arrow MiB and Gateway durable capture bytes in both provisioned-vCPU and CPU-second normalizations. Bifrost `Measurement meanings` defines retained bytes as inserted Arrow memory, not acknowledged payload or estimated rows.
- **Exact locations:** shared `crates/wyrd/wyrd-testing/src/capacity.rs:371` (`Window::measure`), `:411` (`until_stop`); binary `src/bin/capacity/query/isolated.rs:190,238`; `query/competing.rs:174,340,380`; `gateway/run.rs:581,604`; `gateway/capacity.rs:360,1014,1084`; `verification/run.rs:907`. All binary locations share the `crates/wyrd/wyrd-testing/` prefix.
- **Source proof and affected consumers:** `until_stop` freezes resources then awaits unfinished work at lines 423–425. `Window::measure` awaits that entire operation before its sole closing metrics read at line 391; the returned `Metrics` and `Usage.telemetry` therefore include request drain. Bifrost L1 and L2 difference the returned inserted-byte counter against their opening scrape into `retained_mib`. Their required MiB/T/P and MiB/C consumers are `query/mod.rs:588–600,1229–1230`. Gateway L1 and L2 build `Durable::between(baseline, ended)` from the same post-request-drain scrape, expose `capture_bytes`, and derive B/T/P and B/C at `gateway/mod.rs:472–490`. Final `last`, settlement and integrity reads have a separate legitimate correctness purpose and must remain.
- **Actual admission sibling proof:** Bifrost open-loop checks `due < end` before sleeping, Verification checks scheduled stage offsets, and Gateway sleeps to each planned offset then checks only lateness/capacity. None rejects a new admission when the actual clock has crossed the declared end after waking. Gateway's `MISS_AFTER` explicitly permits a small late wake; Bifrost and Verification also admit it. The shared Window documentation assigns this invariant to its work future, so freezing CPU alone cannot enforce it.
- **Meaningful scenario and consequence:** a final admitted Bifrost write inserts Arrow bytes only after the ten-second stop and then acknowledges. Rows/wire bytes are now correctly late, but retained bytes are divided by ten seconds and the CPU sampled before that insertion. Similarly, a final Gateway stream stages capture during drain and the outbox persists it before the returned scrape; those bytes improve measured efficiency without the corresponding CPU. Separately, an ordinary slightly late timer wake can launch another scheduled arrival after CPU froze. These are routine tail/scheduling paths in supported workloads and violate the explicit clock boundary.
- **Accepted portions preserved:** CPU freezes before scrape/drain; final request latency survives; late request/row/wire counters are separate; existing engine schedules, cancellation, task ownership and durable acknowledgements remain appropriate. This finding does not reopen HDR collection, cohort retention or correctness settlement.
- **Smallest correction and burden:** complete the existing `Window` measurement handoff so the practical stop-boundary server work-counter scrape is distinct from the later drained/cohort/correctness scrape. Route retained/capture byte work to that measured boundary. Reuse the current metrics/resource owners; do not estimate retained bytes from acknowledged rows, rewrite durable work, or introduce a synchronized clock/collector. In the existing three open-loop admission loops, enforce actual end after waking and before admitting, preserving scheduled/missed accounting and draining already admitted work. These local producer boundaries prevent invalid work attribution; downstream denominator guards cannot reconstruct it.
- **Focused closure proof:** use an existing driver-to-Repetition seam with final write/capture released after CPU freezes: measured retained/capture bytes and both required normalizations must not gain the drain work, while final integrity/cohort and late accounting retain it once. Cover sibling L1/L2 conversions by the same source handoff. A controlled final scheduled wake after end must launch nothing and retain missed/accounted scheduling; already admitted work still drains. The current freeze-callback and synthetic late-row tests do not cover these omitted byte/admission consumers. No broad benchmark suite is needed for this correction.
