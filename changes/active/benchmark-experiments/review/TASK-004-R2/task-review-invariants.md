### INV4-R2-01 / FIND-TASK-004-1 — required byte work still includes drain

**Classification:** INCORRECT, incomplete original fix.

**Obligation:** REQ-006/007, original TASK-004 Scenario 5 and R1 F1 require completed work and CPU/T on the measurement clock, with drain work separate. The approved matrix explicitly includes retained Arrow MiB and Gateway capture bytes per CPU-second and per provisioned vCPU. Bifrost authority defines retained bytes as actual memtable bytes inserted, not acknowledged payload or a row-count estimate.

**Producer-to-consumer proof:**

1. `capacity.rs:384–391` awaits `until_stop`. That function freezes CPU and then awaits unfinished `work` at `:423–425`. Only after work has drained does `Window::measure` scrape metrics. It returns this post-drain scrape as the only closing `Metrics` and uses it for `Usage.telemetry` (`:402–404`). Thus the changed shared owner freezes CPU correctly but does not freeze server work counters with it.
2. Bifrost L1 `query/isolated.rs:190–192,238–241` takes that returned `after`, subtracts the opening `INSERTED` counter and sets `retained_mib`. L2 `query/competing.rs:340–344,380–381` does the same. Their row and OTLP-wire counters now exclude late acknowledgements, so they no longer share the byte numerator's interval.
3. `query/mod.rs:588–600` derives required MiB/T/P and MiB/C from `retained_mib`; L2 equivalents are `:1229–1230`. These consumers use the frozen measured seconds and CPU.
4. Gateway L1 `gateway/run.rs:581–586,598–605` similarly builds `Durable::between(baseline, ended)` from the post-request-drain scrape. L2 `gateway/capacity.rs:1014–1016,1084` does the same. `Observed::repetition` exposes `capture_bytes`; `gateway/mod.rs:472–490` derives its required B/T/P and B/C. Later `last`/integrity/settlement scrapes have a legitimate cohort-correctness role; they must stay separate from the measured work counter boundary.

**Reachable failure and consequence:** A final in-flight Bifrost write inserts its retained Arrow bytes after the 10-second stop, then returns its acknowledgement. Its rows and wire bytes are late, but its retained bytes are still divided by 10 seconds and the pre-insertion CPU. Similarly, Gateway's final stream can stage capture while draining and the outbox can persist it before the returned scrape. Those durable bytes count toward pre-stop efficiency. A slower drain can therefore improve required byte efficiency even though the counted server work happened outside the CPU interval. This is routine supported tail work, not unusual external input or hypothetical host stress.

**Related actual-stop path:** Bifrost `competing.rs:174–190`, Verification `run.rs:907–937`, and Gateway `capacity.rs:360–379` gate by a scheduled due offset and then sleep. None checks the actual admission clock against end after waking. A final timer waking a few milliseconds past stop can still launch new work after CPU froze; Gateway allows it if lateness is within `MISS_AFTER`. The shared `Window::measure` documentation correctly assigns “admit nothing after stop” to its work future, but those open-loop futures do not implement that invariant. This is the existing F1 stop boundary, not a request to change scheduling/rates or task ownership.

**Minimum correction and burden:** Complete the existing shared measurement owner so measured server work counters are captured at the stop boundary and remain distinct from the final cohort/correctness scrape. Route the existing retained/capture byte conversions to those measured counters, keeping late byte work explicit if reported. Do not substitute acknowledged-row estimates for retained Arrow bytes, alter durable acknowledgements, or remove final integrity/drain scrapes. Enforce the actual stop in the existing admission loops while preserving missed-arrival accounting and draining admitted tasks. This is a bounded extension of existing owners; a new collector, clock service or driver redesign is unnecessary.

**Focused closure:** At a real measurement-to-Repetition seam, release a final write/capture only after CPU freezes and assert that measured retained/capture bytes and their normalizations stay unchanged while the final cohort/integrity and late counts include it exactly once. Check the sibling L1/L2 conversions. A paused-clock last arrival waking after end must not launch; already admitted work must still finish. The current shared freeze callback and synthetic late-row tests do not exercise either omitted consumer boundary.
