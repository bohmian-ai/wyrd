## Challenged scenario and materiality

The cross-tenant producer scan still chooses the oldest 64 tenants (scheduler.rs:82; verifier_executions.rs:678–699), while the local claim exclusions apply within each chosen tenant. Thus 64 outstanding oldest tenants can delay preparation for tenant 65 until earlier handoffs progress. I did not retain this as a material regression finding: the bounded oldest-first scan predates this candidate, retained-due/blockage scenarios already exist, completion releases the claims, and the approved task explicitly reuses existing bounded pass/capacity limits. No supported scenario was established where this candidate permanently strands independently executable work after recovery. The tests demonstrate same-source exclusion and independent work, but do not establish fairness for an arbitrary population beyond the existing scan bound. This observation does not prescribe pagination, a new scheduler, or a stronger availability guarantee.
