## Limits and rejected expansion

- This is a read-only static concurrency audit. No builds, tests, benchmarks, service startup or synthetic load were run. Candidate task evidence claims passing focused tests; this report does not independently claim their execution. There is no measured contention or scheduling-overhead conclusion.
- The single registry mutex includes HDR snapshot copying and can delay producers. The approved specification explicitly recognizes synchronization cost and selects no throughput target; source alone does not prove a material liveness regression. No per-series lock redesign is proposed.
- Simultaneous calls to `install()` could race between the enabled check and global installation; only one can win, and the other returns the recorder installation error. Traced supported benchmark startup calls it once before producers. Concurrent live installation is not a supported workload path and is not grounds for an expanded lifecycle protocol.
- `WyrdServer::new` retains a late-install fallback in BoundServer serving; the production benchmark runner passes a backend installed before boot, while the test harness ordinarily disables its per-server metrics listener and the benchmark journey installs explicitly. The generic startup behavior belongs to the behavior/system reviews; this concurrency pass does not infer an unsupported live recorder switch from that fallback.
- Counter saturation, allocation failure and panic recovery do not establish a supported concurrent workload failure here. This report does not prescribe unrelated overflow hardening or recovery machinery.
