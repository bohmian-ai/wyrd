### S-1 — Mandatory changed-item rustdoc gate remains incomplete

- Classification: **VIOLATION**, mandatory repository gate.
- Rule: root AGENTS Code: “Every new or changed Rust item has rustdoc ... `# Errors` on fallible items ... Missing rustdoc blocks merge.” `agent_docs/rust.md` Rustdoc explicitly includes fields, private helpers, test helpers and tests.
- Exact locations and proof:
  - `crates/wyrd/wyrd-testing/src/bin/capacity/verification/run.rs:1113–1122`: new `acknowledgements` returns `Result<Distribution, String>` and can return the histogram selection/merge error, but its three-line doc has no `# Errors`.
  - `crates/wyrd/wyrd-server/src/app/server.rs:95` and `:393`: both renamed/retyped `metrics: Option<MetricsBackend>` fields lack rustdoc. Their semantic state changed from a Prometheus render handle to backend ownership transferred through constructor/bind/run.
  - `crates/shared/wyrd-benchmark/src/lib.rs:200`, `:245`, `:271`, `:1139`: docs still link to `enable`, which this change removes in favor of `install`/`enabled`; there is no such item in the new crate. These are the owner docs readers use to understand opt-in recording, including newly added/moved `record_timing`.
- Consequence/materiality: explicit merge gate fails; private backend ownership and the acknowledgement diagnostic's failure behavior are undocumented, and the activation links point at a removed operation. This does not allege an observed runtime failure.
- Smallest correction: document only these changed items, describe the backend fields' ownership/absence semantics, add the acknowledgement `# Errors` covering its actual selection/merge failures, and replace the stale activation references with the actual install/enabled contract. Preserve behavior; no abstraction or new test is needed. Check the rest of the changed-item rustdoc inventory while making this bounded correction, without documenting unrelated old items.
- Closure proof: source inspection of those docs against the signatures/call paths; focused documentation/link verification for the changed benchmark owner if available. Format check suffices for the comment-only source correction; no benchmark or broad journey rerun is justified by documentation alone.
