## Y-001 — INCORRECT: raw snapshot conversion erases refusal evidence before setup/drain

**Authority.** REQ-003 requires overflow and missing evidence to be explicit. REQ-004 includes correctness bookkeeping, backlog and health and forbids silently substituting zeros or weakening validity. TASK-001 scenarios 3–4 explicitly require refused/overflow evidence and setup/polling/drain. This is an acceptance obligation, not a request for speculative availability hardening.

**Location.** `crates/wyrd/wyrd-testing/src/release_server.rs:358–359,568–594` (`LocalServer::metrics`, `Metrics::of_snapshot`). Siblings: `gateway/run.rs:259–269`, `verification/run.rs:933–956`, `query/mod.rs:1619–1636`.

**Source-proven path.** `Registry::metric` refuses registration at `MAX_METRIC_SERIES`, increments `dropped` and returns no series; the standard recorder supplies a no-op handle. `Metric::gauge` refuses a non-finite update, increments `rejected` and retains its previous value. Both failures reach successful JSON snapshots. `of_snapshot` copies present numeric values while dropping all `dropped`/`rejected` evidence. `Metrics::sum` returns zero for an absent family. Gateway `settle` therefore returns zero remaining work when active/pending series were refused; Verification drain similarly accepts zero backlog. Query `Residence::all_published` accepts missing live-memory/staging/claim readings as zero when any published file exists. A refused update can likewise present a stale zero as current state.

**Reachability and consequence.** These explicitly required recorder failure states reach the benchmark's normal successful snapshot path and real setup/drain callers. No claim is made that the healthy Gateway journey or ordinary declared workload exhausts 1024 series. The defect is a successful setup/drain decision from telemetry already known to be incomplete. `Population` invalidates refusals within measured intervals, but these raw consumers bypass it; setup/warmup and final shutdown reads do not necessarily receive a later population validation. Interval refusal deltas also do not automatically invalidate a later interval for an earlier refusal. This proves false healthy/settled evidence, not universal whole-experiment false PASS or actual loss of accepted server data.

**Smallest correction.** Validate failure metadata at the existing shared benchmark snapshot-to-metrics boundary and return an error before setup/drain consumes known incomplete readings. Keep absent-unused-family behavior for valid snapshots and production parser contract tests. A cumulative read can conservatively refuse recorded drops/rejected updates because it cannot reconstruct a missing/current gauge. Reuse existing snapshot fields and `Result` propagation through `LocalServer::metrics`; avoid per-engine guards, alternate recorders, retries or lifecycle services. Separately callable conversion must not offer an accidental validity bypass.

**Focused proof.** In-process snapshot fixtures with `dropped > 0` plus absent backlog gauges, and a present stale-zero gauge with `rejected > 0`, must produce failed evidence rather than successful zero backlog. Keep the healthy six-consumer proof and histogram-count preservation. No workload or service is needed to prove the conversion boundary.
