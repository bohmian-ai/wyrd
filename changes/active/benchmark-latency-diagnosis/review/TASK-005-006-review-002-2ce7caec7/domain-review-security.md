## Proposed finding SEC-R2-1 — malformed tenant credentials change stable public error classification

- **Classification:** REGRESSION / VIOLATION.
- **Obligation:** spec INV-001 preserves stable errors, and REQ-021 preserves authorization semantics. Server error codes and their remediation are machine-readable primary contracts under root AGENTS.
- **Changed source:** `crates/wyrd/wyrd-server/src/components/auth/token_extract.rs:95–106,159–172`; shared producer `crates/shared/wyrd-auth-verify/src/lib.rs:803–826`. Consumer mapping `crates/wyrd/wyrd-server/src/http/error.rs:237–257,261–291` is unchanged but newly reached by these tokens.
- **Source-proven scenario:** present a well-formed compact JWT, signed with a known deployment key, with a valid principal tenant but malformed `permissions` (the existing verifier test at auth-verify `:1651–1662` constructs exactly such a token). At prior candidate, the HTTP helper deserializes complete AccessTokenClaims and fails, yielding `401 WYRD_AUTH_401_UNAUTHENTICATED` with tenant-plane detail before verification. At candidate, unverified_tenant succeeds; verify_on invokes jsonwebtoken decode of full claims, whose JSON decode failure becomes AuthError::Jwt; server jwt_error_to_wyrd maps Json to `400 WYRD_AUTH_400_BAD_TOKEN_FORMAT`. An unavailable verifier instead now returns `503 WYRD_AUTH_503_VERIFY_UNAVAILABLE`, whereas the prior pre-read still returned 401 for that malformed claim set.
- **Observable consequence/materiality:** a client handling the existing authentication refusal now receives a caller-format error (or retryable infrastructure refusal when verification is unavailable), with different stable code, status and remediation, solely because a performance optimization moved parsing. Both candidates refuse access; this is a supported public negative-flow classification regression, not a claimed permission bypass. The user disclosed the changed validation stage, but stage disclosure does not itself amend INV-001 or authorize these wire changes.
- **Sibling paths:** token-exchange routes now use the same shared helper but have their own bad-subject mapping and DelegateToken verification; Gate previously read only tenant and continues to map failed verification to unauthenticated. Do not globally change AuthError mapping, since wrong signature, issuer, audience, tenant and malformed JWT envelope have their established independent errors.
- **Smallest correction:** preserve the existing HTTP classification at its current request extraction/error owner. Keep the cheap tenant-only success path, but before exposing failed verification/unavailable outcomes, apply the existing full-claim shape precheck classification to the original token. Thus a successfully verified request still decodes full claims only once, and malformed-claim requests retain the previous refusal without weakening signature/tenant checks or modifying global JWT error mapping. Alternatively restoring the previous pre-read is smaller mechanically but loses the successful-request optimization; no new auth cache, error profile or public contract is needed. Verify affected token-exchange classification too and preserve its established error through its existing owner if the same gap appears; mere movement of a pre-SQL refusal is not separately claimed as a defect.
- **Focused closure proof:** through the existing server HTTP authentication fixture, submit the signed malformed-permissions token and assert prior stable 401/code and no authenticated handler execution, both with verifier configured and unavailable. Check malformed envelope still returns its established format error, valid-shape bad signature remains invalid-token, valid credential succeeds, and wrong tenant/surface still fails. Reuse existing key/claim/verifier fixtures; no full journey aggregate or new harness. The existing verifier malformed-permission unit test alone proves refusal but not the HTTP classification.
- **Correction burden:** bounded error-path classification and focused negative assertions at one existing HTTP owner. It does not require full claims parsing on successful cache hits or changing public errors for other verifier failures. This proposal must receive independent validation; no stable FIND ID is assigned here.
