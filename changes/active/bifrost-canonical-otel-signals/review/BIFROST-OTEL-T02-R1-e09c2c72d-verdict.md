### FIND-02-R1-3 — MAJOR: the exact Parquet schema fingerprint is nondeterministic and omits layout identity
- Obligations: REQ-003, REQ-004, INV-003, INV-008, AC-008, AC-011; remediation Scenarios 5 and 6; closeout correction `b44200d43`.
- Locations: `crates/vala/vala-bifrost-redux/src/schema/fingerprint.rs:19`, `crates/vala/vala-bifrost-redux/src/schema/fingerprint.rs:66`, `crates/vala/vala-bifrost-redux/src/tables/fields.rs:234`, `crates/vala/vala-bifrost-redux/src/parquet/memory.rs:133`, `crates/vala/vala-bifrost-redux/src/parquet/memory.rs:212`, and `crates/vala/vala-bifrost-redux/src/parquet/memory.rs:326`.
- Scenario: a nested canonical schema is reconstructed after restart or from a separately built schema with equivalent metadata inserted in a different `HashMap` order. `from_arrow_schema_exact` hashes `Debug` output of each top-level `DataType`; nested `Field` debug includes unordered metadata, while top-level field nullability and metadata are not hashed at all.
- Consequence: an identical persisted layout can receive a different envelope/staging identity and fail recovery or publication, while a nullable/non-nullable top-level drift can collide and pass a decode-side comparison.
- Supporting evidence: the exact implementation hashes only top-level name plus `format!("{:?}", field.data_type())`. The same module explicitly documents that nested `Field` debug metadata-map order is unstable. Canonical nested fields carry multiple metadata entries. Parquet footer construction, projection validation, and accumulator observation use this value as the decode identity.
- Counterevidence: the helper correctly distinguishes raw variants such as `Utf8` and `LargeUtf8`, which fixes the normalized-catalog collision. That does not make the representation deterministic or include top-level nullability.
- Ponytail recommendation: keep the normalized catalog fingerprint unchanged. Replace exact-mode debug serialization with one deterministic recursive layout hash that preserves exact Arrow variants, field/child names and order, and nullability at every level; ignore non-layout metadata or sort it deterministically if it is part of the intended decode identity. Reuse SHA-256 and the existing schema traversal patterns; add no dependency, registry, or third fingerprint type. Keep the change limited to the existing exact Parquet memory-envelope/schema-key callers.
- Required outcome: identical reconstructed nested schemas always have the same exact fingerprint; every decode-relevant type, order, name, child shape, and nullability change produces a different fingerprint; normalized Iceberg/catalog identity remains unchanged.
- Closure verification: add focused fingerprint tests proving exact `Utf8`/`LargeUtf8`, `Binary`/`LargeBinary`, and nullability differences; prove metadata insertion order does not change the result; and prove a written footer validates against an independently reconstructed identical schema while refusing layout drift. Run the exact tests via `mise exec -- cargo nextest run --locked -p vala-bifrost-redux --lib --features test-support,bench-support -E 'test(=...)'`, then `mise run test:bifrost:integration:redux`.
