- Fork proto test `cases/plans/scalar_subquery.rs:282-316` serializes and decodes the native relational plan and still refuses duplicated rows. This establishes the new registry-based aggregate survives ordinary physical encoding; it does not assert a newly invented protocol.
- Real peer journey `peer_network/live_subquery.rs:233-272` provisions one client, supplies one published and one live duplicate scalar input, and requires execution refusal for both Filter and Projection. It cannot pass on successful set-join results. The shared client is reused instead of weakening an assertion or adding retries. It does not individually measure memory cleanup after the new negative queries.
- Existing remote literal/footer journey and representative live join remain, and committed R2 evidence records their focused commands passing alongside the corpus/mapper/codec checks. These pin the R1 bounded-transfer behavior; no runtime-performance measurement is inferred from optimizer comments.
- Existing Analytical peer journeys qualify cancellation, loss after output, graph release, deadline and graceful shutdown of the unchanged lifecycle owners. The committed previous Oracle lane evidence is useful supporting coverage; no fresh whole-lane or external-environment run was performed in this discovery review.

It remains a verification limit; no candidate source shows a new owner/leak, and no assertion/timeout/retry/skip has been modified to hide it.
