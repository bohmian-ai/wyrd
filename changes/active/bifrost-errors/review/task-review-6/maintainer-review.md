## Root owner and existing alternatives

The latest fixed-value logic is a pure classification rule, with no retained resources or identity. A private function next to `Filter::is_scalar` is appropriate; wrapping it in a new service/trait/type would add no ownership. The rule cannot simply reuse “not a column” or generic absence of columns: its contract includes outer references but excludes opaque/volatile forms. Native `Expr::apply_children` already owns expression-child enumeration; using it eliminates manual enumeration of CASE conditions, branches and optional children while the positive list controls which operations may establish invariance. The generic walker is inspected in `expr/src/tree_node.rs:46–116` and includes both CASE branches/conditions, BETWEEN endpoints, IN elements and LIKE operands.

The two materially relevant consumers remain discoverable: `LogicalPlan::max_rows` feeds the correlated analyzer's at-most-one acceptance in `logical_plan/invariants.rs:188`, and the uncorrelated shared rewrite tests that bound before adding `single_value` in `scalar_subquery_to_join.rs:383–405`. Neither consumer acquired a query-shape patch. The aggregate and physical-expression changes extend native owners at the level that knows their runtime invariants. The Wyrd leaf only snapshots native predicates at the execution boundary it owns.

The latest matrix puts a variable probe into 23 pure expression shapes, checks both equality orders, and includes fixed outer/literal probes plus input-column/volatile negatives. This is a readable small table rather than a new testing abstraction. SQL controls add exact-row valid correlated queries and invalid siblings; the existing peer join journey adds the grouped key CASE query including an unmatched row. These tests make the maintainer-visible contract substantially clearer than a single reproduction.
