## Diagnosis and required correction

1. **FIND-TASK-001-1 — listing refusals become accepted Degraded results.** The Scribe gRPC listing handler returns distinct credential, tenant, ticket, and binding refusals (`wyrd-server/src/grpc/scribe_tail.rs:66-135`). `TonicTailReadTransport` erases their status to `TailReadError::State` (`vala-bifrost-redux/src/scribe/tail_rpc.rs:255-332`); `RegistryTailStreamDiscovery` further erases connection, credential, ticket, identity, and RPC failures (`wyrd-server/src/oracle/tail_discovery.rs:50-184`). Oracle degrades every non-deadline discovery error (`vala-bifrost-redux/src/oracle/mod.rs:3498-3542`). Thus a trust-boundary refusal can yield published rows with a valid Degraded terminal. Preserve a closed error reason through the existing private transport/discovery boundary, then let Oracle's single query-terminal decision degrade only genuine ready-Scribe availability loss. Fatal credential, ticket, tenant, binding, malformed response, audit, cancellation, and deadline failures must fail. Keep ordinary listing outage degradable; avoid string matching and public selectors.

2. **FIND-TASK-001-2 — fragment faults become availability.** `ScribeTailResolver` and its follower reduce signed schema/projection mismatch and local open failures, including memtable capacity refusal, to string-valued resolution (`vala-bifrost-redux/src/oracle/follower.rs:1039-1058,1459-1495`). The Scribe peer maps all resolution errors to eligible source loss and pre-row execution/stream errors to unavailable (`wyrd-server/src/oracle/peer_service.rs:318-371`). Oracle then degrades these before rows (`vala-bifrost-redux/src/oracle/live.rs:493-540`). A local capacity, staged schema, decode, or integrity failure can therefore be treated as best-effort evidence. Preserve the original closed reason at the Scribe producer/follower boundary and use the existing private peer status and `DispatchError::Capacity` mechanisms. Only actual source absence or transport loss before rows may degrade; resource, schema, projection, predicate, integrity, and execution faults fail. Preserve published follower semantics and the existing late-row failure behavior. Do not add a second classifier at each consumer.

3. **FIND-TASK-001-3 — staged IO blocks the async Scribe poll.** `LiveTailBatches::into_stream` advances `StagedTailReader::run_batches` during one async stream poll (`vala-bifrost-redux/src/scribe/tail_rpc.rs:604-646`); the reader synchronously opens and decodes Parquet (`scribe/staged_tail.rs:59-101`). The Scribe runtime worker can remain blocked with the staged reference and admission lease held even after cancellation. Oracle can observe its own deadline separately; the defect is Scribe worker blockage and delayed Scribe-side cleanup. Isolate staged blocking work with the repository's existing Tokio blocking mechanism while keeping one-window pull demand, bounded buffering, and current staged/admission ownership. On cancellation/drop, schedule no further window and release ownership after any in-flight protected read exits. Do not materialize whole runs or add a scheduler.

4. **FIND-TASK-001-4 through -6 — mandatory Rust source shape.** New fallible journey functions in `wyrd-testing/tests/bifrost/oracle/distributed.rs:974,1087,1296,1447,1655` and helper in `oracle/support.rs:324` lack `# Errors` despite `AGENTS.md` §16. Added function-local imports in `vala-bifrost-redux/src/oracle/live.rs:404`, `wyrd-testing/tests/bifrost/oracle/distributed.rs:1088`, `wyrd-spec/src/vala/api.rs:1024-1025`, and `vala-bifrost-redux/src/scribe/tail_rpc.rs:1296` violate `architecture/agent-rules.md`'s module-top import rule. Changed qualified signature types in `oracle/bindings.rs:248`, `oracle/live.rs:575`, `wyrd-testing/tests/bifrost/forge/public_support.rs:314`, and `oracle/exec.rs:6690` violate its bare imported type rule. Add concise error-condition docs; move imports to each owning module; import and use bare signature types. These changes preserve behavior and need no new abstraction.
