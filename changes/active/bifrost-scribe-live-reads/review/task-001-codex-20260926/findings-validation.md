### FIND-TASK-001-3 — REVISED

- **Discovery IDs:** CONC-002, FOLLOW-01. **Class:** VIOLATION. **Obligation:** `AGENTS.md` §6 prohibits blocking IO in async request paths without an explicit strategy; REQ-005 and AC-004 require bounded live production and query-owned cleanup on cancel, disconnect, and deadline.
- **Location and producer-to-consumer evidence:** `crates/vala/vala-bifrost-redux/src/scribe/tail_rpc.rs:604-646` invokes `StagedTailReader::run_batches` and advances its iterator inside one async stream poll. `crates/vala/vala-bifrost-redux/src/scribe/staged_tail.rs:59-101` synchronously opens a local file, reads Parquet metadata, and decodes windows. `crates/vala/vala-bifrost-redux/src/oracle/follower.rs:1089-1129` and `crates/wyrd/wyrd-server/src/oracle/peer_service.rs:340-356` poll that stream on a server runtime worker while its staged reference and follower admission lease are held. One window limits resident rows, not blocking time; skipped predicate windows can extend a single poll. Oracle's own `select!` can observe its deadline separately, so the discovery claim that Oracle necessarily misses the deadline is rejected. The supported consequence is worker blockage and delayed Scribe-side cleanup while a poll is blocked.
- **Correction:** Isolate staged Parquet open/decode from the async Scribe poll with the repository's existing Tokio blocking mechanism, keeping one-window demand/backpressure and the current staged/admission ownership. Arrange cancellation/drop so the async request stops waiting and no further window is scheduled; any already running synchronous operation must finish or cooperate before its protected file is retired. No new general scheduler, unbounded prefetch, or whole-run materialization is justified. This correction is at the Scribe producer, not an Oracle timeout guard.
- **Focused closure proof:** A staged-source live read with a controlled slow/blocking window shows that the async runtime remains responsive, a cancel/deadline stops further production, and the staged reference and admission lease release after the in-flight operation exits. The existing memtable-only lifetime journey does not prove this path.
