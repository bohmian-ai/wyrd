## Proposed finding

**BEH-001 — INCORRECT, REQ-002 / REQ-004 / INV-002 / AC-005.** Private active-stream discovery loses failure identity, so a security refusal can become a usable Degraded query result. `ScribeTailGrpc::list_active_streams` returns `PermissionDenied` for a binding or signed-ticket refusal (`wyrd-server/src/grpc/scribe_tail.rs:85-135`). `TonicTailReadTransport::list_active_streams` converts every tonic status to `TailReadError::State` (`vala-bifrost-redux/src/scribe/tail_rpc.rs:250-265,328-333`). `RegistryTailStreamDiscovery::discover` then converts every transport error to another generic `State` (`wyrd-server/src/oracle/tail_discovery.rs:151-158`). `Oracle::discover_live_routes` catches every non-timeout error, marks `listing_lost`, and continues (`vala-bifrost-redux/src/oracle/mod.rs:3514-3532`). A ready Scribe that rejects an invalid or misbound discovery ticket therefore yields published rows with a Degraded terminal instead of Failed. The same erasure covers a tenant-binding refusal and invalid schema/binding status. The existing journey's rejected peer ticket is for fragment execution, after discovery, so it does not cover this path. **Correction:** preserve typed fatal versus availability outcomes at the existing discovery/transport boundary and let Oracle degrade only actual ready-Scribe availability loss; make discovery trust-boundary refusals fail the query. Prove it through the real-server query path with a discovery-ticket or binding refusal and assert Failed plus client rejection, alongside the existing availability Degraded case.
