## Proposed material finding

### SYS-007-01 — MISSING: direct Arrow completion drops required row/byte terminal accounting

**Violated obligation:** REQ-014 and TASK-007 requirement 4: bypass IPC/content hashing while row and byte counts and terminal footer rules remain unchanged; INV-006 prohibits skipping terminal validation on the faster path.

**Changed location:** `crates/vala/vala-bifrost-redux/src/oracle/dispatcher.rs:590–597` (`LiveFrame`), `crates/wyrd/wyrd-server/src/oracle/peer_service.rs:364–386` (producer), `crates/vala/vala-bifrost-redux/src/oracle/live.rs:754–760` (consumer).

**Producer-to-consumer evidence:** The local Scribe yields each batch without accumulating output bytes or producer row totals and emits `LiveFrame::Complete(WorkerScanStats)` on drain. That payload has no fragment output row/byte totals. The leader adds only `batch.num_rows()` for local batches; `encoded_bytes` stays zero because only wire frames call `add_bytes`. Any Complete is then accepted unconditionally, unlike the wire footer branch at live.rs:790–803, which reconciles fragment identity, completed status, bytes and rows. Remote gRPC still runs `AttemptEncoder` and preserves its accounting; every colocated production read takes the deficient branch through `OraclePeerTransportDirectory::execute`.

**Observable consequence:** Every direct Arrow fragment loses byte accounting and producer-to-consumer row/byte reconciliation. Missing completion and post-completion checks still work, so this is not a claim that arbitrary truncation currently returns successful results. It is a concrete missing explicitly preserved acceptance property, and the current focused test asserts the weakened local completion payload succeeds rather than proving parity.

**Smallest correction boundary:** Keep direct Arrow transport and existing executor/decoder owners. Have the Scribe producer retain checked local output row/byte totals and attach them to its local terminal, with the signed fragment identity already available from the request. The decoder independently accumulates the corresponding local Arrow byte/row counts and refuses inconsistent completion. Reuse existing completion/error rules; retain remote encoding and hashing unchanged. Do not reintroduce IPC just to obtain counts. Local bytes necessarily describe actual Arrow output rather than nonexistent encoded payload, and that distinction should be explicit. No new transport, exporter, retry or lifecycle owner is required.

**Focused closure proof:** Extend `live_frames_release_batches_incrementally_and_validate_the_footer` to demonstrate nonzero local byte accounting, matched completion, row/byte mismatch refusal, missing completion and post-completion refusal. Add a focused producer-to-decoder check (or existing local journey assertion) proving the emitted local terminal matches actual batches; remote footer check remains passing. Proof must retain the no-IPC/no-hashing condition.
