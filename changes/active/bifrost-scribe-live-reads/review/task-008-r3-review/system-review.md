## Proposed finding SYSTEM-001

- Classification: **INCORRECT** (incomplete follow-on shutdown correction).
- Obligation: the follow-on correction says open fragment streams end on server shutdown; architecture requires structured cancellation, release of source references and bounded shutdown preserving replay evidence. A slow/paused reader is explicitly the rationale of the changed service field documentation.
- Changed location: `crates/wyrd/wyrd-server/src/oracle/peer_service.rs:573-601`, especially the shutdown race at 578-585 after a schema/batch yield.
- Producer -> consumer evidence: Scribe fragment execution creates DataFusion output and returns its stream (`ScribeFragmentExecutor::execute`, `oracle/follower.rs::PhysicalPlanFollower::execute:1431-1460`). The gRPC async stream retains that worker stream while yielding encoded frames. Tonic 0.14.6 `codec/encode.rs::EncodedBytes::poll_next` only polls the application stream when its body is polled. Cargo.lock pins Hyper 1.10.1; its `src/proto/h2/mod.rs::PipeToSendStream::poll:150-165` returns Pending on `poll_capacity` when buffered data remains, before body polling at line 185. Cancelling the token neither resets that HTTP/2 stream nor drops its application body.
- Reachable scenario: an authenticated remote leader opens a normal fragment producing more than its HTTP/2 receive window, then stops consuming (for example downstream client backpressure). The next encoded chunk is pending capacity. The Scribe pod begins shutdown. Even a stale registered cancellation waker cannot make Hyper bypass its capacity check, so the select does not run and the worker stream retains source references/leases.
- System consequence: `wyrd-tonic/src/server/mod.rs:234-243` uses graceful serving. Tonic 0.14.6 `transport/server/mod.rs:925-963` runs detached connection tasks and invokes graceful_shutdown on the stop signal; its server waits for watcher closure at 868-876. `app/server.rs:727-888` drains these transports before Bifrost role shutdown, so the blocked connection can exhaust the server drain deadline and force Bifrost abort instead of clean residue publication/drain. In the retained in-process harness, aborting only the outer serve task does not reset that connection, the exact fidelity gap the follow-on intends to close. No claim that this causes tenant leakage or acknowledged-data deletion: replay evidence remains the fallback.
- Smallest correction boundary: make shutdown terminate the affected peer transport/connection independently of downstream body polling, using the existing peer-listener/server shutdown owner, and thereby drop the underlying fragment execution. A source-body select or a detached producer pump alone does not release a transport body blocked behind send capacity. Restrict this action to a server already shutting down and preserve public transport, unrelated query lifecycle, normal pull backpressure, and durable Scribe recovery. Connection reset can represent availability loss; requiring an Unavailable trailer to reach a receiver that refuses flow-control credit is not a realizable closure requirement.
- Focused closure proof: extend the existing real peer network lifecycle proof with a receiver that keeps its fragment open and withholds reads long enough to exhaust HTTP/2 credit; then cancel the Scribe server. Before the logical query deadline or resumed consumer reads, demonstrate the producer/source lease drops and server shutdown settles without burning the drain deadline. Keep the existing paused-producer loss, normal client cancellation, and terminal failure-after-rows proof. No new benchmark or harness is required.
