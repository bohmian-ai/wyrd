## Closure and verification assessment

FIND-007-10's previous defect was that cancellation lived inside a response body whose consumer could stop polling it. R4 puts the stop signal on accepted socket IO, where the connection driver can observe it independently, and reuses the existing stream ownership and role-drain machinery. The normal path forwards socket IO; only cancellation of an already-stopping server changes behavior. This is the smallest credible boundary correction, rather than another consumer guard.

FIND-007-9's invalid state was manufactured by the streamed-status converter. Its one added arm preserves the existing producer's tenant class and lets the already-existing fatal error/audit consumers act. No parallel footer verification, error code or audit path is added.

Oracle-only coverage is specifically grounded in `AnalyticalConnectionLease::drop` (`oracle/analytical.rs:3296–3311`): a cut coordinator connection decrements its existing ownership share and hands a zero-connection graph to the ingress-owned settlement driver; it does not release the graph directly or spawn untracked cleanup. `Oracle::shutdown_owner` then calls `Oracle::shutdown`, whose `oracle/mod.rs:2875–2898` explicitly shuts down Analytical worker ownership before the capacity report and drains pending reservations. The supervisor subsequently joins its retained graph lifecycle and preserves failed settlement as residue. These owners still run after the transport task joins. Supplied `peer_network::analytical::one_attempt_peer_loss_and_cancellation_join_every_pod` exercises real Oracle-only followers with active graph leases, peer loss/caller cancellation, failed leader result, no successor activation, release on survivors and clean surviving-pod shutdown. It is not a dedicated graceful Oracle-only blocked-window test; the new window test stops Scribe. Source tracing establishes why the changed transport stop feeds the existing Oracle connection-loss/settlement path rather than bypassing it, and existing journey evidence supports the sibling lifecycle contract.

FIND-007-8's authority paragraph now describes cap-free shallow references, the query execution pool and source ownership through stream completion/drop (`bifrost-design.md:309–317`). It no longer promises retained-byte/batch snapshot caps. FIND-007-7 is a non-runtime whitespace correction; supplied checks are credible but its final closure belongs to the standards/validation pass.

The new flow-control proof infers a blocked producer from finite transport buffers, substantial valid output and stalled production; it does not directly instrument HTTP/2 capacity. Its undrained receiver, pre-drain successful stop and recorded RED/GREEN are credible focused evidence for the diagnosed path. No test or timeout was weakened to obtain that result. The retained-server harness proves real socket and lifecycle behavior, not OS process-kill equivalence or broader capacity qualification.
