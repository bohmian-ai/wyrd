## Proposed finding

### MAINT-008-1 — mandatory type dependency shape is reintroduced in the new footer path

- **Classification:** VIOLATION; related to the original `FIND-007-4` dependency-declaration correction.
- **Governing authority:** `architecture/agent-rules.md`: “Bring types in with `use` and use bare names in signatures”; it explicitly applies to struct fields, parameters and returns. TASK-007-R1 acceptance criterion 4 requires owned new/materially changed declarations to use top-level imported types. Maintainer style makes the module import block its readable dependency surface.
- **Changed locations:** `oracle/exec.rs:1111` and `:1137` introduce `tenant: wyrd_spec::DataTenantId`; `:1138` introduces the qualified `ArrowReaderMetadata` return; `:1593` adds another qualified tenant parameter. `scribe/claim_assembly.rs:87`, `forge/managed/policy.rs:260`, and `parquet/writer_properties.rs:121` introduce qualified tenant fields/parameters. The new test writer helper at `oracle/exec.rs:3990` also returns qualified `WriterProperties`.
- **Evidence and caller tracing:** Published loader calls `verify_scanned_footer_tenant` at `exec.rs:1034`; hot/staged `hot_stream` calls `tenant_proven_reader_metadata` at `:2955`. `Oracle::local_hot_sources` supplies the authenticated tenant to `hot_metadata_key`. `ScribeStagingRuntime::assemble` fills the new claim request field from `context.binding.tenant`, which `ClaimAssembler::encode` places into the existing writer plan. Both `ForgeManagedRewrite::{plan,rewrite_plan}` pass `self.binding.tenant` through policy to rewrite properties. These are required production paths, not unreachable utility declarations. `parquet/footer.rs` and `scribe/parquet_writer.rs` already demonstrate the prescribed top-level `DataTenantId` import.
- **Concrete maintenance cost:** The central tenant-proof and writer signatures add domain dependencies outside their owning module dependency manifests and repeat long type spellings across a boundary being actively simplified. A maintainer auditing the top-of-module imports cannot identify the newly introduced identity and reader-metadata types there. This also prevents the cumulative candidate from satisfying the explicit R1 import-shape correction despite fixing its earlier cited declarations.
- **Smallest correction:** Import the new signature/field types at the existing owning module or test-module import block and use their bare names in these changed declarations. Preserve type identity, feature gates and all runtime behavior. Qualified constructor/value expressions are permitted. Do not perform unrelated old import cleanup, introduce wrappers, or change the footer design.
- **Focused closure proof:** Inspect these declarations and their imports; formatting and scoped compile/Clippy verification suffice. No runtime test is needed for an import-only correction.
