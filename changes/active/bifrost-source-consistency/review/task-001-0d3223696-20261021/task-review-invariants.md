### INV-REV-03 — Expiry can run before capture insertion and leak it indefinitely

Classification: **INCORRECT**. Violates INV-006, INV-002 expiry and AC-002's deadline cleanup/refusal requirement.

Exact changed source: `crates/vala/vala-bifrost-redux/src/scribe/tail_rpc.rs:805–829`, `FetchLiveTailService::retain`. It spawns the expiry task at 814; the task sleeps until `deadline`, removes `capture_id`, and finishes; only afterward does the caller insert the corresponding capture at 821. No insertion/expiry handshake or stored expired state links those operations. `capture()` checks expiry only while awaiting unsettled publication; its successful synchronous memory/registry selection can finish after deadline. `open_capture` checks id/query/binding/stream but contains no deadline check of its own.

Reachable interleaving: a listing begins with positive remaining time, but local capture selection/locking consumes that time. `retain` spawns a now-ready timer on the multi-thread runtime. Another worker polls it, removes a not-yet-inserted id, and completes before the caller inserts. The capture then exists with an AbortHandle for an already completed task. The listing's Oracle deadline/cancellation may already have dropped its receiver, so no caller learns the id to release it. The sole expiry removal has already happened. Even without a near-expired input, the caller can be descheduled after spawn until expiry; this is a lifecycle ordering bug independent of synthetic load.

Sibling ownership checked: `CaptureTable::{insert,get,remove}`, normal explicit release (which aborts the timer), `LiveCaptures` best-effort release, remote listing timeout and lost-response handling, and expiry unit test. The ordinary paused-clock unit test lets insertion happen before time advances and cannot expose the ordering defect. No other sweeper owns these orphan entries.

Consequence: raw batches and staged-file leases can remain pinned past deadline for the Scribe lifetime. A supposedly expired capture also remains locally openable if its id was received; authenticated execution may separately reject its old peer deadline, but that does not release the leaked resources.

Smallest safe correction: make expiry removal unable to finish before its retained entry is installed (using the existing capture-table/timer lifecycle), and reject an already-expired capture before exposing its authority. Preserve idempotent foreign/query-bound release and the opened-reader lease contract. A new cleanup subsystem is unnecessary. Closure proof: deterministic expiry-at-registration/interleaving test proving no capture survives even when expiry becomes ready before insertion and no explicit release arrives; keep ordinary expiry, explicit release and opened-file retention tests.
