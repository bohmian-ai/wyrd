## Material proposed finding

### CONC-R1-001 — Persistence still holds retired Arrow after its original charge is returned

- Preserve stable ID **FIND-TASK-001-1**; classification **INCORRECT**.
- Violated obligation: INV-006 / AC-002 and the R1 requirement that the existing admitted charge follow the allocation until its last physical holder drops. Bifrost admission/memory requires the one shared root to cover retained ownership; the correction must preserve persistence and replay progress too.
- Exact correction boundary: `crates/vala/vala-bifrost-redux/src/scribe/persistence.rs:528` (`ImmutableGeneration::from_frozen`), particularly `:557`, and newly changed `:568–581` (`frozen_snapshot`, which creates an unrelated default charge).

**Producer-to-consumer evidence:**

1. `ImmutableGeneration::from_frozen` shallow-clones `frozen.batches` into `rows` at line 557, but ImmutableGeneration has no field retaining `frozen.charge`. `frozen_snapshot` shallow-clones those rows again and sets `charge: Arc::default()` at line 581; that new owner can never receive the original memtable retirement lease.
2. This is production, not a fixture: shard selective rotation, full rotation and replay preparation all call `ImmutableGeneration::from_frozen` (`shards.rs:1641`, `:2150`, `:3403`). PendingGeneration and PersistenceJob retain Arcs to it. The worker clones its Arc at `persistence.rs:2001` and retains it across `deliver_completion(...).await` at `:2070`.
3. Delivery sends PersistenceComplete, then waits for shard visibility acknowledgment (`persistence.rs:2111–2141`). The shard can process that completion and immediately process a queued retirement sweep before the persistence worker is scheduled again. More directly, replay completion calls `release_committed_generation_memory` inline at `shards.rs:2702`, while the live `front: &PendingGeneration` still owns the very same ImmutableGeneration and the worker is still awaiting its acknowledgment.
4. Retirement now splits the existing immutable charge and deposits it in `retired.frozen.charge` (`shards.rs:2411`; `memtable.rs:1170–1174`). If no capture/frozen clone is left, dropping that memtable entry drops the last reference to this charge, returning the original root bytes. The persistence worker and, during replay, the current front still retain the original Arrow allocations through `ImmutableGeneration.rows`, without the charge.

**Observable consequence:** the root reports capacity free while those buffers are still physically resident. Replay may admit/reconstruct the next generation immediately, and normal shard work may reuse the freed capacity while completed persistence futures remain scheduled behind other work. Source retention is bounded by those workers rather than accounted by the existing shared root, so the requested last-holder invariant remains false. This is the same missing allocation-owner propagation as FIND-1; it is not a request for a new quota or a different persistence lifecycle.

**Smallest testable correction:** propagate the original shared `RetainedArrowCharge` through the existing ImmutableGeneration payload and its frozen snapshots, just as the candidate already does for captures and opened memory sources. Reuse the existing charge and lease; do not create an independent default owner for shallow-cloned original buffers, change retirement ordering, delay WAL/publication progress, or reserve the bytes again. Preserve the already-established pre-readiness rollback behavior.

**Focused closure proof:** extend the existing charged shard/retirement fixture to retain an actual `ImmutableGeneration::from_frozen` across retirement after all captures and the original frozen clone drop. Require unchanged root charge and cap refusal while that payload remains; require exact one-time return only after its last clone/snapshot drops. Include a completion/replay handoff assertion if necessary to pin the production ordering. This needs no new harness, full journey run, or capacity benchmark to demonstrate the diagnosed gap. The current test passes because it never creates this holder.
