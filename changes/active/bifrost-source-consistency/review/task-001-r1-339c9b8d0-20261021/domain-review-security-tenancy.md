## Prior finding closure

**FIND-TASK-001-2 — CLOSED.** The prior report's two producer-to-consumer failures are both removed at the existing capture owner:

1. `retain` constructs an entry containing its deadline, installs it, rejects/removes it if already elapsed, and then spawns its expiry. Even if another worker runs the spawned timer immediately, insertion has already happened and no later insertion occurs. Release racing with expiry is idempotent. A release before the abort handle is stored can leave only a timer that later finds no entry, not retained data.
2. `open_capture` checks `retained.elapsed_at(Instant::now())` before projection/read, so awaited schema resolution or delayed timer polling cannot authorize an elapsed source open. Already-open reads retain their own resources, as required.

The new `a_capture_elapsed_before_installation_is_refused_and_retains_nothing` test passes an already-due deadline and immediately asserts refusal, zero entries and zero staged leases. `an_elapsed_capture_refuses_a_new_open_before_its_expiry_runs` prevents its single runtime thread from polling cleanup across expiry, verifies the entry still exists, and asserts the late open fails while an earlier reader retains its staged files. These are direct tests of the previously missing behaviors. The source ordering additionally proves removal-before-installation is no longer possible. Existing successful-open, foreign-query/substituted-ID, foreign-query release, explicit release and timer-expiry tests remain.

**Related FIND-TASK-001-3 — CLOSED within this domain.** Original-deadline propagation and the shared release timeout cover both failed-acquisition and last-route cleanup. The new real-mTLS stalled-release test exercises both the failed-admission path and that release implementation. It calls `release` directly for the second case; actual `LiveCaptures::drop` propagation was confirmed separately in source.

**Related FIND-TASK-001-4/5 — security-facing closure supported.** Private listing/release now document malformed authority, expiry and cancellation/partial-retention behavior matching their bodies. Current Bifrost source-selection guidance distinguishes listing loss from fatal accepted-capture loss. This report does not replace the standards review's complete rustdoc audit or the maintainer review's complete prose audit.

**FIND-TASK-001-1** is primarily the accounting domain. R1's source retains the original charge alongside reads and does not weaken tenant or capture authority; this report makes no independent claim of exhaustive byte-accounting closure.
