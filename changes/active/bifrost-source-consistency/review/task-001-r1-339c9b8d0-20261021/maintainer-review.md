## Material proposed finding

### M-R1-001 — Persistence still detaches shared Arrow buffers from the new accounting owner

Classification: **INCORRECT**; prior stable cause **FIND-TASK-001-1**, not a new finding number.

Obligation: approved `INV-006`, R1 FIND-1's transfer to the shared physical allocation lifetime, `AGENTS.md` §§5/15's single invariant owner, and analytical reliability's bounded active/immutable ownership. The correction expressly requires the last physical holder to return the charge once while preserving persistence/replay behavior.

Changed correction boundary: `scribe/memtable.rs:1648` introduces `FrozenMemtable.charge`, `scribe/shards.rs:2411–2412` detaches and deposits the immutable lease, but the sibling persistence conversion at `scribe/persistence.rs:528–581` omits that same owner. Exact producer and consumer evidence:

1. `ImmutableGeneration::from_frozen` stores `rows: frozen.batches.clone()` at line 557. Its fields (lines 485–523) have no charge owner. This is a shallow Arrow clone holding the same allocations; the new `FrozenMemtable.charge` is discarded by this conversion.
2. `ImmutableGeneration::frozen_snapshot` shallow-clones those rows again and initializes `charge: Arc::default()` at line 581. That is a different empty slot, unrelated to the one that receives the retired bytes.
3. Production shard `prepare_and_queue_generation` constructs this value and `submit_front` gives it to `PersistenceJob`. The worker `process_job` retains both `job.generation` and its local `Arc::clone` across completion delivery. `deliver_completion` retains the job while awaiting `visibility_result_rx` (lines 2096–2157).
4. `handle_persistence_completion` marks the generation durable and can synchronously enter `complete_replay_generation`, which calls `release_committed_generation_memory` at `shards.rs:2702`, before `handle_command` sends the visibility acknowledgment at line 1425. Ordinary retirement can likewise be processed before the awakened worker is next scheduled. Acknowledgment does not synchronously destroy its receiver's Arrow references.
5. Retirement removes the memtable's frozen holder and deposits the detached charge there. With no capture or frozen clone left, that slot drops and returns the bytes, although the actual worker/job `ImmutableGeneration.rows` still physically hold them. The new accounting test explicitly drops its frozen clone but never constructs/retains the production persistence value, so its green result does not cover this path.

Observable consequence: the root advertises those bytes as free before all physical holders release them. Another admitted write can consume that capacity while the persistence worker still retains the retired Arrow allocation. This violates the same root-cap lifetime invariant being remediated. The maintenance cost is an incomplete ownership boundary: changing the normal buffer conversion silently loses accounting even though all capture owners appear correct.

Smallest correction: carry the existing shared charge through the existing `ImmutableGeneration` conversion and its frozen snapshot, just as the capture/read conversions now do. Reuse the same `Arc<RetainedArrowCharge>` and existing lease Drop; do not add another reservation, governor, retirement wait, or persistence protocol. Keep staging, visibility acknowledgment, replay, rollback and WAL progress unchanged. Inspect all constructors of `ImmutableGeneration` and `FrozenMemtable` for the same conversion rule.

Focused closure proof: extend the existing owner-level retirement fixture to retain the real `ImmutableGeneration::from_frozen` value while retiring the memtable and dropping all captures/frozen values. The root must remain charged, and reject growth into those bytes, until that persistence holder drops; then release exactly once. Exercise its `frozen_snapshot` holder too so reconstruction cannot install an unrelated empty slot. A deterministic holder test suffices; no scheduler stress or new harness is needed. Run the exact focused test and narrow existing persistence/replay owner coverage through mise. The defect and proposed correction require independent validation before becoming the final ledger.
