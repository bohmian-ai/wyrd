## Producer-to-sink assessment and reuse

**Publication state:** the migration's AFTER INSERT trigger increments a per-tenant/table/node counter in the inserting transaction; counter-row serialization orders that node's commits. Replay inserts nothing. `insert_artifact_set_fenced` reads the counter before COMMIT; `ClaimPublisher::advance_published` changes the registered authority and revision together through `advance_all_atomic`. Publication marks refuse a contradictory capture between possible SQL acceptance and local advancement. `finish_committed` restores missed revisions, and boot restores node revisions before capture readiness. The existing publisher, registry, catalog and recovery owners are extended; there is no second scanner or durable evidence subsystem.

**Read state:** `OracleTableCuts` returns pointer, hot candidates and revisions from the same statement snapshot. The notification cache remains freshness-only; explicit eviction bumps its generation so an older racing fill cannot repopulate it. `LiveCapture::take` holds writable/immutable read guards through the staged-registry decision; it excludes published memory generations and leases only unserved staging. Oracle checks all reports, including explicit empty captures, before physical execution/admission. A stale selection drops its retained routes and repins under the original deadline/profile. Follower assignments bind the exact capture, query and writer authority. Execution opens that capture and fails on loss instead of reacquiring.

**Retention:** R1's `RetainedArrowCharge` is a justified shared slot for the existing root-backed `ScribeMemoryLease`, rather than a new reservation or governor. The bucket carries it into `FrozenMemtable`; captures and projected reads carry it into `MemtableSource`, fetch/projection rewrites and opened streams. Retirement splits the existing immutable lease with no root accounting change and deposits it into that shared slot. However, the sibling `FrozenMemtable -> ImmutableGeneration -> frozen_snapshot` conversion does not carry it; see INV-R1-01 below. The new focused test covers captures and a projected `CapturedRead`, but does not pass through that production conversion.

**Expiry and release:** registration precedes timer activation; an already elapsed registration is removed before returning an ID. `open_capture` checks the stored monotonic deadline before projection independently of timer polling. Existing opened readers keep memory/file owners after registry removal. Failed-listing cleanup and last-route Drop pass the original absolute deadline to the same `RegistryTailStreamDiscovery::release`; its shared `timeout_at` cancels stalled peer release waits and leaves Scribe expiry responsible for abandoned retention. Local release remains synchronous. No sweep, renewed timeout, replacement capture or process-wide failure was added.

## Proposed material finding

### INV-R1-01 — FIND-TASK-001-1 remains open: persistence loses the generation's shared Arrow charge

- **Classification:** INCORRECT; continuation of the prior shared allocation/accounting cause, not a new finding ID.
- **Violated obligation:** INV-006 / AC-002 and R1 FIND-1's explicit requirement that the retiring generation's existing charge remain attached across active/frozen/capture/opened-reader **and persistence/replay sibling holders**, until the final physical holder drops.
- **Exact boundary:** `crates/vala/vala-bifrost-redux/src/scribe/persistence.rs:528–565` (`ImmutableGeneration::from_frozen`) shallow-clones `frozen.batches` at line 557 but retains no `frozen.charge`; its reverse conversion at line 581 explicitly creates an unrelated empty charge. This is the immediate production consumer of the changed `FrozenMemtable` representation. `memtable.rs:1169–1174` consequently drops the only deposited owner once no capture/frozen clone remains.
- **Reachable path:** normal selective and rotated persistence submission and replay `prepare_replay_state` all call `from_frozen` (shards lines 1620–1646, 2104–2175 and the rotated-generation owner). `PersistenceWorker::process_job` retains an `Arc<ImmutableGeneration>` while `deliver_completion` sends the completion and awaits its visibility acknowledgment (`persistence.rs:1990–2071,2096–2141`). Replay completion calls `release_committed_generation_memory` **while `front.generation` is still alive**, then advances the replay owner before returning (`shards.rs:2696–2748`). The normal retirement lane can likewise run after the shard sends acknowledgment but before the worker resumes and drops its generation. Neither holder owns the deposited charge. The converted generation and any `frozen_snapshot` therefore still physically hold the Arrow allocations after the memtable's last charge owner drops.
- **Observable consequence:** the root can report and admit the returned bytes while persistence still retains those same allocations. Tight shared-memory caps can be overcommitted; captured rows are protected only until the last *charge-carrying* holder drops, not the last physical holder. This is precisely the lifetime mismatch FIND-1 was intended to remove, now narrowed to the unconverted sibling owner.
- **Why current proof misses it:** `a_retired_generation_stays_charged_until_its_last_holder_drops` constructs captures/read but no `ImmutableGeneration`. The modified freeze-clone regression drops its `FrozenMemtable`s with a comment that production persistence holds such a clone; production instead converts those rows into an `ImmutableGeneration` which omits that clone's charge. Recorded green tests do not refute this source path.
- **Smallest testable correction:** carry the **same** existing `Arc<RetainedArrowCharge>` through `ImmutableGeneration::from_frozen` and its frozen snapshot, preserving the existing split/deposit/Drop lifecycle. Do not add another reservation, quota, barrier or deferred WAL/publication retirement. Audit all production shallow-copy consumers of this generation owner; keep the already-correct capture/stream rewrites. A focused retirement proof should retain the actual converted persistence generation after dropping the frozen/capture/read holders, assert exact root bytes stay charged and cap growth is refused, then drop that final holder and assert one exact release. Cover the reverse frozen conversion too. Use the owning existing fixtures and focused mise selector, not a new harness.
