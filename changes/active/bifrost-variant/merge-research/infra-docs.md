## Cargo.lock regeneration procedure (after Cargo.toml and crate manifests are resolved)

1. Push the combined compaction fork commit (hazard 1) and pin it in `Cargo.toml`.
2. `git checkout --ours Cargo.lock`. OURS carries the git-fork and `[patch.crates-io]` graph, which is the expensive part to re-resolve. Main's additions are registry crates.
3. Run `cargo metadata --format-version 1 >/dev/null` **without** `--locked`. Cargo adds the missing packages (openidconnect `=4.0.1`, oauth2 `=5.0.0`, webbrowser `=1.2.4`, opentelemetry-http 0.31, toml_edit 0.22, and their transitive deps), prunes removed crates (governor, skald-observer, …) and re-fetches the new compaction rev. Do not run `cargo update` / `generate-lockfile`: they would float every registry crate. If you want main's exact versions for the new crates, follow up with `cargo update -p <crate> --precise <ver from origin/main:Cargo.lock>`.
4. `cargo hakari generate && cargo hakari manage-deps`, then repeat step 3 so the lock reflects the regenerated workspace-hack.
5. Verify: `cargo metadata --locked`, `mise run check:workspace-hack`, `mise run check:deps` (one each of arrow/datafusion/parquet/object_store; no `rustls feature "ring"`).
