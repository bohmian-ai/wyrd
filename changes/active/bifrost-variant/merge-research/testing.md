### Top 5 hazards

1. **Event time.** The two sides disagree on where a row's event time comes from:
   - Ours (TASK-005, cfe21dc90) removes the managed `wyrd_event_time`. Each table declares its own time column instead (`created_at` for observations and audit).
   - Main (REQ-187: be6ab6b5d, 6e84727c9, c42b7ccff, 047d8bebd) has the client stamp `wyrd_event_time`, and Scribe enforces an admission window (`PAST_EVENT_TIME_EXEMPT`, `shift_receipt_clock_for_test`).

   Main's new tests (`observe_ingest.rs`, `scribe/describe.rs`, `capacity/load.rs`) and harness code (`server.rs:2017`) still use `wyrd_event_time`: 24 references in the merged tree. All of them must be rewritten to the table time column, or deleted where they only test client stamping.
2. **Audit model.** Main's Scribe outbox (d2af088b9, 70a6f4a4e, 1e57da5cb) supersedes ours' `audit_staging` and hash-chain usage:
   - Main has no `vala_sql::queries::audit_staging`, no `seq`/`entry_hash`/`prev_hash` columns, and no `CreateTableRequest.audit` field.
   - Ours' `TypedPayloadJourney::append_audit_decision` (`verification_runtime.rs` HEAD:2747-2790) and five merged `audit: None` sites break.
   - The merged `vala.system.audit_log` schema is owned by the redux/server-sql group: main has utf8 `detail` and `wyrd_event_time`; ours has a Variant `detail` and `created_at`. The harness's `ORDER BY` and its detail rendering depend on that choice.
3. **Bench binaries.** Main replaced every capacity bench with one `capacity` binary (dec4213fa, 5c3bb79b3) and explicitly deleted `bifrost_query_capacity` per `opitimization-and-benchmarks` REQ-010. Ours extended `bifrost_query_capacity` (tiers, `--writes`, telemetry and logs fixtures) and renamed `bifrost_ingest_capacity` to `bifrost_client_queue`. Ours' TASK-003 and TASK-005 evidence cites `bench:bifrost:query-capacity`.
4. **`release_server` API drift.** Ours replaced `Envelope` with `Placement::{Host, Scoped}` as the 4th argument of `LocalServer::start` and removed `envelope()` and `cgroup_stat()`, adding `cpu_usec()` in their place. Main's new `capacity` binary still calls the old API at merged `capacity/main.rs:497,950` and `capacity/step.rs:236`, and uses `Capture::start` with 3 arguments from its own `profile.rs` copy (`capacity/step.rs:538`). This merges silently and fails to compile.
5. **Workspace lints.** Main enabled `[lints] workspace = true` on wyrd-testing (515f16c97). That turns on pedantic, `unwrap_used`, and `allow_attributes_without_reason`. None of ours' new wyrd-testing code (`profile.rs`, `release_server/os.rs`, `gateway_capture.rs`, `object_reads.rs`, `scribe/recovery.rs`, both kept bench binaries, the Variant journeys) was written under those lints, so expect a large `mise run lints` fallout.

Lesser silent hazards:

- `superuser_pool()` is now sync on main.
- `wyrd_queue::BatchBuilder` (main) vs `RowPreflight` (ours).
- `CARD_REF` was removed on main.
- `#[expect(clippy::float_cmp)]` may become unfulfilled.
