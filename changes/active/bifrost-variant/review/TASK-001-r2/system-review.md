## Failure-path summary

- **Scribe process restart:** invalid Variant input has not reached WAL, so it cannot reappear during replay. A valid append cancelled after shard dispatch remains shard-owned and follows the pre-existing durable ACK/replay protocol.
- **PostgreSQL or object-store outage during ingest:** admission-clock or durable-fence failure refuses/withholds the request; the Variant change adds no alternate acknowledgement path. An ambiguous fence commit is reconciled by exact durable identity and otherwise poisons admission while retaining the group for restart.
- **Oracle peer/storage outage, timeout, or cancellation:** no failure path crashes the shared server. Before streaming, children are cancelled and joined. During streaming, the terminal settlement owns cancellation and releases request-local admission and read claims.
- **Forge crash, cancellation, or catalog outage:** per-batch lineage validation precedes publication. Publication uses the existing definite/not-submitted/acceptance-unknown split and durable reconciliation. No row-lineage-specific retry, metric gate, duplicate scan, setting, or second metadata protocol was introduced.
- **Rolling replacement:** fresh processes reconstruct Scribe state from valid WAL, Oracle sessions install the same Variant SQL owner, and Forge recovers from Iceberg plus durable operation state. The changed Variant mechanisms carry no process-local authority that must survive replacement.

## Material proposed finding

### SYS-TASK-001-1 — Late Variant query failures lose the required stable catalog identity

- **Classification:** INCORRECT
- **Violated obligation:** `REQ-019` requires invalid JSON, numeric overflow, excess depth, and excess encoded size to fail with stable catalog codes as query errors. The remediation acceptance for `FIND-TASK-001-5` additionally requires identical stable code/details for interactive and distributed Variant failures independent of human `Display` text.
- **Exact location:** `crates/vala/vala-bifrost-redux/src/oracle/query_stream.rs:450-505,1317-1339`; `crates/wyrd-spec/src/vala/api.rs:813-899`; `crates/shared/wyrd-client/src/bifrost/query.rs:104-146,185-219`.
- **Evidence:** `settle_attempt_output` preserves a Variant failure only while awaiting the first physical batch. After the schema and any successful batch have been yielded, `QueryStreamEvent::Batch(Some(Err(error)))` calls `terminal_error_code`. That mapper has no Variant branch and the closed `QueryTerminalErrorCode` has no Variant identities, so every `VariantQueryError` becomes `QueryExecutionFailed`. The client then reconstructs `BifrostError::QueryExecutionFailed`. This path is reachable when an earlier scan batch contains valid `parse_json` input and a later batch contains invalid JSON, an out-of-range number, an over-deep value, or an oversized value. The current journey makes every selected row invalid, so execution fails on the first batch and does not exercise the late path.
- **Observable system consequence:** the same SQL operation returns `WYRD_VALA_400_VARIANT_INVALID_JSON` (or the corresponding exact Variant code/details) when the bad value appears in the first batch, but returns `WYRD_VALA_500_QUERY_EXECUTION_FAILED` when valid rows were produced first. Because a failed terminal invalidates the whole result, no partial rows are accepted, but callers lose the stable classification needed to correct input rather than treat it as a server failure.
- **Smallest testable correction:** preserve the existing typed/tagged `BifrostError` through the existing late query-terminal contract, for both interactive and distributed streams, without adding a prose parser, alternate carrier, setting, check, or retry. Add one existing-target journey that forces at least one successful emitted batch before each representative Variant failure and asserts the terminal maps to the same exact catalog identity as the pre-stream path; include an unrelated late execution error to prove it remains generic. The correction must reuse the established terminal/error catalog rather than introduce a Wyrd-only side channel.
