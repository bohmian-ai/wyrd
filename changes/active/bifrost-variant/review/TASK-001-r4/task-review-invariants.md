## Proposed findings

### INV-R4-001 — INCORRECT: projecting a child of a null verification summary fabricates a value

- **Violated obligation:** REQ-009's persisted `drift_report` and `eval_summary` contract, INV-002 (no semantic loss/fabrication), and TASK-001's requirement that Struct access remain exact DataFusion `get_field` while built-in typed payloads remain equivalent to their source values.
- **Location:** `crates/wyrd/wyrd-server/src/verification/results.rs:700-742`; `crates/shared/wyrd-queue/src/variant.rs:336-387`; coverage gap at `crates/wyrd/wyrd-testing/tests/bifrost/server/verification_runtime.rs:1075-1120`.
- **Evidence:** An absent `drift_report` is authored with a null parent but child values `""`, encoded JSON `null`, and `""` (`results.rs:707-716`). An absent `eval_summary` similarly has a null parent over five numeric zero children (`results.rs:721-741`). The candidate pins DataFusion 55, whose `get_field` execution returns `StructArray::column_by_name` directly rather than intersecting the child validity with the parent validity. The candidate's own shared Variant reader documents the same reachable fact: neither Parquet nor `get_field` pushes a null parent into its child (`variant.rs:336-345`). `mask_placeholders` repairs only a Variant child whose metadata and value bytes are both empty; it does not mask the producer's valid encoded JSON-null child and cannot repair primitive `String`/integer/float children. The focused Oracle fixture consequently filters `s['method']` to `WHERE s IS NOT NULL`, and the end-to-end result test selects children only for the scored Drift row, leaving the absent-parent projection untested.
- **Observable consequence:** For an unscored Drift row, `drift_report['method']` and `drift_report['verdict']` return empty strings rather than SQL null, while `to_json(drift_report['features'])` returns the string `"null"`. For a Drift row with no Eval summary, `eval_summary['total_tasks']` (and its siblings) returns zero rather than SQL null. Callers filtering, aggregating, or serializing these children observe fabricated report data even though the parent summary is null.
- **Required testable correction:** Preserve the nullable parent's validity for every projected child while keeping the public Struct schema and DataFusion `get_field` contract unchanged. Add focused Oracle and real hot/published-path assertions that every `drift_report[...]` and `eval_summary[...]` expression is SQL null when its parent is null, including `to_json(drift_report['features'])`, and that scored summaries remain unchanged.
- **Relationship noticed:** This is adjacent to the candidate's empty-byte Variant-placeholder repair, but that repair covers only one child representation; root-cause follow-up should reconcile it with earlier rounds.

### INV-R4-002 — INCORRECT: predeclared built-in admission can return a later Variant error before an earlier schema error

- **Violated obligation:** Locked write-error precedence in spec revision 11 and TASK-001 Scenario 1 (`exact limits, error precedence/details`). Unsupported/wire-mismatched or undeclared fields must be refused before Variant byte/JSON/depth failures.
- **Location:** `crates/vala/vala-bifrost-redux/src/tables/mod.rs:217-269`; `crates/vala/vala-bifrost-redux/src/scribe/execution_lanes.rs:601-634`.
- **Evidence:** For predeclared built-ins, `validate_predeclared` immediately calls `validate_declared_variants`, which first validates Variant field identities and then every Variant value (`tables/mod.rs:217-253,256-269`). `enforce_builtin_source_contract` invokes that validator before it checks the complete user-field order/schema and before the source fingerprint (`execution_lanes.rs:621-633`, followed by `decode_rows` fingerprinting at `:562-568`). Therefore one reachable Arrow batch containing an undeclared field or a non-Variant field with a wire/type mismatch plus malformed/deep/oversized bytes in a declared Variant returns the later Variant error first. Canonical signal batches do not have this defect because `validate_canonical_user_batch` explicitly checks undeclared fields and every declared field identity before its Variant walk (`tables/signal.rs:904-940`).
- **Observable consequence:** The same malformed request's public error depends on whether the destination is a canonical signal table or another built-in table, and predeclared built-ins violate the locked first-failure contract. A caller receives (for example) `WYRD_VALA_400_VARIANT_INVALID_JSON` even though the request must first be refused for an undeclared or wire-mismatched field.
- **Required testable correction:** Make every built-in validator establish the complete declared schema in locked order—undeclared fields, then logical-field type/wire identity—before traversing Variant values. Add a trust-boundary test for a predeclared built-in that combines an earlier undeclared/type failure with a later invalid, oversized, and too-deep Variant and asserts the earlier stable refusal, no acknowledgement, and no durable row.
- **Relationship noticed:** The canonical-signal validator already expresses the required ordering; root-cause follow-up should determine whether prior remediation covered only that sibling path.

## Overall result

**FAIL**

The candidate implements most of TASK-001's cross-layer contract, including exact Variant integers, typed terminals, Oracle registration, v3 lineage, and Bloom sizing. It does not satisfy the task exactly because nullable built-in Struct children leak placeholder values through the required `get_field` surface, and predeclared built-in admission does not enforce the locked error precedence when schema and Variant failures coexist.
