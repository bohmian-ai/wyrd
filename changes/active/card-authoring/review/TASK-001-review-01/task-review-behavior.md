## Proposed findings

### BEHAVIOR-001 — INCORRECT: replacing a reference retains the replaced dependency

- **Obligation:** REQ-002 direct mutable edits and captured current values; REQ-008 equivalent incremental/constructor definitions; AC-002; TASK-001 Scenario 1 native field/reference semantics.
- **Locations:** `crates/shared/wyrd-client/src/authoring/mod.rs:450–453` (`Binding::set_runs_on`); sibling affected writers `authoring/verifier.rs:537–552` (`AgentCall::add_workspace_input`, `add_workspace_file`); sink `mod.rs::Graph::add` and `cards/handle.rs::declare_authored`.
- **Source proof:** `set_runs_on` assigns the new canonical reference but appends the new dependency list to all previous dependencies. Workspace map insertion likewise replaces the old map value but appends local Artifact dependencies; replacing an Artifact mount with a scope value removes none. `Dependencies::absorb` only extends vectors. `Graph::add` unconditionally consumes every captured dependency, independent of whether a current reference still targets it. It refuses unequal same-identity captures. Cards then uploads every Artifact in that list before graph declaration.
- **Reachable failing scenario:** Create local policy Artifact A from an unavailable old path. Mount A at `/inputs/policy.json`, then replace that mount with local policy Artifact B at a different exact version and a valid path. The canonical AgentCall now contains only B, but declaration still tries to upload A first and fails on the old path. Building the identical final call directly with only B succeeds. If replacement A/B share an identity but differ only in local source descriptor, final offline declaration refuses with SpecDuplicateSubmission although only B is referenced. Similarly, setting one sibling Trigger and then another retains the old Trigger submission; same-identity edited replacements conflict. Trigger replacement is an explicit setter, so this is not an ambiguous duplicate-add contract.
- **Observable consequence/materiality:** Normal incremental edits can block an otherwise valid graph on an obsolete local file, publish no-longer-selected local data, declare removed Trigger Cards, or produce a false duplicate-identity refusal. This affects the primary editable authoring API, not an exotic wire input.
- **Smallest correction boundary:** Keep dependency capture owned by the reference positions that can be replaced, so replacing runs_on or a workspace destination removes that position's old contribution while preserving dependencies still used by other live positions. Maintain canonical overwrite behavior, snapshot semantics and actual-conflict refusal. Do not add upload guards, a parallel graph validator, global caches, or change registration semantics. Merely deduplicating by identity is insufficient: stale distinct identities remain, and silently choosing same-identity content would weaken conflict detection.
- **Focused closure proof:** Offline tests compare direct construction with repeated trigger/workspace edits and assert that only current dependencies remain; include one Artifact mounted at two destinations to ensure replacing one preserves the other. A focused existing SDK journey can replace an invalid old source before declaration and prove only the valid final source publishes. No new harness is needed.
- **Verification:** Not covered by the three local tests or four journeys. Source tracing establishes the append-only mismatch; no additional Cargo command was run by this reviewer.
