## Material finding

### INV-01 — INCORRECT: replacement edits keep superseded dependency captures

**Violated obligation:** REQ-002 requires editable definitions, and REQ-008 requires equivalent incremental and constructor-style definitions to produce equivalent native specs and staged request sequences. TASK-001 explicitly includes editable binding fields and captured definitions, and says mutations affect their receiver. The documented `set_runs_on` is a replacement setter, so this is ordinary supported authoring rather than unusual malformed input.

**Locations:** `crates/shared/wyrd-client/src/authoring/mod.rs:450-453` (`Binding::set_runs_on`), and sibling producers `crates/shared/wyrd-client/src/authoring/verifier.rs:537-552` (`AgentCall::add_workspace_input` / `add_workspace_file`). Common append-only collection is `mod.rs:72-74`; consumers are `Graph::add` at `mod.rs:253-275` and Cards::declare_authored at `cards/handle.rs:354-367`.

**Failing trace:**

1. Construct a valid Verifier binding. Set its runs_on to `Linked::sibling` of Trigger `T@1.0.0` with spec A. Then set runs_on to another `Linked::sibling` of `T@1.0.0` with spec B (for example, an edited description/activation). Attach the binding to its Service. The final canonical binding contains only the second reference, exactly as a binding constructed directly with B would.
2. Each setter overwrites `binding.runs_on`, but `Dependencies::absorb` appends both captured definitions. Service::add_verifier transfers the whole list into the root. Graph::add visits both, finds their same identity with different spec content, and returns `SpecDuplicateSubmission` before loader validation. Direct construction with B alone does not have that conflict. A supported final edit is consequently undeclarable because an obsolete local value remains active.
3. The same shared-state mistake reaches publication: call `AgentCall::add_workspace_file("/inputs/policy.json", &local_artifact.file(...))`, then replace that entry with `add_workspace_input` at the same path. The canonical workspace map now contains only Scope(input), but the local Artifact remains in captured dependencies. Step -> Verifier -> Service carry it into Graph::add; declaration.artifacts retains it; Cards::declare_authored prepares/publishes it. A missing obsolete file makes an otherwise valid final graph fail; an existing obsolete file is uploaded despite being absent from the final graph. WyrdState shares this path.

The workspace case is not a proposal to impose duplicate-alias rules on workspace paths. The explicit alias-refusal obligation covers Service component aliases; these workspace methods currently use replacement insert semantics and have no fallible duplicate refusal. Their dependency ownership must stay consistent with whichever final value they store. The runs_on replacement alone establishes the finding independently.

**Sibling writers inspected:** Binding::new/registered, set_runs_on, add_on_failure and add_on_verdict_change; Service compose/add_verifier; Agent add_verifier; AgentCall new/add_input/add_workspace_input/add_workspace_file; CodeCall artifact; Step/Verifier additions and Dependency::absorb. Append-only captures are appropriate for actual additions. set_runs_on and workspace insertions are the dependency-bearing writes that can supersede old values while retaining their old captures. Both Cards and state consume the same invalid snapshot.

**Observable consequence/materiality:** legitimate local editing can fail with a false duplicate-definition error, or perform unwanted Artifact publication/fail on an irrelevant local path. It breaks required constructor/incremental parity and the promised final declaration snapshot. The issue does not require a crash, race, unusual durable input or a new server behavior.

**Smallest testable correction:** fix capture ownership at the replacement producers so replacing a binding target/workspace value also replaces the dependencies owned by that position, while preserving dependencies still required by other binding fields or workspace entries. Keep existing shared loader validation, equal-definition deduplication, genuine active-conflict rejection, upload owner and wire contracts. Do not merely relax Graph's conflict guard or globally delete dependencies by identity: that could hide real conflicting active definitions or remove a dependency still used by another field. No new lifecycle, cache, parser or general graph machinery is needed.

**Focused closure proof:** compare edited and directly constructed binding declarations after replacing a same-identity sibling Trigger with different content; the final declaration must contain only the replacement and succeed. Compare edited and directly constructed AgentCall declarations after replacing a local-file workspace value with an input and with another file; obsolete captures must disappear, including no obsolete publication plan. Include one second workspace/binding field that still needs the old dependency to prove the correction preserves shared captures. Existing local canonical/snapshot tests are sufficient owners for this proof; no new harness is needed.

**Correction burden:** bounded changes to dependency-owning replacement positions plus focused local regressions. Deleting setters would remove requested edits; rejecting every replacement would change supported setter behavior; downstream publication guards would not repair false conflicts or constructor parity.
