## Existing-owner comparison

File loading owns discovery, workspace defaults, filesystem containment, !file expansion and path resolution before typed validation and ordering. These stages cannot consume an editable captured child without inventing files or dropping by-value capture semantics. Body and Captures retain raw values and current dependencies; they neither resolve filesystem reference paths nor implement native field validation. Duplicate-map bookkeeping is required because JSON objects otherwise erase attempted duplicates before shared validation sees them. Local code-file descriptors are an explicitly approved convenience and are materialized at the snapshot boundary.

Graph's recursive collection coalesces equal captured identities and rejects conflicting snapshots. It does not build execution edges, select a Card root, validate graph composition, resolve external identity or register anything; `declaration_input_from_cards` and the existing canonical graph still own those rules. File-resolution caching is keyed by physical paths and cannot replace in-memory snapshot collection. Thus this is an extension of the earlier authoring owner, not an unearned second graph store. Merely removing the staging types or substituting a typed spec would lose deferred edits and capture replacement. No DRIFT proposal is justified by a line-count preference or by the fact that both workflows eventually produce Cards.

Cards' new match replaces public entry-point separation, while the existing sole-publication operation, saga, scratch lifetime and state pull/hydration remain their owners. It is composition of the approved publication-first behavior, not duplicate registration machinery. The plain-JSON named kind setters correctly leave domain parsing to serde/Prompt/kind validators rather than hand-maintained operator or reference maps.

## Proposed finding

### M3-001 — Reference-position lowering is also used as root admission, leaving Artifact outside the common Card workflow

Classification: **MISSING / INCORRECT**. Changed locations: `authoring/kinds.rs:310-338`, `authoring/mod.rs:803-807,934-936`, and the missing Artifact conversions beside the other named-kind adapters (`kinds.rs:34-71`, `verifier.rs:62-88`). Consumer/proof location: `sdks/wyrd-sdk-rust/tests/integration/authoring.rs:1435-1443`.

Authority: revision-4 REQ-001 includes all twelve named Card kinds; REQ-004 gives validate the current complete local definition graph; REQ-006 admits authored Cards to the existing declaration owner. The named-Card table includes Artifact and outer metadata setters. The maintainer guide requires a workflow and its retained values to have a coherent, discoverable owner. `CardDefinition`'s own rustdoc additionally says every named Card type converts into it.

Source-proven paths:

1. `Artifact::from_path("policy", "1.0.0", path).validate()` reaches the generated common validate method. That method constructs a FieldValue as though the root were a reference slot. Local Artifact conversion intentionally contributes only `Captures.artifacts`, with no Card in `Captures.cards`. Graph decodes the local descriptor, then always calls `declaration_input_from_cards(&authored)` with an empty list; `order_cards` refuses `Cannot order an empty card tree`. This happens even when the Artifact's identity and spec are valid. A local Artifact nested beneath a Service does not fail this way because its containing Card supplies the root.
2. An ordinary nonlocal `Artifact::new("document", "1.0.0").artifact_kind("document")` validates as a Card but cannot be passed to `Cards::declare(&artifact)`, `WyrdState::declare_with(&artifact, ...)`, or `CardDefinition::from(&artifact)`: Artifact has only the FieldValue conversion. Every other named Card gets the root adapters. The public inventory conceals that omission by calling `CardDefinition::new(..., artifact.spec())`. This manual reconstruction carries neither the Artifact's labels/annotations nor its local source/extract state.

Consequence/materiality: Artifact is an explicitly supported ordinary Card, not a hypothetical variant. Its fluent type offers a common validation operation that refuses a valid local root for an unrelated empty-tree error and cannot participate directly in the promised declaration input grammar. Maintainers currently must know whether an Artifact is in a reference slot, rebuild it as a different type for root use, and manually preserve metadata that the generic reconstruction does not expose. The public inventory can stay green while this family is disconnected from the common workflow.

Smallest correction boundary: distinguish authored-root admission from conversion into a field reference at the existing authoring/declaration adapter boundary. Preserve the intentional external reference plus publication-first behavior when a local Artifact occupies a field. Admit the named Artifact root with its complete metadata/current captures, and use existing Artifact decode/validation and sole-submission preparation/saga behavior for any local source. Do not manufacture a containing Service, reconstruct a spec-only Card, add a wire form, or implement another upload/registration workflow. No graph-store or validator replacement is required. The concrete correction must retain source/extract information rather than add an infallible conversion that silently drops it.

Focused proof: directly exercise the named nonlocal Artifact as a Card root through the public adapter with labels/annotations intact; validate a local Artifact root without an empty-tree refusal; and exercise its source-bearing declaration through existing Artifact publication proof rather than making another harness. Retain the current nested local-first/ref-only tests to prove the correction does not change field-reference semantics. Cargo checks are requested through the orchestrator, not run by this reviewer.
