### BR3-001 — MISSING: four approved field replacements have no public operation

**Obligation:** REQ-001/002, Actions/checks support table and AC-007 explicitly promise `Action.extract(...).from(...)`, Agent-action/check `agent` replacement, and each-check `each` replacement. Task Scenario 1 requires every approved field and both editing styles; Scenario 3 preserves captures when action/binding values are replaced.

**Location:** `crates/shared/wyrd-client/src/authoring/verifier.rs:284–290` and `:398–411`; associated constructors at `:262`, `:268`, `:333`, `:368`.

**Reachable producer-to-consumer proof:** `Action::extract("inputs.old")` produces a private Body containing `from`; its generated edit methods cannot write that field. No method converts public FieldValue/JSON/native Action back into this Action. Consequently `Action::extract("inputs.old").from("inputs.current")` cannot express the approved edit before attachment to Step. The Agent forms similarly allow inputs/workspace edits but cannot change their current Agent while retaining those fields/captures. An each check can change operator/expected but cannot change `each`. Parent-level `Step::action` or `Requirement::check` replaces the complete sub-value; rebuilding it requires callers to reconstruct sibling input/workspace/operator fields and does not provide the specified single-field replacement.

**Materiality:** These are explicitly approved editing operations in the primary new API, not speculative inputs or naming preferences. Agent replacement additionally owns captured child definitions. The public inventory exercises the constructors and so misses the defect.

**Smallest correction/testable outcome:** Complete the approved edits at the existing authoring value owner, preserving discriminant, sibling fields, current capture replacement and deferred validation. `from` is a small addition to existing field machinery. Public proof must edit these four fields and compare to direct construction; an Agent edit must drop the old captured Agent without dropping a current workspace Artifact. Reuse Body's existing setter/capture behavior; do not add a validator or registration workaround.

**Correction burden / API caution:** `agent` and `each` currently occupy associated constructor names on the same concrete types; Rust cannot add same-named inherent setters to those exact types unchanged. This is a real tension between the present representation and the approved constructor/setter table. I do not prescribe an extension trait, new public hierarchy, compatibility alias or renamed API. Constructor return representation was not fixed by the spec, so missing edits are not automatically proof that the approved behavior is impossible. Independent validation should resolve the smallest conforming representation; if it requires changing the approved public grammar, identify that exact conflict and route to specification revision rather than silently dropping the setter promise. The non-colliding `from` gap remains independently correctable.
