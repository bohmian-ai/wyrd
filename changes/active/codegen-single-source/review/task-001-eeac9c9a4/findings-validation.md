## Decision-complete minimum correction

Keep the existing Rust contract owner, extraction example, lowerer, and generated module. Fix the information at its Rust source and use the installed schemars facilities; do not parse Rust with a new tool, maintain field-name overrides, restore handwritten interfaces, introduce a directional DTO family, or add consumer guards.

1. For **always-emitted Option fields**, add explicit default metadata at their Rust declarations using the existing serde/schema annotation mechanism. `#[serde(default)]` is behavior-preserving for the ordinary Option fields here: serde already accepts a missing field as None, and serialization remains unchanged. It supplies `default: null`, so existing output lowering makes the property required and nullable. Do not use `#[schemars(required)]`: the installed derive calls `_schemars_private_non_optional_json_schema` and removes the required null union. Do not default required non-Option inputs.
2. For **response-owned fields skipped on None**, existing `#[schemars(with = "<underlying Rust schema type>")]`, retaining current serde default/skip attributes, represents the emitted value accurately and leaves the property optional. This covers the table-description fingerprint/compaction fields and response-only scalar/reference skipped fields. Apply this at the owning declaration, not a generated TS field list. For `Option<serde_json::Value>`, the underlying Value still admits null: `Some(Value::Null)` is serialized, so never strip null from genuinely opaque JSON.
3. **Shared request/output source contracts require preserving both meanings.** `PhysicalLayoutWire.time_column` (`vala/api.rs:417-418`) also belongs to `RegisterTableRequest` (`:444-445`) and durable layout JSON. Its accepted nullable/omittable input must remain intact; replacing its ordinary schema with String would narrow that input schema. Use the existing `schema_with` capability at that owning field to retain the original input schema and carry its underlying serialized-value schema in a schema extension; the existing lowerer reads that metadata only in output mode. `SchemaObject.extensions` and `schema_with` are available in the pinned dependency; `auth/revoke.rs::reason_schema` is a repository precedent for source-owned custom schema derivation, and `wyrd_spec::schema` is the existing schema utility owner. This is one bounded addition to the existing projection path, not a new generator framework or public runtime API. No annotation may modify serde wire behavior, input requiredness, or the lowerer's existing Card/request policy. The extension must describe the underlying schema, not blindly delete all null branches.

Sibling closure is part of this one correction, not an extra scenario matrix. Inspect these existing output-owned definitions through the same producer: WorkflowRun/WorkflowStepResult; CardRegistrationOutcome/CardSummary/ListCardsResponse; CredentialMetadata/PrincipalSummary/PrincipalPage; ProviderCredentialView; QueryTerminalFrame.error; and Judgment's reachable FeatureDriftReport, SkippedTask and AssertionResult. In Bifrost's reachable DataTypeSpec Timestamp variant, the unskipped `tz: Option<String>` has the same always-emitted-nullable rule, and an explicit Option default does not change request requiredness. Keep existing `with` overrides such as the registration URL projection while adding default metadata.

Already-correct siblings must stay correct: `FieldSpec.metadata` (`vala/api.rs:322-323`) is a defaulted map skipped when empty, so the current schema/lowerer already emits an optional non-null map. The same installed derive suppresses serialized default values for skip predicates. Do not turn defaulted/skipped collections into required fields or change non-skipped defaulted collections' presence. Shared CardRef/Card/spec authoring definitions retain their input acceptance; unrelated preexisting semantic refinements (for example, requiring a server-resolved canonical layout's time column through a new DTO) are outside this correction.

The installed schemars 0.8.22 source was inspected: `gen.rs::SchemaSettings` has no directional setting; `schemars_derive::schema_exprs::field_default_expr` uses the actual serde default and skip predicate; `insert_object_property` accounts for defaults; and `schema_with` plus schema extensions allows the bounded shared-field metadata above.
