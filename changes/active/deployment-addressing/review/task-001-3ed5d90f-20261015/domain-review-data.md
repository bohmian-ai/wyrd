## Owner-raised Agent save/default question: source-confirmed, not a retained task finding

The reported behavior is real: `skald-agent/src/agent.rs:674–699` reconstructs a runtime Agent using `run_config_from_agent_run_config_spec`; that converter (`844–860`) starts with `RunConfig::default` (`run.rs:38–47`, max_iterations 10, tool_concurrency_cap Some(8)). `to_spec` (`784–791`) writes the effective runtime config back, so omitted max_iterations and tool_concurrency_cap become explicit values; it also emits empty verified_by rather than retaining an input list. `to_card` (`652–659`), to_wire, save/to_yaml_string, Python save/to_yaml_string/to_card/model_dump_json all converge on that projection. Public Card holders themselves retain their spec; the lossy transformation is runtime Agent projection. Runtime defaults are not a hash canonicalization rule: serializing those explicit values changes spec bytes and registration hash.

However, this review must not invent a new acceptance requirement: REQ-008's exact authored local save/load preservation concerns Prompt forms; REQ-009/INV-004 require preserving the stored Agent and hash during invocation overrides, which do not call these save projections. Original task's Agent route extension and R1 FIND-001-2 require preserving route across loading/saving, and this candidate does preserve it. FIND-001-14/R2-AC-05 specifically require route/provider/model/ref identity and actual downloaded execution, not complete runtime AgentSpec projection equality. The cumulative diff shows these default conversion and verified_by-empty behaviors as retained context of the changed Agent route owner, not a newly introduced writer or required route regression. Architecture defines verified_by semantics but does not make this unrelated generic local Agent projection repair part of the bounded approved task.

Therefore no DATA-001 is retained on this evidence. Recommend track the source-confirmed runtime-Agent export loss separately unless the orchestrator identifies a stronger original obligation or newly reachable regression; the owner raising it is not itself approval to expand this task. A separate correction should keep authored durable config and verification bindings on the existing Agent owner, resolve execution defaults without rewriting them, and prove load→save spec/hash preservation plus explicit config mutations; it should not change global runtime defaults or add a second loader. This is a scope assessment, not a claim the export behavior is safe or desirable.
