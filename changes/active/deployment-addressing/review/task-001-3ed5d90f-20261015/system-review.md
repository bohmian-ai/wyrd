## Owner-raised Agent export issue (scope note, not a system finding)

The reported behavior is real: `Agent::from_card` applies `run_config_from_agent_run_config_spec`, which starts with runtime defaults; `Agent::to_spec` projects those runtime values back, materializing absent max_iterations and tool_concurrency_cap. The latter is Some(8), also the loop's effective fallback when absent (`loop_runtime.rs:369`), so the cited case changes serialization/hash, not actual concurrent execution or route. `to_spec` also emits an empty verified_by rather than retaining bindings; that deserves assessment against the complete registry/identity obligations by the task/validation reviewers, not a speculative system-availability claim here. No loaded Agent is exported and re-registered in the required installed-CLI stage. REQ-008's exact authored-form preservation language expressly addresses Prompt forms. I therefore do not invent a new defaulting policy or remediation based solely on the R2 test discovering this adjacent export behavior. This source note lets independent validation decide any stronger applicable obligation.
