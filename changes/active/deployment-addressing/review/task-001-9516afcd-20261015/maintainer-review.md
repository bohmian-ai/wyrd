## Material findings

### MAINT-R2-001 — MISSING / INCORRECT — FIND-001-5 is only partially repaired: the shared schema checker accepts malformed standard schema keywords

**Location:** `crates/skald/skald-spec/src/prompt.rs:235–310`, particularly `check_schema`'s catch-all at line 307.

**Authority:** FIND-001-5 requires schema syntax validation at the existing shared pure acceptance owner, reused by portable/native compilation and runtime builder finalization. REQ-006/007/008/011 and AC-006 require invalid schemas to be refused before storage/provider IO. Maintainer-style requires the documented typed contract to match actual acceptance; the skill requires conventional standard validation rather than an incomplete substitute.

**Source evidence and reach:** `AuthoredPrompt::compile` builds native/portable requests and calls `Prompt::new`; `Prompt::new` derives the response schema and calls `check_output_schema`, which enforces OpenAI object root and invokes `check_schema`. Card deserialization/registration and builder finalization converge here. `check_schema` checks a selected set of keywords and accepts every other value without validation. For example, `{"type":"object","properties":{"score":{"type":"number","minimum":"one"}}}` reaches a nested `minimum` string and returns success. `{"type":"object","$ref":7}` also returns success. These are malformed schemas, not unknown provider extension options. The code and documentation expressly call the result structurally valid JSON Schema, while the inline comment admits a structural subset. Existing tests cover `type`, `required`, and `properties` examples and do not close this general syntax contract.

**Consequence:** Invalid output declarations still register and are forwarded upstream, moving an authoring refusal into a provider failure or unsupported interpretation. Maintainers must expand a private partial JSON Schema implementation each time a standard keyword exposes this gap. The problem remains the original shared acceptance authority, not a new per-provider caller defect.

**Smallest correction:** Complete standard schema syntax validation in this same pure shared construction boundary; reuse a conventional offline JSON Schema validator/meta-schema mechanism rather than extending a second ad hoc keyword language. The workspace already declares `jsonschema` (`Cargo.toml:119`), although `wyrd-skald-spec` currently does not consume it; assess its pure/offline mode and dependency cost in that narrow owner. Preserve provider-native extension options, exact authored valid schema bytes, existing provider compatibility checks, and the no-network-reference requirement. Do not add registration-only or SDK-only guards. The implementation choice must validate the declared schema dialect honestly, not silently accept malformed standard keywords.

**Focused proof:** Extend existing schema compiler/builder and real registration refusal owners with nested malformed numeric/string/reference/subschema keywords plus a valid nested schema, exercising portable and native forms and asserting no Card write/provider request. Keep the current focused selectors; no new harness or whole-suite gate is needed.
