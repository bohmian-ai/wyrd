### BREV-5 — retain FIND-001-5 — INCORRECT: schema validation still accepts malformed schemas

Obligations: REQ-006/007/008/011, AC-006 and R1 FIND-001-5's schema-syntax correction. Exact location: `crates/skald/skald-spec/src/prompt.rs:255–310`, especially the default arm at 307; producer `authoring.rs::portable_request` and native `Prompt::new` at 398–407; Card acceptance `wyrd-spec/src/card/prompt/spec.rs::{new,deserialize}`.

A concrete portable Prompt with ordinary text and `response_format: {"type":"object","properties":{"n":{"type":"number","minimum":"wrong"}}}` passes every branch of `check_schema`: `type` and `properties` are valid, but `minimum` falls through unchecked. Likewise `$ref: 7`, `minLength: -1` and `uniqueItems: "yes"` are accepted. These are malformed known JSON Schema keywords, not unrecognized vendor extension fields. Native schema fields and builder finalization reach exactly the same partial validator. PromptSpec decoding compiles that accepted value and therefore admits standalone/inline registration; rendering copies it to upstream structured-output fields. The user gets a registered invalid Prompt and a late upstream rejection instead of the promised field-specific authoring refusal. The new tests demonstrate several selected keyword checks, not complete schema validity.

Smallest safe correction: finish schema-syntax validation once at the existing pure shared `check_output_schema` acceptance boundary, used by authored/native/builders, using standards-backed offline schema validation rather than extending this partial keyword whitelist one defect at a time. Reuse the workspace's existing JSON Schema implementation where it can meet the no-IO foundational boundary; disable remote resolution and preserve schema bytes. Keep the separate destination compatibility checks, field-specific errors, valid local-reference/nested schemas and native extension preservation. No server-only or per-SDK guard, network schema retrieval or new schema store is appropriate. Focused closure: extend current authoring and builder negative tests with wrong known keyword types and nested paths; extend the current public registration negative owner to prove refusal before storage/IO and retain a valid nested/local-reference positive. No historical failing run needs to be manufactured.
