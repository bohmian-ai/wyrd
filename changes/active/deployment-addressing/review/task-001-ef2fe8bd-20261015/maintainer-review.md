## Material findings

### MAINT-001 — VIOLATION — required rustdoc is missing on the changed compiler and route preparation path

- **Locations:** `crates/skald/skald-spec/src/authoring.rs:273`, `:328`, `:386`, `:451`, `:480`, `:561`, `:625`, `:701`, `:717`, `:734`, `:745`, `:764`, and `:798`; `crates/skald/skald-spec/src/prompt.rs:60`, `:73`, `:81`, `:90`, `:94`; `crates/skald/skald-spec/src/request.rs:92`–`:160`; `crates/wyrd-spec/src/card/prompt/spec.rs:59`; `crates/vala/vala-eval/src/orchestrator/judge.rs:137`.
- **Rule:** AGENTS.md §16 explicitly requires substantive rustdoc on every new/materially modified item, including private functions and tests, and `# Errors` on every fallible function. The maintainer guide's Documentation section makes this blocking even when checks pass.
- **Evidence:** New lowering/validation helpers have one-line descriptions but no `# Errors` sections. `native_request` rejects mixed forms, provider/format mismatch, `body.model`, and typed decode failures; `portable_request` can reject Jev, missing content, media and settings; `lower` rejects assistant media and malformed binding syntax. The new Prompt serde methods and changed `PromptSpec::deserialize` have no method rustdoc. `SkaldJudgeInvoker::agent_for` materially changes route admission and caching but still has no rustdoc at all.
- **Reachability and maintenance consequence:** Card decoding calls Prompt deserialization → compilation → these helpers. Judge invocation calls `agent_for` before execution. These are the shared places a maintainer must change to adjust authoring or execution admission; the refusal and cache contracts are absent at those seams. A public summary on `compile` does not document the private items required by §16.
- **Affected items in this finding:** The authoring methods `native_request`, `portable_request`, `PortableMessage::lower`, `check_format`, `openai_chat`, `anthropic`, `google`, `refuse`, `within`, `positive`, `stops`, `to_body`, and test helper `compile` lack `# Errors`. Prompt's new `PartialEq::eq`, `Serialize::serialize`, `Deserialize::deserialize`, and `JsonSchema::{schema_name,json_schema}` lack method documentation. ProviderName's new associated `Err` type and its Display/serde/schema methods lack item documentation; its `FromStr::from_str` already has a substantive description and `# Errors` and needs no duplicate prose. `PromptSpec::deserialize` and `SkaldJudgeInvoker::agent_for` lack method documentation. New compiler test helpers `refused`/`body`, both new compiler tests, `ScriptedGateway::call`, and `execution_route_isolated_through_tool_loop` also contain explicit panic paths without the required `# Panics` documentation.
- **Smallest correction:** Add accurate item-level intent and error-condition rustdoc to those changed items; document the changed judge preparation's cache and cancellation behavior and the named new tests' panic conditions. Do not add an abstraction, script, or permanent documentation check.
- **Focused proof:** Static review of those functions against their actual branches and AGENTS.md §16; existing formatting/lint/doc checks after the documentation edit. No new behavioral test is needed for prose.

### MAINT-002 — INCORRECT / REGRESSION — the shared public Agent caller still projects provider-era addresses

- **Location:** `crates/shared/wyrd-client/src/gateway_caller.rs:270`–`:287`; corroborating stale test expectations at `crates/shared/wyrd-client/tests/integration/gateway_caller.rs:532` and `:587`.
- **Rule:** Maintainer guide: public contract and implementation must describe the same operation; AGENTS.md §§2, 8–9 require the shared client to project the server contract. Approved REQ-001/REQ-010 and AC-008 require named deployment targeting and local/server parity. `architecture/wyrd-design.md` Agent section explicitly says the deployment is never derived from the Prompt provider.
- **Evidence:** The Anthropic arm sets `body.model = model.model.to_string()`, losing the deployment. The server's `anthropic_messages` parses that string using `ModelRef::from_projection`, which requires `<deployment>/<model>`. The Google arm emits `/v1beta/models/<model>:generateContent`, whereas the mounted/declared route now takes `/v1beta/models/{deployment}/{target}`. The same arm classifies a target as Vertex by comparing the deployment's name to the literal `"vertex"`. That name is no longer a provider discriminator. The public caller's docs still describe provider-era projection and its mock test expects the old route, so a green mock result would preserve this mismatch.
- **Producer-to-consumer path:** Each SDK's observed invoke → shared `Run::invoke_on` → `wyrd_gateway_registry` (correctly creates `ModelRef { deployment, model }`) → `PublicWyrdGatewayCaller::call` → `NativeCall::project` → changed public ingress. The in-process server caller separately carries the correct typed `call.model`, so server-only judge success does not validate this path.
- **Consequence:** Anthropic Agent calls are rejected as malformed model addresses; Google Agent calls miss the named route. A Google deployment named `vertex` is refused for its spelling, despite local Vertex refusal already belonging to the Prompt-provider boundary in `Run::invoke_on`. These stale projections make the newly documented shared API unusable for those providers.
- **Smallest correction:** Fix the existing public projection: send the complete address in Anthropic's gateway-bound body; include the deployment path segment for GenerateContent while encoding the model as a segment; remove deployment-name-based provider classification. Preserve the existing explicit local Vertex rejection at the Prompt-provider boundary. Update this owner's docs and mock assertions together. Keep the public HTTP and in-process invocation adapters in their existing owners; no shared transport or replacement orchestration is needed.
- **Focused proof:** Update `gateway_caller::public_gateway_call_context_and_errors` to use independently named Anthropic/Google deployments and assert the exact addressed body/path. Add/extend the existing real SDK Agent gateway journey to execute both protocols, so its receiver is the actual Wyrd ingress rather than a mock accepting an obsolete route. Existing focused command for the mock test: `mise exec -- cargo nextest run --locked -p wyrd-client --test integration -E 'test(=gateway_caller::public_gateway_call_context_and_errors)'`. This review did not run it.

### MAINT-003 — MISSING / REGRESSION — Agent's durable projection discards the declared execution route

- **Changed location:** `crates/skald/skald-agent/src/agent.rs:708` (`Agent::to_spec`), with the receiving constructor at `:601` (`Agent::from_card`).
- **Rule:** AGENTS.md §5 requires the meaningful retained domain state to have one concrete owner. Approved REQ-009 and INV-004 require a persisted Agent route and distinguish it from a per-run override; the current design's Agent contract requires the declared route to survive loading and forbids hidden native fallback.
- **Evidence:** `to_spec` unconditionally constructs `ExecutionRoute::Native {}`. `from_card` reads the Prompt, tools, run config, and metadata but never retains `card.spec.execution_route`. `Agent` has no field retaining that declared value. Consequently `Agent::from_card(gateway_card, ...).to_spec()` changes the route to native. The shared Run and Vala judge now interpret the spec route outside Agent before constructing a new Agent, but the canonical public Agent loaders continue to bypass those wrappers.
- **Reachable sibling consumers:** `from_yaml_path` → `from_yaml_str` → `from_card`; `from_wire` → `from_card`; Python `Agent.from_yaml` and `Agent.model_validate_json` use those constructors. `to_card`, `to_wire`, YAML save, and Python model dump use `to_spec`. Direct `Agent::run`/`run_with` use the retained/default provider registry; they do not recover a lost route. The existing save/load journey constructs only a native Agent, and the new gateway tool-loop test injects a provider registry manually, so neither proves a declared gateway route survives loading.
- **Concrete maintenance consequence:** There are now two hand-assembled route-aware paths and a public route-blind Agent owner. Updating route behavior at the apparently canonical Agent API silently changes persisted Card data and can execute a gateway-declared Agent through host-native providers. The required behavior depends on which constructor/caller a maintainer chooses.
- **Smallest correction:** Retain the declared `ExecutionRoute` on the existing Agent owner through Card/YAML construction and projection; keep per-invocation effective binding separate from that declared value. Reuse the existing gateway registry/provider override seam for host execution and reject a gateway declaration when its execution environment has not supplied that route, rather than executing natively. Extend the existing owner; do not add a second Agent loop, loader, transport, or runtime. Preserve the explicit server-native refusal and existing host-specific gateway callers.
- **Focused proof:** Add a gateway-Card load → `to_spec`/save → reload roundtrip in the existing Agent construction target, and execute a loaded gateway Agent against a scripted caller while a native provider records zero calls. Cover the Python public YAML/JSON loaders because they share this constructor. Verify the existing route-isolated tool-loop test still uses distinct per-run bindings. The test must start from the declared gateway Card, rather than manually attaching a registry to a newly native Agent.

- `WyrdGatewayCaller` is earned by real public, server, and test implementations. The existing Agent bounded loop is reused; a new orchestration layer would be unnecessary.

- The compiler's stateless provider lowerers and CLI's ordered list writer do not need utility structs. Their data/lifetimes remain invocation-owned.
- Large matrix tests and short native-option wrappers were not rejected for line count or naming preferences. No optional redesign is proposed.
