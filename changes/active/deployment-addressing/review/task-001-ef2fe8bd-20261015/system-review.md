### Important

- **SYS-001 — INCORRECT / MISSING: the shared public Agent caller does not implement the revised non-OpenAI addressing contract.** Location: `crates/shared/wyrd-client/src/gateway_caller.rs:270–295` (the changed `NativeCall::project`), with the response-dialect set at lines 140–168. Violates approved REQ-009/REQ-010/REQ-011 and AC-005/AC-008: Anthropic, Gemini and Jev Agent addresses must survive public ingress, and arbitrary deployment names must remain separate from provider identity.

  Producer-to-consumer path: `crates/shared/wyrd-client/src/observe/invoke.rs:77–125` resolves the invocation's immutable route, constructs `PublicWyrdGatewayCaller`, and passes its deployment to `skald_agent::wyrd_gateway_registry`; `crates/skald/skald-agent/src/gateway.rs:78–94` produces a `ModelRef { deployment, model: Prompt.model }`; the registered provider's `send` forwards it unchanged to `PublicWyrdGatewayCaller::call`, which calls this projection before shared authenticated HTTP transport. The projection still puts only `model.model` into an Anthropic body (line 271), while server `gateway/ingress.rs:390–398` parses that field with `native_model`, requiring `<deployment>/<model>`. A normal `claude-sonnet-4-5` Prompt therefore receives a structured invalid-model refusal before provider IO. A slash-containing model could instead be interpreted as the wrong deployment/model address. Gemini's projected URL omits the deployment segment (lines 284–285), while the mounted route and extractor require `/v1beta/models/{deployment}/{target}` (`ingress.rs:519,562–575`); a normal model gets no matching route. The guard at line 279 also refuses an otherwise valid Google deployment named `vertex`, even though deployment names are arbitrary and the owning observed invocation already rejects actual Vertex Prompts by `ProviderName` (`observe/invoke.rs:94–99`). Finally, `ProviderRequest::JevSystemOne` falls into the unsupported wildcard; the same server already ships `/v1/systemone` with addressed model parsing (`ingress.rs:451–511`).

  Observable consequence: local observed Agents using the required Anthropic, Google or Jev routes cannot complete, across the first-class clients projecting `Run::invoke_on`. Reconnection, server restart, an alternate same-provider deployment, or credential rotation does not repair this deterministic client projection. OpenAI calls and the independent in-process server judge caller remain available; this is a request/capability failure, not grounds to fail the shared server process. Fallback does not repair a request that never reaches admission.

  Smallest safe correction: complete the existing shared `NativeCall`/`Ingress` projection, preserving the entire `ModelRef` until gateway resolution: addressed Anthropic model, deployment plus escaped complete Gemini model suffix, and the existing Jev systemone route/native response and error decoding. Remove the deployment-name-as-provider test; preserve the actual Prompt-provider Vertex refusal at the existing invocation boundary. Do not alter direct protocol translations, add admin-read requirements, create another client transport, or introduce local Vertex support. Siblings to cover together are OpenAI Chat/Responses, Anthropic, Google and Jev branches of this one projection; retain the separate in-process `ServerWyrdGatewayCaller`, which passes `call.model` explicitly and does not have this prefix-loss defect.

  Focused closure proof: extend the existing real SDK Agent journey to invoke hydrated Anthropic, Google and Jev Agents through non-reserved named deployments and assert the exact target and upstream model/key. Include Google on a valid deployment named `vertex`, plus an actual Vertex Prompt's explicit local refusal before IO. Exercise at least one named fallback and capture requested/resolved targets through the same Agent caller. The existing `native_ingress_preserves_named_deployments` test (`sdks/wyrd-sdk-rust/tests/integration/gateway_inference.rs:907–1051`) manually sends correctly addressed requests with `reqwest`; it never calls this projection and cannot close this gap. `agent_routes_and_pre_run_overrides` at line 650 exercises OpenAI only. Use the existing repository-managed Postgres journey wrapper and exact selector, with no new harness; owning language projection tests should continue to use the same shared implementation.
