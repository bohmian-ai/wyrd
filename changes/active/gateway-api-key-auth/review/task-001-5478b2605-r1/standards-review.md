## Material finding

### REPO-001 — Incomplete required Rust documentation on changed lifecycle operations

Classification: VIOLATION. Blocking under the explicit AGENTS.md §16 / agent-rules rustdoc gate, independently of ordinary style severity.

Locations:

- crates/wyrd/wyrd-testing/tests/gateway/harness.rs:219–243, Journey::deploy and new Journey::deploy_as.
- crates/wyrd/wyrd-server/src/components/gateway/api_keys.rs:72–106, GatewayApiKeys::authenticate.

Evidence: deploy_as awaits put_as twice; put_as asserts an accepted response and try_put_as expects a successful send. Neither deploy_as nor the materially changed deploy documents those panic conditions. Cancellation between these writes also leaves the credential stored without its deployment. GatewayApiKeys::authenticate awaits the shared API-key grant. That grant writes key use, mints/stages its decision, and commits before returning; cancellation during that await can therefore leave a staged decision or committed use without a returned principal or cache insertion. The new method's rustdoc covers happy path and Errors but does not describe cancellation/partial progress, even though that behavior matters when safely changing authentication or retry logic.

Consequence: the changed methods omit explicit required lifecycle contracts at the exact points a maintainer must understand partial deployment, grant cancellation and retries. This is a documentation correctness blocker mandated by repository authority; it is not a request to change runtime behavior.

Smallest correction: complete rustdoc on these changed methods, documenting deploy/deploy_as panic conditions and non-atomic credential/deployment writes, and authenticate's relevant cancellation/partial-progress behavior inherited from the existing grant. Preserve existing semantics and reuse the existing owners. Include the analogous grant-facing ingress lifecycle description if documenting that operation in the same pass. Do not add guards, transactions, retries, fixtures or new runtime behavior for this finding.

Closure proof: inspect rustdoc against the complete current method bodies and callees, then run the narrow formatting/documentation checks appropriate to the documentation-only write set. No new behavior test is necessary for prose alone. Keep the already supplied authentication/journey proof; no broad suite is required solely for this finding.
