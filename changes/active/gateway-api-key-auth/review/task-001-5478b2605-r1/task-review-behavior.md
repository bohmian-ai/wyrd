## Reuse and scope falsification

The new cache does not duplicate a pre-existing owner that can satisfy this task unchanged. `verification/cache.rs::VerifierCache` retains parsed immutable Verifier Cards under `(tenant, CardUid)` and charges serialized bytes; its role is unrelated to credential verification, fixed age, or secret retention. The new cache uses the same installed LRU and short synchronous-lock pattern without changing that owner. `wyrd-client::AuthMiddleware::bearer` retains one caller-owned credential and serializes its own refresh/exchange through a client transport. Reusing it would introduce a client transport/self-call and credential-owner lifecycle into server ingress. The new concrete server owner is required by the explicit process-cache behavior, retains meaningful state, and adds no generic cache framework.

Grant orchestration is reused in full. Changing `TokenGrants::api_key` visibility is sufficient; no SQL copy, alternative key parser, issuer, error mapper, audit sink or authentication resolver was introduced. The existing principal-only API-key authentication method belongs to the unchanged OTLP workflow and is deliberately not used for this mint-and-audit requirement.

Every gateway route already mounted by `gateway_ingress_router` receives the shared fallback, including OpenAI file/batch/model routes. These are part of the existing public OpenAI-compatible ingress router, not the management API; the task expressly chooses that router as its boundary and forbids a new route alias. General tenant extraction is unchanged, so warming a hash cannot affect another surface's authentication.

No cache lock encloses key hashing work beyond insertion or any awaited operation. Concurrent cold requests can each independently exchange and audit, as distinct calls to the existing grant. The specification does not promise single-flight exchange or exactly one audit across concurrent misses. Adding a per-key gate would be an unrequested mechanism.
