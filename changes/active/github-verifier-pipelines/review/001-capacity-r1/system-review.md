## Proposed material finding

### SYS-001 — Lane admission does not spend the governed model-call timeout

- Classification: **REGRESSION / INCORRECT**.
- Changed location: `crates/wyrd/wyrd-server/src/components/gateway/caller.rs:129-146`; full unchanged `call.timeout` forwarded at `:164` after the new wait.
- Obligation: preserve existing budgets and deadline behavior (original task), and the existing `WyrdGatewayCaller` contract: implementations submit within the call's timeout (`crates/skald/skald-agent/src/gateway.rs:43-53`). This is a per-model-call bound, distinct from the overall execution ceiling.
- Producer to consumer: hosted `AgentExecutor` creates an Agent with this gateway caller (`blocks.rs:284-287`); Skald's gateway adapter constructs each WyrdGatewayCall with `DEFAULT_GATEWAY_CALL_TIMEOUT = 10 minutes` (`skald-agent/src/gateway.rs:24`, `:150-157`). Its token is created never-cancelled (`:91`), and an Agent without an authored timeout has no additional Agent timeout (`skald-agent/src/run.rs:27-33`, `loop_runtime.rs:157-163`). The candidate waits for a lane permit using only that token, then starts GatewayInvocation with a fresh full call timeout. The wait never spends that call budget.
- Reachable supported scenario: operator sets queued MODEL_CALLS to 1, queued EXECUTIONS to at least 2, and queued execution deadline to two hours (explicitly accepted and asserted by `config::tests::verification_limits_env_applies_and_refuses`, `config.rs:4387-4388`; env producer `:1825-1827`). Concurrent ordinary queued Agents with no shorter authored Agent/Verifier timeout share that one model permit. One slow model call occupies it; the second spends time waiting and then still receives another full ten minutes of gateway execution. Nine minutes waiting plus a two-minute upstream response returns success after eleven minutes for a ten-minute WyrdGatewayCall; with longer contention it can wait beyond ten minutes before any gateway admission. No suspension/approval feature or speculative new workload is needed.
- Observable system consequence and materiality: configured model pressure silently lengthens the existing bounded model operation, retains an active queued execution slot while overdue, and may dispatch/charge provider work after that model call's deadline. The outer two-hour execution ceiling still holds; it does not enforce the smaller model-call contract. Default five-minute queued and sixty-second direct ceilings mask this defect, so the current journey's ten-second outer timeout cannot falsify it. Long execution ceilings are an explicit supported new configuration, not an unbounded hardening request.
- Existing owners / siblings: `ServerWyrdGatewayCaller::call` is the sole new lane-wait owner and `.admitted` is used only by hosted engine composition. The ordinary GatewayInvocation already owns provider deadline/cancellation/accounting and must remain intact; unbound gateway consumers do not need a scheduler or different policy.
- Smallest testable correction: make the existing per-call timeout cover the lane wait and governed call as one operation in this caller, retaining cancellation, lane permit RAII and GatewayInvocation's cancellation/accounting cleanup. Do not reset the timeout after semaphore acquisition. No new configuration, queue, process failure or retry mechanism is needed.
- Focused closure proof: use the existing caller/gateway test fixture with a short WyrdGatewayCall timeout and a held lane permit; assert timeout occurs without gateway/provider dispatch, release the hold and confirm the next call succeeds. Also spend part of a short call budget waiting before releasing the permit, hold upstream past the original remaining budget, and assert the entire call cannot consume a fresh full timeout after admission. Use existing holds and recorded provider requests; no production-scale sleep/load is needed.
