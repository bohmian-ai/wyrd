## Existing-owner comparison and adversarial checks

- Existing `HostedBlocks` was already the shared composition owner; extending it with two retained lanes is sufficient and avoids duplicate runner/service orchestration. `Lane` owns meaningful shared resource dependencies rather than a forwarding or utility abstraction.
- Existing `ClaimLoop` remains the queued execution capacity and fairness owner. Direct `try_acquire_owned` adds only the admission the synchronous path previously lacked, rather than sending direct work through a new queue or scheduler.
- Existing `Workspaces` and `Sandbox` continue to own refusal, checkout, cancellation and cleanup. Their per-lane constructors are the minimum missing state separation; no downstream reclassification or resource fallback is added.
- Existing gateway `GatewayInvocation`, `GatewayLedger`, child-token cancellation and tracked settlement remain authoritative. The per-call lane semaphore is an additional admission bound expressly required before that owner, not a replacement billing/authorization lifecycle. Retaining a permit through later asynchronous capture is not required by the approved admission-only isolation scope.
