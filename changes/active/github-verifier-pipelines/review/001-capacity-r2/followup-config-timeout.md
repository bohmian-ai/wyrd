Sibling grouped and Drift query budgets read the same configured duration and convert to signed milliseconds with saturation (`verification/groups.rs:179`, `verification/drift.rs:752,1034`). The fitter consumes the original duration (`verification/fitter.rs:119,285`). The bound belongs upstream of these divergent conversions.
3. `crates/wyrd/wyrd-sql/src/queries/verifier_executions.rs:71–83,104–137,283–297,413–466,2940–2957`. Scheduled, submitted and grouped runnable rows omit `deadline_at`. Bind 3 is `deadline_for.num_milliseconds()`, a signed 64-bit PostgreSQL bigint. The orchestrator ran the same expression read-only against the managed PostgreSQL instance, replacing `$3` with `9223372036854775807`. It returned SQLSTATE **22008**, `interval out of range`, at `interval_mul` in `timestamp.c:3412`. This is direct proof of the SQL expression failure. The startup and actual first-claim wiring were checked in source.
4. `verification/claims.rs:345–355,407–425`. The failure propagates before commit and the tenant claim transaction rolls back. Attempts and deadlines are unmodified.
