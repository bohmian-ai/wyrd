## Materiality and excluded hypotheses

No source-proven supported-use security, tenancy or persistent-integrity defect was established. The new SQL setters can receive an inconsistent boolean from a hypothetical caller reusing a result identity with different Completion data, but production completion retries retain one transition and identical replay is explicitly the supported obligation; that hypothetical caller is not a basis for adding a new persisted-result validation mechanism. Likewise, reacquisition after unpersisted progress and already-issued IO after cancellation are permitted by REQ-017/INV-006; they do not imply permission to settle obsolete work, which remains fenced.

No domain remediation is proposed. Existing owners remain authoritative: TenantConn/RLS for SQL authority, GithubConnections for installation access, the public pipeline for pinned source acquisition, and RunState/Bifrost for accepted evidence. Metadata batching extends the metadata owner rather than storing execution payload there.
