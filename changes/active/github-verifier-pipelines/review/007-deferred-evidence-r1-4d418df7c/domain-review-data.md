## Proposed findings

### DATA-007-1 — Artifact acceptance precedes the required metadata validation

- Classification: **INCORRECT**.
- Violated obligation: task Selected custody explicitly permits only completed verified File/Artifact handling and requires subscribers' declared type/format/schema to be validated before acceptance; REQ-009 and contracts require exact type/format validation before acceptance.
- Changed location: `crates/wyrd/wyrd-server/src/components/verification/service/evidence.rs:97–108` and `:261`.
- Failing state producer: `subscribers` passes `request.value` to `conform`; `vala-verify/src/blocks/engine.rs:2856–2857` accepts every Artifact declaration for a media slot because only the host knows its metadata. The publisher's additional check handles only File. It then stages the Artifact declaration as immutable evidence.
- Reachable supported scenario: a bound deferred CSV media slot receives an existing Artifact whose selected file is PDF, or an Artifact path that does not exist. The public request accepts an Artifact declaration; `conform` succeeds; publisher returns durable accepted. No hostile input or new feature is needed.
- Consumer and consequence: runner `deferred` reads accepted declaration and passes it to engine. Existing `TenantEvidence::admit` at 538–555 finally resolves Artifact metadata and rejects wrong format/path/size; runner `engine_failure` at 1710–1711 terminates errored. Correcting the Artifact on the same repository/commit/input produces a new content hash and publisher `conflicts` refuses replacement. An invalid first publication therefore poisons all matching consumers instead of being rejected while correction remains possible.
- Sibling paths and existing owner: File publication already consults ObjectInventory before durable acceptance; direct and queued engine evidence admission already share `TenantEvidence::admit`, whose Artifact path uses `artifact_file`→`inventory` (authorized exact registry metadata, path, format, size) and checks slot constraints. `artifact` and select/read also reuse this metadata owner. Pure `conform` cannot perform IO and must not learn a parallel Artifact registry workflow.
- Materiality: the task explicitly ships Artifact publication and a durable accept-once input. Checking only the enum variant fails its admission boundary, and the consequence is permanent bad acceptance for the source and errored supported verification, not merely a late diagnostic.
- Smallest correction: reuse the existing TenantEvidence metadata/admission owner before any acceptance is staged for each eligible subscriber. Preserve the distinction between publication validation under publisher authority and execution under accepted execution authority. Resolve the file/path and enforce declared media format/size through that owner; do not create a second registry/file resolver or remove Artifact support. Refused/unavailable metadata must leave no new acceptance; a later correct publication must still work. Keep per-execution combined resource admission in its existing execution boundary.
- Correction burden: bounded server publication integration and any minimal exposure/reuse of existing admission logic, plus focused Artifact refusal/success proof; no new storage model, schema, queue mechanism or dependency. Deleting the validation or simply relying on later consumer checks cannot preserve accept-once publication correctness.
- Focused closure proof: use an active media subscription, publish a real existing wrong-format/oversize Artifact and bad path, assert typed refusal and no acceptance, then publish a valid Artifact at the same source/input and assert accepted and consumption. Cover at least wrong format and later-correct-publish through the existing server journey owner; keep permission-specific proof with the security review.

### DATA-007-2 — Winning acceptance is discarded when reconciling an overlapping identical retry

- Classification: **INCORRECT**.
- Violated obligation: task REQ-009 says identical matching identity/content replays its receipt; architecture Verifier says identical content returns status replayed; `PublishEvidenceResponse.recorded_at` is the first-accepted time (`wyrd-spec/src/verification/execution.rs:227–228`).
- Changed location: `components/verification/service/evidence.rs:143–151`, then `:157–176`.
- Failing producer-to-consumer path: two identical publishes (including a retry whose original outcome is unknown) can both read `held` empty before either acceptance commits. They compute distinct `now` values, stage the same acceptance batch ID with rows differing at least by recorded_at. Existing batch fence keeps the first and rejects different physical rows; second `accept` fails. The explicit raced-read branch reads the winning Accepted row and confirms matching sha256, but discards that map. Response still derives recorded_at from empty original `held` plus the loser's local now, and status from originally nonempty `fresh`. It returns accepted/new timestamp, although its offered row never became canonical. A later sequential retry returns replayed/the winner's actual earlier timestamp.
- Observable consequence/materiality: overlapping retry responses disagree about the durable acceptance's first recorded time and falsely claim a new acceptance. Payload dedup remains intact; the defect is the public replay receipt contract for the supported retry flow, not an assertion that data was lost. Scope is narrow and the correction does not require stronger atomic publication semantics.
- Sibling paths/authority: `DeferredEvidence::accepted` already returns canonical `Accepted {published,recorded_at}`; sequential replay builds from it and the existing journey asserts receipt equality at `pg_deferred_evidence.rs:352–356`. Scribe's own commit/fingerprint mechanism remains the correct first-writer owner. No additional SQL lock or idempotency store is needed.
- Smallest correction: retain and use canonical raced acceptances when composing the response, including whether this call actually created any fresh acceptance. Preserve all acceptance ACK waiting, conflict detection, partial failure semantics and wake-on-replay. Do not broaden to cross-subscriber atomic transactions or introduce another dedup owner.
- Correction burden: local response reconciliation only plus focused overlapping-identical-retry proof. Deletion of the race recovery would turn safe retry into avoidable error and would not meet the task. Existing canonical read provides the complete required data.
- Focused closure proof: overlap identical publishes against one subscriber using existing request/test facilities; assert exactly one accepted receipt, the retry replayed, same evidence_id and first recorded_at across both and subsequent retry, and one retained acceptance. No new production hook is needed.
