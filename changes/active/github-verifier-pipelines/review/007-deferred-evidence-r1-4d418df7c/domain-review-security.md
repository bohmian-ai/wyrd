## Proposed findings

### SEC-007-1 — Artifact references are durably accepted before their file and slot are validated

- Classification: **INCORRECT**.
- Violated obligation: Task 007 Selected custody explicitly limits publication to completed verified File/Artifact handling and requires subscriber declared type/format/schema validation before acceptance. Contracts Deferred input publication repeats this; REQ-009 requires subscriber validation.
- Changed location: `crates/wyrd/wyrd-server/src/components/verification/service/evidence.rs:97–108` and `:261`.
- Producer-to-consumer proof: the public request accepts `InputDeclaration::Artifact` (`wyrd-spec/src/verification/execution.rs:99–106,177–186`). `subscribers` authorizes the subscriber, then calls only `conform`. Its media/Artifact arm at `vala-verify/src/blocks/engine.rs:2856–2857` returns success unconditionally. The publication handler checks completed inventory only for `File`; Artifact therefore goes directly to `DeferredEvidence::publish` and `accept`, whose fence makes this reference immutable for source/input/subscriber. A supported Artifact with a PDF file can be published to a CSV-only deferred media slot and receive a positive durable receipt. A nonexistent Artifact or nonexistent file path likewise receives acceptance. The resumed engine later calls `EvidenceReader::admit` at engine.rs:740. `TenantEvidence::admit` at hosted/evidence.rs:539–562 resolves the Artifact and rejects absent/path/format/size failures. This is after canonical acceptance, not before it.
- Observable consequence and materiality: the producer receives an accepted receipt for unusable evidence; an execution consuming it errors instead of proceeding. A corrected valid Artifact or File changes the canonical declaration hash and `conflicts` at service/evidence.rs:312–330 refuses replacement for that source/subscriber. This is a normal supported media-input path and a permanent acceptance-integrity failure, not speculative malformed-input hardening. In addition, the publisher's own Artifact read decision is never evaluated before the reference is retained; consumer checks use the execution's different accepted authority.
- Existing owner and sibling paths: ordinary engine admission uses `TenantEvidence::admit`; its `artifact_file` (:324–363) selects a server-authoritative file and `inventory` (:377–399) calls `get_card_objects_by_ref_for` / `authorize_card_ref` under that reader's caller. `TenantEvidence::artifact/read`, workspace/hosted consumers and direct/queued engine paths already share it. Publication is the new path that stops at pure `conform` and fails to use the IO admission owner.
- Smallest safe correction: extend/reuse the existing evidence admission capability at the publication boundary under the publisher's verified caller, resolving the selected Artifact file and validating it against every authorized subscriber slot before any acceptance is staged. Preserve the existing consumer-side checks under the execution's own accepted authority; do not move or weaken them. Avoid a second Artifact resolver, a new storage mirror, or extra consumer guards. Restricting the wire to omit Artifact would remove an explicitly supported input and is insufficient.
- Correction burden: bounded reuse or extraction of the current admission owner; no new product behavior, dependency, persistence decision or harness is needed. The existing File and JSON checks should remain in place or route through that same owner without introducing unrelated execution setup.
- Focused proof: through existing publication/server journey setup, reject a valid wrong-format Artifact, missing Artifact/file path, and unreadable Artifact before acceptance; then publish valid evidence for the same source/input and assert success, proving the refusal left no acceptance fence. A valid matching Artifact must still publish and be consumed. Test the publisher and execution authorities separately where their Artifact permissions differ.

### SEC-007-2 — Delegated publication erases the actor from durable evidence attribution

- Classification: **VIOLATION**.
- Violated obligation: `architecture/bifrost-design.md:206–217` requires every row's accepted subject/actor pair; a delegated publisher records the party it acts for as subject and itself as actor. Security posture Delegation and federation defines verified outer `act` and forbids displacing effective authority with attribution.
- Changed location: `crates/wyrd/wyrd-server/src/components/verification/service/evidence.rs:133`.
- Producer-to-consumer proof: Caller carries verified principal and initiator-first delegation chain (`components/auth/caller_extractor.rs:16–41`). `Caller::attribution` (:100–104), through `wyrd_runtime::delegated_attribution` (`request_context.rs:57–63`), already selects the last verified actor. The new publication constructs `Attribution::new(caller.principal.id, caller.principal.id)` instead. `DeferredEvidence::accept` forwards that pair into `ScribeWrite::Evidence`, and `scribe_outbox.rs:539–546` forwards it unchanged into the evidence Rows attribution. An authorized delegated publish by Service B on behalf of A therefore stores A/A rather than A/B.
- Observable consequence and materiality: retained evidence falsely names the subject as the performer, losing the actual publisher in the canonical evidence provenance. This affects a supported standard delegated token, with no unusual input required. Permission-decision audit correctly preserving the chain does not repair wrong required attribution on the evidence row itself.
- Existing owner and sibling paths: `Caller::attribution()` is already used by verification enqueue (`service.rs:840`) and shared storage evidence handling; `AcceptedAuthority::attribution` and `ExecutionAuthority` preserve the same distinction for background work. Publication has no reason to fabricate a parallel pair.
- Smallest safe correction: use the existing `caller.attribution()` result for the Evidence acceptance. Preserve subscriber authorization, accepted consumer authority and asynchronous audit behavior. No new actor field or token handling is necessary.
- Correction burden: one owner call replaces construction; removing attribution would violate the required columns, and an audit-only test would miss the defect.
- Focused proof: publish under an existing delegated caller and query the accepted evidence row through authorized Bifrost access; assert `sub_principal_id` is the effective subject and `act_principal_id` is the verified outer actor. Keep the ordinary undelegated case principal/principal.
