## Proposed material finding

### STD-007-01 — New SQL subscriber identities are decoded by position

- **Classification:** VIOLATION of an explicit repository rule.
- **Obligation:** `crates/wyrd/wyrd-sql/AGENTS.md`, Queries: “Map columns by name, never by position.” Root Code and `agent_docs/rust.md`, Ownership and allocation, require the same mapping discipline.
- **Exact changed location:** `crates/wyrd/wyrd-sql/src/queries/verifier_executions/pull_requests.rs:532` (two-column subscriber projection), with the same new decoding pattern at line 570 (wake projection).
- **Source evidence:** SUBSCRIBERS_SQL selects `verifier_card_uid, card_uid` from bindings and unfinished executions. `evidence_subscribers` calls `sqlx::query_as` into `Vec<(Uuid, Uuid)>` and destructures `(verifier, subject)`. SQLx tuple FromRow reads columns by ordinal, so the source names never participate in mapping. `wake_evidence_consumers` similarly reads `RETURNING execution_id` as `Vec<(Uuid,)>`. Both are executed production paths called by VerificationControl::subscribers/wake. Existing `GenerationRow` in this same module derives `sqlx::FromRow` and its `CURRENT_SQL` read uses named fields.
- **Consequence and materiality:** This is a present explicit mapping-rule violation at the producer of identities that select the Verifier/subject authorization and acceptance target. The present SELECT order is correct; no current swapped identity or authorization bypass is asserted. The prohibited coupling means same-typed verifier and subject IDs can silently exchange meanings when a projection changes, rather than fail by name. It is retained as a mandatory rule proposal, not as evidence that an already reachable input causes that future edit.
- **Smallest correction boundary:** Keep both methods, SQL semantics, return contracts, authorization, tenant transaction and wake behavior. Decode columns by their SQL names at this existing owner, following the module's named FromRow/row access pattern. A scalar wake result need not gain a general abstraction. Do not refactor unrelated pre-existing tuple queries.
- **Correction burden:** Local projection correction only; no dependency, migration, lifecycle change, public API or new workflow. Tests alone cannot enforce named decoding against a currently matching positional order; broad new test machinery would be inappropriate.
- **Focused closure proof:** Source inspection proves name-based column access; run the owning narrow SQL checks/tests through repository Postgres where available and confirm subscriber identity/result behavior remains unchanged. Preserve all existing tests and domain newtype conversion.
