## Failure boundaries and availability

Scribe unavailability can fill the bounded claim custody lane while park acknowledgements wait. This pauses queued claiming, as operations already specifies for terminal custody, while direct execution uses its separate lane. A failed publisher request is retryable and cannot turn partial/staged bytes into a durability certificate. A failed best-effort wake does not invalidate an accepted receipt because queue recheck independently repairs readiness. Lease loss/cancellation abandons the old wait and permits ordinary fenced recovery; it does not crash the shared server or authorize a stale continuation. Permanent loss of unpublished Scribe WAL remains outside the existing recovery guarantee and is not introduced by this task.
