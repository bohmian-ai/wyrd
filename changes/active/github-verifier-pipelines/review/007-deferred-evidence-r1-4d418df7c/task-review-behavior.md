### BEH-001 — INCORRECT: Artifact publication fixes invalid evidence before resolving or admitting it

- **Violated obligation:** original task Selected custody: “Only completed verified File/Artifact handling … reaches publication” and “Validate authorized subscribers' declared type/format/schema before accepting”; REQ-009 and trust-boundary validation.
- **Changed location:** `crates/wyrd/wyrd-server/src/components/verification/service/evidence.rs:98-107` and `:261` (the only publication validation); reused incomplete validation at `crates/vala/vala-verify/src/blocks/engine.rs:2856-2857` explicitly accepts all Artifact declarations for media slots.
- **Reachable scenario:** a valid authorized publisher supplies `InputDeclaration::Artifact` for a deferred media slot, referencing a missing Artifact/path, a registered Artifact with unsupported format, or one exceeding the subscriber slot max_bytes. All are supported API value forms: shared `Evidence::declare` forwards ArtifactRef unchanged, as do thin Python/TS wrappers and raw HTTP/MCP. `conform` passes; File-only completed upload check is skipped; custody writes the acceptance and returns `status: accepted`.
- **Producer-to-result trace:** `subscribers` → `conform` accepts Artifact without IO; `DeferredEvidence::accept:212-245` stages durable source/input/Verifier fence; `runner::deferred:843-863` injects accepted declaration; engine `run:740` calls `EvidenceReader::admit`; existing `TenantEvidence::admit:538-555` finally resolves metadata and rejects missing/path/format/size. Its `artifact_file:324-348` and `inventory:371-391` already own authoritative completed inventory, exact identity, permission, path and metadata lookup. A missing or malformed reference produces a terminal input failure; no alternative value can replace it because service `conflicts:314-327` compares the now-fixed digest.
- **Observable consequence/materiality:** ordinary ArtifactRef publishers receive a durable positive receipt for evidence that cannot satisfy the declared slot, after which affected PR consumers error and correction for the same commit/input conflicts. This is an explicit required validation boundary with lasting first-write consequences, not speculative hardening or preference.
- **Sibling owners/callers:** HTTP and MCP share VerificationControl; Rust/Python/TS share Evidence::declare; all consumption uses hosted TenantEvidence admission. File inventory verification currently lives in publication separately, while Artifact inventory/admission already has the required owner.
- **Smallest testable correction:** before any subscriber acceptance is staged, reuse the existing TenantEvidence metadata/admission capability under the publisher's caller authority and effective hosted limits for each authorized subscriber's slot. Keep canonical JSON validation, File upload completion, consumer authority on later execution and first-write conflict semantics. Extend that owner narrowly if publication cannot call the existing interface; do not build another Artifact resolver, read bytes merely for metadata, or reject the supported Artifact API. The correction is a bounded admission invocation/adaptation, cheaper and safer than a second validator or downstream guards after acceptance.
- **Focused proof:** publication of a valid uploaded/registered Artifact media file succeeds and its waiting consumer passes. Missing/inaccessible path and incompatible format/oversize Artifact return typed refusal before acceptance, then a valid publication for that same commit/input succeeds (proving the bad one did not poison custody). Existing Artifact admission fixtures and server publication journey owner suffice; no new harness or crash hook.
