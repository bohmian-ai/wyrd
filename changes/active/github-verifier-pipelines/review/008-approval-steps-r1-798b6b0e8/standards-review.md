- Rule: root AGENTS Authority says owning architecture is the contract and implementation drift must be reconciled there; `changes/spec-driven-development.md` Authority says code cannot redefine approved behavior. Task explicitly requires an accurate Verifier owner amendment.

### REPO-003 — VIOLATION — approval read failure exposes raw database diagnostics at public boundary

- Location: `crates/wyrd/wyrd-server/src/verification/approvals.rs:226–230`, `unavailable`; callers at 88 and 91.
- Rule: `agent_docs/errors.md` Crate-local errors explicitly forbids raw database/transport strings in public payloads and requires logging the source while returning a typed or Internal error. Root Code requires structured tracing.
- Evidence/path: `ApprovalDecisions::decided` maps `tenant_conn` and `committed_batches` SQL failures through `unavailable(&error)`. The helper embeds the error Display directly into `WyrdError::ServiceUnavailable.message`. Retained inspection calls `.decided(...).await?` (`components/verification/service/inspection.rs:520–522`), and decide calls retained with `?` (`service/approvals.rs:74`). HTTP returns that WyrdError through the ordinary problem mapper, MCP through the shared error mapper. Thus an authorized status/decide request encountering a database connection or query error receives the raw driver/database diagnostic instead of a stable redacted failure. The runner is the sibling consumer and already logs unavailable errors before deferring; no second custody writer is needed.
- Consequence/materiality: new public error behavior violates the mandatory error boundary and exposes internal connection/query diagnostics during supported dependency outages. No exploit-specific input is required. The pre-existing evidence owner has a similar helper; that does not exempt newly added code, and unrelated evidence cleanup is outside this finding.
- Smallest correction: keep `ServiceUnavailable`, the table detail, retryability and absence-vs-unavailability semantics; log the diagnostic with structured tracing at this owner and return a fixed safe public message. One local redaction assertion against the existing helper/error projection is sufficient; no new dependency, harness, retry service or broad error migration.
