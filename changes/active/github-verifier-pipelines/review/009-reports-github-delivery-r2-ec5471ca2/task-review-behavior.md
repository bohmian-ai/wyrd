## Caller and correction-boundary assessment

The only production caller of Presentation::render remains GithubDeliveries::render. It reads accepted steps, selects the report through the existing contract owner and separately attempts extraction deserialization. The optional source change therefore repairs the lost-report cause at its existing consumer, while preserving the accepted selection rules. Unavailable extraction cannot create a plausible inline location.

Finding::anchors still enumerates locations, evidence and edit location before inline placement. Source resolves those anchors against retained before/after content and selected context; full_pr hunks remain the only inline authority. Active-comparison before/head ranges can support evidence without becoming additional inline hunks. Retained context decoding is a small private projection of the existing serialized output, not a parallel context-selection schema or traversal. Extending this renderer is sufficient; no new acquisition or durable owner is warranted.

Every rendered-report review uses the existing execution marker and Write::Review lookup. Empty comments add no new remote identity. The updated tests that replace no-review expectations correct assertions contradicted by the approved COMMENT requirement; they do not relax report eligibility or remove negative checks. Moving the approval POST to Deployment::post retains authenticated request, JSON decode and 200-OK assertions in that existing fixture owner.

The waiting-Check change deletes the unsafe update branch at Write::send. A second read, lock, ledger or provider-status guard would add machinery without closing the stale-write gap as directly. Existing Check identity matching and terminal PATCH are unchanged. The sequential PG test proves the stronger local rule, while direct branch inspection establishes that delayed lookup completion cannot choose a waiting PATCH. It does not claim concurrent absent-create uniqueness, which the approved contract excludes.

The cooldown correction stays in the existing provider classifier and delay consumer. It does not alter permissions, accepted verdicts, retry counts, response redaction or token ownership. Numeric Retry-After behavior is retained and its previously shortened duration is now preserved. The primary reset branch handles the required zero-remaining response.
