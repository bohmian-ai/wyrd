## CONC-012-R1-1 — abandoned cold loads accumulate outside every cache bound

Classification: INCORRECT. New finding arising from the human-directed G1 addition; no prior FIND ID assigned here.

Violated obligation: architecture/wyrd-design.md:1057–1060 requires bounded gateway buffers/background work; architecture/bifrost-design.md:1894–1909 requires bounded Wyrd-owned buffers/process resource ownership. The local snapshots.rs:26–30 contract already bounds tenant cache/reload retention at CACHE_TENANTS. The task preserves resource-scaling gateway snapshots; G1 sanctions loading, not unbounded retained tenant state.

Exact producer: snapshots.rs:109 and 162–175. Exact missing retirement boundary: 177–183, which runs only after the await completes.

Reachable path: during startup, cache eviction or listener loss, an authenticated tenant's bound verification-originated gateway call misses the cache. load_through installs its tenant cell in loads, then waits for tenant_conn, the snapshot query or commit. If the original verification deadline expires while SQL is waiting, admit_call's timeout_at drops prepared and therefore load_through. A cancelled model-list/batch/read request can reach the same seam. Tokio cancels the initializer and releases its internal permit, but its OnceCell cannot remove the separate GatewaySnapshots HashMap entry. No remaining caller executes 177–183. Background warm/reload may subsequently populate snapshots, so later calls hit cached and never remove the abandoned loads entry either. reset/invalidate do not touch loads. Repeating this ordinary cancellation/outage path across tenant churn retains one heap cell/key per tenant for the process lifetime unless that exact tenant later takes another miss to completion.

Consequence/materiality: process memory grows with the lifetime set of cancelled cold tenants, rather than with CACHE_TENANTS or current load activity, including after requests and SQL work have ended. Concurrent distinct cold tenants also have no admission limit at this map. This is a directly introduced missing bound at a shared process owner, not a claim that one ordinary cancellation exhausts memory or that untrusted users may invent arbitrary tenant IDs. Multi-tenant deployment and deadline cancellation are supported paths. Existing edge/request and SQL-pool limits cannot bound accumulated completed request state.

Smallest correction boundary: keep coalescing in GatewaySnapshots; bound its retained tenant-load slots using the already installed LruCache/CACHE_TENANTS and the neighboring GatewayUsage::retain/TenantUsage::clean approach. A load with live caller handles must not be evicted (which would start a second same-tenant load); an abandoned cell with no callers must be reclaimable. When all slots are actively pinned, refuse a new distinct tenant with the existing retryable ServiceUnavailable rather than retaining another slot. Preserve same-tenant result/error sharing and retry, original caller deadline, generation fencing and background recovery. Immediate removal on every cancellation is not required if idle abandoned cells are bounded and reclaimable. No detached worker, new cache framework, janitor, configuration or spec-level concurrency redesign is necessary.

Correction burden: one existing cache owner plus focused cancellation/capacity assertions. Deleting coalescing would violate the agreed once-per-tenant miss outcome; limiting the SQL pool alone leaves abandoned map entries retained; unconditional LRU eviction can duplicate a live tenant load. The existing usage owner demonstrates the required pin/evict/refuse rule without introducing a generic abstraction.

Focused closure proof: hold one cold load before SQL finishes, join a second same-tenant caller and assert only one load starts; cancel all callers and verify another tenant can reclaim the bounded slot; with all slots pinned, assert a new tenant refuses before its loader starts and the retained count stays within the bound; after release/error, retry and successful warm hits still work. Reuse the existing gateway test owner/held local or Postgres seam. Existing snapshots_retain_a_bounded_number_of_tenants only fills Entries.snapshots and cannot cover loads. The CLI restart success and 77 recorded gateway passes do not exercise this cancellation/boundary assertion.
