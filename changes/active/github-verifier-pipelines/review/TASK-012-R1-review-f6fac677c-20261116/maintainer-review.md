## Prior maintainer findings and materiality

The prior MAINT-01 cause, conflating logical replacement growth with temporary physical scratch, is addressed at Workspace::write rather than patched at each tool caller. The corrected writes_charge_process_scratch test asserts a fitting replacement finishes at 300 bytes and a same-size replacement that cannot fit its temporary copy is Busy and preserves the original bytes.

The prior MAINT-02 cause, encoding JSON before admission, is addressed at the existing producers using one shared byte-free count. stage_json now orders memory/file/scratch admission before to_vec_pretty; extraction counts/adopts before its writer streams the result. No competing staging owner was created.

The prior MAINT-03 cause, returning media while losing runtime custody, is addressed at the existing reader-to-binding seam. The held-provider test verifies the guard survives the real Agent binding call and returns on completion and cancellation. This closes the API lifetime/ownership diagnosis within this review's remit; numerical resource coverage and all failure branches are separately assigned invariants.
