## Failure-diagnosis assessment

G2 is independently supported by source rather than merely the author summary: `Sandbox::exec` at sandbox.rs:391 bounds wall time, :426 passes Monty's max_memory, and :445 wraps execution in timeout_at. HostedLimits defaults are 256 MiB and 10 s; the prior test overrode time to 1 s while appending 4 KiB strings. A time-limit failure before allocator exhaustion is therefore compatible with production semantics and explains the recorded second-assertion failure. The candidate lowers the memory-test allocation budget to 16 MiB, uses the default deadline, and uses a separate 1 s sandbox for the allocation-free loop. MemoryError and time-limit assertions remain, with successful calls after both. This is a focused correction to competing test conditions, not a weakened production limit. Recorded 3/3 passes are not proof against arbitrary process suspension, and no synthetic load or new timeout precedence guarantee is required. The R1 record states a diagnostician agreed; this reviewer independently traced the claimed cause but did not execute or reconstruct that diagnostician session.

G1's symptom follows the actual prior source: admitted() returned None on a cold miss and queued reload, while admit_call turned that into retryable 503; the consumer was init's first completion after restart. The old implementation did queue background work, so the statement that nothing could ever warm the cache would be too strong. The source-backed diagnosis is refusal of the first cold call, not permanent failure to recover. The directly approved correction now routes all snapshot consumers through the existing cache owner and shared load-through. Its race/recovery/bounds semantics are independently assigned to concurrency-rev. The older architecture prohibition is recorded above as narrowly superseded, not silently treated as unchanged authority. The CLI test itself was not weakened.
