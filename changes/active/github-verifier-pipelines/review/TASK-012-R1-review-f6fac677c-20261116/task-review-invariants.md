## INV-R1-01 — Terminal state reads still duplicate large outcomes without custody

Classification: INCORRECT. Existing stable finding: FIND-012-2. Violated obligations: R1-2, TASK-012 OBL-7, REQ-017 retained memory, and the prior correction's explicit terminal/snapshot-read custody requirement.

Exact locations: crates/wyrd/wyrd-server/src/verification/state.rs:820-821 (new decision reader), :157-163 (Decision::of), :924-946 (decide); consumers crates/wyrd/wyrd-server/src/verification/runner.rs:540-541 and :1595-1613 (conclude).

Producer-to-consumer proof: Decision::of clones state.terminal, whose TerminalSelection.outcome is ExecutedOutcome, an owning OutcomeDetails<Map<String, Value>, Compiled> with owned requirement details, steps and evidence (wyrd-spec verification/state.rs:256-264, execution.rs:706-747). RunState::decision returns that clone without obtaining a ByteCharge, unlike its changed sibling publications and restore readers. The initial decide path constructs a Decision and charges only the clone inserted into Held.state; the returned Decision remains a separate allocation. conclude keeps the returned decision alive across persisted(state,...).await. After persistence succeeds, it builds the ResultPayload from this decision; deliver can then wait for an outbox slot before staging. There is no guard for the terminal clone in Offer, Decision, conclude or the runner. The live charge is for Held.state only; the frozen charge is retired after the checkpoint ACK and cannot serve as custody for independent returned copies.

Reachable supported scenario: a queued execution selects an ordinary variable-size outcome containing code/Agent details or step outputs while Scribe persistence is held, or recovers an already-selected terminal outcome and redelivers it. There are two owned outcomes, but the live-state ledger only retains one outcome's charge. The returned decision can remain resident while persistence or delivery is backpressured. This is exactly the terminal/read boundary R1 was required to close, not an unrelated new result-format feature. Size is bounded per execution but remains meaningful across shared queued claims, Bifrost and hosted siblings.

Correction burden and smallest safe correction: extend the existing state read/decision custody mechanism to terminal selections, charging before the additional clone and keeping that independent guard with the returned decision through its actual consumers. Reuse Charged/ByteCharge and the existing runner handoff. Cover both decision() recovery and decide/select's returned value; fixing only one caller is insufficient. Preserve first-decision identity, memory-first transitions, ACK-before-retirement and normal queued delivery. Do not permanently inflate Held's charge to pay for copies that have ended, retain checkpoint charges after ACK, or add a second resource owner. Review result construction as the affected next handoff so removing the terminal guard does not simply move its accounting gap there.

Focused proof: retain a sizable selected outcome, acknowledge revisions while holding a returned terminal decision, and assert the returned copy still owns a separate process charge and prevents a sibling promise; dropping the read returns only its share. Exercise both newly selected and recovered decisions, with the existing runner persistence/delivery wait where necessary. The current tests cover live/revision/publication custody but do not exercise this sibling read.

## INV-R1-02 — The media guard survives, but it never covers simultaneously retained provider encodings

Classification: INCORRECT. Existing stable finding: FIND-012-6. Violated obligations: R1-6 and its explicit instruction to charge simultaneously retained encoding copies before creation; TASK-012 OBL-7/inherited REQ-027.

Exact locations: crates/wyrd/wyrd-server/src/verification/hosted/evidence.rs:770-788; crates/vala/vala-verify/src/blocks/agent.rs:352-358 and :483-505. Existing consumers: skald-spec/src/prompt.rs:936-972, :1771-1800, :1911-1950, :975-1007; skald-agent/src/loop_runtime.rs:202-274 and :372-455.

Producer-to-consumer proof: media reads N bytes and adds exactly E=base64_encoded_len(N) to its charge. The guard stays N+E for the call. It then returns a MediaRef owning E. bind_media_mut creates provider-owned copies: OpenAI makes a fresh data URL for every matching placeholder; Anthropic and Gemini clone data. At even one bind the temporary MediaRef and new provider payload coexist, and 2E exceeds N+E for nonempty media beyond tiny overhead cases. Multiple occurrences of the same supported placeholder create multiple copies with no new reader call or guard. More decisively during an ordinary model call the original bound Prompt remains owned by AgentExecutor, while Prompt::render clones its provider request; Agent::run_prompt retains that rendered template during run_loop. Thus even one occurrence retains at least two full provider encodings throughout a pending call, exceeding the only N+E promise. run_loop additionally extracts seed messages and reconstructs outgoing conversation messages, and tool-bearing runs clone the template for before_model hooks. No byte-accounting capability is invoked by these consumers. Guard lifetime correctness cannot establish sufficient charged size.

Materiality: an ordinary image/PDF Agent with a slow provider can hold media above the ledger's promise while sibling Bifrost/Python work receives the same apparent free memory. Repeated placeholders/fanout amplify this normal supported path; no hostile malformed input or unbounded hardening is needed. The remediation explicitly required encoding-copy accounting, so this is incomplete closure of the original finding rather than a new general Skald accounting project.

Existing test gap: bound_media_stays_held_until_the_agent_call_ends uses HeldMedia's Arc<()> guard and asserts only strong counts; it would pass with a zero-byte charge. The hosted media test asserts N+E remains held, which matches this incomplete implementation and does not measure the owned provider copies or sibling refusal. Completion/cancellation guard release itself is correct.

Correction burden and smallest safe correction: complete the existing runtime-only evidence/binding custody seam so every simultaneously retained media encoding/provider representation is admitted before copying and covered until its owner ends. Reuse ByteCharge and actual existing binding/rendering owners; keep pure MediaRef/wire contracts, provider validation, citations and formatting unchanged. Account the number of bound occurrences and the representations the actual Agent path retains rather than treating the freed raw-byte charge as a substitute for arbitrary encoded copies. No registry, persistent record, provider transport replacement or ledger in wyrd-spec is required. This needs bounded internal custody/accounting plumbing; deleting native media or holding only the initial guard breaks required behavior.

Focused proof: use the existing real binding/held-provider seam with a ByteLedger-backed reader, a sufficiently large media value and a ledger between N+E and the actual simultaneous encoded demand. The call must refuse before the extra copies are made, or sufficient capacity must remain charged so sibling admission fails while the provider is held. Include one ordinary occurrence and repeated occurrences; retain current completion, refusal and cancellation release assertions.
