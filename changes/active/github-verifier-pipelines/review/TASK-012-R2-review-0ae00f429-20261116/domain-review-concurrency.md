## Race and owner analysis

Participant is a local request-lifetime guard over the already accepted GatewaySnapshots loads map, not a second cache workflow. The prior owner removed the same cell only after an await; moving retirement into Drop is the missing lifetime boundary. Existing OnceCell remains the initialization and takeover authority. Locked Tokio is 1.52.3 (`Cargo.lock:8584–8586`); its installed `src/sync/once_cell.rs:338–386` documents and implements permit release on cancelled/panicking initialization and takeover by a waiting initializer. No scheduler, detached worker, janitor, dependency, configuration, new admission rule or duplicate SQL loader is installed.

The Arc-count test is safe under this private ownership invariant: the map and each joined participant are the only strong owners. Join clones while locked. Leave moves its existing handle locally without changing its count, acquires that same lock, then drops it before releasing the guard. Therefore two concurrent leaves cannot both overlook final ownership; a concurrent join either retains the old cell before leave's test or observes its removal and creates a new cell. Cancellation/panic unwinding follows Drop; cancellation before the future's first poll creates no participant. No map lock is held across await or tenant SQL.

Completion removes a cell even when old peers have not resumed. A later miss can start a replacement, as before remediation. Old peers only clone the ended result and retire their own handles; pointer equality prevents them removing the replacement. Success cannot leave an initializer partially running after finish: insert, OnceCell publication and finish contain no intervening await after the loader returns. On cancellation before publication, the existing permit handles takeover. A takeover captures generation when that survivor actually initializes, so listener/invalidation fencing is not weakened. Returning an uncached raced snapshot remains the previously accepted admission race semantics.

The existing background reload/install/requeue owner has deliberately different retry semantics and remains unchanged. Replacing it with foreground share or introducing bounded-cache eviction/refusal would enlarge this correction. The local guard is sufficient to stop request-ended metadata accumulation while preserving accepted active-request coalescing.
