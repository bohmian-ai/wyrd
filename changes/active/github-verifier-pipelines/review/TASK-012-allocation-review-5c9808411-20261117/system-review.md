## Boundary coverage

- Shared resource composition preserves the one process ledger and Bifrost local cap. Governor pool grants, Scribe root leases, query grants, infallible growth/headroom and scratch remain on existing owners. New resource-manager accessors are narrow. However, shared pressure integration does not connect that ledger's Bifrost ownership to workload attribution/admission (SYS-02).
- Scribe ingress and persistence pools join the same manager in `ScribeImpl::build`; bounded Rayon queues and existing cancellation custody remain. Ingress jobs carry frame tenant; mixed-tenant persistence jobs remain unattributed. Jobs wait for CPU on Rayon workers, not Tokio threads. WAL IO pool remains separate. However, fresh ingress never passes shared memory-pressure admission (SYS-02).
- Oracle leader retained roots admit with query deadline, run entry execution and each stream poll on CPU lanes, and keep the operation with the stream. The tracing wrapper propagates inherited lane/context into DataFusion future and blocking spawn hooks. Existing pools, class policy, root schema, plan and stream custody remain. Production build is broken by the existing feature-gated field now accessed unconditionally (SYS-01). Independent remote follower execution does not inherit the leader's process-local context (SYS-03).
- Forge rewrite admits once and translates unavailable admission into existing retryable Capacity before rewrite execution; this avoids the recorded circular wait where the journey frees occupied memory only after a refusal. Rewrite CPU work is wrapped and its spawned DataFusion work inherits the hook. Existing plan/workspace and publication machinery stays unchanged.
- Scratch charge/release behavior remains on ChargedSpillWriter and confirmed-file cleanup. Spill write/flush/finish release lane while IO runs. Revision 16 expressly approves finishing a spilling async poll without a lane and reacquiring on its next poll, including the temporary >C-poll consequence. This is not a defect.

## Proposed findings for independent validation

### SYS-01 — REGRESSION: ordinary server build references a field that does not exist

- Authority: AGENTS requires applicable lints/build; scenario 7 requires affected functional/lint gates; REQ-024 preserves shipped behavior.
- Locations: `oracle/mod.rs:1168–1171` gates `Oracle.resources` on test-support; `:1528–1530` gates initialization; new `:2293` unconditionally reads `self.resources.workloads()` in `execute_retained_root`.
- Starting condition/trigger: compile production `wyrd-server` without test-support. Expected: production Oracle compiles and performs shared admission. Actual: the field is absent from Oracle while its method references it, producing E0609. Downstream server is not buildable.
- Proof: direct mutually incompatible cfg/source at immutable candidate. Orchestrator also identified the existing `lints.log` E0609 at `oracle/mod.rs:2293`; this reviewer did not rerun it. Tests enabling test-support mask the error. Original worktree already has an uncommitted fix; it is excluded.
- Smallest correction: make the required Oracle resource field and initialization unconditional and reconcile its stale test-only rustdoc. Preserve inspection method gating. Verify the default shipped binary compilation, then affected required lints; no new production test harness is necessary.

### SYS-02 — MISSING: Bifrost ownership and fresh Scribe work bypass the shared pressure policy

- Authority: REQ-019 one shared domain and retained-owner accounting; REQ-021 equal targets, live borrowers remain demand, above-target pause and global critical pause; REQ-023 permits mandatory bounded drain; REQ-024 preserves explicitly smaller Bifrost cap. AC-016/018 and task scenarios 3/6 cover actual integration, not only isolated manager arithmetic.
- Locations: `resources.rs:909–936` ResourceState creates the one aggregate `process_charge` with `process.empty_charge()`; `:2820–2868` apply_charge_locked and `:2959–2977` infallible growth resize it. Runtime `resources.rs:123–143` creates charges with owner None; only ByteCharge.attribute feeds an operation's usage. No Bifrost production call attributes its charge. `scribe/execution_lanes.rs:1725–1736` on_lane calls begin, never admit; all new ingress run/decode paths use it. `WorkloadManager::set_local_cap` has no production caller anywhere (only runtime test at workload.rs:895).
- Starting conditions/trigger A: Bifrost query/cache/staging owners hold most of M while Gateway is also demanding; ledger-led pressure reaches 0.95, below critical. A subsequent Bifrost query enters execute_retained_root. Expected: existing Bifrost live bytes participate in its soft-target comparison and pause above-target additions; live retained borrowers remain demand. Actual: `workload_bytes(Bifrost)` stays zero while L includes those bytes. Oracle/Forge admission therefore treats Bifrost as below-target. After its short operation ends, retained Bifrost cache/staging bytes cannot keep Bifrost in demand at all. The common manager cannot apply the specified cross-engine sharing policy.
- Concrete scaled arithmetic: L=950 for M=1000, with 800 Bifrost retained bytes and 150 Gateway bytes. With both demanding, operating target is 475 each (or less with the always-live verification owner, independently reviewed). Bifrost should pause additional operations; its recorded workload usage is 0 so `paused` returns false and admits them. This is a deterministic policy error, not allocator uncertainty.
- Starting conditions/trigger B: parent commitment reaches P while ledger/local Scribe capacity remains available; a fresh external append is submitted. Expected: q>=1 pauses new memory-growing work; previously accepted persistence drains. Actual: preprocess/decode use on_lane -> begin and the unchanged governor checks only local/root bytes. The append can proceed under critical allocator pressure. The same bypass applies to unattributed allocator contention. Persistence bypass itself is correct and must be preserved.
- Additional same-boundary omission: an explicitly smaller Bifrost cap is never given to manager.set_local_cap, so its unspendable share is not redistributed during contention.
- Proof: immutable producer-to-consumer trace above plus workload.rs `paused` and `retarget` using only attributed operation usage/live operations. Existing tests fill generic root ledgers or construct explicit runtime operations, so they do not establish production Bifrost attribution or new-ingress pause.
- Consequence: Bifrost can keep starting/growing new work while competitors are paused, and its idle retained memory disappears from the demand model; full/critical allocator pressure does not stop fresh Scribe ingestion as specified.
- Smallest correction boundary: bridge existing Bifrost root ownership into the same workload manager without a second debit, and provide its already-resolved local cap. Connect fresh Scribe admission at its existing pre-ACK external-work boundary, with its normal deadline/capacity outcome. Preserve existing Bifrost reservations/pools/tenant class policy and allow already accepted bounded persistence/cleanup to run. Do not gate all governor growth, which would incorrectly starve mandatory drain.
- Closure: real Bifrost governor allocations must appear once in Bifrost workload usage, stay demand until actual release, enforce above-target pause and smaller-cap redistribution; fresh external Scribe work must pause/refuse under sampled critical allocator pressure with ledger headroom while accepted persistence still drains. Use existing resource/Scribe integration and focused public append/query journey owners rather than a new allocator harness.

### SYS-03 — MISSING: peer DataFusion execution has no local lane entry

- Authority: REQ-022 actual Oracle/Scribe CPU execution including entry and spawned parallel work, AC-017; design requires integration at actual dispatch, not only leader/output wrappers. All targets share the same implementation, and REQ-024 preserves supported distributed query behavior.
- Locations: server `oracle/peer_service.rs:346–370` ScribeFragmentExecutor constructs follower execution and drains `batches.next()` directly; `:533–590` gRPC entry calls it and encodes output with no laned wrapper. Redux `oracle/follower.rs:1011–1040` directly calls execute_stream and returns the stream. New `oracle/telemetry.rs:33–36,48–51` only wraps spawned work when Inherited::current is Some.
- Starting condition/trigger: an ordinary supported distributed query reads a remote Scribe's hot data while every shared CPU lane in that Scribe process is held by other work. Expected: remote fragment entry and substantial CPU stream work queue for that node's lanes as Bifrost work of the authenticated tenant; network waits hold no lane. Actual: the RPC receives no process-local inherited context, follower starts and polls unlaned, and its parallel spawned work receives None in the tracer and also runs unlaned. The leader's laned root cannot propagate a thread-local lease over gRPC.
- Proof: complete unchanged but affected peer-service -> follower -> execute_stream -> raw batch polling path above; QuerySpanJoinSetTracer's explicit None passthrough. Combined same-process paths may incidentally inherit a caller lane; that does not cover actual remote requests.
- Related traced analytical boundary: `analytical_transport.rs:1375–1433` authorizes a remote stage then calls its per-graph upstream service without lane/context; `analytical.rs:477–540` installs query runtime/tenant scan authority but no CPU wrapper. Pinned datafusion-distributed worker `src/worker/impl_execute_task.rs:47–54` calls `plan.execute` per partition; no parent lane is supplied at remote entry. This follows the same missing-local-entry cause. The Scribe fragment path alone is sufficient to establish materiality; no claim of fresh remote runtime proof is made.
- Consequence: real follower CPU can exceed C and bypass workload/tenant service accounting while local gateway/verification waits; leader-only and single-process DataFusion tests pass despite incomplete production coverage.
- Smallest correction: connect authenticated follower CPU execution and per-graph task drivers to the existing process manager/laned mechanism at the local execution owner, reusing the current spawn tracer. Carry already-verified tenant identity; keep authorization/fences and ordinary query/attempt cancellation, pools and queues. Acquire per running poll/CPU job, release before peer IO; do not add an independent scheduler or hold query-lifetime permits.
- Closure: with all lanes on the remote Scribe/Oracle follower held, a supported remote fragment/stage must not execute CPU probes or finish; releasing a lane enables correct typed output, tenant context and cancellation. Exercise spawned work as well as entry. Existing distributed journey fixtures and owner tests are the credible boundary.
