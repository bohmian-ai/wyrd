## Falsified hypothesis, no remediation

`Sandbox::start` keeps an always-live `Workers.idle` attribution operation (`sandbox.rs:146`), so a completely empty pool can contribute Verification demand. I traced whether this creates a material supported production false-sharing scenario before retaining a finding. Production operator configuration obtains `WYRD_VERIFICATION_MONTY_MIN_WORKERS` through `set_scaled` → `env_positive` (`config.rs:1950,2159`), defaults to one prewarmed worker, and disables the entire hosted owner when verification is disabled (`boot/mod.rs:1367`). A real retained idle worker legitimately belongs in demand. A zero-worker fixture or brief telemetry/replacement lag alone does not establish the material supported-use violation required by the review skill. Therefore this proposal is not retained and creates no remediation work. The complete consumer-level Bifrost attribution concern is outside this report and must be assessed by its assigned system reviewer.
