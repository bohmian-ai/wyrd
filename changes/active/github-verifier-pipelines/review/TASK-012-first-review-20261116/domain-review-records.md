## Proposed finding RECORDS-1

Classification: MISSING. Violated obligation: TASK-012 OBL-7 explicitly requires the single process ledger to cover live queued state and terminal custody; bifrost-design.md Resource and failure invariants requires ownership to remain charged until settled. This is a task integration omission at the materially changed checkpoint charging owner, not an unrelated request to harden existing code.

Primary location: crates/wyrd/wyrd-server/src/verification/state.rs:364–368, where flush clones Held.state into a frozen revision. Related source: :271–321 (Held/Writer retain state with no ByteCharge or ByteLedger), :635–653 (RunState::at installs recovered/live state with no process charge), :1108–1123 (settle clones full output into live record), :910–935 (publication clone into live state), :777–829 (terminal outcome clones), :731–733 (snapshot makes another complete copy). Outbox charge/release is crates/shared/wyrd-runtime/src/outbox.rs:583–596 and :819–826; Checkpoint::COPIES at state.rs:464–468 explicitly covers frozen/encoding/prepared forms rather than independently retained live custody.

Reachable producer-to-consumer scenario:

1. An ordinary queued Verifier completes a step whose output is retained in InvocationSettlement. RunState::settle clones it into Held.state. Publication and terminal selection use the same uncharged owner. Recovery also installs its complete accepted state there.
2. The background writer stages one frozen revision. Only that staged item's weight enters ProcessResources.memory, through Outbox::charging. While it waits, later engine settlements continue changing the live state without growing any process charge, as the coalescing test explicitly proves they can.
3. Once that revision is written, Outbox's release shrinks its full process charge. Held.state still retains the settlement/publication payload while a downstream model call runs, and runner.rs:530–620 keeps the Arc<RunState> through computation, park and terminal handling. A successful flush does not drop that state. If the next engine mutation is absent or delayed, its live payload can remain uncharged indefinitely within the original execution deadline.
4. Sibling hosted admission, evidence reads and Bifrost memory consumers admit from the same ByteLedger::available. They see room that is physically held by live queued state and can promise those bytes again. An item-count claim permit bounds how many states exist, not their retained payload bytes. The runner, claim loop and completion owner contain no enclosing ByteCharge to close this gap.

Observable consequence and materiality: supported queued graphs retain step outputs and publication JSON while other direct/queued/Bifrost work proceeds. Those bytes disappear from cooperative process accounting at every ACK, or never enter it when they are later coalesced changes. The single-ledger admission boundary therefore permits aggregate promises beyond its budget and fails the explicit live-state/custody contract. This does not rely on a benchmark threshold, hostile input, speculative scheduling, or a demand for exact RSS accounting.

Existing alternative and correction boundary: extend the existing RunState/Writer ownership and the existing ByteLedger/ByteCharge, rather than adding a persistence service, allocator or second resource authority. Charge retained live/recovered state and its necessary copies through the same process ledger for their actual ownership lifetime, including between checkpoint ACKs and while terminal/park custody waits. Distinguish the existing frozen/encoding/outbox charge from the live charge so ACK returns only bytes it actually settles; avoid both gaps and double counting. Apply the same source rule to begin/spent/settle/control/publication/decision and recovery/snapshot consumers. Mandatory engine growth can reuse the existing infallible charge mechanism; do not insert persistence waits, per-mutation whole-state serialization, a reserved queued share, or synchronous lease/SQL checks. Exact local accounting representation remains implementation-owned.

Why smaller alternatives fail: keeping only the outbox charge cannot cover the live state after ACK or new coalesced payloads; retaining every old checkpoint charge forever would double-count and block unrelated work after custody ends; lowering concurrency only bounds count and leaves the explicit byte contract false. The correction is one missing integration into an existing owner and ledger, not a new feature.

Focused closure proof: exercise a real RunState with a charging process ledger, settle a variable payload, hold one revision while a later payload is retained, then acknowledge all revisions while the live state remains in use. Assert that retained live bytes stay charged throughout, later growth is included, ACK releases only frozen/encoding custody, sibling admission cannot reuse those live bytes, and dropping/retiring the final state returns its charge exactly once. Preserve existing fast-transition/coalescing and lost-lease assertions. Use existing state/outbox test owners; a new service or full journey harness is unnecessary.
