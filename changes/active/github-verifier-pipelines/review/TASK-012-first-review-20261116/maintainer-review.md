## Proposed findings

### MAINT-01 — Atomic replacement promises scratch occupied by both files only once

Classification: INCORRECT. Location: crates/wyrd/wyrd-server/src/verification/hosted/workspace.rs:1540–1567, especially write's call to admit_write at 1543. Related owner: Workspace::admit_write at 1071–1094.

Violated obligation: TASK-012 OBL-6/OBL-7, charge growth before mutation and keep one process scratch ledger without double promises; amended code-mode REQ-027 requires actual owned/writing bytes charged through settlement/deletion. The maintainer ownership rule is that retained state has one truthful owner; this method currently conflates the final logical /work size with its physical write lifetime.

Reachable path: a declared model fs.write enters Invocation::dispatch, takes Workspace::writer, and calls Workspace::write on the blocking pool. For an existing regular file of 150 bytes and a replacement of 200 bytes, write asks admit_write for only 50. With a 100-byte input, the ledger becomes 300. write then creates an independent NamedTempFile and writes all 200 bytes before persist replaces the old 150-byte target. At that point physical workspace scratch is 450 bytes while the ledger promises 300. Equal-size replacement asks for zero extra bytes despite holding two full files during the atomic write.

Evidence: workspace/tests.rs::writes_charge_process_scratch uses precisely the 100-byte input, 150-byte old file, 200-byte replacement and 300-byte ledger scenario. Its assertion that the replacement succeeds tests final logical size only and misses the transient duplicate. workspace_writes_private_scratch proves replacement at the per-workspace limit, but uses an uncharged workspace. By contrast Workspace::install/unzip and archives_unpack_beside_their_staged_file correctly account the staged archive beside its expansion. All production fs.write callers route through this owner; Python writes use the separate mediated admission path, so this correction need not redesign them.

Consequence and materiality: ordinary replacement near shared scratch capacity can allocate bytes already promised to Oracle spill or another tenant's workspace. This is the explicitly required no-double-promise boundary, not a speculative throughput concern. Atomic replacement and unchanged original content on refusal must remain.

Smallest testable correction: retain Workspace as owner. Keep the logical /work replacement calculation, but reserve the full new temporary file's physical scratch while the old target still exists, then transfer/reconcile the charge after successful rename or temporary-file cleanup. A replacement whose final logical size fits but whose temporary copy cannot fit process scratch must refuse before mutation with the existing busy path. Do not switch to destructive in-place writes or charge the logical /work ceiling twice. No new service, dependency or durable state is necessary. Focused proof should show transient-copy scratch refusal preserves the old file, successful replacement when old-plus-new physically fits, and final scratch returning to only the live file.

### MAINT-02 — Workspace JSON encoding allocates before its admission decision

Classification: INCORRECT. Location: crates/wyrd/wyrd-server/src/verification/hosted/workspace.rs:308–315.

Violated obligation: TASK-012 OBL-6/OBL-7 reserve-before-copy/growth and amended code-mode REQ-027's requirement that new encodings have their own charges. The owner API documents charged staging, but its method ordering does not establish that invariant.

Reachable path and evidence: HostedTools::open invokes Workspaces::open for ordinary declared filesystem/code tools. Workspaces::open passes CallValue::Json to stage_json at 165–171; JSON publications and collection manifests also share stage_json through stage_publication and open. stage_json first calls serde_json::to_vec_pretty(value), then checks memory, combined file bytes and scratch. A large mounted step output is therefore fully encoded even when no process memory is free or the eventual file limit will reject it. The new workspace_inputs_beyond_process_memory_are_busy test uses a roughly 60 KiB JSON input with a 1024-byte memory budget and checks only the eventual Busy result and released ledger; it does not prove admission precedes allocation. Sibling TenantEvidence::stored and Workspace::snapshot correctly charge before reading, and the existing Checkpoint::charge demonstrates a nonallocating serde writer count rather than first building a byte buffer.

Consequence and materiality: concurrent JSON workspace opens can each allocate an uncharged encoded copy before being refused. Pull-request extraction output and step/publication JSON are supported mounts, so this undermines the shared admission boundary during an ordinary memory-pressure path. It is an explicit ordering obligation, not a demand for arbitrary allocator tracking.

Smallest testable correction: enforce encoded-size and ledger admission at the existing stage_json producer before materializing its encoded buffer, using a nonallocating serialization count followed by the existing charged write. Preserve the exact pretty-JSON file bytes and existing Busy/limit classifications. Reuse the current ByteLedger and Workspace scratch reservation; no second resource authority is needed. The focused proof must observe refusal before a whole encoded buffer is built, plus unchanged successful file content and balanced charges. Include cancellation of the staged write in the ownership proof because tokio filesystem work can outlive a dropped wait.

### MAINT-03 — Native-media encoding loses its charge before the bound model call consumes it

The maintenance problem is an API returning owned bytes without their lifetime guard, despite Loaded immediately above having the correct bytes-plus-charge ownership pattern.

Reachable path and evidence: AgentExecutor::bind resolves a declared media placeholder through EvidenceReader::media. Prompt::bind_media_mut at crates/skald/skald-spec/src/prompt.rs:936 dispatches to the provider's actual media binder. The candidate's own comment at evidence.rs:774–776 explicitly records the premature release. The existing pg_hosted_artifacts::evidence_reads_charge_process_memory_before_reading verifies Loaded lifetime, not the media-return lifetime; earlier artifact-file coverage invokes media but does not assert its ledger custody. Authored media slots and native media Agents are supported existing callers.

Consequence and materiality: while native-media requests wait or run, the process ledger advertises their live encoded inputs as free and admits unrelated work against the same memory. Repeating/concurrent media requests can accumulate payloads outside their promised admission. No benchmark is necessary to establish this explicit ownership violation, and the documented shortcut cannot defer an approved invariant until a measurable overrun occurs.

Smallest testable correction boundary: retain the media encoding's ByteCharge through the existing EvidenceReader-to-AgentExecutor binding lifetime until the bound prompt/model call relinquishes that media. Keep the charged representation and its guard together through that seam, analogous to existing Loaded ownership, rather than holding a global permanent reservation or adding a new media execution workflow. Account any additional owned encoding copies at their actual owner; preserve provider binding/validation, citations and wire MediaRef shape. A focused media binding test should hold the provider call pending, prove the ledger still covers retained media, refuse a competing charge that would double-promise it, and release it after completion/cancellation. This is a bounded in-process lifetime correction, not a new public wire or resource policy decision.
