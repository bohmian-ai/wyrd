## Proposed findings

### INV-01 — Live queued state is outside the memory ledger; frozen bytes are charged only after copying

Classification: INCORRECT. Violated obligation: OBL-7 explicitly includes live queued state and reserve-before-copy; inherited REQ-027 requires transfers to retain one charge and new copies to receive their own charge. Pipeline REQ-017 requires retained memory accounting without synchronous persistence or serializing/counting the whole state per mutation.

Location: crates/wyrd/wyrd-server/src/verification/state.rs:354–371 (changed Writer::flush), with Held:272–300, RunState::at:634–662 and select:773–785. Shared source: crates/shared/wyrd-runtime/src/outbox.rs:473–494 and 583–596.

Producer-to-consumer proof: RunState recovers or creates Held.state with no ByteLedger/ByteCharge field or corresponding claim-level charge. begin/spent/settle/publication/select grow that retained state; select clones the complete outcome. Writer::reserve reserves one item slot, not bytes: Outbox::reserve reads reserved_bytes but does not change it or charge process memory. flush then clones held.state at line 369. Only after Checkpoint::new counts the already-copied state does Reservation::stage reach send_reserved and charge its full weight infallibly. That charge belongs to the outbox item and returns when the write completes. Held.state and subsequent snapshots remain alive after that ACK. No enclosing runner/claim owner holds their byte charge: these owners use execution-count permits, and the production runner/state source has no ledger capability.

Reachable scenario and consequence: a queued pipeline retains a large accepted extraction/Agent settlement or JSON publication, persists it, and continues to a slow independent step or waits for its terminal evidence to be acknowledged. After the frozen write is accepted, the outbox returns its charge although the same payload remains in Held.state. Bifrost or a new Python checkout can therefore receive bytes already occupied by that live state. While another frozen revision waits, live state can also grow beyond the older frozen revision's accounting. Multiple bounded queued executions make this a material shared-process capacity violation; the claim-count bound does not account payload size.

Existing owners/siblings: reuse RunState/Held as live-state owner, ByteLedger/ByteCharge as the sole accounting mechanism and the existing Outbox for frozen custody. Writers of the state are begin, spent, forget, settle, publication, control, approval/deferred state changes and terminal selection; consumers include recovery snapshots, hosted publication mounts, runner terminal custody and Checkpoint encoding. A permanent queued share or new persistence store is unnecessary.

Smallest testable correction: retain an independently accounted live-state charge in the existing state owner for its full lifetime and update it for actual retained growth without a full-state serialization/count per mutation. Account recovered state and terminal outcomes as well as intermediate settlements. Preserve the memory-first mutation contract using the ledger's existing infallible accounting where already-accepted mandatory growth cannot be refused; that suppresses competing fallible admissions rather than introducing persistence waits. Reserve the additional frozen-copy/encoding bytes before cloning and transfer that charge to existing outbox custody without charging the same copy twice. Item-slot reservation alone cannot close this gap.

Correction burden: localized accounting and custody plumbing at existing owners; more than deleting a line because live state and frozen/outbox state are distinct simultaneous allocations. No new scheduler, service, database schema or fixed reservation is justified.

Focused proof: retain a variable-sized settlement in RunState, let its revision finish, and assert the process ledger still holds the live state's bytes until that owner ends; grow state while an older revision is held and assert growth is charged. Observe copy accounting before freezing/staging and release only the frozen share after ACK. Preserve existing transition/coalescing assertions.

### INV-02 — Provider-native media returns its memory charge before the provider owns it

Classification: INCORRECT. Violated obligation: OBL-7 one process memory ledger and inherited REQ-027 retained-input/new-encoding charging. No task or user exclusion exempts native media.

Location: crates/wyrd/wyrd-server/src/verification/hosted/evidence.rs:762–783, especially the explicit early-release comment at 774–776.

Producer-to-consumer proof: stored/read return Loaded with a ByteCharge. media grows that charge for the base64 encoding and builds MediaRef, but ByteCharge is local and drops when media returns. AgentExecutor::bind at blocks/agent.rs:335–347 passes that MediaRef to Prompt::bind_media_mut. The native prompt copies its data into a provider request: skald-spec/src/prompt.rs:936–966 dispatches to provider-specific binding; OpenAI construction at 1911 onward creates a retained data URL/file_data, with corresponding native payloads for Anthropic and Gemini. The prompt then stays in the Agent/provider flow throughout model work. Neither MediaRef nor the bound prompt carries the reader's charge, and model-call semaphore admission is not memory accounting.

Reachable scenario and consequence: an ordinary declared Agent uses an image or PDF native-media input with a slow model. After binding, its encoded bytes remain resident while ledger capacity is returned and can be lent to another capability. Repeated bindings/fanout can hold multiple encodings while each individual read fits. This contradicts the explicit shared-memory promise on a normal supported Agent path; a per-file maximum is not an aggregate ledger charge.

Existing owners/siblings: TenantEvidence owns read admission; AgentExecutor's binding/invocation owns the provider prompt lifetime. Reuse the existing ByteCharge guard mechanism across that handoff and cover each bound native-media input. Ordinary textual/workspace input staging must retain its existing lifetimes. Adding a runtime-only guard directly to the pure wire MediaRef is unnecessary and would contaminate that contract.

Smallest testable correction: hand the charge to an invocation-scoped owner alongside the media and retain it until all prompt/provider-owned bytes for that invocation settle, charging any simultaneously live encoding copies before allocation. Preserve IO-free Skald wire types and avoid a new media transport or registry. Merely charging before encoding is insufficient while the returned value has no owner for the charge.

Correction burden: narrow internal evidence/binding handoff; no public API, database or deployment decision is needed. Deleting the base64 path would break supported native-media Agents.

Focused proof: use an Agent with native media and hold its model request open; verify the process ledger retains the encoded payload charge and refuses overlapping admission that cannot fit. Completing or cancelling the invocation must return the charge, with existing media behavior preserved.

### INV-03 — The execution deadline drops settlement ownership before host work finishes

Classification: INCORRECT. Violated obligation: OBL-3 explicitly requires settlement before result selection/checkpoint/resource release even when a block future is dropped; code-mode AC-009 requires timeout cleanup with active work cancelled or settled.

Location: crates/vala/vala-verify/src/blocks/engine.rs:840–867, in interaction with the changed local ToolCallsOwner at 1870 and settle at 1917; check equivalent at 2018–2040.

Producer-to-consumer proof: HostedTools::open registers its TaskTracker wait as the session settlement at hosted/tools.rs:214–228; blocking at 431–445 spawns actual non-abortable fs work and keeps its writer/concurrency permit. The attempt owns ToolCallsOwner as a local value and registers settlement futures inside it. Authored inner timeout returns into attempt, which correctly awaits settle. In contrast, run wraps attach/drive and all those attempts in timeout_at(deadline). If the original execution deadline passes while extraction is running or while settle itself is waiting, that entire timed future is dropped. Local ToolCallsOwner and its pending settlement are dropped, run returns DeadlineExceeded, and the runner maps that into its terminal lifecycle. There is no cleanup owner outside the timed future; the only HostedBlocks settle is process-wide shutdown. Blocking work cannot be cancelled by dropping its JoinHandle and can continue holding the private writer/workspace after the execution returns.

Reachable scenario and consequence: a supported Agent starts fs.extract near its original execution deadline; bounded but slow physical extraction exceeds that remaining time. The engine publishes an execution deadline result before the required settlement finishes. The same occurs when the Agent already stopped and the engine is awaiting a held extraction at the original deadline. Terminal/checkpoint sequencing can therefore advance with outstanding host work, contrary to the port's explicit ownership contract. This is separate from the safe retention of an Arc within the blocking closure: retaining scratch does not await the required settlement before result selection.

Existing owners/siblings: ToolCallsOwner already owns settlement; retain it at a scope that outlives cancellation of the timed driver rather than add a task runtime. Agent actions and Agent/code checks share this root issue. The real HostedTools TaskTracker must remain the host-work completion source. Caller abandonment has no result to await, but original execution expiry does and must drain before returning its classified outcome.

Smallest testable correction: keep started invocation settlement ownership outside the timed drive; on original deadline, stop/drop running compute and dispatch, then await the existing registered host-work settlements before returning DeadlineExceeded or committing a terminal outcome. Preserve the original deadline and error classification; cleanup must not restart computation or replenish budgets. Avoid spawning a replacement execution engine or changing durable authority.

Correction burden: a bounded engine ownership adjustment using the existing settlement mechanism. Removing the timeout or changing it to an authored step timeout would break the original-deadline contract.

Focused proof: extend the existing SettlingToolset scenario with an original execution deadline shorter than the held extraction. Assert that expiry prevents new dispatch but the engine result and settlement signal do not finish/drop until the held host work releases; the final result remains DeadlineExceeded. Existing one-second authored-timeout scenarios use run_engine's sixty-second outer deadline and do not prove this path.

### INV-04 — Failed workspace deletion returns scratch that is still occupied

Classification: INCORRECT. Violated obligation: OBL-6 release only after deletion/ownership transfer, plus inherited REQ-027 retaining scratch charges through cleanup failure.

Location: crates/wyrd/wyrd-server/src/verification/hosted/workspace.rs:465–508, especially failed recycle branch 491–495 and remove's discarded result.

Producer-to-consumer proof: Workspaces::open and admit_write charge the shared scratch ledger before staged/extracted/Python/fs.write bytes land. Workspace::drop moves that charge into cleanup. If empty_root fails, it invokes remove, whose remove_dir_all error is logged but not returned, and then drops scratch unconditionally. The non-recycled path likewise calls remove and drops its local charge on return regardless of success. Thus a surviving file or partially cleaned directory no longer owns a charge, and shared Oracle/Forge/hosted admission can reuse its bytes. Boot clears this prefix only after restart; it does not free the bytes in the running server.

Reachable scenario and consequence: directory permissions or a filesystem IO failure prevent cleanup of an otherwise valid charged workspace. A supported operational fault then leaves real scratch occupancy while advertising it as available. Repeated failures can exhaust the filesystem used by unrelated Bifrost work and invalidate aggregate scratch limits. The invariant explicitly covers cleanup failure, so its low frequency does not make it optional.

Existing alternative and smallest correction: preserve the existing workspace cleanup/recycle owner and retain its charge conservatively when deletion cannot be confirmed, returning bytes only after success. The same candidate already implements this exact policy in crates/vala/vala-bifrost-redux/src/oracle/spill.rs:230–245: surviving spill bytes remain charged for the rest of the process and boot cleanup reclaims them. Apply that established ownership policy to both workspace cleanup paths; no janitor, retry service, new registry or durable record is required. The cleanup operation must make its success observable rather than only log it.

Correction burden: small local cleanup/error-propagation change. Swallowing the error cannot establish deletion; simply deleting the recycling optimization would leave the same bug in remove.

Focused proof: make a charged workspace cleanup fail deterministically, confirm data survives and assert the ledger retains at least its charge. Also retain healthy deletion/reuse assertions so successful cleanup returns bytes exactly once. Reuse existing workspace test tier and the established spill failure-test approach where portable.

## Existing owner comparison

The new shared ProcessResources ledger belongs in wyrd-runtime and replaces per-capability idle reservations; it does not duplicate a scheduler. HostedAdmission adds tenant byte admission over that ledger, which the existing count-only semaphores cannot supply; its FIFO/round-robin policy is distinct from engine DAG scheduling. Dispatch extends existing tool resolution and provider invoke_call rather than implementing a second authorization flow. ToolCallsOwner is the appropriate invocation-level settlement/spend owner, but INV-03 shows its lifetime is currently too short at the outer deadline. Workspace recycling and worker reuse extend their existing complete IO/reset lifecycles; neither requires a replacement runtime. The gaps above call for keeping ownership at these existing owners, not replacing them.
