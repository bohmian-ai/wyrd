## Producer, sibling and lifecycle tracing

### ASGI evidence and failure projection

The application creates observations under the existing native Run; the adapter owns only protocol timing and entry/exit. The producer chain is `__call__ → state.run → PyRun.__enter__/__exit__ → otel._enter_run/_exit_run`, then existing observe/Bifrost admission. Request completion restores execution-local correlation and does not flush. The separate lifespan producer chain is `_start → PyWyrdState.start_bifrost/start_telemetry → existing native lifecycle`, followed by app shutdown, `_drain → PyWyrdState.shutdown → flush_telemetry + native shutdown → BifrostLifecycle.shutdown`.

`BifrostLifecycle` still owns NotStarted/Starting/Started/Closed, exclusive startup claims and retry-on-ambiguous-drain-failure. The adapter's local `drained` boolean controls one protocol invocation's cleanup attempt; it does not replace the native state machine, assert durability after failure or reopen a writer. Sibling explicit startup.failed, shutdown.failed and shutdown.complete paths call the same guard. Abnormal established teardown now reaches it too. A failed secondary drain is caught and logged in `_drain`, leaving the original app failure primary. The unsupported-lifespan fallback remains compatible with the prior validated disposition; no new evidence warrants resurrecting the rejected pre-first-receive policy proposal. Explicit application-owned failure message bodies remain forwarded unchanged, as required by the narrowed prior finding.

All Wyrd-created error output sites share `_diagnostic`: startup refusal, partial-startup cleanup log, final-drain log/failure response and generated post-receive app-startup failure. Unexpected arbitrary bodies are withheld at this producer rather than separately redacted at sinks. Existing WyrdError projection remains trusted; the exact known import remedy reuses its current owner. No blacklist or second error catalog was added.

### Guided workflow and host identity

The existing InitArgs/DevInputs/DevServer workflow remains the single bootstrap. Guided selection precedes resolved setup writes; regular init returns no agent. Every sibling host uses the same enum/installer and the same `launcher()` representation for display and direct argv. The selected host's existing configuration outcome must pass `McpInstallReport::into_result` before launch; failed selected connection cannot silently fall back to another host. Config-directory detection and launch-program presence remain distinct. A program present but failing spawn is handled by the separately required failed-start path and does not end serving.

Guided startup does not create a second supervisor: Agent is an additional field of DevServer, observed during the existing server/UI wait, then settled using the existing child routine. Diagnostic redirection reuses the existing log facility so server output does not corrupt the agent terminal. SavedTerminal captures/restores only invoking terminal attributes. Agent completion, interruption, failed spawn and server/UI exit converge on existing run/stop ownership. Only the child Wyrd started is signalled; session/process-tree ownership is not expanded.

The Python console script already delegates the same parser/dispatcher and waits for Tokio settlement. The TypeScript wrapper now recognizes init as the foreground signal-owned command. The rename does not introduce a parallel installed-client implementation.
