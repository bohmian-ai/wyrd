## Prior SQL rollback closure

Re-read `gateway_apply_is_atomic_and_tenant_scoped` (`pg_administration_tests.rs:1500–1776`) and `stored_credential` (`:396–413`), not only its passing status. Its successful apply first persists `managed-key/openai` holding `SUBMITTED`, referenced by `primary`; `shared/openai` has existing `untouched`/`secondary` references. The failing composite submits `managed-key/openai` rotation first and then a managed `shared/anthropic` replacement. Both submitted credentials are referenced and pass document validation. The first upsert therefore executes; the second hits the immediate existing provider FK before deployment-level adapter checks can run. The expected error is the FK-mapped `GatewayResourceConflict`.

After abort, the test compares complete row JSON and ciphertext for both credentials and all deployment documents, including unrelated `untouched`. It then reads the production snapshot and actually opens the retained managed envelope with the configured keyring and exact tenant/name/provider binding, asserting `SUBMITTED`. Thus unchanged names/counts cannot hide an accidental secret rotation. The outbox still records the allowed permission decision for the failed operation. **FIND-TASK-001-6 remains closed**, without a new failure-injection mechanism or altered concurrency semantics.
