## FIND-TASK-001-2 closure

1. `dev.rs:317-337` preserves the prior remote-origin refusal and now refuses **any protected default key without saved `[dev].tenant`**, including a same-origin key, before local-data selection, installation or child startup. The saved-slug conflict guard remains. This avoids adopting a preexisting client selection as local setup.
2. `DevServer::run` (`:548-564`) reads the retained default key and calls `proven(saved_key_config(...))` before `save_settings` and `provision`. `saved_key_config` (`:1310`) supplies `credential: Some(key)` over `Environment::Fixed(HashMap::new())` and `GlobalConfig::default()`, with explicit selected endpoints. The resulting selector is None and cache is InMemory. `ClientConfig::resolve_credential` returns the explicit credential before login/file tiers; `AuthMiddleware::new` creates a disk-store handle only for Disk. Consequently neither ambient credentials, saved login, nor disk-cached access token can stand in for the exact key or rewrite protected files during preflight.
3. `proven` exchanges that key and performs the existing bounded tenant Card read. Rejection settles the owned server and returns static recovery guidance. No setup/issuance follows it. `saved_client` remains a distinct post-setup path: its fixed environment contains only config-home, loads the real saved settings and retains ordinary saved-login/default-key/cache precedence. Shared auth precedence was not changed to solve a dev-specific concern.
4. Supported partial save remains valid: `save_settings` commits `[dev].tenant` before provisioning; `save_local` writes a new key before endpoints. A key-before-endpoint partial run therefore retains its dev identity and can pass exact-key proof. Missing endpoint still leaves `configured` false. Completed selection plus key suppresses automatic offers after listener changes; explicit gateway/host requests remain honored.

The expanded `pg_tests::server_dev_repeat_and_partial_failure_preserve_state` proves the no-dev same-origin state with and without a genuine recovered platform credential, compares credential/config bytes, checks the listener is free and uses an operator-session tenant read to detect forbidden issuance. The competing-login segment obtains a real access token from B, saves it for A's same origin/slug, and targets B's database using B's signer. Shared saved-login renewal source returns that unexpired bearer without replacement; B's issued token remains valid there. Thus this is a usable competing credential, not an arbitrary invalid token. A's exact key is invalid there; refusal now happens before file writes. Existing A resume, missing-endpoint partial save, no-reissue/recovery, remote refusal and corresponding-setting override segments remain.
