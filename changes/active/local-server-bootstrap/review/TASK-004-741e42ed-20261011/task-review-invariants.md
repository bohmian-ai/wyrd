## State and sibling-owner tracing

**Provisioning authority.** Input TenantSlug reaches only the server `setup --tenant`; DSNs remain in inherited environment. The server checks active tenant state before touching root creation, then delegates root initialization and authenticated tenant creation to its existing owners. CLI parsing consumes the existing one-time output rather than constructing a durable tenant or key. Parsed DataTenantId reaches both the safe active-state message and saved-key prefix validation. API-key authenticity is subsequently proven by the actual shared-client exchange/read, not by the prefix test alone. A wrong-prefix default is preserved and rejected; a same-prefix invalid key can never produce the ready message.

**Persistence authority.** `CredentialsFile` remains the common file/lock owner for saved logins, API-key token cache, and bootstrap. Inspected sibling `SavedLogins::{save,remove}` and renewal paths: they hold the same directory lock and rewrite login tables while preserving the default profile. `cache_api_key_token` rereads under that lock and only writes cache entries beside the exact matching default key. New `save_local` similarly rechecks the actual default under lock; passing the expected key prevents a changed key between unlocked identity preflight and persistence from being overwritten. Equal-key retry performs no credential rewrite, so retained cached-token bytes survive. Credential and endpoint are deliberately separate commits; recovery text acknowledges that partial state instead of pretending there is an atomic cross-file transaction.

**Reader precedence.** Existing `ClientConfig::resolve_credential` retains explicit/environment credentials, saved user login, then default key precedence and selector refusals. Bootstrap preflight rejects an unrelated selected saved login for the target origin. Verification reconstructs a client with only the saved config directory, making an ambient API key incapable of masking missing persistence. Existing tenant selectors/unusable selected logins remain an actionable refusal, not silently cleared user settings.

**Lifecycle authority.** The new DevServer earns ownership by retaining installed server, endpoint/local inputs and child across calls. One-off migrate/setup use the same command construction, null stdin and kill-on-drop. Ordinary server stdout/stderr remain available for its redacted diagnostics; setup/migration output is captured because it may carry one-time secrets. On interrupt/error the outer owner calls stop; normal unexpected server exit is classified as failure. The async local tty reader has cancellation points and shares the installer's grammar; declining does not call the editor. Python/Node changes remain at foreign-runtime signal projection rather than implementing another server lifecycle.
