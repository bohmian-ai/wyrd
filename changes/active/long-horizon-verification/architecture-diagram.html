Late evidence: session revisions

A sealed revision and its verdict never change. Evidence that arrives after sealing opens the next revision of the same session key. That revision holds everything before it plus the new items, so the Verifier always judges the whole conversation.

What “runtime resource” means

Card

Declarative and versioned. You author it and register it: a Verifier, a Trigger, an Agent. It describes what should happen and never changes once a version is registered.

Runtime resource

Created by the server while work happens. It has an ID, a lifecycle and state, but nobody authors or versions it. A Verifier execution at /verification/executions/{id} is one today.

Session

The same kind of thing as an execution. It is an evidence bundle that stays open, keyed by an ID the caller already has (an order or conversation ID), so any producer can append without coordinating, and seals into exactly the bundle a Verifier already accepts. It is not a new Card kind.
