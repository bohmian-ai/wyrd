### SR-R3-001 — VIOLATION — new fallible poll-driving helper omits its error contract

**Prior boundary:** FIND-TASK-001-6. Original sites and the R2 FrameAgent panic omission are closed; this is a newly introduced helper in the same mandatory documentation boundary.

**Violated rule:** AGENTS §16 says every new/materially modified Rust item, including private test helpers, requires rustdoc and “Every fallible Rust function or method MUST include a `# Errors` section naming the error conditions.” Agent rules repeat the hard rustdoc gate. Task-review explicitly retains missing rustdoc as blocking.

**Exact location:** `crates/wyrd/wyrd-server/tests/integration/pg_verification_groups.rs:188–196`, `Support::tick`; returned failure path at `:223–225`.

**Evidence and consequence:** tick drives a real GroupPoller. Its docs explain advancing/committing a scheduler tick and have # Panics only. Its Result returns poller's GroupPollError after committing the cursor and any preceding complete enqueues. `partial_group_reads_enqueue_nothing_until_a_complete_poll` calls it and explicitly expects the Read error. The real failure contract is therefore intentionally exposed to this helper's callers but absent from its mandatory Errors documentation. This fails the explicit documentation completion gate; it is not an allegation that the test or production error propagation is wrong.

**Smallest correction:** add # Errors to this helper documenting propagated GroupPollError conditions and the commit/partial-progress behavior already implemented. Keep setup/commit assertion behavior and the existing Panics documentation. Reuse GroupPoller::poll's error distinction; do not alter control flow, add a wrapper/harness/test/check or request a product decision. Source inspection closes the prose correction, with ordinary owning format/lint verification as applicable. Batch it with any independently validated remediation; do not create a new behavioral or style-only program.
