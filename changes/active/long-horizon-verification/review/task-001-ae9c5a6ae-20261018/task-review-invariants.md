## Proposed material finding

### FIND-TASK-001-2 / INV-R3-002 — INCORRECT: source selection does not preserve eligible lifecycle activity

**Violated obligations:** REQ-003/004/005/009, AC-006 and the original task's idle/finality/whole-snapshot boundary. REQ-004 explicitly measures idle from the newest visible source input/result row and forbids execution before idle/max_age. Refused submission attempts are not source executions (queue refusal authority and the existing FIND-2 correction). The user-approved one-page discovery ceiling and one selected identity result for capacity/membership do not authorize a different idle clock or treating a refused attempt as the group start.

**Exact locations:** `crates/wyrd/wyrd-server/src/verification/groups.rs:201–216` (raw first activity controls candidate finality); `:139–144` (bounded selection directly controls Ended); `:248–278` (refusal exclusion occurs only after discovery); `:583–599` (only earliest `places` executions contribute activity); `:737–757` (newest/first computed only from that returned prefix). Producers: `components/verification/service.rs:610–647`; queue acceptance/refusal: `crates/wyrd/wyrd-sql/src/queries/verifier_executions.rs:1240–1385` and `:1721–1743`. Consumers: snapshot coverage at `groups.rs:353–359`, existing queue coverage/settlement and runner source-limit outcome.

**Reachable path A — a bounded overflow witness becomes a false idle clock.** Let ceiling=2, idle=10s, max_age=100s, finality=200s. Four accepted executions of one source tuple have input/result activity entirely at t=0,1,2 and t=20 respectively; poll at t=21. Discovery sees the active group. The ranked statement returns only the first three execution IDs, because `places=ceiling+1`; it excludes all rows of the fourth. `Ended::judge` sees newest=2 and declares idle, although the group's newest eligible source row is t=20 and neither idle nor max_age has elapsed. Snapshot pins overflow and the runner emits inconclusive early. Subsequent activity solely in later IDs can also be hidden by identical prefix coverage. This is deterministic for the stated row set, not a cross-query race or an unexecuted claim about scan order.

The comment at `:585–588` explicitly acknowledges that over-limit activity/coverage are truncated and assumes the overflow reason is sufficient. It is sufficient evidence of overflow; it does not satisfy the Trigger's independent required end condition. Early inconclusive is observable, and when a prior group verdict exists it can dispatch an `on_verdict_change` reaction before the configured end. All source slots of that tuple and the shared queue/Operator consumer are affected; SDK guards or a runner check after enqueue do not correct the source.

**Reachable path B — a refused row can expire a group before any real source is old.** Enqueue stages the input before `accept_submissions` decides a key conflict or target refusal. A conflicting request can choose group G, be stored under its own execution ID as manual/errored/attempts=0, and retain its input row. Let that refused row have t=0, a later accepted execution in G t=61, finality=60s, and clock=62. The real group's earliest source is t=61 and is within finality. Candidate SQL computes MIN(at)=0 over the raw refused row and the accepted row, and rejects G through HAVING before `selection` can call `refused_submissions`. Future polls cannot recover it while that row remains retained. No outage, producer loss, cursor starvation, synthetic load or out-of-scope retention policy is needed.

**Smallest correction boundary:** keep GroupPoller/Sources and the existing queue refusal authority. Preserve the one bounded selected identity result as the sole capacity/membership authority and exact-ID payload predicates. Correct the existing discovery/end owner so source eligibility is established before an attempt can determine finality, and full eligible group activity—not merely the earliest overflow witness—determines idle/max_age/coverage. In particular, a refusal that selection would drop must not prune the group before selection, and capped payload membership must not silently cap the lifecycle's newest time. Reuse query-side summary/selection facilities and current refusal/coverage owners as appropriate; no new store, producer IO, cursor requirement, budget, queue, API or timer is needed. Private SQL/control-flow remains implementation-owned. Merely increasing the ceiling or marking the timing shortcut `ponytail:` does not meet the approved condition.

**Focused proof:** extend the existing server grouped seam with (1) N+2 accepted executions whose first N+1 are idle but final execution is active; before idle/max_age there is no enqueue, then the eventual due execution carries the existing overflow marker without fetching the over tuple's payloads; (2) an old settled refused attempt followed by recent accepted activity under the same group, proving first-source finality uses accepted activity and the due snapshot includes the accepted IDs. Use fixture activity times/tick clock and existing queue/refusal support, no wall-clock delay or new harness. Keep the N+conflict/N+1 proof and mixed exact-ID/null behavior green. These source eligibility/lifecycle checks should be grouped with residual FIND-2 rather than opening one defect per source slot or caller.
