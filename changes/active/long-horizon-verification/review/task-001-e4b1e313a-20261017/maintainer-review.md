## Material findings

### MNT-001 — INCORRECT: generated InputSlot accepts an object that the Rust contract cannot decode

- **Location:** `sdks/wyrd-sdk-ts/wyrd/src/card-types.ts:2364` and `:2429`; source boundary `crates/wyrd-spec/src/card/verifier/mod.rs:128` and `:175`, and `card/verifier/reference.rs:185`.
- **Governing rule:** AGENTS §§2/9 require one shared typed wire contract; maintainer-style's Python/TypeScript section explicitly makes a public declaration that permits invalid calls a maintainer finding. Generated artifacts must be corrected through their source/generator.
- **Evidence and reachability:** the new union includes `InputSlotVariant5`, defined as `{ readonly type: "source" }`, in addition to `string`. Rust's `Source(SourceText)` is an untagged variant, and `SourceText` is a transparent `String`. Consequently `{ "type": "source" }` is neither a valid typed slot nor a string source and cannot deserialize into `InputSlot`. A typed Verifier document can nevertheless contain `inputs: { turns: { type: "source" } }`, be written as a Card file and passed to the existing `Cards.registerFromPath` loader/registration path. The generated declaration has certified a shape that the authoritative parser rejects. The same source schema is used by `gen_schemas` and the TypeScript emitter; a clean regeneration alone does not establish parity.
- **Maintenance and public-contract consequence:** callers following the exported type receive an avoidable registration failure, and a future maintainer cannot safely use the generated union as the accepted wire shape. This is a phantom public input kind, not a naming preference.
- **Smallest correction:** correct the existing `wyrd-spec` InputSlot schema projection for the tagged typed-slot/untagged-string union, preserving its runtime wire behavior and source validation; regenerate the existing TypeScript artifact. Do not add a second TypeScript validator or make the server accept the phantom object. The outcome must contain only the four real typed object variants and the source string.
- **Focused closure proof:** add a focused schema/runtime parity assertion for InputSlot covering a valid source string and refusal of `{ "type": "source" }`, confirm the emitted TypeScript no longer includes the phantom interface/union member, and run the owning codegen/typecheck checks. Existing source-slot decoding tests prove the valid string case but do not cover this false generated alternative.

### MNT-002 — VIOLATION: new fallible duration trait methods omit required error documentation

- **Location:** `crates/wyrd-spec/src/card/trigger.rs:139` (`TriggerDuration::fmt`) and `:153` (`TriggerDuration::deserialize`).
- **Governing rule:** AGENTS §16 requires a `# Errors` section on every fallible Rust method, including private and trait methods, and makes missing required rustdoc a blocker. Maintainer-style repeats this requirement.
- **Evidence:** the formatter has only “Writes the authored text.” before returning `fmt::Result`; deserialization has only “Decodes and validates authored `<n><unit>` text.” before returning `Result<Self, D::Error>`. Nearby `SourceReference::fmt` in `card/verifier/reference.rs` demonstrates the repository's explicit formatter-error documentation pattern.
- **Consequence:** the new public duration contract's decoding failure boundary is undocumented under the repository's mandatory rustdoc gate. This is a documentation correctness exception to the ordinary non-blocking style threshold, not a request for a structural rewrite.
