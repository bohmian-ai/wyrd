## Proposed material findings

### INV-REV-001 — INCORRECT: judgment completion time suppresses uncovered late evidence

**Obligation:** REQ-003/004 and AC-006 require late-visible rows timed within finality to remain eligible for a later whole-group snapshot; coverage, not judgment wall time, determines whether a source row was judged.

**Location:** `crates/wyrd/wyrd-server/src/verification/groups.rs:223–228` (`BindingPoll::candidates`); related `GroupState::covers` at `crates/wyrd/wyrd-sql/src/queries/verifier_executions.rs:985–993` and group poll coverage check at groups.rs:170–175.

**Producer-to-consumer evidence:** Direct/queued producer payloads stamp source times when execution happens and stage them on process-local outboxes. Bifrost publication can lag independently across server replicas. Suppose snapshot A saw source input X, but result X (or another source execution) was already timed at T and is published only after A's result becomes visible at J, with T < J and within finality. The newly visible row increases uncovered source membership. Candidate discovery first LEFT JOINs the prior group result and requires `MAX(s.at) > j.judged`, where `j.judged` is its `MAX(ended_at)`. Every source time may remain <= J, so the group never reaches `group_states`; its membership-aware `covers` method cannot repair the earlier omission. This applies to source inputs and source outcomes through the shared `surfaces` UNION.

**Consequence:** The durable available source row never enters a revised judgment unless unrelated later activity happens. A null or passing group result can remain authoritative after a failed source outcome is retained. This is permitted publication lag, not permitted outbox loss: the row exists and is eligible.

**Minimum correction:** Correct discovery at the existing `GroupPoller`/coverage boundary so a group cannot be excluded merely because source activity predates a judgment's completion. Reuse the existing execution coverage/state for deduplication and serialization; do not add a producer write, lifecycle store, receipt barrier or pending-source inventory. Preserve finality and bounded reads.

**Focused proof:** A real-server grouped journey should retain a first snapshot, publish a previously unavailable source input/result with an activity time earlier than that snapshot's result ended_at and within finality, then prove exactly one later whole-group judgment includes it and the old snapshot stays unchanged. Include aligned null-to-outcome transition; no days-long sleeps or synthetic load.

### INV-REV-002 — INCORRECT: an arbitrary one-hour discovery horizon permanently loses retained due groups

**Obligation:** REQ-004 says failed discovery remains retryable on later ticks; AC-006 requires scheduler recovery. Only retention/outbox loss are accepted missing-history boundaries under REQ-003/005.

**Location:** groups.rs:53–57 and 218–221 (`DISCOVERY_SLACK`, `BindingPoll::candidates`).

**Evidence/path:** Every source surface is restricted to `at >= due.clock - idle - 1h`. The only persisted cursor is `next_run_at`; claiming it advances to the current cadence and does not retain the old source-time window. After an outage or prolonged query failure exceeding idle+1h, retained source rows of a group with no judgment are outside the query forever. They can no longer reach `Ended::judge` or the existing execution queue. The code's own shortcut comment explicitly acknowledges this loss. Owner authentication/arming after the same delay has the same result. No source retention deletion or outbox loss is necessary.

**Consequence:** An accepted, fully retained group never gets its first judgment after recovery; similarly uncovered historical activity can be abandoned. Bounded pagination is permitted; silently abandoning history after a private fixed hour is not the approved completeness trade-off.

**Minimum correction:** Remove this extra history-loss policy. Keep discovery bounded under the existing scheduler/binding cursor and analytical coverage owners while ensuring retained uncovered groups remain discoverable after missed polls. Reuse existing cursor/coverage; add neither hot-path group bookkeeping nor a new recovery pipeline. Do not fix by merely increasing the magic hour.

**Focused proof:** Use controlled fixture source times/cursor scheduling to resume a binding after more than the current discovery horizon with retained eligible rows and prove the outstanding group is eventually judged once; exercise a subsequent unchanged poll as a no-op. This can share the late-publication discovery correction/proof boundary with INV-REV-001 if the validator finds one minimal implementation.

### INV-REV-003 — INCORRECT: raw-row cutoff bypasses required source-execution ceiling judgments

**Obligation:** REQ-009 requires counting eligible distinct execution identities after deduplication, permitting exactly the ceiling, and completing inconclusive/source_execution_limit_exceeded when exceeded; physical duplicates/retries must not consume entries. REQ-006 requires bounded reads, not silently missing judgments above another private cap.

**Location:** groups.rs:59–61, 159–163 and 263–269.

**Evidence/path:** `identities` selects an unaggregated UNION ALL of input/result rows with LIMIT 100001. `poll` checks `rows.len() > 100000` and continues before refused-submission filtering, `Ended::judge` identity deduplication and `snapshot`'s distinct-execution ceiling check. Thus a retained source set of 100001 inputs for one source binding (well above default source ceiling 1000) receives no completed inconclusive execution. Repeated/overlapping physical rows can also hit this cap even when unique source membership is small. Finality filtering happens later too: rows beyond finality can fill the cap before eligible membership is examined. All source slots use this one path; the runner cannot generate its required explicit reason because nothing is enqueued.

**Consequence:** Larger groups disappear from verification instead of producing the specified inspectable bound result; physical duplication changes whether a logical group is judged. Repeated polls do not reduce the retained count, and the separate discovery horizon eventually abandons the group.

**Minimum correction:** Enforce bounded discovery/membership selection at the existing GroupPoller analytical identity owner using eligible, deduplicated execution identity rather than refusing the whole group by raw row count. Preserve exact membership/order and coverage for readable selections and use the existing queued source-limit outcome for actual unique-execution overflow. Do not collect unbounded payloads, truncate a judgment, add a new authored limit or duplicate downstream guards.

**Focused proof:** A bounded source query test/journey must prove raw duplicate/overlapping rows cannot change unique membership/ceiling verdict, and an eligible source set beyond the current raw-row boundary still yields exactly one completed inconclusive/source_execution_limit_exceeded result without payload collection. Also exclude rows beyond finality before they consume logical membership. Use existing Bifrost fixture mechanisms and normal load.

### INV-REV-004 — INCORRECT: accepted duration values panic the shared scheduler

**Obligation:** REQ-004 gives Trigger-owned positive durations; AGENTS.md requires no parsing/input-driven panics and safe shared server ownership. A tenant's accepted Trigger must not repeatedly terminate the scheduling capability.

**Location:** `crates/wyrd-spec/src/card/trigger.rs:104–114`; groups.rs:218–220 and 636–644.

**Evidence/path:** `TriggerDuration::parse("999999999d")` succeeds and produces 86,399,999,913,600 seconds, which fits the TimeDelta constructor but exceeds chrono's representable DateTime range. A group binding pins that valid value without further bound validation. With it as idle, `due.clock - span(idle)` in discovery panics immediately. With it as finality and ordinary idle, discovery succeeds but `first + span(finality)` in `Ended::judge` panics when a group has rows. The locked chrono 0.4.45 `DateTime` Add implementation explicitly calls `checked_add_signed(...).expect("DateTime + TimeDelta overflowed")`; subtraction has the equivalent behavior. Scheduler poll transactions unwind, so their claimed cursor does not commit. `VerificationRuntime::run` marks the scheduler unhealthy and restarts it from the same owner, allowing the same due binding to crash it again; unrelated bindings/tenants share that capability. Runner/fitter/Operator tasks remain separate, so this is a scheduling-capability fault, not a claim that the entire process dies.

**Consequence:** A publicly accepted group Trigger repeatedly crashes shared scheduling and degrades verification health. The invalid runtime state is produced by arithmetic over the accepted duration, not by Bifrost availability or an impossible database timestamp.

**Minimum correction:** Make the existing duration/time comparison boundary safe for its accepted domain with checked or elapsed-duration comparisons; use chrono's existing checked facilities and preserve mathematically valid long durations without introducing an arbitrary product cap. The same owner must handle discovery lower bounds, finality and idle/max_age consistently. No new timer framework or platform-specific mechanism is needed.

**Focused proof:** Exercise the largest accepted s/m/h/d durations against a normal fixture clock and source rows, proving discovery/end eligibility never panics and matches elapsed-time/finality semantics; then prove a neighboring ordinary binding remains schedulable. A pure boundary test plus the narrow scheduler integration seam is sufficient; no full journey suite is required for closure.
