## Producer-to-consumer tracing and reuse assessment

The authored contract is the single declaration owner. Both server registration and Card loading reach `spec_from_kind_value`, whose generic decode wraps the existing serde mechanism; it does not introduce another validator or identity resolver. Removing fields under deny_unknown_fields makes stale authoring fail before registry persistence. Ordinary Run slots retain exactly the same optionality and mode validation. Although check_activation now checks only for a samples slot, Verifier validation still prohibits mixing samples with other slots, mixing drift with Run checks, and steps in a Window Verifier; deleting validate_schedule therefore does not admit a previously forbidden mixed-evidence schedule.

BindingProjector still resolves the exact Verifier and projected subject. NewBinding and the SQL INSERT no longer carry selectors; the additive migration drops that redundant column. CLAIM_SQL continues to obtain the execution's exact UID/version, subject/window, accepted authority and baseline data. ClaimedRow distinguishes scheduled and submitted inputs by their existing closed shape, with submitted maps and route overrides unchanged. The runner loads the exact pinned Verifier, passes run/window into DriftEngine, and the latter uses existing ObservationWindow/Reader/scorer owners. The subject/time/tenant constraints are not replaced by inferred identity. Requirement IDs still key each report, and existing validator uniqueness and check-to-slot compatibility prevent report collisions or arbitrary undeclared features.

The existing alternative was precisely the same execution and scoring owners with a redundant selector map used only as a membership filter. Extending them by deleting the filter and redundant representation is sufficient. No new loader, queue, resolver, cache, scheduler or scoring workflow is necessary or present. New testing helpers reuse existing deployment and submit flows; Custom-only fixtures avoid waiting for a baseline they do not declare. Removal of the old omitted-optional-slot test is justified because its asserted behavior directly contradicts REQ-012, and the replacement SDK scenarios assert the new complete requirement set.
