## Producer-to-consumer and lifecycle audit

The admission invariant is `reserved <= floor(3C/4)` and `unreserved <= C-floor(3C/4)`, including unused reserved slots. Reservation creation charges its share before any source item can exist. Spending a slot transfers ownership into `pending` and `staged_reserved` before queue send; it does not charge again. Dequeue, batching and retry transfer items between containers without releasing ownership. Writer success/terminal consumption releases each item's original share. A failed send releases immediately. Dropping a Reservation releases only its unspent slots. These are the existing Outbox's capabilities, not a second admission service.

For concurrent shutdown, `queue`'s read/write fence excludes a queued send once the fence is taken. Every shutdown then waits for the same writer to stop before touching the final counts. Exactly the caller seeing nonzero `pending.swap(0)` owns the staged reserved snapshot and release; losing callers return zero before that swap. A concurrent unused reservation drop affects only `reserved`, not `staged_reserved`, and cannot be released twice. Late stages release their own admission and count loss without entering pending. The source ownership argument is stronger than claiming the current-thread join test forces every historical race.

Direct verify owns two reserved source slots across engine execution; canceled/error paths drop unused slots. Queued submissions reserve both destinations before input staging. Scribe retries exact input slices until terminal handling or success; handoff occurs only after the complete successful slice and enumerates original input order. Lost inputs release the contained downstream reservation on drop and never create a submission. On successful ACK, the pre-held submission slot prevents downstream-full shedding. SQL outage retains admitted submissions for retry; no producer starts SQL IO. Runner result reservation happens before execution, and a full share maps to existing defer rather than burning an attempt or discarding a completed result. Settlement keeps existing lease fencing and stable result identity.

The final replay test now uses an actual downstream observation. Its replay send completes before its HTTP response; the later sentinel send follows that response in the same tenant. Outbox appends channel arrivals in order, cannot run a later slice for a busy tenant, and retries an older failed slice first. Scribe ACK handoff preserves original item order, and the same generic downstream outbox preserves it again. `accept_submissions` iterates its slice before SubmissionSink commits. The distinct sentinel's visible execution therefore places this healthy replay processing before final count 4, even if the previously recovered row was already visible. Source `(3,1)` remains before replay, correctly avoiding a claim that accepted replay input rows must deduplicate. This is a test barrier for healthy recovery, not a promise of delivery across terminal rejection, crash or expired shutdown.

Audit/span/capture siblings remain unreserved producers whose overflow is permitted counted loss. No authorization decision awaits outbox persistence and no audit error enters verification errors. Existing shutdown continues closing producers/draining Scribe before submission drain; retained reservation ownership fits that lifecycle. A process crash still loses memory-only rows, and a deadline may abandon them. Nothing in the changed client response strengthens that boundary.
