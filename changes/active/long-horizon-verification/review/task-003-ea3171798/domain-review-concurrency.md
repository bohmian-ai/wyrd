## Concurrency invariants and remediation closure

### FIND-TASK-003-1: closed by source

At `outbox.rs:336–368`, shutdown first takes the channel sender under the write lock and waits for the tracked writer to finish (cancelling it at deadline if necessary). Its `pending.swap(0)` then elects one finalization owner. Only a caller receiving a nonzero value takes `staged_reserved` and releases the paired shares. A concurrent caller observing zero returns without touching the reserved count. This prevents the prior split where one caller held the item count and another held its reserved subset.

This pairing is stable despite surviving Reservation handles. After the queue fence, a reservation can only take the late-send path: it releases its own charged share and counts that item lost without changing pending or staged_reserved. Dropping unspent reservation slots likewise changes only reserved admission. Before the fence, send publishes pending and staged-reserved counts under the read lock before the writer can receive the item. Once the writer has ended, no writer release races finalization. The chosen correction therefore closes the shared source rather than merely guarding subtraction at a consumer.

The new `concurrent_shutdown_releases_reserved_losses_once` test stages reserved and unreserved work, retains a separate unused reservation, joins two shutdowns, asserts exactly one aggregate loss report/count and verifies the remaining slot survives until Drop. Its current-thread execution is a useful regression check, but does not deterministically force every cross-thread ordering; the finalization ownership argument above supplies the concurrency proof. Existing normal-drain and deadline-loss behavior is preserved.
