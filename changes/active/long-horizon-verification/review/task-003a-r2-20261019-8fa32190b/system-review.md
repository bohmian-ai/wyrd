## R2 correction and deployment assessment

1. **Elapsed time:** `RECORD_GROUP_ACTIVITY_SQL:202–205` extracts fixed elapsed seconds before adding an interval to PostgreSQL statement time. All accepted duration units are whole seconds with a 365-day bound; there is no calendar-month/year authoring ambiguity to preserve. This fixes DST behavior at the single activity owner without changing authored text, local clocks, or retry/debounce mechanics.
2. **Refusal shape:** the additive `20261019000000_verification_refused_shape.sql` strengthens only the authority-NULL alternative of the existing CHECK. It requires every window/record/input/route/snapshot field NULL while preserving terminal metadata requirements and authority-present rows. Both actual refusal producers (owner rejection and expired incomplete snapshot) already emit this shape. Constraint rejection fails the one tenant transaction; the scheduler rolls it back, retaining pending.
3. **Migration deployment:** the new file does not modify the applied 20261018 checksum. SQLx migration ownership remains `wyrd-sql/src/lib.rs::MIGRATOR`; platform-only migration lease/application and serving checksum/readiness validation remain the existing owners (`lib.rs::MigrationLease`, `validate_schema`, `schema_check.rs::verify_migrations`, server `ServerPostgres::connect_from_dsns`). An invalid historical row would cause migration validation to refuse startup rather than be silently discarded; no unsafe rewrite/reset is added. Existing pre-release policy does not require a retained-data upgrade or mixed-version rollout protocol.
4. **Embedding note:** adding a migration file alone can evade an existing incremental macro compilation cache because this crate has no directory-watching build script. This limitation predates this candidate. Here the same committed remediation also changes `wyrd-sql/src/queries/verifier_executions.rs`, requiring this crate to recompile; the release build embeds the new file. No source touch or new build machinery is required to accept this candidate. The repository already has `migrations_embed_count_matches_files` for embedded/source parity. I did not execute a build-cache experiment.
5. **Rustdoc:** Slot visitor additions change no runtime, deployment, or recovery behavior.
