## Material finding

### STD-001 — Missing panic contracts on new/changed Rust items

- Classification: `VIOLATION`; repository documentation blocker under AGENTS §16, not a proposed runtime redesign.
- Rule: AGENTS §16 requires every new or materially modified Rust item, including private helpers and tests, to have substantive rustdoc and says, “Add `# Panics` whenever a panic remains possible.” The final agent-rules Rust documentation rule makes incomplete rustdoc `BLOCK_BEFORE_MERGE`.
- Locations: `crates/wyrd/wyrd-server/src/mcp/gateway.rs:323` (`descriptors`), `:329` (`descriptors_unscoped`), `:339` (`write_descriptors`); `crates/wyrd/wyrd-server/src/mcp/mod.rs:439` (`every_tool_schema_is_accepted_by_common_tool_callers`).
- Evidence: all three new projections call `gated()`, which parses embedded schemas and explicitly panics at `gateway.rs:313` if one is not a JSON object. `gated` correctly documents this invariant in its own `# Panics` section, but none of the newly introduced entry points documents or links that panic contract. The modified schema-catalog test now includes the gateway descriptors and directly panics on missing/create-tool or schema assertions, but its rustdoc has no `# Panics`. The materially changed connectivity test in this same diff already shows the required nearby pattern by naming its assertion failures under `# Panics`.
- Consequence: the touched entry points/test do not meet the repository's explicit documentation completion gate; maintainers reading those item docs are not told the invariant failures that terminate catalog construction or fail its proof.
- Smallest correction: document the embedded-object-schema panic condition on the three projection entry points (a concise reference to the existing `gated` invariant is sufficient), and add the changed unit test's assertion-failure conditions. Keep the existing parsing, assertion, authorization, and schema checks intact. No new helper, production behavior change, or runtime test is needed.
- Closure proof: static inspection of the affected rustdoc against their bodies and `gated`; normal formatting. Do not manufacture a malformed static schema or a failing test solely to prove documentation.
