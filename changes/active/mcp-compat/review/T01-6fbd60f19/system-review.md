### SYS-001 — MISSING: ADK negative journey never reaches the refused MCP call

- **Obligation:** REQ-003 negative framework behavior, AC-001 real client/server journey, original T01 Scenario 5: call a hidden tool through the framework's generic path and surface a tool error carrying a Wyrd problem code without tearing down the session.
- **Changed location:** `sdks/wyrd-sdk-python/tests/integration/mcp_frameworks/test_agent_frameworks.py:338-346`.
- **Producer-to-consumer evidence:** `adk_run` builds the viewer toolset from the reader-visible catalog. The test asserts that the resulting declarations equal that catalog, then asks the scripted model for `provider_name(HIDDEN_WRITE)`, which is absent. Installed ADK `flows/llm_flows/tools/_caller.py:83-99` rejects absent names in `_get_tool`; lines 449-457 capture that failure, and lines 529-555 return `build_tool_not_found_response` before invoking the tool runner. The test checks only that this local function response has an `error` key. Actual ADK MCP invocation instead goes through `tools/mcp_tool/mcp_tool.py:685-690` (`session.call_tool(self._mcp_tool.name, ...)`) and its separate `run_async` MCP error handling at lines 569-625. That path is never exercised by this negative test.
- **Observable consequence:** the suite remains green if a real server RBAC refusal crashes an ADK tool invocation or loses its Wyrd problem code. It establishes local unknown-tool recovery, not the required interoperability failure boundary. This is a proof defect; no unproved production authorization bypass is alleged.
- **Smallest testable correction:** retain the existing viewer catalog assertion and exercise a known hidden descriptor through ADK's existing public MCP invocation/tool API under the viewer credential, so the request reaches Wyrd. Assert the returned tool error contains `WYRD_PERMISSION_403_DENIED_RBAC` and that the framework remains usable for the guide call. Reuse the existing real-server fixture and ADK transport/tool owner; do not add a server authorization layer, change public names, or create a replacement transport. This belongs in the current framework journey file.
