## Proposed findings

### INV-01 — VIOLATION: ADK compatibility is obtained with a Wyrd-side MCP adapter

- **Obligation:** spec objective requires discovery/conversion/invocation "without Wyrd-specific adapters"; non-goals exclude an SDK-side MCP adapter. Original Scenario 6 and material stop conditions require stopping on forwarded dotted names rather than silently changing the compatibility mechanism.
- **Location:** `sdks/wyrd-sdk-python/tests/integration/mcp_frameworks/test_agent_frameworks.py:174-188,212`; public instruction at `docs/src/content/docs/reference/mcp-tools.md:29`.
- **Evidence and reachable consequence:** both ADK tests instantiate `ProviderNamedMcpToolset`, which copies each framework-produced tool and replaces dots itself. The provider grammar assertion at `:325` therefore measures Wyrd's rewrite, not native ADK compatibility. The documentation tells users to reproduce that subclass. Native ADK `McpToolset.get_tools` constructs `McpTool` from the server-listed name; native `McpTool._build_declaration` uses `self.name`, while `_run_async_impl` calls `self._mcp_tool.name`. The candidate exploits that split with custom adapter code. Native OpenAI naming and Pydantic `.renamed` are existing framework mechanisms; the ADK subclass is new machinery covering precisely the behavior under verification.
- **Smallest correction boundary:** delete the custom ADK identity adapter and its documentation recipe. Use a native framework configuration only if it actually satisfies the same all-tool provider-name rule without adding a Wyrd adapter. Native ADK `tool_name_prefix` alone retains the dots, so it is not evidence of such a solution. If the locked framework cannot satisfy this requirement natively, route the conflict to spec revision/owner decision as the original task requires; do not rename Wyrd wire tools or add a replacement adapter as remediation.
- **Closure proof:** inspect model-facing declarations from the native ADK toolset against the complete advertised catalog, assert the provider grammar, and invoke guide to prove identity routing. An assertion after custom mutation cannot close this finding.

### INV-02 — MISSING: ADK negative journey never reaches Wyrd authorization or checks a Wyrd problem code

- **Obligation:** original Scenario 5 requires a hidden write through each framework's generic call path to return a tool error carrying a Wyrd problem code, not an unhandled client exception; REQ-003 and AC-001 require the real negative user journey.

- **Observable consequence:** this test remains green if Wyrd accepts an explicitly named hidden tool or if ADK crashes when handling a real Wyrd authorization refusal. Local non-discovery does not prove INV-002's defense at dispatch or the requested framework error handling.
- **Sibling paths and existing mechanisms:** OpenAI's public generic `server.call_tool` and Pydantic's public `MCPToolset.direct_call_tool` actually transmit the original name and assert `WYRD_PERMISSION_403_DENIED_RBAC`.
