# Landing hero animation mockups

Three alternatives for the animation in the docs landing-page hero. The copy,
header, and CTA are identical in all three so only the animation differs.
These are review mockups: nothing here is wired into `docs/`.

## Preview

```bash
cd changes/active/positioning/design/mockups
python3 -m http.server 8000
```

Open `http://localhost:8000/`. No build, no dependencies, no network requests.
`#a`, `#b`, or `#c` in the URL opens that option directly.

The dashed strip at the top holds the review controls (option selector, theme,
pause/play, replay). It is not part of the proposed page.

## Options

| | Concept | What it argues |
|---|---|---|
| **A** (recommended) | One request, then the service. A finance report is verified before it leaves: two assertions pass, a policy Agent cites `BANK-ACCOUNT-DEMO-001`, Wyrd returns failed, the application holds. A clean report passes. Then the view widens to the whole request stream with the first request still pinned. | Verification changes an in-flight decision, and that decision is one of many in a busy service. |
| **B** | In the request path at scale. Requests flow continuously through four lanes: service, assertions, gateway-backed judgment, application. One request opens into its three results, then the flow resumes. | Verification sits inside the request lifecycle; assertions and judgments are different kinds of work. |
| **C** | Decisions become retained proof. Three decisions resolve at request time; afterwards their evidence lands in Bifrost, repeated fields pack, and an earlier failure is read back with its Verifier version, policy, and evidence. | Real-time decisions stay attributable later. |

## What is illustrative

Everything. No server, SDK, or benchmark produced any of it.

- Beat durations and token speeds are reading pace. They are not latency or
  throughput, and the lanes in B are slower or faster only to show that the
  two kinds of check differ.
- Request ids (`r-0412`…) are ordinal labels, not counters or measurements.
- The packed-evidence drawing in C is schematic. Its size is not a compression
  ratio, byte count, or cost.
- All names, addresses, identifiers, policy files, and versions are synthetic.
- Wyrd returns judgments; every proceed, hold, or review is drawn as the
  application's action.

## Limits

- Fonts: Familjen Grotesk and Fragment Mono render only if installed locally;
  otherwise the system sans and mono fallbacks show. The real site ships both
  through `@fontsource`.
- Token values are copied from `docs/src/styles/wyrd-tokens.css`; a real
  implementation imports that file.
- The service stream, lane tokens, and evidence columns are generated by
  `hero.js` and hidden from assistive technology. Each option carries a full
  text description instead.
- With `prefers-reduced-motion`, each option opens on a complete static
  rendering. Play or Replay then steps through the beats without transitions.
- Pausing and resuming restarts the current beat rather than continuing
  mid-beat.
- Result shapes are not yet checked against the executed quickstart output.

## Files

- `index.html`: the hero, the three stages, and the review controls.
- `hero.css`: tokens, layout, and all motion.
- `hero.js`: the beat timer, the controls, and the generated repetitive rows.

The preview bundles the installed Wyrd font assets locally; it makes no external
font requests. Font license files are included alongside the assets.

Browser verification completed for all three concepts: actual animation
advancement, pause/replay, light/dark palette, local fonts, reduced-motion
static states, desktop/mobile overflow and JavaScript runtime exceptions.
Desktop/mobile review captures are in `previews/`. These are illustrative
mockups; no application benchmark or storage-cost measurement was performed.

The design detector reported advisory findings for the inherited hero eyebrow
and heading treatment, deliberate request-stream motion, a diagram accent
border, and the schematic packing height transition. These were not suppressed.
This preview is for concept selection; production animation performance and
complete accessibility qualification remain implementation work.
