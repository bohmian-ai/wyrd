Illustration: one request, then the whole service

A synthetic finance report is ready to send. The application asks Wyrd to verify it first. Recipient authorized passes. Destination private passes. A policy Agent, reading the report through the gateway against a sharing-policy PDF, cites the prohibited identifier BANK-ACCOUNT-DEMO-001 and the sharing policy requirement fails. Wyrd returns failed and the application holds the release for review. A second report without the identifier passes all three requirements and the application releases it. The view then widens to a busy stream of service requests, each with its own passed, failed or inconclusive judgment, and the application proceeding or holding accordingly. Illustration: verification in the request path at scale

Requests enter the service and pass through Wyrd verification on the way to a response. Assertions, such as recipient authorized and destination private, are evaluated directly. A gateway-backed judgment, in which a policy Agent reads the report with a policy PDF, takes its own path and its own time. One representative request, r-0412, is expanded: recipient authorized passed, destination private passed, sharing policy failed citing BANK-ACCOUNT-DEMO-001. Wyrd returns failed and the application holds the release. Across the stream, passed requests proceed, and failed or inconclusive ones are held by the application. Illustration: decisions become retained proof

Three requests are verified at request time. Request r-0412 fails and the application holds it. Request r-0413 passes and the application releases it. Request r-0414 is inconclusive and the application routes it to review. The responses have already returned when, asynchronously, the evidence for each requirement result is retained in Bifrost.
