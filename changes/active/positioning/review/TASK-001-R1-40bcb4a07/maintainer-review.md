- **Producer-to-consumer evidence:** `finance_service.rs:80` now requires `InputSlot::fields_of::<Release>()`; `finance_release.rs` serializes a Release and passes it as one positional object, exercising the expanded Target::project branch. Python's positional model flows through its unchanged Inputs::One bridge into the same branch. The TS result predicate requires separate decoration on verify, wait, status and typed reads so its public result type stays coherent.
- **Existing alternative:** At the base commit the finance Rust program already declares named JSON Schema slots and invokes `Inputs::named`; `InputSlot::json` and plain schema values remain the existing Rust authoring mechanism. Python already accepts model classes for a Verifier's inputs and keyword values for invocation. TS already accepts named bare JSON Schema slots and named invocation objects (`nativeInputs`), so converting a model into new public authoring inputs is not a prerequisite. Existing Rust/TS `result.outcome.verdict` and Python `result.verdict` carry the authoritative value for direct pass comparison. The base finance program and current wrappers demonstrate those owners, rather than merely hypothetical alternatives.
- **Observable consequence and materiality:** Publishing onboarding now depends on newly committed public authoring/invocation/result contracts forbidden by the approved documentation change. This adds a recursive schema extraction API and language-specific schema interpretation/result decoration that future SDK maintainers must preserve across every constructor, typed read and asynchronous result path. The TS changed type test explicitly weakens its previous raw-wire-result-to-SDK-result assignability assertion to account for the new required predicates. This is a concrete public/maintenance burden, not a preference for fewer lines.
- **Smallest correction boundary:** Remove the added public convenience/projection/result machinery from this task and adapt the finance examples/source-backed API to existing named inputs, existing bare schema slots and direct verdict comparison. Preserve pre-existing Python model-class authoring and its recursive/nested-reference handling; either restore its prior owner when deleting the shared exposure or retain only the minimum private implementation needed for that pre-existing behavior. No replacement schema framework, result wrapper or downstream guard is required.
