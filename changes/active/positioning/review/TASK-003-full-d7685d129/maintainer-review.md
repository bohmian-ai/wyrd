## Proposed finding

### MAINT-FULL-001 — REGRESSION: deferred first Window sample loses Node's producer span

**Changed locations:** `crates/shared/wyrd-client/src/observe/mod.rs:437` and `:477`; `sdks/wyrd-sdk-ts/native/src/cards.rs:1074`–`:1081`.

**Authority:** `architecture/wyrd-design.md:1037`–`:1042` requires a queued Bifrost write to record a `bifrost.enqueue` PRODUCER span in the caller's own tracer, with server ingest linking the batch's producers. Maintainer-style requires safely followable workflow ownership; the warm/cold split must preserve this established trace bridge. REQ-017's first-write startup does not approve dropping that evidence.

**Reachable producer-to-consumer trace:** Configure a TS state with managed telemetry, enter a normal active Node span and submit its first valid Window sample without `startBifrost`, as REQ-017 now directs callers to do. Native `submit` scopes only `observe.stage(...)` in `crate::trace::traced`. Because there is no writer, `record_or_stage` validates and returns `Evidence::Window` without calling `drift_value`, so that scope invokes no producer callback. Native `trace::spawn` then carries only the caller span into the async `enqueue_staged` future. `finish` awaits startup and calls `drift_value` after the original producer-opener scope has ended. `WriterPool::insert_rows` (`bifrost/handle.rs:217`) asks `transport::trace::producer` for the write context. Its PRODUCER callback is absent; its documented fallback returns the CALLER span directly. No Node `bifrost.enqueue` span is created for that admitted sample. The server therefore links the original caller rather than a caller-owned enqueue span.

**Sibling/alternative tracing:** Warm TS samples still enqueue synchronously inside `trace::traced` and create the proper span. Python wraps its entire synchronous runtime/block-on invocation in its producer scope; Rust uses its ordinary tracing path. Existing native caller-table writes already use the async caller-context fallback; that unchanged surface is not a new finding here. The regression is the newly deferred Window branch of previously traced submissions. Existing transport tests explicitly distinguish caller-context fallback from a foreign-runtime producer opener, so the two contexts are not interchangeable implementations of the required span.

**Concrete cost and materiality:** A maintainer now has two paths for the same public sample operation with different evidence semantics, and the new native rustdoc claims that samples are recorded after startup without disclosing the lost required span. Every first sample on the recommended no-explicit-start TS path is affected, including concurrent samples staged while startup is pending. This is a direct required trace-contract regression in normal use, not speculative hardening or a style preference. Rows and subject/Run IDs may still land correctly; their successful persistence does not prove the missing span.

**Smallest testable correction:** Repair the existing Node staging/trace bridge so a deferred Window sample creates its producer span through Node's existing producer opener and carries that span's context to the eventual enqueue. Keep the existing lifecycle gate, facade/pool admission, Run-evidence enqueue, warm synchronous path, and Python/Rust behavior. Reuse `native/src/trace.rs`, `transport::trace` and the existing caller-context bridge rather than adding a telemetry provider, a second writer, a replacement observation workflow or eager startup for every submit. The correction belongs at this async handoff; removing staging or forcing Run submissions to start Bifrost would alter unrelated behavior and cost more.

**Focused proof:** Extend the existing TypeScript action-timeline/observation journey with a valid first Window submit under a real Node span, omit explicit startup, drain, and assert the caller-owned `bifrost.enqueue` PRODUCER span and its server consumer link. Retain warm-submit assertions and concurrent-row persistence proof. The existing action-timeline test explicitly calls `state.startBifrost()` before its sample, while the new lazy-start test asserts rows only; neither exercises this missing trace contract. No new harness or dependency is needed.
