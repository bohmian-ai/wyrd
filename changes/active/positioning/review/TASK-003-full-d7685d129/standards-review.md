### REPO-FULL-001 — Published evidence-retention guarantees exceed the actual owner

Classification: **INCORRECT / VIOLATION**.

Locations: `docs/src/content/docs/understand/how-verification-works.md:190`, `understand/technical-questions.md:53`, and `build-and-verify/verify/run-a-verification-and-inspect-its-evidence.md:40`; generated `docs/public/llms-full.txt` repeats them.

Violated rules: docs CONTRIBUTING requires a concept be proved against its owning architecture; docs AGENTS prohibits unsupported performance/production claims; docs PRODUCT requires technically honest evidence and no unmeasured guarantees. `architecture/bifrost-design.md` outbox contract and operations runbooks §Scribe outbox path explicitly retain terminal rejection, shedding/unreachable and shutdown-deadline loss modes.

Source proof: `scribe_outbox.rs:18–34` describes terminal/projection rejection, unreachable destinations and shutdown-deadline loss without changing the operation. Runtime `outbox.rs:112–126` defines those LossReason variants; stage at 348+ counts refused unreserved work, and shutdown at 610+ abandons unwritten items at its deadline. Direct verification reserves its inputs/result slots (`components/verification/service.rs:601–605`), so this finding does **not** assume its successfully admitted result is shed through the unreserved stage path. Its reserved rows still reach the same sink and bounded shutdown/rejection behavior. Dispatcher `outbox.rs:1135–1138` waits for previous in-flight work/backoff as well as linger, and `dispatch` at 1028+ enforces finite concurrency. `SCRIBE_LINGER = 50ms` (`scribe_outbox.rs:137`) bounds batching eligibility, not durable-write completion or total backlog delay.

Reachable scenario: while Scribe is unavailable, accepted direct results remain in the outbox. A graceful server stop reaches its existing shutdown deadline before Scribe recovers; outbox shutdown cancels pending writes and counts them lost although the caller already received the verdict. The new prose says a clean shutdown writes everything and only an abrupt stop can lose it. A busy/retrying lane likewise can exceed the asserted 50ms-before-write interval. After loss, a missing query row is not evidence that a record merely has not been written *yet*.

Consequence/materiality: readers of the public assurance/evidence tutorial are told a stronger retention and timing guarantee than Wyrd provides, which changes how they interpret absent proof and graceful stop. This is a contract claim, not an optional wording preference or a request for stronger durability.

Smallest correction: correct these three source paragraphs to distinguish nonblocking result staging, batching linger, acknowledged durability and eventual visibility; preserve counted terminal/unreachable/shutdown-deadline loss and state that a missing row alone cannot establish the verdict or future arrival. Remove the absolute storage/timing/loss promises. Reuse the current outbox contract; do not add synchronous persistence, retries, durable queues, runtime changes or benchmark machinery to make the prose true. Regenerate full-text docs through existing docs:generate, then run focused existing docs tests/commands/links/generated checks. No new runtime test is needed for a prose correction to already implemented failure boundaries.
