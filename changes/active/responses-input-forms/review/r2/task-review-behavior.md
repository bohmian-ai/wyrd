## Caller-to-result and falsification traces

The actual agent uses an OpenAI client pointed at `${caller.serverUrl}/v1` with a Wyrd access token acquired through existing SDK auth. The new `echoAgent` uses the actual Responses model rather than constructing raw captured requests. Its tool returns structured text output, which that SDK emits as content parts. The recording provider changes its answer only after it sees a function-call-output item, so success demonstrates continuation rather than just initial decoding. Its first answer contains a function call, second answer a completed assistant message. The caller receives the final result. The test's upstream assertions prove each required changed form crossed public ingress; the provider fake is only the external model and does not bypass Wyrd server/admission/adapter behavior.

The raw gateway body is not the normalized Skald value. `typed_body` deserializes a borrow purely as validation, then returns original JSON. `native` only replaces the model. Consequently extra function-call IDs/status and message shorthand can remain in raw provider-bound JSON even though Skald's canonical representation drops unmodeled item members. That existing difference does not violate the approved task. The new schema describes easy input at that ingress/authoring boundary; it does not require changing canonical serialization or every sibling runtime writer.

Malformed content (number, missing role, unrelated discriminator) is not rescued by normalization: only missing type plus a present role is made a message; existing serde rejects absent/wrong-typed required fields or invalid parts. The easy schema uses corresponding required fields and discriminator restrictions. Nonmessage tagged items continue through the canonical decoder. String input and existing typed message inputs remain supported by the untouched input enum branch and preexisting round-trip test. Prompt `with_tool_result` and agent `tool_result_message` are the sibling production result writers: their `.into()` calls use the same From<String> owner and retain original string wire shape. Python is the only production caller of `text()` and performs a documented projection, leaving stored result untouched.

No new identity, parsing transport, traversal, workflow, lifecycle or IO abstraction duplicates an existing capability. The pure serde input adapter must exist because the canonical tagged item representation cannot directly decode easy strings/missing tags. The installed Schemars customization is needed because derive cannot infer serde rewrite acceptance; publishing its alternative once reaches JSON schemas, OpenAPI and generated language declarations without downstream escape hatches.
