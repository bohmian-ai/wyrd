## Material findings

### STANDARDS-001 — Local Python properties now establish network connections

- Classification: VIOLATION / REGRESSION.
- Rule: `architecture/references/languages/python-api-and-stubs.md:84` prohibits hidden IO in property accessors. The adjacent constructor rule and `architecture/wyrd-design.md:291` defer connection to the first **server operation**. `AGENTS.md` §6 also requires a blocking strategy for async paths.
- Changed locations: `sdks/wyrd-sdk-python/src/state/mod.rs:1726`, `:1742`, `:1758`, `:1774`; `sdks/wyrd-sdk-python/src/bifrost/mod.rs:680`, `:892`, `:898`. The shared producer is `sdks/wyrd-sdk-python/src/client.rs:119` (`LazyConnection::get`).
- Source evidence: the four Cards view getters invoke `self.cards(py)?` before returning the view. Bifrost's `table`, `dropped`, and `producer_count` invoke `self.handle(py)?`. These reach `LazyConnection::get`, which synchronously blocks on the shared Rust connection under `py.detach`. Those connections perform credential exchange and, for Bifrost, persistent gRPC dialing. Releasing the GIL does not move the calling Python thread to a worker.
- Reachable consequence: `Cards().data` can read configuration, exchange credentials, and fail without any registry operation; `Bifrost().producer_count` can dial the server instead of returning local state. The public `_BifrostBase` forwards these properties directly (`python/wyrd/bifrost/_client.py:693`, `:727`, `:733`), so `AsyncBifrost().producer_count` also blocks the event-loop thread during first connection. `tests/unit/test_sdk_client_instantiation.py:23` explicitly chooses these property reads as first use and asserts the resulting no-credentials failure; this is positive source evidence of the regression, not a hypothetical caller.
- Required correction: keep local views and metadata access local before connection. Cards views must retain/share their parent's single lazy connection and defer initialization until their first actual registry operation. Before native Bifrost connection exists, report its retained table and empty producer/drop counters; after connection, read the existing native state. Continue to use the same shared Rust connection for actual server work and preserve eager `connect`. Do not add another resolver, transport, or per-view connection.
- Focused closure proof: with credentials absent and with unreachable endpoints, read every Cards view and Bifrost/AsyncBifrost local metadata without connection or error; then perform an actual server operation and assert the same stable eager/lazy connection error. Run the async property scenario on the event-loop thread so an accidental native dial is observable. Retain a real-server journey proving parent and typed views share the same selected client.
