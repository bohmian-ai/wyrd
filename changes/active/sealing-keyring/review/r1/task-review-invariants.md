## Producer-to-consumer and sibling tracing

The write authority is `GatewayAdministration::put_credential`, not a client or keyring configuration entry. It validates permission and source, derives tenant from the caller, seals the trimmed value with tenant/name/provider inside authenticated bytes, and writes only redacted source and opaque envelope. The one Gateway SQL upsert replaces ciphertext together with source/provider. Environment/Vault writes clear ciphertext through the same optional envelope field. The original schema's source-versus-ciphertext CHECK survives dropping the separate nonce/version columns; source changes cannot leave an orphaned envelope through this path.

Gateway admission obtains one consistent SQL snapshot and decodes the envelope. A missing or undecodable snapshot value becomes empty bytes, which cannot decrypt. Resolution checks credential existence, revocation and matching deployment provider before decryption, then checks all binding identities. Failure returns a credential error before provider dispatch. The existing Environment/Vault source assignment path and mounted-file reader remain intact; only managed secrets bypass assignment, as before, with their tenant authority supplied by authenticated payload binding.

Rotation includes every non-null Gateway ciphertext, including revoked entries. Cross-tenant selection is explicitly through OperatorPool. The update compares tenant, credential name and exact old ciphertext; concurrent credential replacement, deletion or sibling replica rewrap cannot be overwritten. A source replacement clears the old envelope and loses CAS safely. Rewrap decrypts/reseals opaque bytes without rewriting the bound payload, so tenant/name/provider survive rotation. Existing auth human/trusted issuer/platform secrets retain their prior selection and update behavior. Existing retirement runbook requires all writers to switch and a later zero-remaining pass; the implementation adds no competing retirement authority.

Dev provisioning retains the key outside `versions/`, so release replacement does not select a fresh key. Temporary-file staging, `sync_all`, and no-clobber publication avoid publishing partial files and avoid concurrent first-run replacement. A preexisting key follows the same existing bounded, regular, owner-only server reader as explicit operator key files. Invalid or permissive files fail before serving rather than silently replacing encryption authority. Both explicit file and inline env choices are passed through unchanged; conflicting/empty supplied sources remain the server config loader's refusal boundary.
