## FUP-AUTH-001: direct verification omits subject admission

**INV-DIRECT-001 and B-001 are supported and share one cause. Classification: INCORRECT.**

The producer is `crates/wyrd/wyrd-auth/src/issuance.rs:355–380`: a family account without a selected root yields RootRequired; selecting a root resolves Scoped graph access. Runtime `Principal::card_attribution` (`crates/shared/wyrd-runtime/src/principal.rs:207`) exposes that state. `RbacCheck::check` (`permission_check.rs:65`) only checks effective_permissions.contains(permission); a wildcard operation grant does not enforce the separate Card limit.

The HTTP execute handler (`crates/wyrd/wyrd-server/src/components/verification/routes.rs:348–365`) and MCP EXECUTE (`src/mcp/verification.rs:197–224`) call VerificationControl::execute, then `service.rs:472–636` run_direct. At `:490`, its admission decision passes subject=None into authorize_run. The latter (`:932–973`) checks verifier-run permission, then matches (subject, card_attribution). Both Card refusals require Some(subject): RootRequired returns workload_context_required; Scoped rejects a UID outside its set. None reaches success. The sibling enqueue consumer (`:683–689`) supplies Some(&request.card_uid), enforcing both cases at the same decision/audit boundary. That existing narrower mechanism fully covers the missing direct behavior.

No downstream owner repairs this omission. `service.rs:849–895` resolves tenant Verifier/subject/owner rows through the cache without supplying caller Card access. `src/verification/cache.rs:88–114` parses the target and gathers binding environments. `crates/wyrd/wyrd-sql/src/queries/verification_target.rs:49–61` refuses readiness/missing Verifier/missing subject only. `src/verification/hosted/blocks.rs:123–159` builds evidence readers, engine and optional gateway executor; CallerTraces::new constructs ordinary Oracle query context, not subject admission. A scalar Verifier using supplied evidence need not invoke the gateway or read trace evidence, so downstream gateway subject checks are no universal backstop. System execution attribution supplies no new permission. Successful direct results are staged at `service.rs:614–623` with the requested subject.

A ready same-tenant scalar Verifier, existing subject, hosted blocks and ordinary verifier grant therefore suffice: a rootless family account can execute despite RootRequired; a rooted caller can execute an out-of-graph subject despite Scoped access. No cross-tenant access is needed. The previously present None argument is no exemption: this candidate introduces RootRequired and changes the shared consumer under complete emit/verify requirements.

**Authority and minimal correction:** spec REQ-010/012/033, auth supplement Authorization/Verification and request context (`:384–405`) and direct verification (`:782–787`), plus TASK-002 scenarios 2/3/7 require the independent Card limit. Pass the request subject through the existing direct authorize_run decision, as enqueue already does. Preserve one audit decision, refusal before reservation, ordinary Card reads, System execution and AnyRegistered rootless privileges. No additional permission engine or public/security decision is needed. Focused direct HTTP/MCP proof should cover RootRequired, Scoped outside/inside graph and authorized AnyRegistered rootless cases, with no result staging after refusal.

## FUP-AUTH-002: native ingest refuses state-selected User context

**B-002 is supported as a positive-flow gap, not an authentication bypass. Classification: MISSING/INCORRECT.**

`crates/shared/wyrd-client/src/state.rs:762–787` pins the loaded state client to its Service UID. AuthMiddleware::for_service (`auth.rs:864–900`) retains its credential and sets context. bearer (`:966–980`) returns an existing BearerToken unchanged: no exchange makes this User token root-signed. `src/bifrost/grpc.rs:272–300` sends that bearer and the pinned x-wyrd-workload-uid together.

The production native mount (`crates/wyrd/wyrd-server/src/grpc/mod.rs:360–365`) uses gate().clone().into_server() inside transport admission, without the OTLP authentication adapter. `crates/vala/vala-bifrost-redux/src/gate/mod.rs:1145–1157` authenticates before dispatch. `gate/auth.rs:157–184` verifies for Bifrost, parses the selector, then refuses whenever needs_root_resolution returns true. That shared predicate (`crates/shared/wyrd-runtime/src/request_context.rs:91–100`) returns true for a rootless bearer, including a User with sufficient grants and a genuinely valid requested tenant Service root. The request never reaches native frame attribution or acknowledgement.

Existing narrower machinery already implements the needed semantics: AuthenticatedPrincipal::select_root (`wyrd-server/src/components/auth/principal_extractor.rs:86–105`) retains normal verification, opens the authenticated tenant connection only when selection needs resolution, and calls `wyrd-auth::select_request_root` (`issuance.rs:397–424`). That owner validates the root/family snapshot, intersects signed Card access, preserves permissions/account/expiry/chain and selects context without issuing a token or recording activity. OTLP gRPC (`wyrd-server/src/grpc/otlp.rs:275–305`) already applies that selection and supplies the verified value to Gate admission. Equal signed selectors avoid registry work; different signed selectors fail. Native mounting has no equivalent step.

**Authority reconciliation:** `architecture/wyrd-security-posture.md:495–499` explicitly says native verification is store-free and native accepts only signed roots/refuses unresolved selectors. This is real contradictory owner prose. However, that exception was introduced in the cumulative implementation: the architecture diff adds the paragraph. The approved normative packet grants no native exception. Spec Scope and authority explicitly directs replacement of owning security prose; REQ-013 and auth supplement User access token and WyrdState (`:408–419`) require an existing User bearer with automatic root on owned IO. TASK-002 scenario 3 expressly includes native admission; scenario 4 includes User bearer states. The auth supplement (`:376–379`) permits registry work for explicitly selected unresolved request roots while normal signed-token verification remains synchronous/store-free. TASK-002 evidence line 316 calling native refusal “by design” cannot amend these obligations. TASK-003 schema/readback ownership likewise does not defer this auth flow.

Thus the native verifier is locally fail-closed, consistent with the security report, but production composition cannot deliver the approved positive flow. Correct composition and conflicting owner prose together. Do not simply remove the unresolved-selector refusal: without validated replacement context that could silently discard or forge ownership.

**Minimal correction boundary:** reuse server-owned optional-root selection/shared auth before native admission, as OTLP already does. Preserve Gate native frame validation, permissions, row attribution, readiness, lifecycle, transport/size bounds and acknowledgement ordering. Keep normal signature verification store-free, no broader live-grant lookup, no machine credential requirement for Users, no ignored selector or unowned fallback, and no per-scoped-record SQL. Private adapter shape is reversible implementation detail. Update the introduced security-posture exception to accurately distinguish store-free verification from explicit request-root selection. This implements an already approved context decision; no new public token/API/security policy decision is needed. Keeping signed-root-only native support instead would narrow approved behavior and require specification approval, not a task workaround.

Focused closure proof: a normal existing User Bifrost bearer plus WyrdState native observation reaches acknowledgement with unchanged identity and validated owner/subject; unknown/foreign/wrong-kind root, mismatched signed root, missing operation grant and out-of-graph subject refuse; already-signed-root and bare rootless generic admission remain valid. Selector-parser or OTLP tests alone cannot establish native production composition.
