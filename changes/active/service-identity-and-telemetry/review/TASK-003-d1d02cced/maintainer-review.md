## MR-1 — Accepted evidence delivery depends on current public Card visibility

- **Classification:** INCORRECT / REGRESSION; material ownership error.

- **Obligation:** TASK-003 scenarios 5/7 and storage supplement “Original action, not delivery identity” / “Shared Service and subject dimensions”: trusted delivery retains accepted context and cannot relabel or lose it through forwarding/retry. Maintainer-style requires the lifetime's owning context to retain the state its later stages need.
- **Source-proven path:** A rootless unrestricted caller makes an authorized gateway call about a registered standalone observation target. `GatewayInvocation::attribute` validates it directly with SQL, not through the new descriptor cache. While the provider call or stream is in flight, an authorized deletion soft-deletes that unreferenced Card. When capture later reaches an otherwise cold local or peer Scribe, `row_dimensions` uses `read_descriptor` -> `get_card_by_uid`; that existing public lookup explicitly filters `status != 'deleted'` (`wyrd-sql/src/queries/cards/get.rs`, SELECT_BY_UID). The cached path succeeds if previously warmed, but the cold path silently omits this descriptor. `stamp_dimensions` then returns `CardScopeDenied` for the carried subject. `ScribeRefusal::from_scribe` classifies it as Rejected and `ScribeSink::tally` consumes/drops the writes. The provider call already succeeded. No process crash or unusual malformed input is needed.
- **Concrete consequence/cost:** Valid completed evidence disappears depending on another pod's cache history and Card lifecycle timing. Every future trusted producer must understand a hidden live-registry precondition despite already owning accepted authority. Mixed frames can lose sibling writes together. Immutable descriptor values do not imply that public visibility lookup remains available.
- **Existing alternative and smallest correction:** Preserve the existing registry owner and public authorization lookup. For already accepted trusted UIDs, resolve immutable descriptors independently of current public visibility, using the retained tombstone lookup already provided by the SQL Card owner (`get_card_for_reconciliation` demonstrates the retained-row mechanism) or the equivalent narrow descriptor read on that owner. Keep rootless public membership checks fresh and non-deleted; do not use retained rows to authorize new public writes. This fixes the cold-cache failure without a second cache, writer, JWT profile, or generic retry mechanism. It also avoids expanding gateway/execution persistence merely to repair this failure. The literal approved admission-freezing obligation remains the behavioral standard when choosing the final correction.
- **Focused proof:** Admit an attributed call, pause before capture delivery, soft-delete its otherwise unreferenced subject, then deliver through a fresh descriptor resolver. Query exact original attribution/descriptors; repeat with the existing warm resolver and a peer receiver. Both must agree, and a new public rootless write about the deleted Card must still refuse.
