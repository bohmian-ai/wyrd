## SYS-001 — Provider-attempt spans discard the admitted call origin

- **Classification:** MISSING.
- **Location:** `crates/wyrd/wyrd-server/src/components/gateway/capture.rs:403` (`otlp_spans`), `:438` (`spans_batch`); contrasted with the correctly extended `calls_batch` at `:351`.
- **Violated obligation:** REQ-034 and REQ-051–052, TASK-003 Scenario 5's gateway/internal-capture originating context and Scenario 7's context retention through provider attempts; storage supplement “Original action, not delivery identity” and “Shared Service and subject dimensions”; `architecture/bifrost-design.md`'s per-row accepted-origin stamping. These require admitted origin on trusted signal rows as well as the gateway summary.
- **Reachable producer-to-sink evidence:** A configured Service/Agent call reaches `GatewayInvocation::facts`, which stores the admitted `GatewayCallContext` in `CallFacts`; `CallCapture::from_facts` retains it in `self.subject`. `calls_batch` writes the workload/subject/Run/environment from that context. In contrast, `otlp_spans` passes only call ID, operation, provider and `GatewayAttemptSpanFieldsV1` into `otlp_span`; the only context it subsequently changes is the trace parent. `otlp_span` at `:995` serializes attempt accounting fields plus GenAI protocol attributes, none of which contain the admitted workload, subject, Run or environment. `spans_batch` projects all attempts under a single hard-coded gateway `service.name` resource. `CallCapture::project` adds only per-row account owners to the resulting span batch. `Chunk::attributed` adds principal columns and adds original request only for `ScribeTable::Calls`.
- **Consumer evidence:** `ScribeBatch::into_frame` sees no carried workload/subject UIDs on these span rows, so `row_dimensions` cannot describe their originating Cards. `managed_arrays` consequently stamps null workload, subject and Run; `stamp_dimensions` retains the observed gateway service label and null environment, and uses null subject descriptors. The original call request is absent too, so the span's `wyrd_request_id` becomes the content-derived delivery-frame request. Both local and peer routes reach this exact path. Retry/WAL recovery/compaction faithfully preserve the wrong row and cannot reconstruct the missing context.
- **Observable consequence and materiality:** A normal successful or failed provider attempt for Service A / Agent B / Run R / environment production appears as gateway-owned uncorrelated telemetry. Queries scoped to the exact workload, observed subject, Run or configured environment miss the very provider attempts produced by that work, and request correlation disagrees with its gateway summary. This affects every captured configured call, including streaming, fallback attempts and verification-triggered calls; it is not a dormant or malformed-input case. Trace IDs still link the attempt, but trace linkage does not satisfy the independently queryable origin contract.
- **Smallest testable correction:** Extend the existing `CallCapture` attempt-span projection to carry each capture's retained admitted origin onto each of its projected attempt rows, including its original request; repeat the correct origin per attempt in mixed-capture batches. Reuse the existing row-attributed stamping/registry-resolution path to derive canonical descriptors. Preserve raw gateway instrumentation labels, span/parent identity, account ownership, attempt outcomes, bounded projection, schema IDs, and existing failure isolation. No new writer, public headers, JWT claims, registry owner, retry machinery or batch-item tracking is needed. Adding a query-side inference/join is insufficient because origin must survive as row data.
- **Focused closure proof:** Extend an existing gateway capture/journey case with two calls from distinct admitted contexts and multiple attempts, including one streamed/verification-driven case already supported by the harness. Read actual `bifrost.traces.spans` rows for those gateway calls and assert workload/subject/Run/environment, five canonical descriptors, original request and account pair independently from the summaries. The existing local/peer retry seam should confirm those carried fields remain identical after a retry; the existing lifecycle proof remains sufficient once producer rows contain the correct values. No new broad suite or harness is required.
