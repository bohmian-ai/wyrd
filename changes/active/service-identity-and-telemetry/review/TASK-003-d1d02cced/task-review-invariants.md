## INV-R1 — gateway attempt spans discard accepted call origin

- Classification: **MISSING**, material correctness failure.
- Violated obligation: REQ-051 carries context through all telemetry, gateway and trusted delivery; REQ-055 explicitly preserves captured context through gateway attempts; REQ-056 freezes Service/subject/environment/Run/trace; TASK-003 scenarios 5 and 7 require accepted originating gateway context. Bifrost architecture requires internal rows to carry their accepted origin.
- Exact correction location: `crates/wyrd/wyrd-server/src/components/gateway/capture.rs:438` (`CallCapture::spans_batch`), with the omission visible at `:403` (`otlp_spans`).

Reachable failure: make an ordinary successful configured gateway call for Service A, Agent subject C, Run R, environment prod. Admission builds GatewayCallContext and CallFacts/CallCapture retain it. `calls_batch` at lines 354–385 copies the accepted workload, subject, Run and environment. However, `otlp_spans` reads only call ID, trace context, operation and GatewayAttemptSpanFieldsV1; that closed attempt record contains none of the missing origin. `spans_batch` combines all captures under one resource with `service.name = wyrd-gateway` and calls `project_spans`. Thus its projected subject and Run are null, environment/version are null, and it has no workload column.

Downstream cannot restore the omitted values: `CallCapture::project` supplies only each attempt's account pair as Owner. `scribe_outbox.rs::Frame::attributed` appends that pair, and appends original wyrd_request_id only for Calls, not Spans. `ScribeBatch::into_frame` resolves descriptors solely from UID columns actually present. `managed_arrays` produces null workload when a Rows frame carries none, preserves null subject/Run, and falls back to the content-derived frame request ID. `stamp_dimensions` therefore retains the observed gateway service label. The same rows travel through local or peer delivery and recover exactly these incomplete values.

Observable consequence: the call row identifies A/C/R/prod, while its provider-attempt span identifies the gateway service with null workload/subject/Run/environment and a different request correlator. Service/component/Run/environment queries omit the attempt evidence, and the span does not join its originating permission decisions through wyrd_request_id. This affects normal supported successful gateway requests, not an exotic input. Multiple origins in one capture batch amplify the loss.

Sibling inventory and correction boundary: OpenAI/Anthropic and other ingress adapters, streaming and buffered invocations, Batch HTTP operations, and verification-backed gateway invocations converge on CallCapture. Calls and Spans are sibling outputs of that owner. ServerSpans is a separate producer sharing the span destination; Results/ExecutionInputs/Audit share the outbox but should not change. The generic outbox and Scribe already preserve row-carried origin and cannot infer a missing per-attempt context after captures are combined.

Smallest testable correction: extend the existing CallCapture span projection to carry each attempt's already accepted workload, subject, Run, environment and original request in the canonical row inputs, repeating its own capture context for each attempt. Reuse the existing carried-column/Rows admission mechanism and descriptor resolution; do not infer from provider fields, account IDs, trace membership or another call, and do not expand the closed provider attempt payload contract or add another pipeline. Preserve raw gateway resource/provider attributes and current span trace/parent identity. Simply adding an OTLP Card attribute before the existing `project_spans(..., None, ...)` is insufficient because that projector has no authorized Card scope; the accepted context belongs to the existing trusted row projection.

Focused closure proof: extend the existing configured gateway capture journey to query the linked `bifrost.traces.spans` rows as well as calls and assert all accepted origin fields, original request, correct pair, and unchanged trace/attempt fields. Include two calls with distinct origins in one outbox flush; use the existing peer/recovery proof for retained physical rows instead of another harness. The current configured gateway test at compatible.rs:480–546 reads calls only and cannot detect this omission.

Correction burden is bounded to the existing capture projection and its focused proof. Changing generic delivery or stamping would be larger and could wrongly adopt one frame's origin for mixed-origin rows.

## INV-R2 — public native drift rows can supply forged shared dimensions

- Classification: **INCORRECT**, material public-contract and evidence-integrity failure.
- Violated obligation: REQ-051 derives identity descriptors server-side and accepts environment as context; REQ-052 says public managed descriptors cannot be forged before ACK. TASK-003 explicitly requires public forged managed/derived values to fail before ACK. Bifrost architecture, row identity section, states that public supplied dimensions are refused.
- Exact correction boundary: `crates/vala/vala-bifrost-redux/src/scribe/execution_lanes.rs:564` (`decode_rows`, the public/native admission context), supported by permissive `stamp_dimensions` at `:1265–1283` and `tables/mod.rs:388–408` (`validate_predeclared`).

Reachable failure: an authorized rootless editor sends a correctly shaped native IPC row to described `bifrost.drift.observations`, changing the shared nullable service_name/service_version/deployment_environment columns from null to arbitrary strings. `ObservationsTable::arrow_fields` declares all six ordinary Utf8 fields. Gate reserves audit, gateway calls and verification result/input/feature tables, but permits drift observations under the ordinary table write grant. Native dispatch carries Frame attribution and empty accepted descriptors/environment for this rootless request.

`decode_rows` reserves the seven managed fields and wyrd_ names; the six dimensions are not reserved there. `ObservationsTable` uses the default `validate_predeclared`, which checks declared shape, Variant contents and whole Structs, with no dimension-value check. The schema is valid. `stamp_dimensions` keeps supplied Service fields whenever workload has no descriptor (`owned.map(value).or(observed)`) and keeps supplied deployment_environment whenever no accepted environment exists. The forged values therefore persist and ACK succeeds. Supplied subject descriptors are silently replaced, also contrary to the explicit pre-ACK refusal, but the retained Service/environment forgery establishes the material defect independently.

Observable consequence: an ordinary public native writer can manufacture Service/version/environment filter values in canonical retained drift evidence despite having no validated workload or accepted environment. The shared cross-table query contract now returns client-invented canonical dimensions. This is within explicitly required negative-flow coverage; operation permission to emit evidence does not authorize overriding server-derived descriptors.

Sibling inventory: canonical spans/logs/metrics already rederive and refuse forged raw promotions and subject descriptors; they must preserve their approved unowned-resource promotion behavior. Dynamic user tables may legitimately own fields with these names and must not acquire mandatory dimensions or restrictions. The other predeclared system tables are public-write reserved and receive legitimate non-null row-carried context from CallCapture/ResultPayloadBuilder/Audit through trusted Rows frames. The SDK drift producer already fills all six dimensions with null in `wyrd-client/src/observe/drift.rs::rows`; thus a correct public payload requires no SDK redesign.

Smallest testable correction: enforce the shared-dimension input rule at the existing native public admission boundary for the non-signal built-in path: supplied non-null dimensions must refuse before stamping/ACK; accepted context then supplies their values. Keep trusted Rows frames' accepted values and canonical telemetry's resource-derivation validation intact, and leave dynamic fields alone. Do not add a global unconditional null check to validate_predeclared: peer/outbox Rows frames arrive as Arrow IPC and legitimately carry non-null accepted environment. No new public error or contract is needed; reuse the existing native schema/value refusal mechanism.

Focused closure proof: extend existing public native admission proof with the actual drift observation schema and parameterized non-null mutations of each shared dimension, both rootless and with valid workload/environment context; assert refusal and no stored rows. A valid null-dimension row must still persist the accepted context. Retain the existing owned/unowned signal and trusted mixed-origin positive checks. This uses the existing server/native journey and needs no new dependency or harness.
