## Exact dependencies and existing-owner comparison

Manifest and lock agree on iceberg-rust `850d308a8c50cdd7890ecfdf5bfd9825efebb241` and iceberg-compaction `c213af00eac40377d800e24f3ed68945034e7de4`. Inspected read-only local Cargo checkouts at those exact HEADs, including the SQL native no-op implementation/tests and compaction's output request, writer-location and grouping consumers. Relative to prior pins, iceberg-rust changes only `crates/catalog/sql/src/catalog.rs`; compaction changes only Cargo manifests/lock to resolve that Iceberg revision.

The implementation extends existing publication records, snapshot properties, writer path grammar and native TableMetadataBuilder/compaction location generator. It does not add a writer, history service, cache, SQL projection or output object. The in-memory output table view is necessary because storing `write.data.path` would mix per-attempt output placement into immutable persisted definition properties; the native writer already consumes that property.

Compared new `Forge::retained_definition` (`compact.rs:514`) with existing `BifrostCatalog::retained_definition` (`bifrost_catalog.rs:1472`). Both reuse `TableDefinition::of_metadata`. Forge owns only `Arc<dyn iceberg::Catalog>`; that trait exposes retained-location listing, whereas the indexed `load_table_version_location` is an inherent concrete SQL-catalog method. The new Forge method therefore reuses its existing trait-visible retained-reference listing and native metadata parser. Requiring concrete catalog ownership or another cross-owner service solely to avoid this small lookup would enlarge the correction. It reads historical documents until the exact version matches and fails closed on unavailable evidence. No DRIFT finding is established from this difference; performance is not measured here.

The selected version need not be an extra scalar in `RewriteHandoff`: the handoff's validated output paths already carry it, and the same owning attempt's policy is transferred separately to `RewriteCommitIdentity` before commit. This preserves the existing handoff's no-authority role and the required durable lineage without another workflow.
