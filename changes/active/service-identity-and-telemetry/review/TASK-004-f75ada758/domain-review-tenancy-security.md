## FIND-TASK-004-4 closure

The prior defect was a reachable integrity contradiction inside one tenant: promotion JSON could claim identity dimension `beta` for an unchanged object and SQL partition belonging to `alpha`, causing Iceberg equality pruning to omit accepted rows. It was not a demonstrated cross-tenant disclosure.

The producer remains `scribe/file_list_writer.rs::build_inserts`/`insert_artifact_set_fenced`: one fenced publication writes the SQL time/dimension columns and promotion JSON from the same `PhysicalPartition`. `vala-sql/src/queries/file_list.rs::PromotableHotFileRow` now projects granularity, start and dimension bytes through `HotFileCatalog::list_promotable` on `TenantConn`.

At `forge/scribe_promotion.rs:439`, `validate_durable_partition` decodes the SQL columns with `TimePartition::from_durable_columns` and `PhysicalPartition::from_dimension_bytes`, decodes the record's partition and compares the entire typed value. At line 550, `read_promotion_demand` applies it when `only` is present. The actual publication worker always reaches that branch: `revalidate_promotion` (line 950) rereads precisely its planned IDs using `Some(&planned)`, then checks the demand against the plan, reads/checks the object and only returns `DataFile`s after every validation. Deferring this comparison from scheduler planning to worker revalidation preserves the existing durable terminal-failure owner; it does not permit unchecked append. Existing object identity/checksum/footer/schema/spec/order/time checks remain.

The focused existing integration test `forge::promotion::scribe_promotion_integration_rejects_physical_datafile_mismatch_before_catalog_io` now drives same-type value substitution, literal-to-null, null-to-literal and time-position substitutions through the real scheduler/worker. `assert_mutation_is_refused_before_catalog_io` checks refusal, zero catalog commits, no object deletion and unchanged settlement; the intact composite fixture still promotes both objects. The new valid-value cases directly exercise the old omission, rather than relying on malformed JSON or unknown spec refusal.

**Disposition: CLOSED.** The guard belongs at this consumer because it joins independently persisted evidence immediately before unchanged-object promotion. Recomputing historical partitions from current definitions or scanning every row would be broader and unnecessary.
