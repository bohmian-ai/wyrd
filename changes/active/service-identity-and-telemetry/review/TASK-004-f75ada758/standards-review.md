## Material findings

### REPO-004-2 — SDK table versions expose wire strings instead of their required integer types

- Classification: **VIOLATION**, public-contract consequence.
- Rule: `architecture/bifrost-design.md:120–128` explicitly distinguishes canonical JSON strings from TypeScript SDK `bigint` and Python exact integers; approved revision 13 `spec.md:447–454` says the same. Root client/server and nested SDK rules require faithful typed projections.
- Producer-to-consumer proof: Rust `TableVersion::serialize` produces a decimal string. N-API `native/src/lib.rs:1225–1228` serializes the description to JSON. TS `wyrd/src/index.ts:7` aliases its public `TableDescription` directly to generated `BifrostTableDescription`; `:1457–1458` returns `lifecycleValue` unchanged. Generated `card-types.ts:5757` correctly declares the wire version as `string`. Python native `src/bifrost/mod.rs:949–960` also serializes the description unchanged; sync `_client.py:1036` and async `:1294–1296` only cast it, and the public typed dictionary declares `table_version: str` at `:1416`.
- Reachability/evidence: existing TS `tests/integration/table-time-column.test.ts:80` and Python `tests/integration/bifrost/test_table_time_column.py:91` explicitly expect `"1"`. These are ordinary public `describeTable`/`describe_table` callers. Values beyond 2^53 remain text rather than the promised SDK integer type; consumer integer operations/types violate the approved API even though the string itself is lossless.
- Smallest correction: retain canonical wire strings and the generated wire declaration. At the existing SDK response boundary, project the version directly to TS `bigint` and Python `int`; expose matching public description types and route both Python sync/async methods through that same projection. Preserve all other description fields, errors, and native writer/version binding. Do not alter the JSON contract, add aliases, or pass through JS `number`.
- Closure proof: language-owned boundary checks for 1, 9007199254740993 and 9223372036854775807 assert actual bigint/int values and exact values; update the existing public describe journeys and language type checks. No new server service or broad harness is needed.
