## Local material findings

### MNT-R3-1 — INCORRECT — Python Workflow selector failures claim DataCard validation

**Location:** `sdks/wyrd-sdk-python/src/state/mod.rs:2590–2620`, particularly new `PyWorkflowCards::load` UID parsing, exact-name parsing, and mixed/incomplete branch. Related source docs/stub projections and `tests/integration/cards/test_cards_crud.py:586–594` preserve the same wrong code.

**Reachable scenario:** `cards.workflow.load(space="workflow-loading", name="code-review")`, `load(uid=valid_uid, space="workflow-loading")`, a malformed UID, or an invalid named selector fails locally before any read. `load` calls `WyrdPyError::validation` directly or through `parse_space/name/version`. That helper is explicitly the DataCard helper: `crates/wyrd/wyrd-interfaces/src/error.rs:63–74` constructs `WyrdError::DataValidation`. The catalog at `crates/wyrd-spec/src/error.rs:1910–1922` supplies `WYRD_DATA_400_VALIDATION`, title `DataCard validation failed`, and remediation `Fix the DataCard schema, artifact, stats, or interface metadata.` The normal Python mapper preserves this catalog metadata. No DataCard schema or artifact participated in these failures.

**Rule and concrete consequence:** Revision 12 INV-007 and the SDK projection/error obligations require consistent stable error semantics; AGENTS §§4,8–9 and the error reference require operation/resource-appropriate actionable errors. Python callers branch on a Data-specific code for a Workflow selector request, while the TypeScript selector boundary uses the existing neutral `WyrdError::Validation`. The newly written Python error docs and journey assertions entrench that false contract, making later maintenance and agent remediation point to unrelated DataCard fields.

**Smallest correction:** use an existing appropriate derive-backed request/selector error at the Python Workflow boundary and neutral shared identity parsers, preserving the field/selector message and central metadata conversion. The catalog already contains `WyrdError::Validation` (`WYRD_SPEC_400_VALIDATION`, lines306–319), used by the equivalent TS parse boundary; a new error framework/catalog variant is unnecessary to fix this proven defect. Preserve errors returned by shared registered loading. Do not globally redefine the genuinely DataCard-specific `WyrdPyError::validation` helper used by Data interfaces.

Update source error documentation and source stubs, regenerate declarations, and correct the existing public Python journey assertions. Extend that existing test with malformed UID/space/name/version cases and verify the resulting code/title/remediation identifies the request fields and does not instruct the caller to repair DataCard metadata. Keep pre-read refusal and server permission/not-found errors intact. This is a contract defect, not a documentation preference.
