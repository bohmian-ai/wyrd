## Proposed findings

### BEH-R3-001 — INCORRECT — Python Workflow selector failures use a DataCard error owner

**Violated obligation:** Revision 12 REQ-054/INV-007 and its public client contract require the SDK to project existing stable error semantics. `architecture/wyrd-design.md` Client model says durable errors do not differ by language; error guidance requires relevant fields/resources and correct remediation. The catalog's DataValidation is specifically DataCard schema/artifact/stats/interface validation, not a generic boundary validation code.

**Location:** `sdks/wyrd-sdk-python/src/state/mod.rs:2591–2622`; shared parse helpers at `3051–3071`; producer `crates/wyrd/wyrd-interfaces/src/error.rs:64–76`; metadata `crates/wyrd-spec/src/error.rs:1909–1923`. Public TS equivalent is `native/src/workflow.rs:76–101`.

**Producer → consumer evidence:** Python `cards.workflow.load(uid=..., space=...)`, incomplete selector, invalid UID, invalid space/name or invalid version routes to `WyrdPyError::validation`. That helper constructs `WyrdError::DataValidation`; central exception projection preserves its catalog metadata. Consequently callers receive `WYRD_DATA_400_VALIDATION`, title “DataCard validation failed”, and remediation “Fix the DataCard schema, artifact, stats, or interface metadata.” No DataCard was read or validated. TS's equivalent invalid selector yields the existing generic `WyrdError::Validation`/`WYRD_SPEC_400_VALIDATION`. The committed Python journey now explicitly asserts DataValidation for versionless/mixed Workflow selectors; that assertion documents the defect rather than closing it. Shared Rust loading remains correct for typed exact selectors.

**Observable consequence:** a Python caller classifying errors is directed to the Data subsystem and an unrelated corrective action for a malformed Workflow selector. Correcting the user’s Workflow identity/selector is the actual remediation.

**Smallest testable correction:** use the existing generic catalog Validation at the selector/field-parsing boundary. Preserve the central Python mapper and DataCard-specific validation helper for actual DataCard validation; do not globally change its semantics or introduce another exception/code/validator. Correct mixed/incomplete/UID and field errors together, update source docs and regenerate declarations. Retain exact named/UID contracts and pre-read refusal. Extend the existing Python journey or nearest public selector test to assert code, title and remediation for at least mixed and malformed-field failures; prove no Cards request is issued before refusal. No runtime, graph or transport change is needed.
