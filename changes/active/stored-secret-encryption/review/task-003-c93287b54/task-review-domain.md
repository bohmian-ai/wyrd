## Proposed blocking finding

### DOMAIN-001 — VIOLATION: human renewal can lose an evaluated audit decision

- Requirement: REQ-008–009 retain owner audit behavior; AGENTS.md Audit requires each permission decision staged on the process Scribe outbox. Security posture § Audit integrity and privacy explicitly requires staging once the decision is known, outside the operation transaction.
- New location: `crates/wyrd/wyrd-server/src/components/admin/identity.rs:457–467`, calling `crates/wyrd/wyrd-auth/src/connections.rs:440`, then existing `begin_locked` at `:853–857`.
- Starting conditions/trigger: an authorized human-connection renewal reads and renews successfully; Postgres becomes unavailable or the pool times out before the second connection is acquired (or acquisition succeeds but the slot lock fails). This is a normal supported dependency-failure branch of this new operation.
- Expected: its allowed permission decision is already staged exactly once, regardless of whether persistence can begin; the operation fails without waiting on audit.
- Actual: `decide` calls `audit::authorize_recording_denial` (`audit/mod.rs:146`), which returns allowed decisions without staging. The route stages errors from `stage_renewal` only. Successful preparation passes the unrecorded event to `renew_encryption`; `begin_locked` stages only after connection acquisition and advisory lock succeed. A failure before that line propagates through the new handler without any staging. The new route also defers the known decision across remote KMS IO.
- Consequence: an evaluated resource-administration permission decision disappears from accountability during precisely the persistence failure being returned. This is not a ciphertext/state-corruption claim. Although the helper predates this task, this route newly exposes that failure path; no unrelated auth audit overhaul is requested.
- Smallest correction: have the new renewal flow stage the evaluated decision once when known using the existing process outbox, and prevent the later owner commit path from staging it again. Preserve denied/refused/success audit cardinality, nonblocking audit, permission behavior, and no transaction during KMS. Implementation may reuse or adjust the existing owning mechanism.
- Closure: focused real-Postgres owner/HTTP test with a recording outbox makes preparation succeed and persistence acquisition or lock fail, then asserts the stable store error, unchanged committed envelope, and one allowed decision. Also assert success and provider failure still produce one decision, and denial one denied decision. No new audit persistence mechanism is needed.
