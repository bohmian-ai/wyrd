## Producer-to-consumer and failure assessment

**Creation:** `TenantProvisioning::provision` builds the verified platform operator pair and forwards it through administration creation and `BuiltinTables::ensure_tenant`. SYSTEM provisioning has one SQL owner taking the explicit creator pair. Its insert uses the existing per-tenant partial unique index and `DO NOTHING`; the subsequent read returns the winner's identity, without rewriting its creator. The defining backfill, dev fixtures and callerless builtin reconciliation pass the sentinel pair. Bifrost `create_table_locked` holds the existing tenant/table advisory lock, checks an existing control/physical registration before writing, and passes creator only to the new control row. OLAP `upsert_table`'s conflict update excludes both creator columns. Service/Agent projection's conflict update also excludes them. Operator connection updates retain creation fields.

**Replay/concurrency:** Registration reserves within the existing registration transaction under the four-part unique constraint. Same-pair concurrency converges on the existing row and uses the existing request-hash conflict/replay path. Manual queue enqueue takes a transaction-scoped lock whose identity includes both principals and the key, then reads the same pair under TenantConn RLS. Its advisory hash does not include tenant; a cross-tenant hash coincidence can serialize unrelated requests, but cannot change the tenant-filtered replay result or violate the required identity semantics. This is not a correctness finding. Background schedule/observation deduplication remains keyed by binding and occurrence/source record; sharing SYSTEM does not collapse owners' bindings. Ordered binding locks/ordinal creation and queue lease fencing remain in their existing owners.

**Authority durability:** Manual acceptance copies the authenticated effective Principal and chain into AcceptedAuthority and removes the credential ID. RunAuthority derives the accepting pair from that snapshot; background acceptance resolves owner and active SYSTEM within the tenant transaction and stores the owner's recovered effective authority. INSERT writes pair and snapshot together. CLAIM returns those stored fields while changing execution/lease metadata; retry/settlement SQL never assigns pair or authority. `into_claimed` decodes the stored JSON directly. Eval constructs its protected judge Caller from the loaded snapshot, not a fresh subject lookup or the observation writer. Input reads retain SYSTEM's narrow table-UID grants while `SystemReadAuthority::serving` carries the accepted subject and history. Missing owner or SYSTEM prevents background acceptance; the observation sink now emits a binding-specific warning and continues healthy siblings.

**Ingest and retention:** Gate derives attribution from verified identity; ingress passes it through owned native/canonical decode context. Managed arrays stamp both non-null identity columns for Observation policy. Audit's None policy keeps the server-built payload pair instead of replacing it with the outbox sentinel; ordinary dynamic declarations still reject reserved names. Card and Run correlation checks remain separate. Claim sampling reads subject values; actor never becomes the stratum. Outbox coalescing compares the pair and hashes both values into the existing content-derived batch identity; peer capture carries the same pair. Persistence/replay retain already stamped rows rather than resolving identity again. This change does not promise stronger audit/outbox durability: acknowledged Scribe writes retain existing guarantees, and unacknowledged in-memory outbox loss remains logged/counted under the existing contract.
