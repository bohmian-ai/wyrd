## Material finding

### `SERVER-R2-1` — selected remote Oracle delivery loses all ingress deadline enforcement

- Classification: **REGRESSION / INCORRECT** (`FIND-TASK-003-R1-9` not fully closed).
- Violated obligation: After the generic HTTP timer hands off, the captured Oracle deadline must govern preparation and first-batch waiting and preserve typed timeout/cancellation; role-separated forwarding cannot hold an HTTP concurrency slot indefinitely.
- Exact path: `query/service.rs:268–271` cancels the edge timer. `oracle/forwarding.rs:148–153` captures the deadline; `:187–206` selects the remote route. `connect_before_delivery` at `:465–484` bounds only connection attempts. `route_remote_once` at `:504–509` awaits `deliver(...)` without the captured deadline; `forward_remote` at `:299–317` can await peer credential refresh and then `OraclePeerServiceClient::forward_query` with no local deadline or tonic request timeout. `edge_timeout.rs:122–128` awaits the response without any timer after handoff.
- Reachability/consequence: A gateway with no local Oracle selects a ready remote lease. If a connected peer accepts the RPC but stalls before response headers (or token refresh stalls), the request can remain pending past both the configured edge timeout and the public query deadline; the client receives neither the typed `WYRD_VALA_504_QUERY_TIMEOUT` nor a terminal response, and the protected concurrency permit remains occupied. The former generic edge timeout would at least terminate this pre-header wait. The current successful journey selects the in-process local Oracle, so it cannot disprove this path.
- Testable correction: Reuse the already captured monotonic deadline in `ReadyOracleForwarder` to bound the **selected remote delivery future**, including credential acquisition and the initial `forward_query` response, mapping expiry to `BifrostError::QueryTimeout`. Keep the existing connect-before-delivery selection, signed absolute deadline, exactly-once delivery/no retry, and remote cancellation-on-drop semantics. Do not restore the generic edge timer or add a new public deadline. A focused test should select one connected peer whose delivery future never returns, advance beyond a short query deadline, and assert typed timeout plus dropped delivery; an HTTP role-separated test should verify the protected request settles and releases its slot. The local preparation journey remains the positive control.
