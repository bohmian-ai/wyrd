### `FIND-TASK-003-R2-2` — CONFIRMED — VIOLATION: new edge service lacks mandatory rustdoc

- **Source:** `STD-R2-1`. **Obligation:** `AGENTS.md` §16 and `architecture/agent-rules.md` make intent/workflow rustdoc mandatory on every new Rust item, including associated types, and `# Errors` mandatory on fallible methods.
- **Exact location and reachability:** `crates/wyrd/wyrd-server/src/http/middleware/edge_timeout.rs:59-103`. `Layer::Service` and `Service::{Response, Error, Future}` are undocumented. `poll_ready` can propagate wrapped readiness failure and `call` can resolve to wrapped failure or `Elapsed`, but neither rustdoc block names errors. `apply_protected_edge` constructs this layer for protected routes, so this is production code, not a dormant helper.
- **Consequence:** the candidate violates an explicit hard completion rule despite compiling and passing runtime checks.
- **Smallest correction:** add concise rustdoc on those four associated types describing their edge-stack roles; add `# Errors` to `poll_ready` and `call` for propagated inner failure and, for `call`, generic edge expiry. Keep the service behavior unchanged; no checker or abstraction is warranted.
- **Focused closure proof:** direct source audit of those items, then `mise run fmt` and `mise run lints` on the corrected tree.

### `FIND-TASK-003-R2-3` — REVISED — REGRESSION: selected remote query delivery has no captured-deadline bound

- **Source:** `SERVER-R2-1`. **Obligation:** specification's one original public query deadline and typed timeout/terminal contract, `architecture/bifrost-design.md` query/forwarding boundary, and R2 `FIND-TASK-003-R1-9`: after protected-edge handoff, Oracle's captured deadline governs preparation and first-batch wait without leaving a protected request pending forever.
- **Exact path and reachability:** `crates/wyrd/wyrd-server/src/query/service.rs:257-279` hands off before `state.bifrost.query_sql`; Gate dispatches through its attached `ReadyOracleForwarder` (`gate/mod.rs:591-620`, `boot/mod.rs:1054-1082`). On a forwarding-only ingress, `oracle/forwarding.rs:136-207` captures the deadline and selects remote candidates. `connect_before_delivery` (`:465-486`) bounds only dialing. `route_remote_once` (`:488-509`) awaits selected delivery indefinitely. `forward_remote` (`:293-318`) awaits `credentials.bearer(false)` and `client.forward_query` before response headers, without a local timeout. `EdgeTimeout::call` (`http/middleware/edge_timeout.rs:98-129`) stops racing after handoff. The existing server test covers only an in-process local Oracle; the role-separated journey at `wyrd-testing/tests/bifrost/server/query.rs:755-780` proves the remote route is production-reachable, but not its silent-peer timeout.
- **Consequence:** a connected selected peer that does not return response headers, or a stalled credential refresh, can occupy the HTTP concurrency slot past the edge and query deadlines without a typed `WYRD_VALA_504_QUERY_TIMEOUT`. The old generic edge bounded this pre-header phase, so removing it exposes a regression. The peer's timeout after headers is a different body-stream boundary and is not claimed here.
- **Smallest correction:** reuse the already captured monotonic deadline at the existing `route_remote_once` owner to bound the selected `deliver` future, including credential acquisition and initial tonic response, mapping local expiry to `BifrostError::QueryTimeout`. Preserve the pre-delivery connect selection, signed absolute deadline, one selected envelope/no retry, peer error mapping, and cancellation by dropping the in-flight future. Do not re-arm the generic HTTP timer, add a public deadline/configuration, or alter terminal-body behavior in this correction.
- **Focused closure proof:** a deterministic forwarding test selects a connected peer whose delivery never resolves, advances a short request deadline, and asserts typed timeout, future drop, and no successor delivery. Extend an existing role-separated server journey or equivalent real HTTP/peer path to show a selected silent remote query settles and releases the protected request slot; retain the local preparation-beyond-edge and ordinary-route edge tests as controls. Run exact named tests, the owning Bifrost server journey lane, `mise run fmt`, and `mise run lints` on the final tree.
