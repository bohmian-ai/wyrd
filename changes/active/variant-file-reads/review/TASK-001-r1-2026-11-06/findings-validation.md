## Final deduplicated ledger

### FIND-TASK-001-1 — REVISED / VIOLATION — retained computed memory lacks query accounting

Discovery: `INV-001`; system/domain comments about eager allocation share this cause and create no additional findings.

**Obligation and exact boundary.** TASK-001 explicitly requires temporary query allocations to remain governed/releasable; Bifrost Resource and failure invariants require bounded Wyrd buffers and hard-bounded Oracle memory. Locations: `scribe/memtable.rs::LiveCapture::read` (1990–2023), `ReadableSource::project` (2293–2310) and `AdaptedRequirements::evaluate` (2573–2623), through `tail_rpc.rs::open_capture` and `follower.rs::live_leaf`.

**Independent producer/consumer proof.** Ordinary `SELECT value + 1 ...` is absorbed by the live leaf, encoded, parsed and forwarded to the retained capture. `project` evaluates every in-range batch and appends the newly allocated results to one vector before returning. Arithmetic creates fresh arrays; a partial exact filter can copy closure arrays and logical fallback can allocate reconstructed arrays. `read` returns only `Arc::clone(&source.charge)`. `RetainedArrowCharge` in `scribe/memory.rs:353–385` holds the original retired-generation lease set once; it does not grow for query outputs. `MemtableSource` retains these original charges across rewrites/open streams but never receives a separate charge for new outputs. The session pool cannot account Arrow allocations automatically: existing `OracleQueryMemoryReservation` explicitly registers a MemoryConsumer and calls `try_grow` (`resources.rs:3951–3991`); no corresponding registration exists along this new path.

**Material consequence.** A supported computed query now retains output proportional to the entire captured partition before streaming, whereas baseline canonical projection shares source arrays and computes outputs on pull. Several concurrent accepted queries can exceed their recorded grant without corresponding pool usage. Holding original source charges and later observing zero after cancellation do not govern the new allocations. This is an explicit budget failure, not a request to improve arbitrary Arrow allocation instrumentation.

**Selected minimal correction and burden.** Reuse the admitted follower session's existing query pool/reservation mechanism at the shared memory-read owner, carry query-allocation ownership separately from immutable-generation charges through returned batches, source clones/rewrites and open streams, and release on partial failure/drop/cancellation. Account the additional retained materialization incrementally rather than after the entire capture is evaluated; growth beyond the existing grant must refuse without publishing the retained cohort. Bound current-batch evaluation/fallback workspace within that existing execution budget. Do not create a new resource root, change generation-charge meaning, charge shared source buffers again, or charge only leader delivery. This is a moderate cross-owner correction because the current private read/request/result path lacks the pool and query-allocation owner; threading them through the existing path is necessary. No generic allocator interception or new resource framework is authorized. Smaller fixes that merely increment a metric or clone source charges cannot govern the actual retained bytes.

**Focused closure proof.** Extend existing memory/follower owner tests with a bounded query pool and multiple captured computed-output batches whose aggregate exceeds its grant: typed resource refusal, no retained partial provider and no reservation residue. A fitting computed/filtering read must account additional buffers and release them on plan/stream drop while original generation charges remain until their final holder drops. Keep existing cancellation/retirement semantics. The discovery proposal's larger generic allocation problem is narrowed to this newly introduced query-retention boundary; no unrelated ingestion/accounting project is required.

### FIND-TASK-001-2 — CONFIRMED / REGRESSION — absorbed scalar outputs lose execution values

**Independent proof.** Pinned DataFusion `5f4b171` `core/src/physical_planner.rs:355–402` wraps the main plan in ScalarSubqueryExec sharing runtime results with its expressions. `LiveUnionBoundary::optimize` moves computed projections through a live union and the live leaf absorbs them without excluding scalar outputs. A nonempty `SELECT id, (SELECT max(id) FROM table) AS m FROM table` therefore reaches `resolved` with a populated runtime scalar in `self.projection`. This is a small local extension of the existing predicate snapshot mechanism; no new codec, scalar coordinator, follower exception or unsupported-expression framework is needed. Rejecting all projection absorption would destroy the approved leaf-read benefit and is not an acceptable simplification.

**Focused closure proof.** Extend the existing scalar snapshot owner test with no-WHERE scalar output and a scalar nested in a computed output.
