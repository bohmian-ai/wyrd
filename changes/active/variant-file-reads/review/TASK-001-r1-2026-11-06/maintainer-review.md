## Existing-owner and deletion check

The strongest apparent alternative is leaving filtering/projection entirely in `MemtableSource` or ordinary operators above it. That source receives already logical batches: in the baseline, `ReadableSource::project` reconstructed required Variant roots before those operators could evaluate their paths. Reusing that later stage alone therefore cannot meet the task's no-unrelated-reconstruction outcome. The candidate adds adaptation at the existing physical-generation boundary and still uses the existing memory source afterward. Its filter/projection execution is required at this earlier boundary; it is not a duplicate capture, lease, partitioning or reader workflow.

For files, the existing `hot_parquet_scan` and DataFusion operators already suffice, and the candidate uses them. For requirement authentication/schema derivation, the existing follower and codec suffice, and the candidate extends them. For the union projection gap, the existing installed boundary and DataFusion `ProjectionPushdown` suffice, and the candidate composes those mechanisms. I found no added abstraction whose safe deletion would preserve all of the assigned behavior.
