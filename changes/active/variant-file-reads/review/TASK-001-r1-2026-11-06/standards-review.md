## Proposed findings

### RSR-001 — VIOLATION: test observation adds an unconditional execution API

- **Location:** `crates/vala/vala-bifrost-redux/src/oracle/codec.rs:107`, `:124`, `:177`, `:366`; `oracle/follower.rs:207`.
- **Authority:** RU Types: “pub(crate) by default; pub only for the intended surface”; W final diff audit requires public-contract effects unchanged unless approved; approved spec Scope forbids a public execution API and original task forbids a new public API.
- **Evidence:** Previously crate-private payload and parser are now `pub`; the new `RemoteScanOutputs` and every expression-bearing field are `pub`, and `RemoteSourcePlaceholderExec::with_requirements` is public. `lib.rs` exports `oracle`, which exports `codec` and `follower`, so normal downstream Rust code can decode/manipulate the private expression payload. `FollowerSourceResolver::resolve` now exposes it in its public signature. The only out-of-crate parser consumer is the changed cross-crate journey at `peer_network/live_subquery.rs:212`. The task explicitly says preflight visibility was widened for that test. In contrast, the nearby execution observation re-exports in `oracle/mod.rs` and the new reconstruction counter are gated by `test-support`.
- **Consequence/materiality:** Consumers acquire an unconditional parser and expression-requirement contract for the private execution envelope. This expands the supported Rust execution surface solely to inspect a test, violating an explicit approved boundary even though the SDK query wire surface is unchanged. This is not an assertion that the accessor bypasses authentication in the production request path.
- **Smallest correction:** Keep production payload parsing/construction and the resolver seam at their needed internal visibility; expose any cross-crate observation only through the existing test-support surface. Preserve the same production authenticated requirement flow and both literal assertions. Narrow the resolver surface if necessary rather than publishing the private payload merely to satisfy its signature. No new protocol, feature or SDK surface is needed.
- **Closure proof:** Static visibility/caller review in normal and test-support configurations plus existing compile/lint and exact scalar-subquery journey; confirm normal consumers cannot call the new private parser/requirement API.

### RSR-002 — VIOLATION: changed-item rustdoc gate is incomplete

- **Locations:** `scribe/memtable.rs:2359` (`logical_column`) and `:2537` (`AdaptedRequirements::evaluate`); `wyrd-testing/tests/bifrost/oracle/distributed.rs:1252` (`prove_variant_memory_answers`); `oracle/follower.rs:468` (`live_leaf` docs).
- **Authority:** Root Code and RU Rustdoc explicitly require every changed/new item to document invariants and `# Panics` when it can panic; mandatory rustdoc is not waived by review materiality. Documentation must describe the changed workflow accurately.
- **Evidence:** `logical_column` indexes `projection[column]`, `physical.column(column)` and source schema fields without documenting their alignment/range invariant under Panics. `evaluate` indexes a restored batch using output `Column` indices and calls `expect("restored just above")` at line 2616; its documentation has Errors but no Panics/invariant section. New `prove_variant_memory_answers` indexes first/last documents and rendered cells without documenting that its fixture is nonempty and has the expected row shape. `live_leaf` still promises memtable rows and empty leaves at the closure schema and exact append bounds, although the changed code builds `output_schema` leaves and receives projected/inexact statistics after exact filtering.
- **Consequence/materiality:** Maintainers are not told the new internal range/schema invariants they must preserve, and the central changed source-building description promises a schema/statistics contract the new code no longer uses. This is the explicit mandatory changed-item documentation gate, not a request to add defensive runtime machinery.
- **Smallest correction:** Document the real panic invariants (or remove invariant panics through an equally small existing-state expression), and update `live_leaf` to explain output schema and projected/inexact filtered statistics. Keep this bounded with the same remediation; do not add guards, new helpers or tests solely for docs.
- **Closure proof:** Source-level check of these items and targeted rustdoc/lint verification; no new behavioral suite required by this finding.
