## Proposed finding SYS-001

Classification: **REGRESSION / INCORRECT**. Location: `crates/vala/vala-bifrost-redux/src/oracle/live.rs::LiveScribeExec::resolved` (especially lines 459-466), together with new projection absorption at lines 585-603 and fragment projection encoding at lines 489-501.

**Obligation.** TASK-001 requires logical results and complete unsupported-expression fallback to remain exact while extending the common requirement path. REQ-001 requires valid ordered outputs to reach the owner; preserving supported scalar-subquery queries is a concrete regression boundary, not a request for new SQL support.

**Reachable failure.** Query a nonempty live table with `SELECT id, (SELECT max(id) FROM <table>) AS m FROM <table>`. The pinned physical planner (`datafusion/core/src/physical_planner.rs:355-402`, revision `5f4b171`) places a `ScalarSubqueryExec` around the entire main plan, with shared results referenced by its projection expression. The candidate's `LiveUnionBoundary::optimize` moves the main computed projection through the live-containing union, and `LiveScribeExec::try_swapping_with_projection` absorbs its scalar expression without rejecting it. The coordinator successfully computes the scalar before polling the live input.

`resolved` snapshots only `self.predicate`. With no predicate it returns immediately, leaving `self.projection` unchanged; with a predicate it likewise leaves outputs unchanged. `fragment`/codec then encode those outputs directly. Pinned `physical-expr/src/scalar_subquery.rs:186-214::try_to_proto` explicitly discards runtime `results` and serializes the scalar's index, type and metadata. It does not serialize the populated value. Follower `signed_requirements` (follower.rs:145-180) parses this expression without an enclosing scalar coordinator/results context. Pinned proto `physical_plan/from_proto.rs:354-361` explicitly refuses a `ScalarSubqueryExpr` outside a surrounding `ScalarSubqueryExec`.

The resulting observable behavior is query execution failure before tail IO, even though the scalar is valid and already computed. Both in-process mixed and remote Scribe topologies consume this same payload/parser. The baseline leaves this scalar output in the leader's ProjectionExec, where it reads the populated results correctly. Existing two-row scalar-output refusal journeys do not catch this: their expected failure still happens.

**Failure scope and recovery.** `signed_requirements` returns a redacted resolution fault; `scribe_start_error` maps it to terminal dispatch, and the leader fails the affected query. It does not kill the shared server or stop sibling capabilities. Restarting the same build cannot recover this query shape; correcting output materialization can. No durable corruption or source-authority widening occurs.

**Smallest correction.** At the existing execution snapshot owner (`LiveScribeExec::resolved`), snapshot every absorbed output expression through the existing recursive `snapshot_physical_expr` before constructing the fragment, including the no-predicate path. Keep aliases/order/schema and keep the original plan's runtime-bound expressions for later executions, just as predicates already do. A pending output must fail before dispatch. This needs no new protocol, planner, public API, wrapper, or follower trust exception. Rejecting unsupported projection absorption and retaining the existing leader projection is also semantically safe, but must preserve the approved covered Variant projection behavior; snapshotting the already-populated scalar uses the existing owner/mechanism directly.

**Focused proof.** Extend the existing live scalar/query owner with a successful nonempty live scalar output, including a scalar nested inside a computed output and the no-WHERE case. Assert correct repeated value and logical output schema through the SDK in both already-supported topologies, and inspect that the signed output payload carries a literal rather than a runtime scalar index. A focused owner test should reset/repopulate the shared result and resolve the same immutable plan twice, proving outputs snapshot each execution rather than freezing the first result. Preserve the existing two-row refusal and predicate tests. Static source proof establishes the defect; no reproduction was run during this review.
