## Proposed blocking findings (require fresh validation)

### SYS-1 — INCORRECT: invalid Score confidence/probabilities become accepted judgments

- Authority: REQ-010 explicitly sends nonfinite numbers and values outside the selected provider's native contract through the existing check-validation-error path; REQ-012 retains selected native confidence/probabilities as evidence. Jev's owned response contract documents Score confidence `0..1` (`skald-spec/src/wire/jev.rs:123–129`). Probability values have the same unit-interval interpretation already enforced for Choice (`transform.rs:91–95`).
- Exact owner: `crates/vala/vala-verify/src/blocks/transform.rs:110–114` destructures `JevAnswer::Score { score, .. }`; `grade:216–248` only validates `score`. The optional confidence and probabilities are ignored before `serde_json::to_value(answer)` at122 captures them.
- Supported trigger: a declared three-level Score question, policy `greater_than_or_equals: 2`, native JSON answer `{type: score, score: 2, legend: {"0":"low","1":"mid","2":"high"}, confidence: 1.5}`. Alternatively supply valid confidence and a probability below0 or above1. Optional metadata is supported and is deliberately retained by this task.
- Expected: only this requirement becomes inconclusive with an explicit unusable-answer reason through `BlockError::Terminal`; no pass is accepted and no extra model invocation occurs.
- Actual: native f64 deserialization accepts1.5; existing Jev provider (`clients/jev.rs:95–111`) and gateway typed response (`adapter/mod.rs:434–452`) do not impose numeric semantic validation. Transformer passes score2 to `evaluate_operator`, yields Passed and retains invalid metadata as actual. Typed nonfinite metadata is likewise unchecked. Existing malformed tests cover only invalid score itself, and the nonfinite owner case at `transform.rs:515–525` covers only Noul.
- Consequence: an unusable native answer can produce an accepted successful verification, contrary to an explicit refusal boundary. Confidence must remain evidence and must not change a valid policy's judgment, but malformed confidence is still invalid data.
- Smallest correction: validate present Score confidence/probability values at the existing selected-answer transformer owner, reusing the unit predicate. Preserve absent optional fields and all valid low-confidence judgments. Add a small owner table for valid/invalid/absent metadata and a representative hosted malformed answer proving the error path/call count. No provider transport, schemas, SDK API, or storage redesign is required.
