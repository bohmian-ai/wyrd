A judge sees an apparently complete empty search and may stop looking despite missing evidence.

This is a narrow traversal/control-flow reproduction, not a full tool integration run. Smallest correction: propagate the existing traversal-cut bit through the evidence search result at the workspace owner. ### INV-2 — VIOLATION: input evidence units outlive their process-memory charge

Authority: REQ-020 requires existing resource limits; REQ-019 applies existing admitted resources. The approved workspace design's provenance section explicitly requires shared backing and existing memory charges, and Wyrd's hosted resource authority requires materialized retained memory to remain counted while in use.

Location: `crates/wyrd/wyrd-server/src/verification/hosted/workspace.rs:1744–1760`, `:1768–1778`, callers `read_evidence` at `:1463` and `search_evidence` at `:1638`.

Starting state/trigger: a mounted text/JSON source fits the memory ledger; one or several allowed concurrent `fs.read`/`fs.search` evidence requests materialize its units. This uses ordinary supported inputs and tool concurrency, not synthetic host load.

Expected: materialized canonical unit text/coordinates remain admitted while the caller reads/matches/serializes them; insufficient capacity uses the existing busy-stop path. Actual: `units_of` charges only source byte length in local `_held`, constructs an independently allocated `Arc<[Unit]>`, and returns that Arc while dropping `_held`. Both selected JSON and ordinary text/JSON branches have this shape. The returned units contain owned strings and Citation/locator data. `read_evidence` and `search_evidence` hold those units during iteration after their only memory charge has returned; `Invocation::blocking` adds only a CPU/permit guard, not a memory charge. No-match searches issue no reference, so reference charging does not cover any of this state. Concurrent requests can therefore each be admitted against already-returned capacity while prior full unit collections remain live. Short-line inputs further expand per-unit structural memory beyond original bytes.

Proof: direct ownership/lifetime trace through the exact return statements and callers, contrasted with the registered `/work` branch's retained `ExtractedView._memory`. Existing full-ledger test checks refusal while reading a file, and reference-memory tests check retained citation entries; neither asserts input unit memory remains charged after `units_of` returns. This is a structural resource-invariant defect, not a claim that a test failed or that an OOM was observed.

Smallest correction: keep the transient input-unit allocation under the existing ByteLedger for its actual consumer lifetime, using the workspace's existing memory admission and busy mechanism. No new quota/registry/pool is needed. Add a focused owner test holding a returned input view and checking that memory remains charged until that view is dropped, plus a capacity-refusal assertion covering the admitted units rather than only the initial byte read. Preserve selected-value visibility and exact coordinates.
