## Final deduplicated finding ledger

### FIND-TASK-001-2 — Principal CardRef declarations misdescribe SDK results

- **Discovery source:** MNT-001. **Status:** REVISED. **Classification:** INCORRECT public client typing.
- **Violated obligation:** Task's consistent typed Rust/Python/TypeScript principal results and `AGENTS.md` §8 generated declaration parity.
- **Location and producer-to-consumer path:** `crates/wyrd-spec/src/auth/tenant_principals.rs::PrincipalSummary.card_ref` serializes a structured `CardRef`; shared `Principals::list` returns it; Python `sdks/wyrd-sdk-python/src/principals.rs::list` passes it through `operators::to_python` into a dictionary while `python/wyrd/stubs/principals.pyi` describes `dict[str,str]`; TypeScript `wyrd/src/index.ts::PrincipalSummary` describes a loose record though `CardRef` is already imported.
- **Observable consequence:** TypeScript accepts missing or arbitrary CardRef keys; Python typing asserts every value is a string although the wire can contain null UID, and neither declaration accurately guides use of discovered Card identity.
- **Smallest safe correction:** Reuse `CardRef` in the TypeScript result. Give the Python stub source a precise typed mapping for the actual dictionary with required identity fields and optional/null fields, then regenerate public `.pyi`; do not claim the runtime returns Python's `CardRef` class or hand-edit generated output. No serialization or server behavior changes are required.
- **Focused closure proof:** A typed client check that reads the required CardRef fields from a discovered Card-bound principal in both SDKs, plus `mise run py:typecheck`, the owning TypeScript typecheck, and `mise run codegen:check`.
