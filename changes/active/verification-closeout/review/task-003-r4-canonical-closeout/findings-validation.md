## Final deduplicated finding ledger

### FIND-TASK-003-1 — INCORRECT — support-desk deployment checks only model name

**Source:** BEH-001. **Obligation:** Spec R4 decision 14 and REQ-010 require `deploy` to verify the Prompt model deployment and name the missing model with remediation. **Locations:** `examples/support-desk/python/support_desk.py:91-93`, `examples/support-desk/rust/support_desk.rs:122-132`, `examples/support-desk/typescript/support-desk.ts:77-80`. **Producer to consumer:** The checked-in Prompt declares `open_ai_chat_completion/gpt-4o`; `skald-workflow::gateway_model` projects that to gateway `openai/gpt-4o`; `Gateway.deployments()` returns typed provider/model identities; each example discards provider and compares only `gpt-4o`; `Run::invoke` later uses the exact pair. All three public example callers and their corresponding SDK journeys reach `deploy`. The existing gateway identity and deployment list already solve the lookup; no new helper or contract is earned. **Consequence:** a same-name deployment under another provider gives false deployment success and invocation then fails; an absent deployment message omits the configuration action. **Correction:** in each example compare the exact gateway provider/model identity of this Prompt with each deployment, and make the existing missing-model refusal name that identity and the action to configure it. Preserve registration, capture policy, and existing error type. **Closure proof:** focused cross-provider collision and absent-deployment checks in the narrowest existing example or SDK journey surface; retain the three language happy-path journeys. No extra deployment options or model-capability policy is required by this finding.

### FIND-TASK-003-2 — REGRESSION — Oracle drain waits on other roles' memory

**Source:** INV-1. **Obligation:** selected-role shutdown must finish against its own residual state within the process deadline while preserving the shared capacity limit. **Locations:** `crates/vala/vala-bifrost-redux/src/oracle/admission.rs:737-771`, `resources.rs:1740-1758`, `crates/wyrd/wyrd-server/src/state.rs:684-700,1948-2008`. **Producer to consumer:** Oracle, Forge, and Scribe follower reservations charge the existing `MemoryHolder` ledger and one shared pool. `shared_memory_reserved` sums every holder. Oracle admission reads it as its own completion predicate and residual report; `Oracle::shutdown_owner` rejects that nonzero report; `Bifrost::shutdown` aborts selected owners, including Scribe, before their ordered drain. This is reachable on a mixed-role pod with an Oracle query drained and another role legitimately holding memory. The resource governor already publishes exact `oracle_memory_used_bytes` in `ResourceSnapshot`; no second governor is justified. **Consequence:** Oracle consumes the common deadline and can block Scribe shutdown because of bytes Oracle does not own. **Correction:** use existing Oracle-holder accounting for Oracle completion and residual reporting while retaining both pre-enabled wakeups and the process-wide capacity governor; preserve the delayed Oracle-child release check. Do not silence a real Oracle residual or move sibling memory into Oracle ownership. **Closure proof:** a mixed-role shutdown with live non-Oracle bytes completes Oracle drain, plus the delayed Oracle-child-memory release case still waits and reports accurately. A separate global-memory drain, if needed by the process, belongs to its existing process/storage owner, not Oracle's report.

### FIND-TASK-003-7 — REGRESSION — panic restart treats detached work as stopped

**Source:** DATA-1. **Obligation:** Forge fast self-reclaim of an unexpired attempt is safe only after the preceding incarnation's physical plan and heartbeat work has ended. **Locations:** `crates/wyrd/wyrd-server/src/app/supervise.rs:119-180`, `crates/vala/vala-bifrost-redux/src/forge/worker.rs:2148-2191,2427-2470,6140-6177,8319-8350`, `crates/vala/vala-sql/src/queries/forge_tasks.rs:890-900`. **Producer to consumer:** a panic skips `run_event_loop`'s `join_spawned`; the unretained plan task and heartbeat detach on pool drop; supervisor rebuilds with the same owner; startup passes that owner into `reclaim_expired_attempts`; SQL clears an unexpired attempt while the original work may remain live. The exact task-attempt checks on later SQL transitions and the table lease protect some publication paths, but `commit_rewrite` checks the lease rather than the cleared task attempt; clearing the row cannot establish physical quiescence. The only startup caller passes `Some(self.owner)`; periodic reclaim passes `None`, so the correction must preserve both paths. **Consequence:** overlapping old and replacement work under one durable owner can continue after the replacement is ready, including a stale attempt reaching the catalog publication boundary. **Correction:** make unexpired self-reclaim conditional on the prior worker incarnation's plan runners and heartbeats actually having stopped. Reuse the worker's existing stop token, attempt pool, and join ownership; if a panic leaves that proof unavailable, retain ordinary lease-expiry and table-fence recovery instead of using same-owner identity as proof. Preserve fast reclaim after a normally joined loop, existing exact-attempt SQL transitions, and sibling server availability. **Closure proof:** a focused supervisor restart with a plan held in flight across a worker panic proves the successor does not reclaim it before physical quiescence or lease expiry, and an orderly stopped worker still reclaims its old unexpired attempt. Do not add a new persistent fence or change the shared worker restart policy merely to satisfy this proof.
