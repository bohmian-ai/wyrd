## Proposed finding

**SYS-001 — MISSING required late-Scribe recovery proof.** The task's Scenario 5 RED and acceptance criterion require an Oracle-only pod to stage an outbox write while no Scribe is registered, then discover a later Scribe and deliver that same write through shutdown. `wyrd-testing/tests/bifrost/server/query.rs:764-810` creates the complete role-separated cluster with `start_spec`, then creates a table and performs the audited query only after cluster startup returns. Thus the Scribe is already started before this audit is staged. The test proves a boot-before ordering and peer delivery during drain, but it never holds a pending outbox slice across Scribe absence and late membership arrival. `verification_runtime.rs:61-155` likewise starts the whole cluster before staging its result. The reachable recovery path in `ScribePeers::channel` depends on a snapshot that changes from zero Scribes to one; these tests do not exercise that transition with pending work. An implementation regression that drops a slice while the peer roster is empty could leave the stated journeys green and lose audit or result evidence during rolling start. **Correction:** use the existing delayed-last-node cluster fixture to keep the Scribe offline, stage one audit decision on the Oracle-only process, verify it remains pending, start the Scribe, then drain the Oracle and read that decision from `vala.system.audit_log`. Keep the production route and accepted in-memory loss window unchanged. This is a proof gap, not an independently observed production failure.
