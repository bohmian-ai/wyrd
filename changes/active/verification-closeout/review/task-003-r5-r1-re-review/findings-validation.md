## Final deduplicated ledger

### FIND-TASK-003-2 — INCORRECT — Oracle shutdown misses its own infallible bytes

**Sources:** SYS-R1-001, DDATA-R2-1, follow-up. **Obligation:** Oracle drain reports and awaits its own query memory, including a child reservation after the admission slot returns, without waiting for other roles. **Location:** `crates/vala/vala-bifrost-redux/src/oracle/admission.rs:739-790`; producer `src/resources.rs:2678-2711`. **Consequence:** when the shared cap or query grant leaves no governed room, an Oracle child can hold only infallible headroom while shutdown sees zero Oracle bytes and proceeds to later process teardown. The current admission test holds governed Oracle bytes and cannot catch this. **Correction:** extend the existing resource governor's Oracle-holder attribution to include Oracle infallible headroom, then use that exact figure for Oracle's shutdown predicate and residual report. Retain the global cap, both armed wakeups, and exclusion of Forge/Scribe headroom. The existing governor is the writer and source of truth; a separate Oracle counter or a consumer-side sum of global headroom would duplicate or misattribute it. **Focused proof:** hold an Oracle child with headroom-only growth after its slot drops, keep Forge memory live, observe nonzero Oracle residual/wait, release the child, and observe clean Oracle completion while Forge memory remains.

### FIND-TASK-003-7 — REGRESSION — startup recovery can self-reclaim before its old work stops

**Sources:** INV-R1-1, SYS-R1-002, DDATA-R2-2, follow-up. **Obligation:** unexpired same-owner Forge reclaim is permitted only after the previous incarnation's plan and heartbeat work has physically quiesced. **Location:** `crates/vala/vala-bifrost-redux/src/forge/worker.rs:2166-2266`; consumer `crates/vala/vala-sql/src/queries/forge_tasks.rs:883-903`. **Consequence:** a startup panic or abort after spawning a recovery plan/heartbeat leaves the shared flag true and the child detached; the supervisor's same-owner restart can clear that unexpired attempt and overlap old work. SQL attempt and table fences constrain eventual writes but do not prove quiescence. **Correction:** use the existing shared quiescence flag and child cancellation ownership across the entire worker invocation, including startup recovery. Preserve the predecessor's state long enough to choose the initial reclaim policy before marking this incarnation active. Mark joined only after all work this invocation spawned has stopped; after an interrupted startup, rely on ordinary lease expiry. Retain fast reclaim after a proven joined predecessor, periodic expiry reclaim, and API availability. No persistent fence or supervisor change is needed. **Focused proof:** interrupt startup recovery with a live plan or heartbeat, then prove the successor does not self-reclaim that unexpired attempt, while a clean joined restart still fast-reclaims.
