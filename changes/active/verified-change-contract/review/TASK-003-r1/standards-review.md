## Material Findings

### Important

- **STD-003-001 — SECURITY / CORRECTNESS — credential lookup becomes ambiguous after relaxing name uniqueness.**
  **Violated rule:** `architecture/wyrd-security-posture.md` requires credentials to bind to the verified exact principal and security uncertainty to fail closed; `AGENTS.md` §9 requires tenant/authz preservation.
  **Location:** `crates/wyrd/wyrd-sql/migrations/20260601000027_verification_bindings.sql:19-29`; existing affected consumer `crates/wyrd/wyrd-sql/src/queries/auth/service_accounts.rs:11-39,175-200`; credential callers `crates/wyrd/wyrd-auth/src/issue_api_key.rs:92-99`, `jwt_bearer.rs:149-158`, and `exchange_api_key.rs:350-364`.
  **Evidence:** the existing query's own invariant comment says `UNIQUE (data_tenant_id, name)` is what bounds JSON containment to one principal and explicitly warns that relaxing it makes credential issuance match multiple rows. The candidate drops that constraint for every Card-bound principal. Because `CardRef.space` is optional, two same-kind/name/version Cards in different spaces both satisfy `card_ref @> $3` when the request omits space; `ORDER BY created_at, id LIMIT 1` then selects the oldest, not the requested effective Card.
  **Consequence:** API-key issuance, workload `jwt-bearer`, or delegation can resolve and mint authority for the wrong same-tenant Card-bound principal instead of failing closed.
  **Testable correction:** replace containment-plus-fallback selection with an exact, unambiguous lookup over the projected relational identity (`principal_kind`, kind, name, version, and resolved space/UID). Resolve omitted space according to the authoritative CardRef context or reject ambiguity; never choose one of several matches. Add a Postgres/auth regression with two same-name/version Cards in different spaces showing that each exact ref resolves its own principal and an unresolved ambiguous ref is refused.

- **STD-003-002 — ARCHITECTURE — new binding workflows have no owning concrete struct.**
  **Violated rule:** `AGENTS.md` §5 and `architecture/agent-rules.md` make struct-centered Rust a hard acceptance criterion: dependency-backed, multi-step workflows must be inherent methods on a cohesive concrete owner; existing functional drift is not precedent.
  **Location:** `crates/wyrd/wyrd-server/src/components/cards/service.rs:1126-1190`; `crates/wyrd/wyrd-sql/src/queries/verification.rs:230-423`.
  **Evidence:** `owner_bindings` accepts `TenantConn`, performs registry IO, walks multiple binding sites, loads referenced Cards, canonicalizes inline targets, and builds persistence inputs as a free async workflow. The new SQL capability is also published as a bundle of free projection/activity/admission workflows rather than methods on a cohesive verification-binding store/handle. These are not deterministic stateless helpers.
  **Consequence:** the new capability repeats the repository's explicitly rejected dependency-threading shape and leaves transaction, persistence, and projection behavior undiscoverable from a clear owner.
  **Testable correction:** place binding freeze/projection/activity operations on the smallest existing or new concrete owner that actually holds the needed registry/transaction capability; keep only digest/conversion logic free when it is pure. Preserve the same transaction and RLS behavior, then rerun the existing focused SQL and registration tests.

- **STD-003-003 — CONTRACT / MAINTAINABILITY — the new SQL API leaks raw UUIDs for durable identities.**
  **Violated rule:** `AGENTS.md` §4 and `architecture/references/languages/rust-core.md` require domain types instead of raw primitives for durable identifiers.
  **Location:** `crates/wyrd/wyrd-sql/src/queries/verification.rs:317-321,381-395`.
  **Evidence:** `record_machine_authentication` accepts a raw `Uuid` principal id, while public `BindingActivity` exposes raw `Uuid` values for `binding_id`, `owner_card_uid`, and `principal_id`. The repository already has `BindingId`, `CardUid`, and `wyrd_runtime::PrincipalId`.
  **Consequence:** callers can interchange unrelated UUID domains and bypass the UUIDv7/type invariants the candidate introduced for binding identity.
  **Testable correction:** make the public API accept/return the existing domain newtypes. If SQLx cannot derive directly for a newtype, decode into a private row and validate/map it before returning; add a focused decode test that refuses an invalid stored binding identity.

- **STD-003-004 — MAINTAINABILITY / HARD BLOCKER — mandatory rustdoc is incomplete on new items.**
  **Violated rule:** `AGENTS.md` §16 and `architecture/agent-rules.md` require rustdoc for every new or materially modified Rust item, including private constants, helpers, and tests, with `# Errors`/`# Panics` where applicable; missing documentation is `BLOCK_BEFORE_MERGE`.
  **Location:** undocumented constants at `crates/wyrd/wyrd-sql/src/queries/verification.rs:30-90`; panic-capable new integration helpers/tests at `crates/wyrd/wyrd-sql/tests/pg_verification_bindings.rs:77-127,129-190,192-273,275-344,346-356,358-412,414-481`; new auth Postgres tests at `crates/wyrd/wyrd-auth/src/issuance.rs:903-1063`.
  **Evidence:** the SQL constants have no `///` intent/invariant documentation. The listed helpers/tests call `expect`/panic but omit required `# Panics` sections; several function docs only restate the scenario without documenting failure conditions.
  **Consequence:** the candidate fails an explicit hard repository completion gate even if compilation and tests pass.
  **Testable correction:** add substantive rustdoc to every listed new item, including the role/invariant of each SQL statement and `# Panics` conditions for test helpers/tests; run `mise run fmt` and the repository rustdoc/lint gates.

- **STD-003-005 — TESTS — no tier-1 SDK journey proves the new public Card status contract.**
  **Violated rule:** `AGENTS.md` §11, `architecture/wyrd-design.md` Doctrine 20, and `architecture/references/languages/testing-workflows.md` require every new user-facing capability to be proved client → real server → client; integration tests never substitute.
  **Location:** `crates/wyrd/wyrd-server/tests/pg_card_registration_route.rs:2695-2716,2749-3110`; changed-test inventory contains no SDK-owned journey.
  **Evidence:** `owner_status_serves_stable_binding_ids_and_exchange_activates` starts an in-process server and drives raw `oneshot_authenticated` HTTP requests, then indexes untyped JSON. It does not use `Cards`/`WyrdClient` against a bound server for the new read contract, and no Python or TypeScript journey was added for the shared public status field. Existing unrelated CLI/WyrdState/platform lanes do not directly assert this behavior.
  **Consequence:** schema compatibility, transport decoding, and public SDK projection of `status.verification.binding_ids` can regress while the added test remains green.
  **Testable correction:** add the smallest real bound-server journey through the public client surface that registers/reads an owner and asserts typed stable binding IDs plus the applicable authorization negative path; add equivalent first-class-language journeys wherever the Card read capability is shipped. Keep the current SQL and raw-route tests as supporting lower-tier coverage.
