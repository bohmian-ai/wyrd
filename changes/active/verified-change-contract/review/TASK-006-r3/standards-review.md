## Rule results and material findings

| Rule and result | Evidence |
|---|---|
| **FAIL — architecture authority must reflect the active trust boundary** (AGENTS §1 and reference-router hierarchy) | STDS-001. The candidate removes signed peer tickets and uses mTLS plus typed contexts (`crates/wyrd/wyrd-server/src/oracle/peer_authority.rs:1–12`, `changes/active/verified-change-contract/spec.md:1443–1461`). Yet `architecture/wyrd-security-posture.md:35,249–267` still *requires* signed, single-use tickets and verification keys; `architecture/operations/deployment-and-release.md:33–34,171,189` still requires peer-ticket contracts; `architecture/bifrost-design.md:833–836` still names ticket rejection. Operators and future implementers receive contradictory security requirements. Update these governing authorities to the approved mTLS/context contract and remove obsolete ticket-specific obligations; retain system-owner audit semantics for untrusted contexts. |
| **FAIL — one deployment-wide migration lease** (`architecture/operations/deployment-and-release.md:134–154`; `architecture/v1/00-foundations/postgres-layout.md:20–31`) | STDS-002. `wyrd-server migrate` calls `wyrd_sql::migrate` and then `vala_sql::migrate` on a pool, then validates (`crates/wyrd/wyrd-server/src/main.rs:196–218`). Each crate takes a *different* advisory-lock key on a separate dedicated session and releases it before the next stage (`crates/wyrd/wyrd-sql/src/lib.rs:38–90,100–122`; `crates/vala/vala-sql/src/lib.rs:35–82,90–115`). No lock spans the combined Wyrd/Vala migration and validation. Two release slots can interleave stages despite the explicit physical-domain lease rule; both current locks also wait without the authority's bound. Make the one-off migration owner hold one bounded, direct-session lock for the whole ordered migration and post-check sequence, reusing the crate migrators beneath it. Add a concurrent-migrator proof that a contender cannot interleave or wait indefinitely. |
| **FAIL — migration and serving schema grant checks** (`architecture/operations/deployment-and-release.md:144–154`; spec REQ-157) | STDS-003. `SchemaCheck` checks migration ledger, login superuser/BYPASSRLS posture, and forced RLS only (`crates/wyrd/wyrd-sql/src/schema_check.rs:23–125`); `ValaPostgres::validate_schema` only adds an app-role catalog `USAGE` refusal (`crates/vala/vala-sql/src/postgres.rs:100–119`). Neither the migration command nor serving readiness proves required role grants, ordinary tenant policies, ownership, or sentinels. A database with a revoked necessary grant can pass readiness and fail on its first real operation; an accidentally over-granted platform role can also pass. Check required privileges and invariants through the existing SQL owners before readiness, then prove a deficient-grant database is refused. |
| **FAIL — raw pool propagation in library code** (`architecture/agent-rules.md`, raw `PgPool` rule) | STDS-004. New `SchemaCheck<'a>` stores `&'a PgPool` and its public constructor accepts `&PgPool` (`crates/wyrd/wyrd-sql/src/schema_check.rs:18–27`). It is a reusable SQL operation handle, not a pool-construction boundary; the rule permits only `TenantConn` and `OperatorPool` in fields/signatures. This new public type allows SQL work to route around the typed tenant/operator boundary. Keep role-specific readiness checks on existing `WyrdPostgres`/`ValaPostgres` or an owner-bound capability, without exporting a general raw-pool SQL handle. Preserve the one-off owner migration boundary separately. |
| **FAIL — every new Rust method has rustdoc and fallible methods have `# Errors`** (`AGENTS.md` §16; `architecture/agent-rules.md`, Rust documentation rule) | STDS-005. New `impl<W: Write> Write for Tee<W>` methods `write` and `flush` have no rustdoc or `# Errors` (`crates/wyrd/wyrd-server/src/main.rs:327–336`), though `write` can fail after a partial terminal write and `flush` can fail. Their surrounding struct documentation does not satisfy the per-item hard gate. Document the behavior and error/partial-write semantics on both methods. |
