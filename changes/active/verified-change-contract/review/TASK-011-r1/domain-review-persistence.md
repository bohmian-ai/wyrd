## Finding

**DOMAIN-PERSIST-1 — INCORRECT — completeness and scores use different source snapshots.** REQ-156 requires a selected target observation missing any configured feature to make the run inconclusive, with no scored details or feature rows. `DriftEngine::try_verify` executes `Reader::complete` first (`drift.rs:502-508`, `549-555`), then issues a separate query for each PSI/SPC feature (`drift.rs:510-572`). `Reader::fold` creates a fresh authenticated query for every statement (`drift.rs:704-739`), and Bifrost pins a snapshot per query rather than across the run (`architecture/references/domain/olap-serving.md`, query path step 4). A manual `DriftWindow` may include future time (`wyrd-spec/src/verification.rs:48-75` validates order and maximum length only), so another observation can be ingested into the same subject/window after completeness passes. If that observation carries only one of two configured features, the later per-feature reads can persist a scored report and feature rows even though the selected target now contains an incomplete observation. With two features, they can also score different target populations. This is reachable without bypassing tenant, audit, or the normal ingest path.

**Required correction:** make completeness and every feature score derive from one consistent query snapshot through the existing query-service authorization and audit path, or compute the check and all required aggregates in one fixed query over that snapshot. Preserve current tenant/subject/window filters, bounded result handling, and existing publication behavior. Focused closure proof should insert an incomplete selected observation between read phases and show the run cannot publish a scored result or feature rows; repeat for PSI and SPC, then run the existing Drift journeys and query/audit lanes.
