## Proposed findings

### B-001 — INCORRECT: wide regex matches suppress otherwise representable search hits

- **Obligation:** REQ-013 requires bounded snippets, one result per matching line, and obtaining larger context via `fs.read`; AC-011 requires regex search under host output bounds.
- **Location:** `crates/wyrd/wyrd-server/src/verification/hosted/workspace.rs:620`, `:623`, `:935–938` in the candidate.
- **Failing caller path:** Upload/select an ordinary text or minified JSON file containing one approximately 70 KiB line beginning `REFUND`, well below the default 20 MiB file bound. A declared, authorized Agent calls `fs.search` with `{"query":"REFUND.*","regex":true}`. `Regex::find` returns the full line; `snippet(..., found.len())` retains it because its bound is `80 + len`. `Collected::push` cannot fit this first hit inside the default 64 KiB result budget, so `search` returns `{"matches":[],"truncated":true}`. A short literal `REFUND` against the same file produces a small discoverable hit. The same path exists for readable scratch files.
- **Consequence/materiality:** A normal regex spanning a long log or serialized record loses the file path and line locator, preventing the intended search-then-read workflow even though a short bounded snippet and metadata fit. This is an explicit required behavior, not a demand for a bigger output budget or arbitrary input hardening.
- **Shared owner and siblings:** `Workspace::search` is the only producer of these hits for both input and scratch, and `snippet` has this search call site. Correct the shared snippet projection, preserving actual line/source identity and the existing `Collected` result budget; no SDK/provider-specific guard is needed.
- **Smallest correction:** Cap snippet text independently of the full regex match span, on UTF-8 boundaries, so a wide match cannot consume an entire response. Continue using `fs.read` for full context. No new option, dependency, search engine or pagination contract is needed.
- **Closure proof:** Extend the existing workspace search test with a long line and a regex spanning it, use a small existing host result limit, and assert a located hit with bounded snippet and response size. Retain short literal, multi-byte text and many-hit truncation behavior.
