## BEH-001 — owning-step skip suppresses a failed evidence cause

- Classification: **INCORRECT**.
- Obligation: REQ-006, INV-006, task scenario 3: when intentional-skip and failure causes affect the evidence for one requirement, failure wins; missing failed evidence stays inconclusive and in the denominator.
- Exact location: `crates/vala/vala-eval/src/blocks/engine.rs:320-326` (`run_requirements`).
- Evidence and producer-to-consumer path: `prepare` records an intentional skip as `Settled::NoOutput { gap: Skipped }`; an upstream failing action is separately recorded as `Settled::NoOutput { gap: Failed }`. `run_requirements` derives `blocked` from only the containing step, then `blocked.map_or_else(|| check_bindings(...), Err)` skips `check_bindings` entirely. Consequently the check's own reference to the failed upstream's output never reaches `Scope::resolve`, and `Judged::missing` sees only the weaker skipped cause.
- Reachable example: declare JSON input `answer` with `draft: false`. Step `broken` has a code action that terminally fails. Step `gated` has ordering dependency `depends_on: [broken]`, an action bound only to `inputs.answer`, and false `when` on `inputs.answer.draft`. A requirement on `gated` binds `steps.broken.output` (or binds both its own output and the broken output) to a code check. This is legal: explicit dependencies are ordering-only, and `validate.rs:724-735` allows a step requirement to read upstream steps. `gated` is intentionally skipped, but the requirement also needs failed evidence. Current result is `not_applicable`; required result is `inconclusive`. Add a passing whole-Verifier assertion and current `all` rollup can become `passed`, whereas retaining the inconclusive requirement must prevent that result.
- Siblings checked: whole-Verifier checks go directly through `check_bindings` and already combine failures correctly; successful-step checks do likewise. `prepare` already combines gaps from action/when/workspace via `Missing::strongest`. The incomplete source is specifically requirement eligibility for a no-output owning step, not `decide` and not each check executor.
- Smallest correction outcome: resolve the requirement's declared evidence causes even when the containing step has no output, combine those gaps with the containing step's cause through existing `Missing::strongest`, and suppress check execution when any required gap exists. Preserve pure intentional-skip N/A, status-only checks on other steps, and all existing whole-Verifier behavior. This boundary owns the implicit containing-step dependency, so the combination belongs here or its reused driver equivalent.
- Focused proof: one library regression using the existing Script and valid spec described above must assert inconclusive requirement, no check invocation, and inconclusive whole verdict alongside a passing requirement; retain a pure intentional-skip control. No new harness or integration suite is needed.
