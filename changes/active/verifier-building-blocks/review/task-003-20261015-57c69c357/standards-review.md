## Findings

### REPO-003-01 — Postgres-backed tool tests remain in the ordinary unit-test namespace

Classification: VIOLATION. Location: `crates/wyrd/wyrd-server/src/verification/hosted/tools.rs:453-454`, and `hosted/tools/tests.rs:23,41,68,108,164,199,231`.

Rule: architecture/agent-rules.md requires tests needing Postgres, Docker or a live server in `mod pg_tests` (or a `pg_*` file), never the fast lane. AGENTS §11 distinguishes credential/environment-free units from dependency integration.

Every new tool test creates an invocation or state. `caller()` calls `test_tenant()`; `state()` calls `test_server_postgres()`, `test_storage()` and `test_catalog()`. These all enter `test_support::shared()`, whose initializer `build_shared()` starts `PgFixture::start()` and constructs a live Postgres-backed BifrostCatalog (`test_support.rs:48-81,103-113,159-186`). These tests are therefore dependency-backed even when a permission refusal prevents a query. Naming them `tests` means an ordinary unit selection, including the task's documented `not test(/::pg_tests::/)` selection, still boots/requires Postgres. The implementation evidence itself had to add the managed Postgres wrapper for the 21 hosted cases.

Smallest correction: put this existing Postgres-backed test module under the sanctioned pg_tests namespace and update focused commands to run that module with the existing repository-managed Postgres wrapper. Preserve the protected-owner assertions; do not replace the authoritative state with weaker doubles to avoid gating. Closure: nextest listing shows these four tests under `verification::hosted::tools::pg_tests::`; the non-pg selector excludes them, and the exact named cases pass under the managed setup. No new test harness or checker is necessary.
