## Producer-to-consumer and reuse comparison

1. **Agent workflow.** Agent/Prompt resolvers produce declarative specs; Prompt compiler-derived placeholder sets are checked in both directions; per-call copies feed `Agent::run_prompt`; tools bind through the existing registry and loop; result validation and `CallProvenance` feed the block seam. Existing `SkaldJudgeInvoker` remains a temporary sibling consumer of the relocated resolver/error/render helpers. There is no second provider transport or copied loop. Fresh Agent/session construction prevents cached principals/workspaces. The retained judge bridge converts BlockError to the legacy judge error only for the existing consumer; the new block executor does not depend on JudgeInvoker/JudgeError.
2. **Storage workflow.** Existing `TenantMedia::resolve` already verifies backend scheme, tenant-qualified path and bounded body before base64 conversion. New `TenantEvidence` appropriately adds digest-pinned uploaded evidence, extraction and citation support through the same StorageHandle. It does not duplicate a client transport or storage backend. However it implements only uploaded files; existing Artifact storage metadata and tenant path owners remain unused. `storage::service::download_init`, `validated_download_path`, `load_artifact_metadata`, Card authorization, and `StorageHandle::get_object_bounded` supply the existing building blocks for that missing branch; reusing them does not require a second storage service.
3. **Protected-tool workflow.** `Invocation::call` reuses `audit::authorize` and each existing authorized operation: `list_cards_for`, `get_card_for`, `get_card_by_ref_for`, Bifrost service operations, and `BoundedQuery`. MCP contributes shared descriptors/argument shapes only, not a loopback dispatch. Sibling HTTP/MCP operations retain their domain checks. A suspicious never-cancelled explicit query token does not alone establish a cancellation defect: `query::service::stream_query` explicitly returns admission/cancellation cleanup guards, so dropping that stream stops descendant query work. No finding is proposed from the comment alone.
4. **Extraction/workspace workflow.** New parsing/workspace ownership is earned: the base has no canonical structured OOXML extraction or mounted scratch workflow. Actions, filesystem tools, and citation validation share `Extraction`, `units` and `locates` rather than independent parsers. The missing pieces are enforcement and propagation within these owners, not a reason for another reader/parser. Direct `/inputs` consumers, archive entries, derived JSON, `/work` files, filesystem results, and citation validation were checked together.
5. **Python workflow.** There is no prior hosted Python owner to extend; Monty supplies worker protocol, pool/checkout lifetime and capability-scoped mounts. The standalone binary is justified by the documented PyO3 link conflict, not a new engine. The parent supplies resource policy and mounts. Installed `monty-pool`/`monty-fs` 1.1.0 were inspected to distinguish actual library guarantees from comments: subprocesses clear env and kill on drop, but mount quota counters are per feed. The candidate must own invocation-wide accounting and hard worker-group containment rather than treating those as supplied by the dependency.

## Material proposed findings

### INV-01 — MISSING: exact Artifact evidence and code sources are not implemented

- **Obligation:** REQ-004 code source is inline source **or exact Artifact reference**; REQ-010 existing Artifact evidence remains usable under normal authorization. Scenario 2/4 and acceptance require concrete hosted implementations rather than refused contract branches.
- **Locations:** `crates/wyrd/wyrd-server/src/verification/hosted/evidence.rs:115` (`TenantEvidence::read`, File-only destructure/refusal at 124); `hosted/sandbox.rs:349` (`CodeExecutor::run`, refusal at 360).
- **Reachable path:** a valid CodeSource::Artifact reaches both code ActionExecutor and CheckExecutor through shared `run` and always returns Terminal. An InputDeclaration::Artifact passed to extraction, native media or workspace reaches shared `read` and always returns Terminal; citations into that Artifact are silently discarded by `located`.
- **Consequence:** supported registered source/evidence can never execute or ground a pass. The handoff note admits the omission; TASK-005 wiring cannot make these concrete implementations honor the branch.
- **Smallest correction:** complete the existing hosted evidence/source resolution boundary with exact authorized Artifact lookup and bounded storage reads, reusing Card authorization, stored artifact metadata, tenant paths, and StorageHandle. Share the branch among extraction/media/workspace/citation consumers and code action/check source loading; preserve exact source digest/runtime provenance. Do not add a separate loader/service or fetch transport.
- **Closure proof:** exercise valid exact Artifact source/evidence through these seams; refuse unauthorized/wrong-tenant/wrong-identity/missing or oversized bytes; prove source hash and original-slot citations survive. These are missing acceptance cases, not full-service execution requirements.

### INV-02 — INCORRECT: writable/scratch accounting resets at each `code.run`

- **Obligation:** REQ-008 and Deployment limits define a **cumulative** 50 MiB `/work` budget and 250 MiB scratch budget **per invocation**; INV-007 bounds retained scratch.
- **Location:** `hosted/tools.rs:261`–`280`, `Invocation::run`; `hosted/workspace.rs:195`–`201`, materialization-only scratch counter.
- **Producer and siblings:** every tool call creates new MountSpecs and sends them in a new `Sandbox::exec` feed, while the Workspace retains files across calls. Installed `monty-pool-1.1.0/src/checkout.rs:2233` creates a new MountTable per feed; `monty-fs-1.1.0/src/mount_table.rs:267` initializes `write_bytes_used: 0`; `common.rs:347`–`361` checks/charges only that counter. A reused MountSpec alone would still reset that library counter.
- **Consequence:** two calls can each write 40 MiB and retain 80 MiB in the same `/work`; further calls exceed total scratch as well. Workspace's local `scratch` counter disappears after inputs materialize and is never consulted by writes. File reads only reject each oversized individual file, not combined retained bytes.
- **Smallest correction:** make the existing invocation/workspace owner retain and enforce the writable accounting and remaining scratch allowance across feeds, including failed calls and concurrent tool calls. Reuse Monty's parent-serviced mount policy where possible, but do not mistake its per-feed quota for invocation quota. Preserve the independent Python time budget.
- **Closure proof:** with small limits, issue two successful individually-under-limit `code.run` writes whose combined bytes exceed the invocation limit; the second must refuse before the write, with prior files intact. Also prove input bytes plus `/work` cannot exceed scratch and failures do not restore spent quota incorrectly.

### INV-03 — VIOLATION: the worker-group ceiling is sampled rather than hard

- **Obligation:** approved Deployment limits explicitly require a **hard combined memory ceiling**, independent of allocator accounting, including idle workers; TASK-003 must prove enforcement or stop.
- **Location:** `hosted/sandbox.rs:282`–`316`, `watch`; start at 90.
- **Evidence/path:** eight independent workers can allocate concurrently below their individual 384 MiB address-space limits. Aggregate usage may pass 2 GiB between 100 ms samples. The watcher measures RSS after allocation and kills only one largest busy worker per tick; it cannot prevent the group from exceeding its ceiling and cannot evict idle-only excess. The source and task evidence explicitly acknowledge this and defer a hard mechanism.
- **Consequence:** approved worker-group isolation is absent; under memory pressure the shared server remains exposed to excess worker memory before sampled intervention. A test with a one-byte sampled threshold proves eventual killing, not a hard boundary.
- **Smallest correction:** enforce the worker group through the conventional OS hard aggregate mechanism (for Linux, a worker-only cgroup memory limit), covering all spawned/warm/replacement workers before requests, and refuse unsupported enforcement. Keep the parent outside that worker group. Do not claim a sampling watchdog as the approved ceiling. If the allowed deployment cannot provide it, route that explicit spec conflict instead of shipping a softer promise.
- **Closure proof:** inspect actual worker-group membership/limit, exercise concurrent allocation with the normal bounded worker count, and prove aggregate memory pressure terminates affected work without terminating the parent. Include idle and replacement workers.

### INV-04 — VIOLATION: tiny DOCX metadata can trigger unbounded allocation in the server

- **Obligation:** INV-005/007 and Scenario 2 require bounded extraction of semi-untrusted evidence; archive byte checks do not waive parser output bounds.
- **Location:** `hosted/extract.rs:317`–`331`, `Extraction::docx_blocks`.
- **Producer/path:** XML `gridSpan/@val` is parsed as any `usize`, then `repeat_n(String::new(), span.saturating_sub(1))` expands it directly. A small zipped DOCX containing a huge numeric gridSpan passes compressed/decompressed byte, entry and text limits. Empty covered cells consume no `text_bytes`; Vec allocation can panic on capacity overflow or abort on OOM in the parent server process. `TenantEvidence::execute`, workspace materialization, and citation extraction all call this parser on the shared process's blocking pool.
- **Consequence:** an input well below file/archive limits can stop unrelated server capabilities; spawn_blocking does not contain allocation aborts or make ongoing parsing cancellable.
- **Smallest correction:** reject invalid/unsupported spans and bound structural expansion in the existing extractor before allocating generated cells, using the existing extraction budget and applicable document constraints. Audit sibling semantic expansions and recursive XML traversal under the same bounded-extraction obligation, without creating a second parser or moving durable logic to a client.
- **Closure proof:** a small document with a huge span must return a bounded terminal refusal; ordinary merged-cell output stays unchanged. Test the refusal without allocating the requested huge vector or intentionally exhausting the host.

### INV-05 — INCORRECT: `fs.read` silently loses the rest of an oversized unit

- **Obligation:** REQ-008 promises bounded reads; Scenario 2 explicitly includes truncation. A caller must be able to consume declared evidence, and partial text cannot masquerade as a complete located unit.
- **Location:** `hosted/workspace.rs:431`–`451`, `Workspace::read`.
- **Reachable path:** a text file with one 100 KiB line (below extraction/file limits), or a PDF page of that size, forms one unit. The first unit exceeds the 64 KiB tool allowance, so it is truncated. `next` is set only when a later unit is encountered; a one-unit file returns `next: null`. With multiple units, the cursor advances to the next unit, never to the remainder of the first. `start` is only a unit index.
- **Consequence:** substantial evidence is inaccessible through `fs.read`; the model receives a prefix with the full page/line locator and no indication of omitted suffix. JSON escaping/path overhead can also make this supposedly bounded response exceed RecordedTool's actual serialized byte ceiling, replacing a readable file with a tool error.
- **Smallest correction:** implement honest, resumable bounded collection in Workspace::read using actual serialized-byte accounting. Retain original locators for chunks and ensure a cursor can reach every suffix; do not silently truncate a whole unit and advertise completion. The existing owning tool can expose its internal continuation shape without another reader.
- **Closure proof:** read an above-limit single line/page to completion through successive bounded results, including quote-heavy/control-character/Unicode content; reconstruct all text, keep locators, and prove every returned serialized result is within the configured limit.

### INV-06 — INCORRECT: Unicode print truncation panics in the parent

- **Obligation:** REQ-008/INV-007 require safely bounded Python output; worker failure must not propagate as a parent-side panic.
- **Location:** `hosted/sandbox.rs:193`–`197`, print callback in `Sandbox::exec`.
- **Reachable path:** the callback slices `&text[..min(text.len(), remaining)]` at an arbitrary byte. If 65,535 ASCII bytes have already been retained under the default 65,536-byte budget, the next printed `é` requires two bytes and is sliced at byte 1. Rust panics because this is not a UTF-8 character boundary. This callback runs in the parent, not the isolated worker.
- **Consequence:** valid sandbox output aborts the enclosing parent task rather than returning bounded output or BlockError; the cleanup path after the await is skipped. The ASCII-only flooding test cannot catch it.
- **Smallest correction:** trim output on a UTF-8 boundary in the existing callback, reusing the same boundary-safe approach already present in Workspace::truncate (locally reuse/extract only as needed). Do not widen budgets or drop output enforcement.
- **Closure proof:** print across the byte limit with multibyte characters; return successfully with valid UTF-8 no larger than the limit, then prove subsequent sandbox operation still succeeds.

### INV-07 — MISSING: original-slot mappings are retained internally but not returned by filesystem tools

- **Obligation:** REQ-009 says workspace paths map back to original input slots; Scenario 3 requires step-produced citations to remain citable by a tool-less downstream judge.
- **Location:** `hosted/workspace.rs:382`–`385` (`sources`), 449–451 (`read` result), 497–503 (`search` result); `hosted/tools.rs:224`–`237` dispatches those values unchanged.
- **Producer and consumers:** Workspaces receive `CallInput.sources` and retain them per materialized file. Only the unit test calls `Workspace::sources`; no production filesystem result or tool descriptor exposes the mapping. `fs.list` returns paths/sizes, `fs.read` returns path/locator/text, and search returns path/locator/snippet. AgentExecutor injects only authored Prompt inputs, so a workspace-only source's slot name has no other route to the model. Paths are arbitrary and need not match slot names.
- **Consequence:** an Agent reading `/inputs/manual.pdf` cannot discover that its citation must use original slot `policy`; generated path-based/guessed citations are rejected and its downstream tool-less check becomes inconclusive. The existing propagation test supplies citations explicitly in scripted output, bypassing this concrete path.
- **Smallest correction:** publish the original source-slot/location mapping from the existing workspace tool owner alongside direct-file located results, and preserve valid original citations from derived data rather than relabeling derived JSON pointers as original locations. Keep the approved ordinary-output citation contract; no hidden Prompt injection or new evidence wrapper.
- **Closure proof:** bind original slot and workspace path with deliberately different names, obtain provenance from concrete fs tool output, pass derived findings/citations through an explicit downstream binding, and validate with real TenantEvidence rather than a citation-accepting double.

### INV-08 — INCORRECT: valid JSON pointers to null or empty values are rejected

- **Obligation:** REQ-009 validates whether a cited location exists in pinned evidence, not whether it contains nonempty text. REQ-004 preserves null/empty values and canonical DOCX/XLSX pointers.
- **Location:** `hosted/extract.rs:554`–`568`, `leaves`, with `locates` at 535–540.
- **Reachable path:** original JSON `{ "answer": null, "comment": "", "items": [] }` has existing pointers `/answer`, `/comment`, `/items`. `leaves` drops null and empty strings, and emits no units for empty containers. `locates` accepts only units or prefixes of units, so all three valid locations fail; an entirely empty object cannot even cite its root. The same producer supplies canonical Office locations, including empty merged cells and null error-cell values.
- **Consequence:** grounded checks of missing/empty content cannot keep correct citations; an Agent passed check becomes inconclusive despite a valid pinned source location. The current evidence tests only use nonempty leaves/containers.
- **Smallest correction:** keep citation existence validation distinct from text-only display filtering within the existing extraction/citation owner. Validate JSON pointers against the pinned JSON/canonical extracted value, or retain explicit location entries for empty values, while continuing to reject metadata fields that are intentionally not source locations and out-of-binding slots.
- **Closure proof:** accept existing null, empty string/array/object pointers in original JSON and applicable canonical extraction; reject nonexistent sibling/index pointers and unreachable slots. Preserve filesystem text behavior and invalid-cited-pass downgrading.
