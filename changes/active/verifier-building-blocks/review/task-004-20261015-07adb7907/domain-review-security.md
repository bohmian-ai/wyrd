- Violated obligation: TASK-004 Scenario 3, lines 107–110, explicitly requires a hosted Agent journey using declared Card/Bifrost and code tools, including denied and delegated access. README lines 208–220 assigns authoring these real journeys to TASK-004 while TASK-003/005 implement and later prove enforcement. - Changed locations: `sdks/wyrd-sdk-rust/tests/integration/verifier_building_blocks.rs:245` (tool assertion at 274–279); `sdks/wyrd-sdk-python/tests/integration/test_verifier_building_blocks.py:163`; `sdks/wyrd-sdk-ts/wyrd/tests/integration/verifier-building-blocks.test.ts:173`; shared declaration `fixtures/cards/verifier_building_blocks/refund-reader.yaml:10`.
- Evidence: the hosted Agent declares and invokes only `fs.read`; all three languages assert exactly that single tool. The fixture's `code` action is a Verifier action, not the Agent's `code.run` tool, so it cannot prove invoke authorization. The remaining new cases cover check failure, citations, host-file refusal, trace/missing/malformed/large evidence, queue/reconnect and extraction formats. No hosted Agent journey invokes Card/Bifrost/code tools with exact invoke grants, denies either independent gate, or runs under narrowed delegation. Repository searches of the sibling SDK integration stories found delegation tests on direct Bifrost/client handles, not verification→Agent→tool paths.
- Producer-to-consumer gap: the SDK's explicit/delegated client establishes invocation credentials; `Observe` sends the verification request through that retained client; accepted authority must then reach the hosted Agent's tool call and its domain capability. Current stories stop before testing this protected downstream consumer with differentiated caller grants. Their real filesystem sandbox test does not test either RBAC gate.
- Observable consequence: a final merged candidate could pass every authored TASK-004 journey while tool dispatch inferred permissions from the Agent, used actor/SYSTEM authority, ignored the exact tool-name scope, or skipped the underlying data gate. This is a required cross-boundary proof gap, not a claim those server defects already exist.
- Smallest correction: extend the existing shared building-block fixture and its three language journeys to exercise a hosted Agent's declared Card/Bifrost and `code.run` calls through the existing runtime. Use existing scoped-key and delegation helpers; cover invoke missing versus domain missing, an exact tool-name grant not covering another name, and narrowed delegated authority. Successful calls must use the accepted subject's allowed resource; denied calls must expose no protected resource data. Keep authorization in existing server owners and reuse existing permission/audit contracts; do not add SDK grant evaluation, another harness, or another transport. Share the fixture semantics across languages.
- Focused closure proof: author and compile/typecheck the cases and confirm their selectors are discovered by existing mise integration lanes. Execute only focused wrapper/fixture checks relevant to any executable changes; full real journeys remain deferred to the coordinated merged change review as the original task directs. This finding does not require prematurely running the full suites or implementing TASK-005.
