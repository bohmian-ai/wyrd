## Proposed material finding

### CONC-R2-001 — INCORRECT, residual FIND-TASK-005-2: an observed Agent capacity refusal can still become a timeout/verdict

**Violated obligation.** R1 FIND-2 requires a real refused Agent `code.run` to stop through Busy and Deferred without spending authored retries or judging capacity pressure. Approved Deployment limits require background capacity refusal to remain queued; REQ-013 preserves cancellation and the existing queue lifecycle.

**Exact location.** `crates/vala/vala-eval/src/blocks/agent.rs:337–341`, with refusal producer/observer at `blocks/tools.rs:83–101,150–169,258–260`. The defect is delayed observation of the session-owned refusal, rather than the corrected Sandbox category or runner release.

**Reachable path and evidence.**

1. An allowed Agent action declares `code.run` and `bifrost.query`, has a declared workspace, and requests both in one model response. Skald's normal tool concurrency defaults to eight (`skald-agent/src/loop_runtime.rs:369`). HostedTools resolves these built-ins under the accepted caller; neither tool combination nor parallel calls is forbidden.
2. With the bounded Python pool held by other controlled work, `code.run` returns Busy immediately; RecordedTool raises the session Refusal. A concurrent query can legitimately remain pending past a short authored step timeout: `hosted/tools.rs:235–246` passes its independent query deadline and does not bound it to the action deadline. An ordinary slow dependency suffices; no stress workload is needed.
3. Skald waits for **all** tool futures (`loop_runtime.rs:661–665`, buffer_unordered then collect). Its `before_model` hooks therefore cannot run while that query remains pending. AgentExecutor is still awaiting `run_prompt`; the post-run `session.refused()` check has not executed.
4. The outer `VerificationEngine::attempt` times out the Agent future (`blocks/engine.rs:350–368`). Dropping the invocation also drops its unread refusal. The result is Retryable("timed out"), spends authored retries (`:374–375`), or settles the action failure (`:378–382`), followed by ordinary requirement/verdict handling. Without an earlier step timeout, the enclosing engine deadline instead returns DeadlineExceeded, which the runner settles timed_out. In either case an already-observed capacity refusal never reaches EngineError::Busy / Deferred.

**Observable consequence.** A valid queued Agent verification can consume retries or terminate because another tool is slow after Python capacity was refused, instead of retaining its execution identity in the queue for actual evaluation after capacity frees. Immediate single-tool proof passes while this concurrent-tool path remains broken.

**Smallest testable correction boundary.** Keep the first-refusal state in the existing per-invocation ToolSession, and make it actively end the AgentExecutor's awaited run as soon as it is raised, dropping pending tool futures and returning that Busy to the common engine. Reuse existing cancellation/notification facilities; preserve typed causes, genuine query/provider errors, explicit caller cancellation, and direct deadlines. Do not patch terminal results afterward, alter generic Skald tool-error semantics for every Agent, reserve whole-execution Python permits, or add a scheduler/queue. No product or public contract decision is necessary: this completes the already-approved first-refusal outcome.

**Focused closure proof.** Extend the existing Agent capacity fixture with a response requesting a real refused code.run plus a controlled pending sibling tool. Use a shorter authored step deadline than the sibling's independent wait. Assert refusal ends the invocation before that deadline, no subsequent model call or authored retry occurs, pending tool work is dropped, and the queued execution defers with refunded attempt before later succeeding under the same identity. A deterministic ToolSession sibling-future test can pin cancellation; retain the current real-pool integration coverage to prove the actual producer category. No host load, broad journey suite, or migration test is required for this closure.
