### MNT-R3-001 — Whole-execution admission omits the existing individual-file ceiling

- **Classification:** INCORRECT / VIOLATION. Independent validation should decide whether this belongs with the existing evidence-admission finding family; this report assigns no new stable FIND ID.
- **Changed location:** `crates/wyrd/wyrd-server/src/verification/hosted/evidence.rs:333–379`, especially the resolved `size` at 340–370 before combined accounting. The existing lower byte-reader guard is at `stored` around 265.
- **Authority:** approved spec Deployment limits (`spec.md:928–950`) caps one input file at `WYRD_VERIFICATION_FILE_MAX_MIB` and permits a slot only to lower deployment limits. REQ-002 keeps server validation authoritative. Maintainer Style requires the owning operation to expose the real invariant and reuse its existing owner; the existing hosted evidence owner now admits the complete set before blocks run. Current runtime documentation also promises per-file 413 before work.
- **Producer-to-consumer evidence:** raw HTTP `decode_body` only decodes the typed envelope. `VerificationControl::execute` passes `request.inputs` to HostedBlocks and `VerificationEngine::run`; queued submissions freeze the same declarations and runner dispatch reaches the same engine. `conform` checks a File's format and optional *slot* max, but no deployment bound. `TenantEvidence::admit` resolves an Artifact's format/slot max and sums both declaration kinds against `files_max_bytes`; it never compares each resolved size with `file_max_bytes`. The only individual deployment check is later in `stored`, reached when bytes are read by extract, native media, workspaces or citations.
- **Reachable outcome:** declare a media slot with no `max_bytes` and supply a File whose `size_bytes` is 25 MiB under the default 20 MiB individual / 100 MiB combined settings. A Verifier with a normal JSON assertion and this optional media slot does not read media bytes and can return Passed. A whole-media `is_not_null` check also resolves the declaration through `Scope::resolve` and compares its JSON representation without `stored`. A selected Artifact between the same two ceilings follows the same path after authorized metadata resolution. If a later step does read it, the individual limit becomes an isolated block failure instead of authoritative pre-work input refusal. The upload-plan/local-PUT guards do not close raw declarations or pre-existing registered Artifact inputs.
- **Concrete maintenance cost:** the complete-set admission owner appears to enforce deployment input bounds while a sibling byte-reader owns one omitted bound. Consequently enforcement depends on which action happens to consume the input, and future executors can silently bypass a declared input limit simply by avoiding byte reads. This has a caller-visible contract consequence, not merely a preferred layout.
- **Smallest correction:** in the existing `TenantEvidence::admit` path, compare each File declaration's or authorized selected Artifact file's resolved size with the already configured `file_max_bytes` before accumulating its combined total, returning existing `EngineError::InputTooLarge`. Keep the lower `stored` check as a byte-read safety boundary for all its consumers, including Artifact code. Preserve slot constraints, authorized lookup, digest/length/sniffing and overflow-safe combined accounting. Do not add a validator, queue rule, SDK loop, upload session, second Artifact loader or new error.
- **Focused closure proof:** extend existing direct/queued admission cases with one file above the individual ceiling but below the combined ceiling, no slot override, and a requirement that would otherwise pass without media reads. Assert direct 413 and queued `errored`/no result before any action, plus within-limit control. Exercise authorized selected Artifact metadata through the existing hosted admission fixture with lowered limits. No large allocation is needed for declared File-size rejection; a small Artifact fixture and lower individual limit suffice. Run those exact cases and only the affected existing route/hosted slice.
