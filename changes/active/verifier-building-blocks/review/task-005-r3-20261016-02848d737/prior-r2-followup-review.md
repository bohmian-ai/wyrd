## Smallest safe correction boundary

Keep the correction in the existing invocation-owned **ToolSession / AgentExecutor**, where the refusal is produced and its lifetime is owned. Make first Busy refusal wake the awaiting Agent invocation, so that invocation returns the recorded Busy and drops its pending Agent/tool futures while still inside the outer deadline. Retain latched first-reason state and a race-safe wait, using the already-installed Tokio synchronization facilities; no new dependency, global cancellation service, or public contract is required. The post-run check may still serve the already-completed/error race. The required behavior is timely propagation of a refusal already observed before the deadline, not overriding a caller cancellation or reviving an expired execution.

Do not alter generic Skald ordinary tool-error behavior, promote all query/provider errors to Busy, patch terminal outcomes afterward, serialize all tools, reserve Python capacity for an entire execution, or add a queue/scheduler. Keep accepted authority, audits/domain grants, workspace/worker ownership, Python reservation refunds, direct deadlines, lease loss and shutdown unchanged. Dropping the run cancels its owned tool futures; this recommendation makes no stronger promise to roll back already-performed work or synchronously settle remote queries. The query's existing independent deadline/lifecycle remains its owner's responsibility.

The hook-only mechanism is insufficient at the consumer boundary it owns. A session-owned wake is justified because a Busy tool error cannot use Skald's ordinary model-visible failure semantics without changing every Agent's tool behavior. No product/concurrency policy choice or unapproved runtime composition work is needed to finish the already-approved refusal invariant.
