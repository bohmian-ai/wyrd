### FIND-TASK-001-2 — Result-producing attempt timeout bypasses started-work settlement

**Sources:** closure review's continued FIND-TASK-001-2; INV-R1-001; CON-R1-001; SYS-R1-001. **Status:** REVISED. **Classification:** INCORRECT / incomplete prior cleanup correction. No new ID.

**Violated obligation:** approved revision-2 REQ-012 and AC-009; original task and R1 extraction cleanup obligation. Started bounded extraction may finish during cleanup, but may not outlive completed invocation cleanup. R1 expressly requires joining existing work before cleanup is complete; retaining workspace/guards alone is insufficient. REQ-011's shared active cap is also exposed when a logical invocation retries before prior work settles.

**Exact source and reachable trace:**

1. Hosted Blocks (`hosted/blocks.rs:197–207`) forwards Agent actions into AgentExecutor. HostedTools::open (`hosted/tools.rs:139–179`) creates Invocation/TaskTracker and stores `work.close(); work.wait().await` only in ToolSession's settlement future.
2. A supported direct or nested fs.extract starts. Invocation::call/blocking (`hosted/tools.rs:273–317`) moves owned writer and Dispatch permit into actual blocking work; Workspace::extract (`workspace.rs:720–764`) can still persist scratch. Both origins share Dispatch; no alternate extractor is implicated.
3. AgentExecutor::invoke (`blocks/agent.rs:410–422`) reaches session.close only after its inner Agent loop returns or Halt wins. ToolSession::close (`blocks/tools.rs:242–250`) consumes/awaits the sole settlement future. This correctly fixes ordinary inner completion but is itself cancellable.
4. Engine::attempt (`blocks/engine.rs:658–702`) supports an authored step timeout earlier than the execution deadline. Its `timeout_at(at, self.actions.execute(call))` drops the complete executor future on expiry, including a session or pending close. It immediately makes the retryable `timed out` result, retries while allowed, or constructs Attempted with ToolCalls::settled. No settlement await exists on that timeout branch.
5. The blocking closure continues, retaining its old workspace/permit. A retry opens a new session with a new Dispatch semaphore (`blocks/tools.rs:317–328`); old work can overlap its new non-code work despite cap 1, or occupy workspace capacity and cause Busy. Without a retry, a produced failed step can settle while old scratch work continues. This is a supported timeout configuration; bounded input/extraction size does not establish a completion-before-authored-timeout guarantee.

**Meaningful consequence:** attempt progression/result settlement claims completion before required bounded host cleanup. The fixed guards prevent premature deletion and writer release; they do not prevent old/new attempt overlap or capacity remaining occupied after reported completion. This is an explicit lifecycle/concurrency obligation, not speculative hardening or a demand for rollback.

Reject those broad additions as independently blocking remediation here. Preserve their existing cancellation, lease safety, no-partial-result and worker/query cleanup semantics during the bounded fix; inspect affected callers if the fix changes their ownership. Do not require async Drop, synchronous runtime-thread waits, durable cancellation journals, process termination or a new lifecycle service. The concrete engine-controlled retry/result path alone sustains this finding.
