## Proposed residual finding

### SYS-R1-001 / FIND-TASK-001-2 — result-producing step timeout bypasses started-work settlement

Classification: **INCORRECT / MISSING**, partial closure of the existing finding, not a new ID or an expanded async-drop guarantee.

Violated obligation: revision-2 REQ-012 and original task Scenario 4 require timeout cleanup to settle started bounded extraction, with no detached work after cleanup. R1 FIND-2 expressly requires joining started work into hosted attempt cleanup and covering exit causes through that owner. Merely retaining resource ownership is not the full required settlement observation.

Exact path:

1. An Agent step with supported `timeout_seconds` runs direct `fs.extract`, or Python awaits that declared child. The extraction starts and remains within its existing input/page/output limits; those bounds do not guarantee completion before an independently short step timeout. `Invocation::blocking` starts it in `TaskTracker::spawn_blocking`, holding writer, workspace Arc and non-code permit (`hosted/tools.rs:306–320`).
2. At the earlier step deadline, `Engine::attempt`'s `timeout_at(at, self.actions.execute(call))` expires (`engine.rs:676–683`). It drops all of AgentExecutor::invoke, whether it is still running the tool loop or already awaiting `session.close()` (`agent.rs:419–422`). Started blocking work cannot be stopped by dropping its JoinHandle. No other caller then polls the session's settlement future.
3. Engine converts expiry to retryable timeout and either starts another attempt immediately or builds `Attempted` with `tool_calls.settled()` (`engine.rs:685–702`). Thus an observable failed/inconclusive result, or a fresh authored attempt, can proceed before the extraction settles. The old workspace and permit remain held, and extraction can still reach `persist_noclobber` (`workspace.rs:758`) after the timed attempt returned. A retried session uses a fresh workspace/Dispatch; its cap does not wait on the old permit. Under a small workspace ceiling the retry can instead hit Busy solely because old attempt cleanup is still outstanding.

Meaningful consequence: the explicit timeout/cleanup contract remains false for a supported result-producing timeout, even though same-workspace serialization and resource lifetime are now safer. Completion/attempt progression is reported before bounded cleanup, so subsequent work can overlap old active operations or face capacity still occupied by a supposedly settled attempt. This is not a demand to crash the parent, roll back scratch writes, interrupt an arbitrary blocking system call, or manufacture a VerificationResult for dropped requests.

Proof gap: `extraction_settles_before_workspace_release` (`tools/pg_tests.rs:329–358`) directly calls `blocking`, drops the await, then explicitly `work.close()`/`work.wait()`. It proves ownership and tracker behavior, not that the deployed timeout owner awaits it. `interrupted_blocking_work_keeps_its_permit` releases held work before its CodeTool returns. Both can pass with the engine bypass intact. The implementation evidence correctly discloses this limit; disclosure does not close the obligation.

Smallest correction boundary: preserve existing step timeout/retry/error semantics, but make the existing engine/Agent/hosted cleanup ownership distinguish stopping execution from completing started-work settlement. A result-producing timed attempt must finish its existing tracked bounded work before publishing settled completion or opening a replacement attempt. Reuse TaskTracker/ToolSession rather than add an extraction service, durable store or per-tool downstream guards. Leave unrelated healthy server capabilities available and keep ordinary domain errors catchable. No implementation shape is prescribed: retaining the existing owner/settlement until the timeout path has joined it is the required outcome. If a timeout must return before this allowed bounded cleanup, it cannot also claim attempt cleanup is complete.

Focused closure proof: deterministically hold started work at the existing blocking/owner seam, drive the actual engine step timeout with a longer overall execution deadline, and show it stops further model/tool dispatch but does not finish the timed attempt or start its retry while work is held. Release it, observe the established failed-step/inconclusive or authored-retry behavior, zero late values/mutations after completion, and a fresh invocation reusing capacity. Exercise this source seam, not host load, sleeps or another worker harness. Preserve no-result external cancellation and process-death semantics; no async-drop promise is requested.
