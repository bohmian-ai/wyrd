## Independent source trace and correction burden

`blocks/tools.rs:101–260` restricts the existing state rather than introducing replacement orchestration. Non-Clone `ToolCallsOwner` alone constructs the private `ToolCalls` state and exposes settlement/record reading. Cloneable `ToolCalls` has private fields, no Default and only private accounting/record/registration methods. Repository Rust reference search found no conversion, constructor or method by which an executor handle can recover or drain its caller's owner. `ToolSession::register_with` (`:315–326`) takes its optional settlement once and immediately registers it. The existing CallLog/request atomic/record slots remain the same state.

`AgentExecutor::invoke` (`blocks/agent.rs:354–434`) registers immediately after toolset open, before fallible resolution. No await separates opening from registration. Its loop/Halt outcome is captured, the session is dropped, and the existing error priority is retained. The Agent drain is removed. Resolve/run/Halt errors after registration return to the same caller-owned completion path.

`VerificationEngine::attempt` (`blocks/engine.rs:650–707`) keeps one owner outside both the retry loop and `timeout_at`. It captures execution's result or existing retryable timeout, settles, finishes timing, then handles Busy/retry/Attempted and records. Cleanup crossing the authored timeout cannot overwrite an earlier Terminal/Busy outcome; still-pending execution retains its previous timeout/retry policy. `judge` (`:733–808`) likewise captures executor success/error, settles, then performs Busy, cited/inconclusive classification and record publication. There is no intervening early return.

Hosted Blocks (`hosted/blocks.rs:197–223`) forwards the same BlockCall. HostedTools::open (`hosted/tools.rs:139–180`) remains the production producer of TaskTracker close/wait settlement. Invocation::blocking (`:295–317`) still moves writer and active permit into actual tracked work; the extraction closure captures Workspace (`:274–285`). Thus dropping delivery ends the waiter, while actual work retains the resources until the existing tracker completes. No second scheduler, runtime, service, guard, polling fallback, dependency or shutdown mechanism is added. Removing the owner would restore the timeout defect; retaining child draining would restore the duplicate capability rejected by the maintainer. This is the smallest complete correction at the existing engine/session owner.

Direct Agent helpers now capture output, settle their retained owner, then return/map/unwrap: Vala `step_recording`, `check`, inline workspace check; hosted recovered-authority/capacity closures and `CodeAgent::call`/`step`. Reference search covers the remaining constructors in crates/SDKs. Temporary-owner handles remain on Code/extract/Echo paths without ToolSession registration, so those constructors do not silently abandon an Agent settlement. These fixture changes preserve their actual result/error consumers.
