## Producer-to-consumer invariant trace

`ToolCallsOwner` (`blocks/tools.rs:101–181`) owns the existing invocation state through its private handle. It has no Clone implementation; its `Default` is the only constructor of that state. `ToolCalls` (`184–260`) is Clone but has private fields and only private accounting/record/registration methods; it has no Default, conversion to owner, settlement extraction or drain API. The executor's `BlockCall.tool_calls` is this restricted handle (`blocks.rs:100–105`). Debug exposes only counts. The split restricts an existing capability, without duplicating the workflow, transport or resource manager.

`AgentExecutor::invoke` opens a session, immediately registers its settlement (`agent.rs:384–385`) and only then resolves declared tools. Consequently resolution failure after opening, normal completion, typed Halt, provider/run failure and subsequent check output/citation failure all leave settlement with the caller. `ToolSession::register_with` takes the session's Option once and defers it through the handle (`tools.rs:313–324`); no await or error boundary occurs between opening and registration. The Agent child drain is gone (`agent.rs:410–434`). It captures Halt before dropping the session and preserves the existing error priority.

Production callers constructing invocation state are `VerificationEngine::attempt` and `judge`. In `attempt` (`engine.rs:660–704`), the owner survives outside the authored timeout and across retries. Only `actions.execute` is timed; its returned result/error or retryable timeout is captured first. The next operation awaits owner settlement. Timer, Busy return, retry decision and Attempted/record publication occur afterwards. Earlier Terminal/Busy cannot be overwritten by cleanup crossing the authored timeout. A still-pending action times out using the prior retryable policy. The request counter and records remain in the same Arc-backed CallLog across every attempt; there is no reset/refund on cleanup.

In `judge` (`engine.rs:772–800`), execution result is captured, settlement awaited, then success/citation judgment, Busy return or inconclusive error are classified and records read. This covers executor errors as well as successful answers. Early returns before opening have no registered work; every error after registration returns through the engine completion boundary. Hosted `Blocks` (`hosted/blocks.rs:197–222`) forwards the same BlockCall and adds no competing lifecycle owner.

The unchanged actual host producer remains `HostedTools::open` (`hosted/tools.rs:139–180`): one Invocation/TaskTracker, one registered `work.close(); work.wait().await` settlement. `Invocation::blocking` (`295–317`) keeps writer and active-operation permit inside tracked blocking work. Workspace capture/owned guards remain unchanged. Dropping a suspended tool ends its delivery future, and unfinished record slots retain cancelled/no-value evidence; caller cleanup waits for actual work without creating a late recipient. The new owner does not create an owning-reference cycle: the settlement retains the tracker, while dispatch/Delivery retain the CallLog handle.

Direct Agent fixture helpers now capture the executor result and explicitly settle their retained owner before returning: `blocks_agent.rs:323–381`, inline check `1045–1067`, hosted authority/capacity closures (`pg_hosted_artifacts.rs:858–881`, `946–963`, `1163–1181`) and `CodeAgent::call` (`1823–1855`).
