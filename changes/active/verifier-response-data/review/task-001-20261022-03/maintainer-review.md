## Material finding

### MNT-001 — Python's authored Check projection omits code response formats

- **Classification/severity:** MISSING; should-fix, blocking public declaration parity.
- **Location:** `sdks/wyrd-sdk-python/python/wyrd/verify/__init__.pyi:218` (`CodeCheck`), consumed by the changed generic `RequirementResult` at line 264 and its `check: Check` field at line 281. Producer: new `crates/wyrd-spec/src/card/verifier/mod.rs:477` `CodeCheck.response_format`.
- **Governing obligation:** TASK-001 scenario 5/acceptance 5 requires authored Python stubs and public types to describe the implemented feature; Python AGENTS requires precise authored native declarations; maintainer style says types carry the contract. `RequirementResult` expressly documents `check` as the Verifier's authored declaration.
- **Evidence and concrete cost:** The runtime serializes the complete check through `Judged::report` into `RequirementResult.check`. A scored code requirement therefore returns `check.response_format`, including its declared custom schema. Rust and generated TS `CodeCheck` expose this field, but Python's `CodeCheck` TypedDict ends at `inputs`. After narrowing a returned `Check` to `kind == "code"`, a Python maintainer/user cannot inspect the returned declaration with the advertised types: the project's installed `ty` reports `invalid-key: Unknown key "response_format" for TypedDict CodeCheck`. The current type fixture exercises only old code shapes, so the full typing lane does not expose the omission. This is an actual valid return shape rejected by the public declaration, not a preference about type names or layout.
- **Smallest safe correction:** Add the optional wire `response_format` member to the existing Python `CodeCheck` TypedDict with the supported scalar/expanded named format shape (JSON schema data, not a Python model instance in a returned record). Keep it absent for old/plain undeclared checks. Extend the existing `tests/typecheck/verify_contracts.py` fixture to accept/narrow a custom code-check declaration and access its optional format. Use the existing runtime journey to assert the returned authored check where useful; no transport, native type, new decoder or generator is needed. Nearby patterns are `AgentCheck`'s authored fields and the generated TS `CodeCheck` declaration.
- **Focused independent reproduction:** A temporary external Python module importing `Check` under `TYPE_CHECKING`, narrowing `check['kind'] == 'code'`, then returning `check['response_format']` fails with the above exact diagnostic using `mise exec -- sdks/wyrd-sdk-python/.venv/bin/ty check --project sdks/wyrd-sdk-python --extra-search-path sdks/wyrd-sdk-python/python /tmp/wyrd-maintainer-verdict-parity.py`. No repository source was changed for the reproduction.
