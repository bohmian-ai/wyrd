## Proposed findings

### CONC-I-1 — INCORRECT: cancellation/expiry is checked before IO, not at checkpoint acceptance

**Location:** `crates/wyrd/wyrd-server/src/verification/state.rs:660–683`, `StateScribe::write` at `:275–298`; acceptance sink `crates/vala/vala-sql/src/queries/scribe_state_heads.rs:137–149`.

**Violated obligation:** REQ-057 and DUR-009/010 explicitly retain cancellation, lease validity and deadline protection; the durability supplement says a stale or expired worker must not gain acceptance merely because a replacement has not run. Architecture canonical verification state likewise retains expiry/cancellation protection. This is also a regression from the removed PostgreSQL checkpoint/publication owner, whose queue-row lock checked running status, current token, unexpired lease and deadline together with the write.

**Reachable producer-to-consumer path:** A queued worker mutates state and calls `durable`. Its `HeldLease::confirm` successfully commits renewal. It freezes the revision, then its shared write waits for reserved capacity or reaches an outbox/Scribe whose acknowledgement is delayed. The user cancels the execution and commits that transaction. `VerifierExecutionQueue::cancel` changes only `wyrd.verifier_executions` (`verifier_executions.rs:612–619`); principal revocation's `cancel_principal` similarly changes only that queue authority. Neither invalidates `vala.scribe_state_heads`. Release the held revision before the original execution deadline. `scribe_state_heads::advance` still sees the same writer and expected revision, and `not_after` is only `run.deadline_at` (`runner.rs:485–490`). It accepts the revision after cancellation. The same missing acceptance condition applies if the queued lease has expired and no replacement has yet claimed the state. Process cancellation may drop the waiter, but cannot retract the write already owned by the shared outbox.

**Consequence/materiality:** A cancelled execution can acquire a new durable invocation, settlement, publication or terminal selection after its cancellation boundary. That state becomes recoverable/inspectable even if queue completion is correctly refused. Losing the response does not repair the accepted-state integrity violation. This is an ordinary cancellation during bounded storage backpressure, not a special malformed input.

**Sibling owners checked:** `begin`, `forget`, `settle`, `select`, both publication paths all converge on `durable` and `StateScribe::write`; queued submit/scheduled/group work uses `runner::state`. Direct executions deliberately have no queue lease. Queue completion/termination checks do not fence the independent Bifrost acceptance transaction. Periodic renewal detects cancellation later but cannot unsend staged writes. Takeover fencing is correct once a replacement changes the head; it does not cover cancellation/expiry before that change.

**Smallest correction boundary:** Preserve the single generic Scribe writer/fence and PostgreSQL queue authority, but make acceptance of a queued state's revision contingent on its still-current running token and unexpired lease in the authoritative acceptance ordering. Cancellation/revocation and acceptance must order on that existing authority, rather than trusting a prior successful renewal. Keep direct execution semantics, expected-next revision, stable batch retries and replay suppression. Another `confirm` immediately before staging is insufficient because outbox/Scribe IO follows it; no second scheduler, execution payload store or background writer is needed.

**Focused proof:** Hold one queued checkpoint after successful lease confirmation and before its Scribe acceptance. Commit authorized cancellation, release it, and assert StateRefused/no advanced head or new recoverable publication/invocation; restart/replay and assert unchanged accepted state. Exercise expiry without replacement separately under the same seam. Existing takeover and normal queued/direct acceptance tests should remain green. The existing cancellation test at `pg_durable_verifier_work.rs:1296–1302` only starts the attempted write after cancellation and therefore does not cover this race.

### CONC-I-2 — REGRESSION: an already-covered publication replay bypasses stale-lease refusal

**Location:** `state.rs:502–513`, `:531–532`, `:563–569`, and the covered fast path `:654–655`.

**Violated obligation:** TASK-001 preserves attempt-scoped receipt/replay semantics and lease cancellation; REQ-057/058 and DUR-008/009 preserve existing publication authority. At the base, `verifier_executions/publications.rs::publication_receipt` runs `HELD_SQL` before returning a receipt, and `accept_publication` takes `LOCK_SQL` with running/token/expiry/deadline predicates before returning an existing holder. The existing task test explicitly expects replay under a stale lease to refuse.

**Reachable path:** Accept a JSON or file publication and complete all pending revisions. Cancel or expire its queue lease, or reclaim it with a new writer, without first attempting a different write on the old `RunState`. Replay the original call as the first operation on that old state. `held.broken` is still false; the old state finds the receipt, uses `held.changes` as ticket, and `durable` returns success because that ticket is already covered. Neither `StateScribe::confirmed` nor a state-head check runs. `Publications::json` reaches `accept_publication`, while `Publications::path` reaches `publication_receipt` before scratch/storage; both return the successful old receipt. Restored state starts with `changes = covered = 0`, so it has the same bypass.

**Consequence/materiality:** The hosted publish contract answers success to an invocation that no longer owns its execution, where the prior owner refused it. This does not erase or forbid authorized inspection of retained accepted publications: the regression is the running tool's stale execution-authority check. It is deterministic and reachable on lost-reply replay around cancellation/takeover.

**Smallest correction boundary:** Reuse the existing held-lease confirmation at the publication replay/success boundary, outside the memory lock, so covered durability is not mistaken for current execution authority. Preserve valid same-call replay without creating a redundant checkpoint. This check belongs to the hosted publication receipt capability; do not make retained inspection depend on an active lease. Fix both JSON acceptance/replay and file preflight replay through their common authority path. This closes the already-covered fast path; it does not substitute for CONC-I-1's acceptance ordering.

**Focused proof:** After one fully accepted publication, make stale same-call replay the first operation after cancellation and after takeover, asserting refusal for JSON and file preflight paths without first issuing a fresh stale write. Also prove a live same-call replay returns its original receipt without adding a revision. The current test `publication_replay_preserves_attempt_identity` attempts a fresh stale publication at `:799–807` before replay at `:809–812`; that sets `broken` and masks the bypass.
