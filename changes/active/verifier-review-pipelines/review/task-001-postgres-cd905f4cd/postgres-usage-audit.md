## Material deviations and minimum correction boundary

### USER-PG-001 — directed removal of per-execution SQL authority

This is explicit user direction, **not** an independent reviewer finding. Source is the three new `scribe_state_heads` operations above, new table, state.rs claim/accepted, batch record advance, state transport/fence plumbing and migration commentary. Current writer generation, accepted revision and authoritative absence are answered by PostgreSQL. Keeping those rows and moving claim/advance into a Scribe background task leaves the rejected authority intact.

Remove the new table/query owner and its application/public-read dependency. Extend/reuse existing Bifrost verification records, shared writer/WAL/batch-commit/replay/read owners for accepted execution position and checkpoint state.
