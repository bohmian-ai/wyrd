## Challenged cases and materiality

The linear fence walk is added read work, not a replacement persisted head or lease protocol. It reuses the existing tenant-qualified immutable batch authority and changes no generic fence retention. Removing it would reintroduce the documented stale/latest-visible recovery gap. No alternative existing owner was found that certifies the accepted execution position without it.

An owner outage can still cause an ordinary analytical query to omit data. That does not violate recovery here: the accepted revision is obtained before the query and an exact missing row becomes Unavailable. Similarly, a published/hot visibility gap causes temporary unavailability rather than stale continuation. No new source registry is needed to make this safe.

Two writers racing the same revision can offer different rows. The first durable batch owns the identity, the other is refused whole, and recovery can inherit the accepted state. The accepted old-worker interval therefore remains represented without demanding an additional ownership mechanism. A previously refused WAL attempt cannot return through replay because replay uses the canonical fence coordinates; a never-fenced execution checkpoint is suppressed.

No new retained finding is proposed. Prior findings 24/25's rejected-head causes are removed; this report does not assign those IDs to generic permitted batch metadata or reopen the withdrawn stronger ownership requirement.
