## Proposed finding

### DATA-R5-01 — REGRESSION: runnable-tenant plan test rejects the retained delivery index

**Location:** `crates/wyrd/wyrd-sql/src/queries/verifier_executions.rs:4397–4400`, with governing query at `:757–773` and plan walker at `:4305–4319`.

**Obligation:** R5 preserves bounded fair tenant discovery, the retained terminal-delivery migration/index, and affected SQL regressions. Root testing rules require the narrow relevant gates and prohibit bypassing a red gate. The established exact test is already named in `tasks/verification.md:99`.

**Source-proven failing path:** The R5 diff removes `verifier_executions_delivery_due` from the plan assertion's permitted indexes and from its rustdoc, leaving only the pending/retrying and running indexes. Production `RUNNABLE_TENANTS_SQL` still has the recursive `owing` term and the materialized `delivering` probe, both reading `verifier_executions` by `delivery_due_at`. Those reads have no status restriction and therefore cannot be satisfied by either allowed status-partial index. Their valid index is the deliberately retained `verifier_executions_delivery_due`. The plan walker visits every relation-read node, including recursive and scalar subplans, regardless of whether the empty-delivery branch produces rows at execution. Consequently that valid plan fails the assertion; a fallback sequence or other index scan also fails it.

**Consequence/materiality:** The changed existing PostgreSQL gate cannot accept the required terminal-discovery query. This is a bounded test regression from rollback/rebuild, not evidence that production tenant scanning is wrong. The recorded GREEN for SQL integration `terminal_deliveries_are_settled_only_by_their_latest_claim` does not execute this library test.

**Orchestrator execution corroboration:** The orchestrator subsequently ran the exact test on the pinned source with repository PostgreSQL and tracing: `mise exec -- scripts/postgres/with-test-postgres.sh -- bash -lc 'mise run db:migrate:all:inner && WYRD_LOG=info,wyrd_sql=debug cargo nextest run --locked -p wyrd-sql --lib -E "test(=queries::verifier_executions::pg_tests::runnable_scan_walks_the_claim_indexes_however_large_the_backlog)"'`. Wyrd/Vala migration apply/idempotence each passed 1/1. This independently executed result corroborates the source diagnosis; this domain reviewer did not run Cargo.

This local correction keeps the same bounded-scan property while acknowledging the approved extra partial index; no production/schema/concurrency decision changes.
