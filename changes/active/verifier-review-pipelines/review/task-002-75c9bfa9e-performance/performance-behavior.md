## Default working-set envelope

Defaults from `hosted/mod.rs:136–159`: 16 admitted workspaces, 50 MiB work/tree bytes, 20 MiB per published file, 100 MiB accepted publication bytes per execution, 1,000 accepted publications, 64 KiB result bytes, and 60-second direct verification timeout. These values can be configured; they are not universal hard limits.

The bounds multiply. Because freeze releases the writer before upload and final accepted-byte admission happens after upload, multiple calls can retain frozen buffers simultaneously. A deliberately slow storage operation can keep one tree's bytes alive while another call snapshots the same workspace. With default C=8 and W=16, a coarse frozen-payload envelope is:

`W × C × 50 MiB = 6,400 MiB = 6.25 GiB`.

This is source-derived capacity arithmetic, not measured RSS, a guaranteed attained peak, or an assertion that all deployments permit enough concurrent Agent steps to fill W. It excludes provider response/argument copies, provenance, disk cache, storage buffers and execution-state revisions. A 50 MiB tree can be composed of several files below the 20 MiB file limit. The 100 MiB cumulative accepted-publication limit does not prevent this transient staging overlap: calls can perform their uploads and be refused only when they reach final acceptance. Conversely, per-workspace writer exclusion prevents concurrent walks/writes of the same mutable tree; snapshot buffers are not created by an unbounded detached publication worker.

Argument retention is a separate amplification: `ToolCallRecord.arguments` stores the whole fs.write content, even for an overwrite or a refused write. `InvocationSettlement::Action` contains the StepResult, whose tool_calls carry those records (`wyrd-spec/src/verification/execution.rs:378,404,763`); RunState::settle clones that settlement (`state.rs:1032–1050`). Rewriting one small on-disk workspace repeatedly can therefore accumulate much more provenance than the workspace's final byte count. Later full-state checkpoint copies/counting/encoding traverse that retained content. The existing result-size, workspace-byte and accepted-publication budgets must not be described as a cumulative bound on this record payload. This follows the task's preservation of existing recording; no new redaction/capture contract is inferred from the performance request.

No approved process-wide ceiling for these buffers or measured exhaustion under a supported deployment was supplied. Per-tree/concurrency/workspace bounds therefore establish a potentially large bounded working set, not a source-proven new violation. The Monty pool's 2 GiB default is for Python workers and must not be represented as covering these host-side publication allocations.
