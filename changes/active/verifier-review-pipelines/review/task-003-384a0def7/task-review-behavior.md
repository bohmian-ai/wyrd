## Proposed finding

### BEH-003-1 — Agent checks spend durable invocation budget while waiting for admission

- **Classification:** INCORRECT.
- **Violated obligation:** REQ-008: invocation ceilings count Agent invocations and capacity admission must not spend an attempt; task admission scenario/O-L65 requires no pre-dispatch spend, O9.2 and OL require correct cumulative accounting across recovery.
- **Location:** `crates/vala/vala-verify/src/blocks/engine.rs:1498`–1506 (`requirement`), versus `:1660` (`judge` admission). Recovery counts these records at `:460`–485.
- **Producer-to-consumer trace:** A prepared Agent requirement executes `engine.spend()`, constructs the next producer, and awaits `engine.begin()` before it calls `judge`. `judge` then waits for the per-execution and shared semaphores through `admit`. Two sibling Agent checks with `limits.concurrency: 1` can therefore both persist begun attempts while only the first has reached the executor. The second waits without having invoked its Agent. If this queued execution is interrupted and reclaimed, `with_checkpoints` takes the maximum recorded attempt for each instance and `agent_attempts` sums both. The unexecuted waiting check is now permanently charged against `max_agent_invocations`. A ceiling that would allow the actual work can instead produce `BUDGET_SPENT` and an inconclusive judgment before the waiting check ever runs.
- **Reachability/materiality:** Multiple Agent requirements and bounded concurrency are ordinary authored behavior. Restart/reclaim is explicitly supported, not an unusual external input. With two checks, cap three, and a crash while check A runs/check B waits, A's resumed invocation can spend the last charge and B never receives its first invocation. The verdict changes because capacity waiting was treated as model work. The persisted pre-admission attempt also falsely reports an invocation that never reached the executor.
- **Sibling/owner comparison:** Agent actions already do the required ordering: `attempt` awaits `admit` at `:1567` before `spend`, producer creation and `begin`. Agent checks share `requirement` and `judge` for both step and whole-Verifier positions; this is one shared-owner correction, not one correction per caller. Busy/definition refusal handling must continue to forget its attempt, and successful admission must still precede durable begin-before-executor dispatch.
- **Smallest testable correction:** Make the existing requirement admission boundary precede Agent budget charging and begun-attempt recording, consistent with actions. Keep one admission acquisition and preserve non-Agent checks, cancellation, checkpoint acceptance, and Busy handling. No new scheduler, durable field, refund protocol, or SDK change is justified.
- **Focused closure proof:** In the existing scripted engine/checkpoint test owner, hold one Agent check under a one-slot run limit, poll its sibling check until it waits, and assert the waiting sibling has no invocation record or budget charge. Interrupt/recover and assert exact executor calls and remaining ceiling. Existing `agent_budget_counts_retries_and_is_never_replenished` at tests.rs:3556–3684 proves active-action interruption and check charging, but never interrupts a check waiting for a permit. `waiting_blocks_release_unrelated_permits` proves permit ownership, not this accounting boundary. No new test was run or added during this immutable review.
