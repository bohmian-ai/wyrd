## Proposed finding INV-003-1

**Classification:** INCORRECT. **Location:** `crates/vala/vala-verify/src/blocks/engine.rs:1500–1513`, with the downstream admission at `judge:1660`.

**Violated obligation.** TASK-003 Scenario 1's admission proof explicitly requires “no pre-dispatch spend”; REQ-008 counts Agent invocation attempts, including checks, and retains that spend across recovery. Queue/capacity waiting must not manufacture an invoked check. This is not a proposed new fairness policy.

**Producer and failing path.** `requirement` spends the Agent budget, constructs the next Producer, and awaits durable `begin`. Only afterward does `judge` await `admit`, which first waits for the run permit and then the shared engine permit. For example, after steps settle, a slow code check holds the sole run permit while a sibling Agent requirement is ready. Polling that sibling records its Agent attempt and consumes the invocation budget although `CheckExecutor::execute` has never been called. A worker crash/takeover during this ordinary capacity wait leaves the invocation record durable. `with_checkpoints` includes that producer in `attempts`; `agent_attempts` counts it on recovery. With `max_agent_invocations: 1`, the restored requirement reports budget-spent/inconclusive without ever calling its Agent. This changes the verdict/evidence of a supported bounded pipeline because capacity waiting consumed its only allowed invocation.

**Sibling owners checked.** Action `attempt` already obtains `admit` before `spend` and `begin`; per-item/repeat and top-level requirements all share the defective `requirement` path. Both Agent and non-Agent checks call `begin` before `judge` obtains permits, so persisted phantom interrupted check attempts originate in the same owner. `RunState::begin` correctly retains the producer it is given; `agent_attempts` correctly conserves recorded attempts. Fixing either storage or recovery would weaken real interrupted-attempt accounting instead of repairing the producer.

**Smallest correction.** Move the existing check admission boundary ahead of its budget spend and durable begin, using the same engine/run permit owner and ordering as actions. Keep the permits through that check, preserve WAL acknowledgement before executor dispatch, and preserve Busy/unavailable forget behavior and real interrupted-attempt accounting. Do not add a second budget, new persisted dispatched marker, or recovery filter: those duplicate an existing admission mechanism and are unnecessary to stop this invalid state being produced.

**Correction burden/materiality.** This is a local ordering correction in the existing requirement/judge owner and one focused regression, not new scheduling machinery. Deleting budgeting or forgetting interrupted records would break required cumulative bounds. The consequence is material even without provider side effects: the sole budgeted check is permanently refused after a supported restart although no invocation occurred.

**Focused closure proof.** With the existing scripted executor/checkpoint fixture, hold the run's only permit in a controlled slow check, make a sibling Agent requirement wait, and inspect the accepted checkpoint before releasing capacity. Assert the waiting check has no invocation record and no executor call. Interrupt and restore under a one-Agent-invocation ceiling; after capacity is available, assert that Agent check executes once and produces its verdict. Also retain the existing test proving genuinely dispatched interrupted work consumes budget. No new harness or provider is needed.
