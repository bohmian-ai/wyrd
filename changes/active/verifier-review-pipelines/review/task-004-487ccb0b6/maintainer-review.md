## Proposed findings

### MAINT-004-01 — Phase rewriting introduces a second, untyped reference traversal

Classification: **VIOLATION / INCORRECT**.

Changed location: `crates/shared/wyrd-loader/src/lib.rs:88-140`, especially `direct` at 116–140.

Governing rule: `architecture/wyrd-design.md`, “Reference-slot inventory”, requires one canonical slot inventory used by loader and diagnostics. REQ-038 requires existing reference-slot validation/workflow reuse. Maintainer guidance requires extending the existing owner before adding another traversal.

The existing alternative is `wyrd_spec::refs::ReferenceSlotVisitor`/`SlotValue`, already used by loader `resolve.rs:68-115`, validation, graph construction, and server `components/cards/resolve.rs:712-750`. It distinguishes reference positions from ordinary data. The precise new gap is converting a Sibling to a direct ref after that dependency has been declared in an earlier phase; an extension of that typed mutation surface is sufficient.

Instead, `direct` recursively visits every JSON object/array in the submission and replaces any single-key `{"sibling": card}` whose identity matches a heavy submission. A Verifier using an artifact-backed code step can legitimately assert an exact JSON result with `check.expected = {"sibling":{"kind":"Artifact","name":"code","version":"1.0.0"}}`. `Check::Assert.expected` is arbitrary `serde_json::Value` (`wyrd-spec/src/card/verifier/mod.rs:799-814`), not a reference slot. If that same Verifier imports the `code` Artifact, `phases` changes the expected value to the bare CardRef before declaration. The engine then judges a different assertion from the authored one. The same traversal also reaches arbitrary literal payloads nested elsewhere in a spec.

Concrete cost/consequence: maintainers must reason about two inconsistent definitions of a Card reference; ordinary data can silently acquire reference semantics. This changes declared verification behavior, rather than merely formatting a private value. The existing phase test asserts the true source slot changed but never asserts arbitrary literal data survives.

Smallest correction: remove the unrestricted JSON traversal and perform the cross-phase rewrite only through the canonical typed reference visitor, extending its mutation operation narrowly if needed. Preserve external refs and every non-reference JSON value. Do not create a second JSON-path/reference inventory or per-kind parser. Focused proof: phase the existing heavy-import fixture with a matching reference-shaped `expected` literal; assert the real source slot becomes direct while `expected` remains byte/value-equivalent, and check representative nested typed slots still transform.

### MAINT-004-02 — Phase partitioning discards the existing dependency order

Classification: **INCORRECT**.

Changed location: `crates/shared/wyrd-loader/src/lib.rs:72-104` (`DeclarationInput::phases`); reachable consumer `verification/repositories.rs:731-750`.

Governing rule: REQ-038 and AC-027 require transitive local graph declaration with existing heavy-artifact completion. `architecture/wyrd-design.md`, “Path resolution rules”, requires imported Cards in dependency order and expressly permits transitive imports. `DeclarationInput.submissions` already documents dependency-first ordering; `order.rs:13-78` obtains that order from the canonical graph owner.

The precise new gap is splitting a valid dependency-ordered declaration into legal single-heavy/composite phases. No new graph store or topological algorithm is needed: the input already carries the canonical order and typed dependency slots.

`phases` partitions every artifact-bearing submission into `heavy`, moves those ahead of all light submissions, and only rewrites references in `rest`. Thus a supported tree `Verifier → artifact-bearing Artifact → schema_ref: ./schema.yaml` fails. The loader discovers and sorts the schema before the Artifact; `ArtifactSpec.schema_ref` is a real `Ref` (`wyrd-spec/src/card/artifact.rs:31-34`). Partitioning then submits the Artifact alone first, still carrying `Sibling(schema)`. Server `validate_and_collect_refs`/`validate_sibling` (`components/cards/resolve.rs:712-787`) correctly refuses it because the schema is absent from that request, irrespective of whether the schema is already registered. `declare_local` converts that refusal into a configuration Check and dispatches no review. A heavy-to-heavy path chain fails for the same reason. The source comment at 72–74 acknowledges this omitted behavior but cannot waive the transitive-import obligation.

Concrete cost/consequence: the new phase owner invalidates the existing graph owner's result and narrows a required workflow. Authors must flatten supported dependency graphs to avoid an undocumented declaration restriction; maintainers cannot rely on the ordered `DeclarationInput` invariant at its consumer.

Smallest correction: derive legal phases from the existing dependency-first order, keeping each heavy submission alone while ensuring every dependency outside its phase has already been declared and its typed Sibling reference becomes direct. Preserve the original root selection, stable phase replay, artifact-source association, complete validation and normal completion; do not invent a second graph traversal/order implementation. Focused proof: extend the existing phase/declaration fixture with a heavy Artifact's path-imported schema dependency (and a short heavy dependency chain), and assert dependency-first successful activation and eventual Verifier admission, including replay. This is one phase-construction correction, not a registry validation relaxation.
