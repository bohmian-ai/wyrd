Change Impact Map

Shows what a proposed change does inside a repository's code, whether it is a deployed service or a published library: which modules and functions it edits, which call paths now behave differently, which entry points reach them, and whether a Claim covers each path. Every map is computed on the server from the exact base and candidate commits, so the same revision always produces the same map.

How the map is computed

bohmian-code-review · extract + pipelineIndex each commit

Fetch the base and candidate trees from the provider without cloning. Parse them with tree-sitter into declarations and references. Store the result without source text, keyed by commit and extractor version.

new · on top of index + resolveBuild the call graph and diff it

Resolve references into call edges and group them by module. Compare base and candidate: symbols added, removed, or edited, and calls added or removed.

new · serverWalk back to entry points

From each edited symbol, follow callers back to routes, jobs, and tools, bounded by hop count. Label each call as resolved or ambiguous.

existing · Bifrost + EvidenceAdd what actually ran

Join functions to code.function spans from production and CI test traces. Attach the Claims and Verifiers bound to each entry point.

existing · wyrd-uiRender only

The browser lays out the server's projection with @xyflow/svelte and a fixed layout. It never computes reach or coverage.
