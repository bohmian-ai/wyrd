## MAINT-001 — The new index deduplicates across accepted workloads/environments

Classification: correctness / accepted-context regression; high priority. This is not a preference about cache implementation.

Changed locations:

- `crates/vala/vala-bifrost-redux/src/scribe/series_index.rs:43`, `:182–194`: the process cache and cross-slice selection use only tenant, UTC hour and `series_id`.
- `crates/vala/vala-bifrost-redux/src/tables/metrics/series.rs:532–543`: in-slice selection independently discards every subsequent row sharing `(hour, series_id)`.

Governing obligations: existing server-owned dimensions in `architecture/bifrost-design.md` (Table and row identity) and `architecture/wyrd-design.md` (Configured Service context / Telemetry setup ownership); REQ-058 requires index scope columns to have the same meaning as their points, REQ-060 requires the rail/pickers/labels to honor the same WHERE. `agent_docs/maintainer-style.md` requires behavior to remain with its authoritative owner.

Producer-to-consumer proof:

1. `gate/attribution.rs:98–115` builds `FrameDimensions` from `auth.workload()` and `auth.deployment_environment`, independently of raw resource/scope/point attributes. `Gate::dispatch_canonical` (`gate/mod.rs:1007` onward) attaches that context to metric ingress; its OTLP batch identity itself includes accepted workload/environment, so these are distinct admissible batches.
2. `tables/metrics/series.rs::series_ids` deliberately hashes metric meaning, bounds and the resource/scope/point identity only, as REQ-056 requires. Workload Card UID and accepted request environment are absent. Identical raw points under two accepted request environments therefore have identical ids.
3. Existing `execution_lanes.rs::stamp_dimensions` (`:1395–1400`) overwrites the point's promoted Service identity and deployment environment from that accepted context. Its existing test `built_in_rows_take_their_dimensions_from_the_frame_context` documents mixed workloads and accepted environment behavior. Architecture explicitly permits application-managed telemetry and says accepted environment overrides resource promotion.
4. Admit a metric for environment `dev`, then the same raw series in the same hour for `prod`, through one Scribe. Both points are valid; their retained `deployment_environment` differs. After the first admission `SeriesSeen` contains `(tenant,hour,id)`. The second gets no series row, because the cache hit ends index admission. Different workloads on the same unchanged raw resource have the equivalent failure. Trusted mixed-context rows can also lose the second scope inside `series_rows` before the cache is involved.
5. `observe.ts:901–909` applies `deployment_environment = 'prod'` (or the second canonical `service_name`) to `bifrost.metrics.series`; `metricSeriesBinds` does the same for key suggestions and labels. No matching row exists, while a point query under that filter succeeds. The metric disappears from its supported scoped rail, and index-based dependent reads cannot represent it.

Material consequence and maintenance cost: the index optimization now silently contradicts the existing authoritative dimension stamper. A maintainer changing configured context would have to know that a second, unrelated series-id notion controls whether scope data is retained. Restarting or overflowing the cache changes visible behavior; within-slice suppression can persist regardless. This is meaningful scoped discovery/data completeness, not an exotic input or a cryptographic collision.

Smallest correction boundary: retain the specified stable `series_id` and the existing accepted-context stamping owner. Extend index-row selection, in-batch suppression, process suppression, and deterministic series batch identity together so rows with distinct supported accepted scope cannot suppress one another. Reuse the already stamped prepared point columns; do not re-resolve Cards or add downstream fallbacks that scan all points. In particular, distinguish the effective workload/Service and accepted environment at the index writer's deduplication boundary. Repeated rows for one stable series remain valid in the existing read model. Do not include per-request timestamps/ids indiscriminately, which would turn the index back into one row per point batch and defeat AC-040. The spec sentence claiming every copied column is fixed by raw attributes needs reconciliation with the stronger existing context contract; the user has authorized potential spec deviations, so this report does not invent an additional approval stop.

Smallest credible closure proof: extend the existing embedded Scribe persistence path with two points batches sharing raw identity/hour but different accepted environments and workloads; assert stable `series_id`, correct point context, and an index row discoverable under each corresponding scope. Also exercise mixed-context stamped rows or the pure selector to ensure within-batch suppression uses the same boundary. Confirm a repeat with unchanged effective scope still emits no extra index row. No new test harness or dependency is needed. Current `points_frame` fixtures set `dimensions: None`, so the inspected repeat/failure tests do not cover this path.
