### Medium

- **SEC-R2-01 — REGRESSION / INCORRECT**, `crates/wyrd/wyrd-server/src/components/principals/routes.rs:403`: bare Bytes extraction bypasses the stable Wyrd error and permission-decision path for a supported configured body size. A deployment may set `limits.body_bytes` to 3 MiB (configuration validation at `config.rs:3466–3474` imposes only a 1 MiB minimum). An authenticated caller sends 2 MiB + 1 bytes to this route. The protected-edge Wyrd limiter accepts that size and reconstructs the request body (`body_limit.rs:193–208`), but Axum's Bytes extractor then applies its independent default 2,097,152-byte limit and rejects before `issue_credential` executes. The result is Axum's plain-text 413, without a Wyrd problem code or the route's permission audit. The previous `Result<Option<Json<CreateUserCredentialRequest>>, JsonRejection>` captured buffering rejection for the repository `body_rejection` mapper. The new `Json::from_bytes` mapping cannot catch an extractor failure that prevents entry into the function.

  Dependency source proof: locked local Axum core 0.5.6 `src/extract/request_parts.rs:100–112` (Bytes uses limited body), `src/ext_traits/request.rs:319–326` (default limit), `src/extract/rejection.rs:40–47,70–72` (413 Bytes rejection), `src/macros.rs:122–131` (status/string response). Repository search found no DefaultBodyLimit override. This is not unbounded input or demonstrated privilege escalation; it violates the explicit stable public-error contract and newly intended permission-before-body-rejection behavior under a supported configuration. Default 1 MiB deployments mask it.

  Smallest correction: retain extractor failure as a handler-owned result and render it through the existing Wyrd error mechanism at the same authorized, tenant-target-validated boundary as other body refusals. Preserve the existing global and extractor bounds, Service empty-body behavior, closed User parsing, and nonblocking audit; no new parser or auth service is warranted. Focused proof: configure a protected server with 3 MiB body allowance, send 2 MiB + 1 bytes to an existing allowed target and an unauthorized/foreign target, and assert stable problem+json/error code and intended permission/target precedence. Also assert a request over the configured Wyrd limit still gets its existing Wyrd PayloadTooLarge envelope. Root was asked to reproduce the exact path; this reviewer did not run Cargo or add tests.
