### FIND-TASK-004-10 — Credential body extraction can escape the stable HTTP error boundary

**REVISED; REGRESSION / VIOLATION.** Discovery sources: SEC-R2-01 and REPO-R2-1. Changed location: `crates/wyrd/wyrd-server/src/components/principals/routes.rs:403`, bare `body: axum::body::Bytes` in `issue_credential`.

**Violated obligation.** Root server-handler/agent-surface rules require Wyrd errors and stable codes. `agent_docs/errors.md`, Public errors and Per surface, requires public HTTP errors through the single Wyrd problem mapper. Original task preserves stable errors and server audit behavior. This public principal endpoint has no gateway/provider-envelope exception. The finding relies on that explicit contract, not an assertion that giant credential requests are a normal successful workflow.

**Independent producer-to-consumer trace.**

1. `config.rs:2364–2366,3188–3194,3466–3474` exposes `limits.body_bytes`, accepts a configured 3MiB ceiling and validates only the1MiB minimum. Default is1MiB. A caller with a valid authenticated session/token can POST application/json, 2MiB+1 bytes, to `/v1/principals/{id}/credentials`.
2. `principals_router:75–87` actually mounts `issue_credential`. `http/router.rs:305–339` installs WyrdBodyLimit using that configured ceiling. Credential paths are not exemptions. `body_limit.rs:105–220` accepts this below-ceiling body, reconstructs `Body::from(bytes)`, then calls the inner service. It does not install or disable Axum's DefaultBodyLimit. Repository source contains no overriding DefaultBodyLimit configuration.
3. Locked `axum-core 0.5.6`, `extract/request_parts.rs:100–114`, extracts Bytes through `into_limited_body().collect()`. `ext_traits/request.rs:319–332` supplies2,097,152 bytes when no limit extension exists. This request therefore fails Bytes extraction before the handler body executes, including before its `authorize`, `require_principal` and delayed JSON mapping. Caller authentication is still performed; nothing here grants authority or creates a key.
4. `extract/rejection.rs:38–47,70–73` and `macros.rs:122–131` render that Bytes failure as the normal Axum413 string response. The handler's `Result<_, WyrdErrorResponse>` cannot catch an extractor failure. `request_id.rs:23–63` adds request ID and enriches only responses already marked application/problem+json; it does not normalize text/plain. Protected-edge tower-error/panic handling likewise does not convert a successful service response with413 status.
5. Prior handler captured `Result<Option<Json<CreateUserCredentialRequest>>, JsonRejection>`. With application/json, locked Axum's OptionalFromRequest implementation in `json.rs:119–137` calls Bytes and returns its error as JsonRejection. The handler mapped that through existing `http/error.rs:103–108` into canonical `WYRD_SPEC_400_VALIDATION`. Current `Json::from_bytes` mapping is unreachable when bare extraction failed. This establishes the regression against actual prior behavior.

**Observable consequence/materiality.** Under a supported server configuration, an authenticated client receives uncatalogued text/plain413 rather than the published Wyrd problem fields/code, and the route's intended authorization/tenant-target precedence is skipped. It creates no credential and does not reveal another tenant's data. Default1MiB deployments are protected by the outer canonical limiter; outer stream IO failures are already mapped. The unusual body size alone would not suffice for a blocker, but the explicit stable public-error obligation and existing prior mapped behavior do. No live high-limit reproduction was performed; this is a complete local source/dependency proof.

**Decision-complete smallest correction.** Keep existing limits, protected buffering, Caller authentication, self/admin authorization, tenant-local target lookup, User-versus-Service semantics and typed DTO parsing. Capture the body as `Result<Bytes, BytesRejection>` so rejection reaches the existing handler owner; convert the failure at the same post-authorization/post-`require_principal` boundary as current JSON/body validation, using `JsonRejection::from(bytes_rejection)` and existing `body_rejection`. Then apply current empty-body and `Json::from_bytes` logic to successful bytes. This guard belongs at the public handler boundary because it owns Wyrd error projection and intended access-before-validation policy. It requires no new parser, error variant, shared transport wrapper, dependency, config or limit increase. `gateway/routes.rs:1107–1113` already demonstrates Result<Bytes, BytesRejection> capture; do not copy its distinct provider-envelope policy.

**Correction burden and alternatives.** A small local capture/conversion restores the prior error contract and preserves current ordering. Deletion of delayed parsing loses the gate-fix's refusal precedence. Disabling/increasing the global Axum limit changes unrelated routes and is unnecessary. A new body framework or global response normalizer is substantially larger and would affect unrelated error policies. Reuse the existing JSON rejection mapper rather than inventing another code or directly serializing problem fields. Shared list/revoke/profile/mint owners need no redesign.

**Focused closure proof.** Extend an existing principal-route integration fixture using `WyrdTestServerBuilder::with_limits_for_test` with a ceiling above2MiB. Submit a valid-auth request with application/json and2MiB+1 bytes, below configured ceiling: an allowed existing target must return application/problem+json with canonical validation code. The same bounded input against an unauthorized/foreign target must preserve permission/target refusal rather than an extractor string response; use existing refusal-fixture ownership. Confirm an over-configured-ceiling request still gets the existing Wyrd PayloadTooLarge envelope. Preserve existing empty-Service success, absent-User refusal, typed User issuance and system/foreign refusal tests. Run the exact new/changed focused selector and the narrow changed-server checks; no new harness, broad gate or full multi-SDK journey collection is necessary.
