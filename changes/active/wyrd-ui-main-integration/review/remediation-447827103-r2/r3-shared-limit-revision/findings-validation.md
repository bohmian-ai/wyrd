## Independent comprehension

The packet fixes two request-size policies competing on the same protected request. Wyrd accepts bytes under the operator's configured ceiling, but Axum's implicit 2 MiB extractor ceiling can subsequently refuse them. The credential route exposes an uncatalogued rejection before its handler can authorize the target and parse typed input. The requested behavior is that a valid request over 2 MiB and below Wyrd's configured ceiling succeeds, while Wyrd still refuses requests above that ceiling and explicit streaming readers retain their own bounds.

The selected approach uses the existing Axum disable layer once in the existing shared protected-edge owner. It introduces no limit option, error mapper, parser, or lifecycle owner. Its important limit is scope: protected extension routers inherit the policy, whereas independently merged routers retain their own policy. The maintainer has already directed this choice; this packet asks an implementer to execute and prove it, with no remaining product decision. This understanding follows the revised task's Diagnosis, Selected correction, Boundary and reuse evidence, and Ordered scenarios sections.

Successful credential issuance from a padded, semantically valid User request is essential proof. A structured 400 from malformed input would prove only changed rejection handling. Above-ceiling canonical refusal and preserved explicit raw-Body bounds prove the correction does not exchange the competing limit for an unbounded consumer.
