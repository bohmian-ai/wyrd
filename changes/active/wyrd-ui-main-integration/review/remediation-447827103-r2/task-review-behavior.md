## Source diagnosis and falsification

**Histogram choice closure.** The original failure is eliminated at its shared host ownership seam. `Chart.choose` invokes `onseries` when supplied instead of writing local `chosen`. Every new latency/rate callback now writes only that plot's key under the current serialized metric input, while the respective `shown` reads the same slot. Grouping/apart changes `input.by`/`input.apart`; `loadMetric` returns that input unchanged. A new view therefore has no stored slot and Chart falls back to its default first twenty current keys. Back/forward restores the earlier slot. Prefixes cannot collide with the numeric JSON key or with each other. A new global reset effect, keyed remount, helper or Chart API is unnecessary. The rate binding is independently present and symmetric; the added browser journey actively toggles latency, while rate's own hide/return path is established by source rather than a separate recorded interaction. The forward step verifies apart title; earlier apart asserts populated geometry, and source preserves it on the same key.

**Recovery proof closure.** The old readability poll is gone. Watch publication occurs only after `append_and_sync_batch_commits` succeeds and after the post-commit state is retained; the targeted slice is not an armed flag or pre-sync submission. `crash_once_held` polls ingestion first in a biased select and fails on an answer, waits for the actual target, drops the ingestion future, then awaits the existing abort/join/drain seam before epoch 2. Both recovered-count and per-context membership assertions remain intact. This report checks those changes without pretending that a local watch proves the entire lifecycle; system review must independently trace cancellation, all writers and `drain` before reconciling F7.

**Password gate failure.** User-supplied diagnosis is corroborated by current source: `create_local_user` immediately calls `role_ids`, which rejects an empty list and resolves every Role in this tenant. The old fixture failed there before it could test queuing. Seeding built-ins and granting viewer repairs setup through existing owners. Runtime `password_login` still acquires KDF capacity before `Windows::admit`; the test still fills the account window before releasing held capacity and requires `PasswordAttempts` with a positive retry delay. No window ceiling, timeout, wait or assertion was relaxed.

**MCP gate failures.** `principals.me` is a read-only safe-profile descriptor already included by the unchanged runtime `descriptors_unscoped`; `catalog` places it immediately after credential listing for every authenticated caller, including Service/delegated callers who can discover a read tool but are refused if its domain operation requires a User. The corrected exact lists/count reflect that actual contract; they add no issuance or write capability. Scope checks and probe ordering remain asserted. Removing this expected read tool would force the test to contradict root's always-available-read-tool rule.

**Public testing helper guard.** `bootstrap_user_key` creates the local User with requested Roles, signs in through the real password route and creates a key through the real principal issuance route; Python/TS wrappers delegate to this owner. `seed_user_keys` inserts metadata rows with no usable secret, one transaction and one SQL creation time, so the existing 105-key pagination journey crosses tied timestamp boundaries. It is explicitly a fixture writer, not an implementation of flush/baseline/due-control behavior or a production API; earlier fixture setup already permits bootstrapping/principal/credential writes. The new exact setup names do not admit arbitrary future controls. No current authoritative REQ-195 text was found in the UI spec/architecture; its stale number in guard prose is not promoted into a new prohibition contradicting established fixture use. Security/standards still must assess the actual SQL/declaration boundary rather than infer acceptance from the allowlist.

**Credential extraction correction.** The supplied cause matches the old `Result<Option<Json<_>>, JsonRejection>` mapping before authorization/`require_principal`. The candidate now delays typed JSON decoding until target admission. Self/admin authorization, tenant connection, missing/foreign/system refusal and subsequent issuance branches remain visibly present. The `Bytes` substitution also changes extraction/content-type behavior, so prior credential security acceptance cannot be carried forward.
