## Final deduplicated finding ledger

### FIND-TASK-001-8 — REVISED — REGRESSION: selected logout can leave a suspended tenant's session reusable

Discovery sources: **DATA-R2-001**, **FOLLOW-001**; continuation of original **DATA-001** selected-route mutation boundary. Violated obligations: specification REQ-033 immediate selected-session revocation and AC-012; R2 preservation of session-only logout/idempotency without live principal/connection reauthorization. Stronger authority fixes observable behavior; the earlier private suggestion to reuse recovery's active resolver does not override it.

**Changed location:** `crates/wyrd/wyrd-auth/src/browser_sessions.rs:329–335`, `BrowserSessions::logout`. Response consumer: `crates/wyrd/wyrd-server/src/auth/browser.rs:513–532`. Existing alternative: `crates/wyrd/wyrd-sql/src/postgres.rs:238–258`, `tenant_directory_entry`.

**Producer → mutation → observable recovery:**

1. Active-tenant recovery (`browser_sessions.rs:221–268`) or verified SSO creates a random opaque identifier; `create_session` :425–450 stores its digest, exact authority and twelve-hour absolute expiry, then the caller commits. The browser can retain this value before any suspension.
2. Public `PUT /platform/tenants/{tenant_id}/status` accepts suspended and active (`components/platform/routes.rs:350–394`). `TenantProvisioning::set_suspended` :365–405 calls and commits `set_tenant_suspended` (`queries/platform/provisioning.rs:166–194`). That query changes only tenant status/time. It deliberately preserves rows, grants and credentials; it neither revokes sessions nor expires their keys.
3. Public `POST /auth/browser/logout` is mounted without `AuthenticatedPrincipal` (`components/auth/routes.rs:56–71`; `http/router.rs:auth_routes` is outside authenticated `/v1` groups). HTTP logout checks exact Origin, selects the matching label and calls the lifecycle owner with the selected typed tenant and possessed value. No global live-tenant middleware intervenes. Native hook forwards `/auth/*` before tenant-page admission; its corrected forwarder includes the cookie. The internal root `?/logout` action also directly invokes Node `BrowserSessions.logout` without a tenant-layout/session prerequisite. Therefore an intervening metadata read that might clear the cookie is not required. nginx's deferred execution does not make the Rust public path dormant.
4. Lifecycle logout parses the embedded tenant/hash, then calls `resolve_tenant_slug`. The helper explicitly returns None for suspension (`postgres.rs:179–205`); its SQL function filters `status = 'active'` (`20260601000000_platform.sql:69–85`). A matching suspended selection consequently takes `return Ok(())` at :335, before TenantConn/revoke/commit. HTTP returns 204 and clears the local cookie, while `revoked_at` stays NULL.
5. Resume before expiry with the same key/principal/grants. The unchanged live query still finds the digest (`queries/auth/browser_sessions.rs:40–55`), and issuer admission now succeeds (`wyrd-auth/src/issuance.rs:600–608`). Re-presenting the saved value authenticates again. A reported successful logout has failed to end its durable authority.

**Consequence and limits:** this is a real post-logout revival after ordinary tenant resume, introduced by R2's guard. It is not an immediate suspension bypass, theft of an unknown identifier, or a demand to revoke all sessions during suspension. Correct logout requires possession of the real value and trusted Origin. Current authentication must continue refusing suspended tenants.

**All shared writers/callers and sibling boundaries:** lifecycle logout is the only production caller of `revoke_browser_session`; Rust HTTP logout is its only production caller. Public forwarding and internal Node logout converge there. Session creation occurs through recovery and callback; expiry purge, insert and exact-digest revoke are the session table's production mutation owners. No hidden suspension/session writer closes this gap. `TenantConn::acquire` :47–59 binds the tenant UUID without active admission; browser table RLS (`20261020000000_auth_browser_sessions.sql:36–42`) compares only that UUID. Exact-digest revoke :57–63/183–192 itself needs no current credential/tenant admission. `recover_in` correctly requires active admission to create authority, whereas `resolve/authorize` correctly require it to authenticate. `view` already uses status-independent `tenant_directory_entry`; its `tenant_by_id` query :58–76 includes suspended tenants and excludes deleted/unknown rows. Bearer/device/CLI revocation, key revocation and connection retirement are separate owners and need no change.

**Decision-complete minimum correction:** retain selected-route/value identity binding at `BrowserSessions::logout`, but derive the embedded tenant's authoritative slug through existing `tenant_directory_entry` and compare that slug with the selected route. For a matching known suspended tenant, proceed through the unchanged TenantConn/digest-revoke/commit. Mismatching, malformed, deleted or unknown values remain no-op cleanup; absent/already-revoked values remain idempotent; directory/store failures retain unavailable semantics. Keep exact Origin, cookie selection, current authentication admission, grant/key/connection restrictions, SQL RLS, time and transaction ownership intact.

Ponytail ladder: deleting the guard reintroduces the relabel defect; reauthorizing current authority repeats the suspension mistake; changing the global active resolver widens admission for sibling login/recovery/workload callers. Existing `tenant_directory_entry` already solves precisely the identity question and is used by this owner. Reuse it; add no resolver/API/raw SQL/manual tenant filter/config/secret/dependency, no consumer guards in Node/HTTP, and no status or suspension redesign. This substitutes an identity read for an inappropriate admission read, within approved behavior.
