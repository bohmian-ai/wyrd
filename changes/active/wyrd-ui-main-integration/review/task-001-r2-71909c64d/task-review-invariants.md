## Producer-to-consumer and sibling audit

The opaque value starts only in `create_session` after recovery authentication or verified provider completion. SQL persists its digest and authority, never its secret. The migration enforces one connection-or-key authority, 32-byte digest, DB creation/expiry and a maximum twelve hours; forced RLS governs reads and writes. SQL query functions retain caller-owned commit. Logout's only production caller is the HTTP browser adapter; the only revoke query remains tenant/digest scoped. Route resolution reuses recovery's existing tenant-directory owner. No permission reauthorization was added solely for logout, so revocation remains possible after authority loss, and recovery-key/other-session lifetime is unchanged.

Read/enumeration, selected API calls, callback completion and logout all reach that same authority. Enumeration validates labels against resolved tenant metadata; selected API requests take exactly one value and its authoritative tenant, never a cookie-label role mapping. Metadata's downstream selected-view check belongs at its projection boundary: it constructs the page success that was previously fabricated. It does not duplicate credential resolution. Non-OK enumeration now propagates safe existing errors and retains outages versus invalid authority distinction. Cookie relay occurs before refusal so dead cookies are removed without clearing live siblings on unavailable answers.

Callback failures retain their original generated error classification through `LoginCompletion`; adapter classification no longer asks a later successful directory read to reinterpret a provider/store outage. Existing device and candidate-test completion paths do not enter the browser adapter. Genuine browser refusal remains the existing same-tenant redirect, with no credentials or untrusted return destination added.

The cleanup correction has one resource owner. The provider wrapper owns Keycloak/Dex; startup common owns the application/Postgres/network/volumes/temp/image tag, and identity adds only its forwarder. Passing saved status into common cleanup fixes failure propagation without moving resource ownership or creating another controller.
