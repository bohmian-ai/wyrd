## Material proposal STD-003-1 — Number coercion precedes bounded-query admission

Classification: **VIOLATION / INCORRECT**. Continue existing **FIND-003-11**, rather than create separate findings for each option or caller.

Governing rules: TS SDK AGENTS N-API bridge requires extracting and validating at the boundary; root AGENTS and errors guide require validation on input and consistent public contracts. The approved bounded-collection rule refuses outside-range values rather than clamping. Its current correction validates a transformed value, not the supplied one.

Exact changed location: `sdks/wyrd-sdk-ts/native/src/lib.rs:1382–1396` (`collect` arguments and admission); upstream `sdks/wyrd-sdk-ts/wyrd/src/index.ts:547–551`; UI consumer `packages/ui/src/lib/node.ts:33–42`. Shared policy is `wyrd-queue/src/json_result.rs::admit_ceilings`. MCP sibling `query/collect.rs::QueryArguments` deserializes integer fields and validates the original integer range.

Producer-to-consumer trace: `WireRequest.max_rows/max_bytes` are JavaScript numbers. Node forwards them unchanged into SDK `collect`, which marks the wrapper done and calls native `collect`. The locked `napi` 3.12.3 implementation (`bindgen_runtime/js_values/number.rs:46–68`, read from the installed crate) implements `FromNapiValue for u32` through `napi_get_value_uint32`. The [Node v26.5.0 implementation](https://github.com/nodejs/node/blob/v26.5.0/src/js_native_api_v8.cc#L2168-L2185) calls V8 `Uint32Value` for a Number that is not already a uint32. Thus unsigned 32-bit conversion happens before the Rust method receives arguments. `admit_ceilings` cannot recover discarded bits or a fraction. The SDK wrapper contains no prior number validation, and neither does the Node executor.

Reachable examples for a tiny authorized query: `maxRows: 4294977296` becomes 10000; `maxBytes: 4294971392` becomes 4096; `maxRows: 1.5` becomes 1. These transformed budgets can collect successfully. MCP receives the original JSON numbers and refuses them (integer deserialization or range admission). The requested ceiling above 10000/16 MiB or a fractional ceiling therefore receives a Node success despite its documented refusal contract. Actual retained output still has the post-conversion shared caps; this is an input/parity defect, not evidence of unbounded allocation or a tenant escape.

Sibling scope: both max options share the same native conversion, all Node consumers converge through SDK collect, and MCP already owns proper integer/range admission. No component/BFF-specific guard is justified. Direct native collection also reaches this boundary, so a wrapper-only guard would leave the owner unsound.

Smallest testable correction: preserve the supplied JavaScript numeric value through N-API extraction (an ordinary lossless Number projection), then validate finite whole-number/range semantics before narrowing, at this existing native collection boundary. Continue to use the shared ceilings/policy, existing Validation projection and current take/drop behavior so a refusal releases the stream even though the TS wrapper is already done. Keep defaults, valid exact maxima, actual-output 413, positional JSON, terminal/EOF validation, close notification, cancellation, and sibling streaming behavior. Regenerate native declarations if their generator output changes. Do not add executor/component guards, transports, settings, retry owners or a second range policy.

Focused closure proof: extend the existing tiny-query Node/MCP admission scenario with modulo-wrap values for both limits and a fractional limit, assert refusal of each original invalid request, no result, and direct SDK stream release; retain defaults/maxima success and existing smaller-valid-budget overflow/cancellation assertions. Existing tests cover only zero/max+1 and do not exercise lossy foreign conversion. Static source tracing establishes this proposal; no fresh live reproduction was executed in this read-only review.
