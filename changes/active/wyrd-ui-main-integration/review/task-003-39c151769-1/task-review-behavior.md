**Exact changed location:** `sdks/wyrd-sdk-ts/native/src/lib.rs:1382–1403`, especially `max_rows: Option<u32>` / `max_bytes: Option<u32>` at 1384–1385 before `admit_ceilings`. Related callers are public `sdks/wyrd-sdk-ts/wyrd/src/index.ts:545–547` and UI `packages/ui/src/lib/node.ts:29–40`.

**Producer-to-consumer evidence:** WireRequest exposes both ceilings as `number`; Node forwards them unchanged to SDK collect. SDK marks the wrapper done and forwards both number options unchanged into native collect. Cargo.lock pins `napi` 3.12.3. The installed dependency's `src/bindgen_runtime/js_values/number.rs:44–58,68` implements `FromNapiValue for u32` through `napi_get_value_uint32`; its final `try_into` is `u32 → u32`, with no check of the original JS number. Node's uint32 extraction truncates fractional values and wraps values outside uint32 range. Consequently native function entry already lost the original budget. `admit_ceilings` correctly validates the extracted integer but cannot detect that transformation.

Concrete finite JSON-safe examples: `max_rows: 10000.5` becomes 10000; `max_rows: 4294977296` (2^32 + 10000) also becomes 10000; `max_bytes: 4294968320` (2^32 + 1024) becomes 1024. A tiny authorized result fitting those transformed budgets is returned successfully by Node, even though each original request is outside the admitted domain. MCP's sibling path sends the original JSON value unchanged and `QueryArguments` deserializes `max_rows: u32` / `max_bytes: usize` (`server/src/query/collect.rs:109–132`), followed by shared range admission: fractions fail deserialization and oversized integers fail deserialization or range admission. Thus MCP refuses requests that Node silently changes into admissible ones. This is source-established reachability, not a claimed fresh live reproduction.

The exhaustive shared-builder/admission search finds only native collect and server ResultCollector/QueryArguments production callers. Current Chart loaders use defaults, but the public closed-read executor and SDK collector are expressly required foundation surfaces; direct `nodeExecutor.run` and direct SDK collection reach this boundary without a Chart. No loader, BFF, builder writer, later consumer, or general server streaming cap restores the original numeric value. Server streaming caps do not govern local whole-JSON collection options. Both row and byte failures share one native numeric-extraction cause.

**Observable consequence:** requested-budget refusal and Node/MCP parity are false for valid JavaScript/JSON numeric input; callers receive rows under a different silently transformed budget. The shared upper cap now protects retained output for ordinary u32 inputs, so this report does not claim that current code can retain more than the shared cap through these examples. It identifies failed input admission and public refusal semantics.
