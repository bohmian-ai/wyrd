## Whole-workflow reuse and failure ownership

The new portable loader is required because the existing SDK facade cannot run in a browser MCP iframe. It sequences existing exact Card reads and existing analytical reads; it does not resolve identities or own registry state. Extending existing `Cards.get/list` and `Bifrost.stream` is sufficient for transport; the candidate uses those owners instead of introducing a second client/service. Server `cards.get` is the current public tool after PR #205; its naming is not an unrelated-upstream finding.

The existing MCP `ResultCollector` previously owned positional Arrow JSON projection. Moving that pure projection into `JsonResultBuilder` lets Node and MCP reuse one encoding/accounting implementation while each retains validation, stream settlement and cancellation. Both production builder callers and both `admit_ceilings` callers were located: server `query/collect.rs` and native TS `lib.rs`; no hidden third collection policy was found. The defect below is before this shared owner, at JS-to-Rust extraction, rather than duplicated JSON accounting.

The browser-session extension reuses Rust `WyrdClient` and existing Bifrost query-only shape. The BFF passes one selected cookie without minting or caching tokens. Native close continues to own response release; cancellation remains request-scoped and does not stop a shared server/process. Panel controllers additionally fence obsolete results where remote cancellation cannot guarantee cessation. Native collection takes the stream before R4 admission, so the four currently tested ordinary invalid values drop it correctly. The additional correction must keep that release behavior.

## Proposed active finding

### INV-003-11 — original numeric budgets can be narrowed before admission (FIND-003-11 remains active)

Classification: **INCORRECT**. Violated obligation: REQ-030's identical bounded-read ceiling domain, original scenario 2, and R4's explicit rule that out-of-range budgets are refused rather than clamped. SDK AGENTS also requires validation at the N-API boundary without forked error semantics.

Exact changed location: `sdks/wyrd-sdk-ts/native/src/lib.rs:1383–1396` (`collect` arguments `Option<u32>` and subsequent admission). Producer/callers: public `sdks/wyrd-sdk-ts/wyrd/src/index.ts:545–547` accepts JS `number` options and passes them unchanged; UI `packages/ui/src/lib/node.ts:37` forwards `WireRequest.max_rows/max_bytes` to that API. There is no earlier integer/range validation in either caller. The native collector is also directly exposed by its generated declaration. Sibling MCP input at `crates/wyrd/wyrd-server/src/query/collect.rs:73–84,109–128,171` advertises integer budgets and deserializes their original JSON values as integer types before shared admission.

Installed `napi` source `src/bindgen_runtime/js_values/number.rs:46–56,68` implements `FromNapiValue for u32` using `napi_get_value_uint32`, then converts an already-u32 value to u32. It does not check the original double for integer/range fidelity. Node's uint32 extraction truncates fractional values and reduces overflowing numbers modulo 2^32. Consequently `max_rows: 4294967299` reaches this method as `3` and passes `admit_ceilings`; a tiny three-row authorized query can succeed. `max_bytes: 4299161600` reaches it as `4194304` and likewise passes. MCP refuses the original above-maximum budgets. A `max_rows` of `3.5` similarly becomes `3`, while MCP's integer argument cannot deserialize that value. These are ordinary JS numbers admitted by the public TypeScript option shape, not alternate transports or unreachable test-only state.

Observable consequence: callers receive success for invalid requested budgets, despite the documented validation refusal and Node/MCP parity guarantee. The effective retained result remains capped by the narrowed value; this is a public admission/error-contract failure, not a claim that the fixed 10,000-row/16-MiB memory caps themselves can now be exceeded. R4 closes the originally tested 0/maximum+1 cases but cannot close the original admitted-domain obligation while it inspects only a coerced value.

Smallest correction boundary: validate the original numeric budget at the existing native collection boundary before any lossy integer conversion, then feed admitted values to the existing shared ceiling policy and JSON builder. Preserve omitted defaults, existing validation error projection, taken-stream release on refusal, notification cancellation, valid-budget overflow errors, and MCP envelopes. Do not add component/BFF guards, a second transport or a new policy/service. A representation that preserves the incoming numeric value is necessary; exact private signature/control flow belongs to implementation. Retain the stable **FIND-003-11** ID because this is the still-incomplete requested-budget admission correction, not a new independent invariant.

Focused proof: extend the existing real Node/MCP bounded-read scenario with a tiny query and original `2^32 + validBudget` values for both fields, plus a fractional value. Each must refuse separately with its existing invalid-input envelope and no usable result; the Node path must preserve stream release and subsequent querying. Retain the present exact-max/default/0/max+1/actual-output-overflow cases. One shared Rust `u32` admission test cannot prove JS extraction fidelity. No broad journey or new harness is needed.

This is source-backed discovery; the counterexample was not executed against a fresh live server during this review. Independent validation should verify the N-API extraction path and original-value semantics, rather than infer them from the supplied green four-value test.
