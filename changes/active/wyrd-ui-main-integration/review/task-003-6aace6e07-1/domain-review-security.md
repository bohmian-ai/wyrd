## Boundary traces and falsification

The shipped POST loader takes its authority exclusively from `locals.browserSession` (`src/routes/t/[tenantKey]/ui/load/+server.ts:13–29`). Hooks resolve that session on every tenant request; `BrowserSessions.read` forwards only the selected cookie and requires Rust metadata for the requested tenant. `BrowserSession.client` passes the private cookie and the request public origin into the existing shared Rust client, without reading an ambient API key. Shared `transport/credential.rs::BrowserSession` validates a single header-safe cookie pair and bare origin and redacts the credential; `transport/http.rs::authenticated` emits the selected headers and `authenticated_url` confines authenticated destinations to the configured origin. The endpoint cannot choose a new server or principal through its panel input. Safe loaded props are returned, not the session object or SDK client. Existing hooks set private/no-store response caching.

The added browser-session Bifrost connection branch reuses the existing query-only sink/constructor shape and existing query client. It avoids bearer-only ingest setup; it introduces no cookie-to-bearer minting, permission merge, session cache or parallel transport. Ordinary bearer clients retain their existing assembly. Cookie authentication remains the existing Rust tenant HTTP boundary; this task does not extend it to MCP or gRPC. The BFF POST performs reads; no new cookie-authenticated durable mutation or origin-bypassing write dispatcher was found.

Exact Card input remains flat `{kind,name,version,uid?}` and cannot name a tenant. The Node adapter calls `Cards.get` unchanged; MCP maps that same reference to the current `cards.get` tool. The existing server selector routes it to `get_card_by_ref_for`, which authorizes `cards:read`, reads under the verified caller and checks an optional UID against the resolved identity. `loadCardHeader` issues its version listing only after that read succeeds, using the resolved kind/name and the same executor. A refused prerequisite returns its problem without dependent reads. Reference formatting preserves the selected kind/name/version and optional UID; it is display/navigation data, not a new authority resolver.

Chart SQL is explicitly authored input permitted by the specification. `loadChart` passes it unchanged with typed bound values; no input is interpolated into SQL. `nodeExecutor` uses the existing SDK stream; `mcpExecutor` calls only the closed read-tool mapping on the authenticated App connection. MCP `QueryArguments` denies unknown fields and projects ordered `QueryParam` values directly. Its validation and bounded collector do not replace SQL admission: both reach existing `stream_query`, which checks capability, constructs `AuthorizedQueryContext` from the verified caller and tenant, dispatches through Gate/Oracle and records object refusals through the existing audit owner. No UI permission judgment, tenant header authority or alternative query service was introduced.

Native collection returns a whole JSON result only after the existing native query stream has completed successfully and supplied its validated terminal; projection errors return `NativeQueryStep::failure`, with no accumulated rows. The shared JSON builder retains positional columns/rows, measures exact compact JSON bytes and returns the existing too-large error. Server MCP uses that same builder and shared admitted range; this is projection reuse, not duplication of authorization or terminal authority. SDK/MCP errors retain code/title into panel denied/error state. Local validation problems come from the generated Rust catalog projection. Unknown MCP transport failures become the existing upstream family rather than empty success.

Strict document/panel schemas admit component inputs and identifiers, not executable callbacks, destination URLs, arbitrary tool names or credentials. `validateIntent` accepts only each catalog component's declared schema; host callbacks own navigation/action execution. The built MCP artifact keeps its App connection inside the host and supplies no generic write dispatcher. The custom app creates its SDK executor only in server-used code; its response contains loaded props rather than its API key.

## R5 and prior closure

**FIND-003-11 is closed within this domain.** `sdks/wyrd-sdk-ts/native/src/lib.rs:1382–1421` now accepts `Option<f64>` for both Numbers. It takes ownership of the native stream, parses both original values through `parse_ceiling` (`:1566`), resolves omitted defaults and only then applies unchanged shared `admit_ceilings`. The decimal round trip admits an exact representable `u32`; fractions, NaN/infinity, negatives and values beyond `u32` fail parsing, while zero and valid-u32 values above policy maxima fail the shared range rule. The prior wrapping/fractional examples therefore cannot become admitted budgets. Every parsing refusal uses the existing catalog validation projection and exits with the stream taken, so no partial result is returned or retained in the stream slot.

The same producer is reached by the direct public SDK collector and Node executor, so the correction is at the foreign-number trust boundary rather than repeated UI guards. MCP already validates original JSON integer budgets and calls the same range policy. Its protocol-specific invalid-params response need not have identical wording to SDK validation. Defaults, exact maxima and actual-output overflow remain governed by the existing shared owner. `parse_ceiling` follows the existing native `parse_deadline_ms` conversion pattern; no new numeric framework, dependency or error family is required.

Current integration source at `src/lib/ui-library.integration.test.ts:186–211` tests wrapping and fractional originals for both row and byte options against Node/MCP, valid maxima, direct SDK refusal followed by a closed same-stream collection, and a fresh successful query. It also retains ordinary zero/max+1 and actual-overflow assertions. These tests exercise the real native-backed SDK path rather than only a pure Rust integer helper.

Related prior closures remain supported at the reviewed boundary: FIND-003-5 actions remain typed host handoffs with reported refusal; FIND-003-6 Node cancellation prevents post-abort results and closes acquired streams; FIND-003-7 local/upstream code/title projections remain structured; FIND-003-12 exact references remain kind-qualified and preserve optional UID. FIND-003-1–4 and 8–10 concern chart/render/import behavior outside this sensitive-domain lens; this report makes no independent visual or import-runtime certification for them.
