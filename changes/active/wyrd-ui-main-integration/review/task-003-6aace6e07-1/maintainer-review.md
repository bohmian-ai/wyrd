## Existing-owner comparison

The material new runtime mechanisms were compared to their existing owners rather than accepted merely because the task named them:

- JSON normalization moves the server's existing bounded projection into shared `JsonResultBuilder`, using existing Arrow JSON encoding. SDK `collect` and server collector both call it; they retain their distinct existing stream protocol and settlement responsibilities. Reusing a leaf encoder alone would not justify replacing those workflows; this change does not do so.
- Native number admission reuses the established `parse_deadline_ms` lossless decimal conversion convention and `validation_error` projection. `parse_ceiling` is a small pure boundary conversion; the range policy remains exclusively `admit_ceilings`. No per-host repeated guard or numeric abstraction was introduced.
- Browser-session query connection extends existing `Bifrost::query_only` construction through one private owner, without exposing an HTTP query client or changing auth/session authority.
- UI loader/executor/view machinery fills the explicitly approved portable-host gap over Cards/Bifrost/verification operations. No existing component orchestration owner in the base provides these outcomes; the new code does not reproduce durable server behavior.

## Remediation and prior closure

FIND-003-11's former maintainer consequence was loss of the caller's actual number before shared admission. At native `collect` (`native/src/lib.rs:1382`), both ceilings now arrive as `Option<f64>`. The stream is taken before parsing, so refusal releases it. `parse_ceiling` (`:1566`) parses the complete number representation into `u32`: fractions, non-finite values, negatives and values beyond `u32` cannot become a different admitted integer. Successfully parsed values still pass shared range admission. This follows the adjacent deadline parser without merging distinct error contracts or duplicating ceiling policy.

The latest integration assertions exercise wrapping/fractional row and byte values through both executors, retain zero/max+1/maxima/default/actual-overflow checks, and check a second collection is closed followed by a successful fresh query. This is an appropriately focused closure proof, rather than a new test harness. Generated declaration differences are documentation; the public JavaScript number signature remains intact.
