## Proposed finding INV-RANGE — Accepted relative range escapes view error handling

Classification: **INCORRECT**. Source-local ID: **INV-RANGE** (validator assigns the next stable FIND number if retained). This is not a reopening of FIND-003-1: explicit/inherited precedence is corrected; the defect is accepting an unrepresentable range and throwing before any panel error boundary.

**Violated obligation.** REQ-030's validated view-document/portable-loader contract, original scenario 1 (invalid input has an honest visible error) and canonical public error requirements. A renderer accepting untrusted JSON must render its invalid-input state rather than raise an uncaught runtime exception. The correction concerns only requests/documents whose dates cannot be represented; it imposes no product retention window.

**Exact locations.** UI-relative `packages/ui/src/lib/schemas.ts:55–61`, `packages/ui/src/lib/loaders.ts:75–78`, and consumer `packages/ui/src/lib/WyrdView.svelte:240–247`.

**Reachable input and producer-to-consumer trace.** A document with the required version/catalog, any valid CardHeader or Chart panel, and `range: {"last":"1000000000000d"}` passes `RelativeRangeSchema`: positive digits followed by `d` satisfy its only value check. `ViewDocumentSchema` uses that same `RangeSchema`, so `safeParse` reports success and `validateView` returns the document. The gallery/custom host/mountView and AppBridge tool-result path can all provide such JSON to WyrdView. Its effect calls `start`, which aborts existing controllers and then resolves the view range before mapping panels or installing per-panel promise rejection handlers. `resolveRange` computes `1_000_000_000_000 * 86_400_000 = 86_400_000_000_000_000_000` ms. This is far beyond JavaScript Date's finite ±8.64e15-ms domain at the candidate's ordinary wall clock. `new Date(now - amount).toISOString()` therefore throws RangeError. There is no enclosing catch in `start`, the effect, mountView or the AppBridge callback that projects it as a canonical visible validation problem. No server query is needed to reach it.

**Observable consequence.** The accepted document fails in the Svelte effect before scheduling any panel, so even a CardHeader that does not need the range fails to load. A replacement with this range also aborts previously valid reads first. The UI's existing invalid-document EmptyState branch cannot render because schema parsing succeeded. This is a renderer/document availability and error-contract defect, not a tenant escape or shared Rust-server crash.

**Sibling callers and authority owner.** Repository search finds three direct `resolveRange` callers: WyrdView `start`, `loadChart` for an explicit panel range, and `examples/ui-app/src/routes/+page.server.ts` with its fixed six-hour example range. Shared `RangeSchema` also feeds Chart input admission. An explicit huge chart range enters `loadChart`; WyrdView catches its rejected load as an internal panel failure, while BFF/custom endpoint handlers directly await `loadPanel` and let it become a framework 500. These are the same unresolved representability cause, not separate findings. Both remote endpoint hosts validate only the inherited absolute context range; that does not validate the chart's explicit relative input. There is no existing relative-range service to reuse beyond `RangeSchema`/`resolveRange`. AbsoluteRangeSchema already uses native Date parsing for its ordering validation.

**TASK-003 attribution.** `git show b0a05de50` shows the same digit-only relative schema, direct `toISOString` arithmetic and pre-panel `start` call in the original foundation package. TASK-027 later changes layout without introducing this path. The cumulative base does not contain this new package.

**Smallest testable correction boundary.** Keep the existing shared schema/resolver owner and native Date range semantics. Ensure an unrepresentable resolved range becomes the existing canonical validation problem, with the field named, before ISO conversion can escape. Reuse that one result consistently: WyrdView displays a document error and schedules no reads for an invalid inherited view range; loadChart returns its normal error props for an invalid explicit panel range, preserving valid siblings; endpoints project the same honest result. Preserve valid ranges, resolve one shared `now`, explicit precedence, authored SQL and existing cancellation ownership. Do not introduce an arbitrary retention cap, separate parser, new settings, new error family, per-host repeated arithmetic checks or replacement loading workflow.
