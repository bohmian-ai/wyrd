## Reachable boundary traces and existing-owner comparison

1. **Browser to BFF to Rust.** `hooks.server.ts` resolves the route tenant on every request using `BrowserSessions.read`; that read selects one cookie and asks Rust for live metadata filtered to the same tenant. The BFF handler refuses an absent `locals.browserSession`, validates component/range/input, and creates a request-scoped `nodeExecutor(session.client())`. `BrowserSession.client` uses the shared `WyrdClient.forBrowserSession`, which retains the opaque cookie privately and forwards only the selected cookie and trusted origin. The existing shared credential validator rejects multiple cookie pairs, header-unsafe bytes and non-bare origins; the HTTP owner attaches the session headers to its configured same-origin requests. Node does not mint, refresh, cache or reinterpret permissions. The new endpoint exposes reads only, including server-admitted read-only authored SQL; it is not a mutation or origin-check replacement. Existing Rust session and authentication owners remain authoritative.

2. **Exact Card tenant/identity enforcement.** `CardRefSchema` is strict and excludes `space`, tenant, URL and selector aliases. The loader forwards the reference unchanged through Node `Cards.get` or MCP `cards.get {card_ref}`. The actual current MCP tool shares `get_card_by_ref_for` with HTTP; that owner authorizes `cards:read` and refuses an optional UID mismatch. `service::get_card_by_ref` opens the registry connection from `caller.data_tenant_id`, rather than any input field. On success, the loader lists versions with the returned kind/name, preserves listing refusal separately and issues no dependent listing after a failed prerequisite. The version action reconstructs an exact reference, while copied/chip identity uses the flat form. No alternative UID resolution, tenancy layer or registry owner was added. The spec's stale MCP table spelling does not justify restoring a removed upstream tool alias.

3. **MCP caller and query ownership.** The browser artifact creates an ext-apps `App`; `mcpExecutor` only calls that connected host's `callServerTool`, mapping the closed read union to actual tools. It does not obtain a credential or choose an upstream server. Server `mcp::bifrost::query` validates `QueryArguments`, then runs the existing `BoundedQuery` with its verified `Caller`. `stream_query` admits the principal's query capability, creates `AuthorizedQueryContext` from the verified principal and data tenant, and delegates actual table visibility/read-only execution to the existing query owner. Denials preserve the existing audit boundary. Typed parameters flow to the existing request, never SQL interpolation. The shared JSON builder replaces duplicate projection logic; it does not replace authorization, IPC validation, cancellation or terminal settlement. The Node adapter's browser-session Bifrost branch reuses the existing query-only sink/construction, avoiding a bearer-only ingest dial without granting cookie auth to gRPC/MCP.

4. **Untrusted documents and actions.** View and component schemas reject unknown fields. The BFF validates before reads; renderer panels validate independently. `Object.hasOwn` prevents inherited component/action names becoming dispatch targets. `WyrdView.act` validates emitted input, suppresses pending duplicates and either updates the local range or invokes the host's supplied action handler. Missing host navigation is explicitly unavailable. The document cannot supply that handler. Foundation currently declares navigation/range actions rather than durable writes, so no write-scope bypass or generic mutation dispatcher is introduced. Standard Svelte text/attribute rendering escapes returned names, titles, SQL and error text; no `{@html}` rendering path was found in the package/examples. Layout state changes do not add an execution/credential surface.

5. **Custom app and artifact.** The custom app intentionally reads under its server's own Wyrd credential, as use case 2 specifies; its pages return loaded props and its endpoint applies the same catalog loaders. It does not project that API key into a browser executor. Browser exports and the self-contained artifact do not runtime-import `wyrd-ai`; only `node.ts` does. The artifact receives documents from the bridge and makes reads through its authenticated host. The gallery is development-only. Production SDK packaging supplies runtime code/addon, not credentials. No additional authentication system or store is needed to satisfy these boundaries.
