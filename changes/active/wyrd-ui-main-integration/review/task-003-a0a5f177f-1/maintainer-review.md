## Material proposal MNT-003-10 — display text aliases distinct multi-column time series

Classification: **INCORRECT**. Changed location: `packages/ui/src/lib/plot.ts:36–45`, especially line 42. Governing obligation: REQ-025 permits one or more numeric y columns and a text series column; REQ-022 requires truthful values. The owner's own contract promises one series per series-value × y. Maintainer guide requires domain values/return shapes to preserve the operation they describe; a caption is not a unique identity for two independent values.

Reachable input: a valid time-series chart with `y: ['c', 'b c']`, `series: 'group'`; result has temporal at, Utf8 group and two numeric descriptors c and b c. SQL quoted column aliases can legitimately contain spaces, and neither schema nor public query contract prohibits these names. At one instant, rows are `['2026-10-20T10:00:00Z', 'a b', 1, 2]` and `['2026-10-20T10:00:00Z', 'a', 3, 4]`. Both `(a b,c)` and `(a,b c)` become label `a b c` at line 42. Map lookup at line 43 reuses their points, and line 44 sums 1+4 to 5.

Independent read-only Node probe of existing dist/plot.js, whose body matches source, returned:

```json
[{"label":"a b c","points":[{"x":1792490400000,"y":5}]},{"label":"a b b c","points":[{"x":1792490400000,"y":2}]},{"label":"a c","points":[{"x":1792490400000,"y":3}]}]
```

There should be four source series with values 1,2,3,4; the candidate draws three and invents a sum 5 without reaching the approved overflow threshold. It can also rank/fold the wrong cardinality later. This occurs after valid shapeChart and both executor paths. Chart's plot, legend, tooltip and aria-label all consume this shared producer; direct apps, WyrdView and bundled MCP inherit it. No sibling producer repairs the identity. This predates R2 and is task-owned in the cumulative original implementation, rather than a reopening of the corrected synthetic other caption.

Smallest testable correction: retain distinct `(series value, y column)` identity inside the existing timeSeries producer before accumulation, then produce distinct attributable display captions when two authored combinations would render the same text. Keep its existing Series return shape and Chart consumers; no new public ID/schema, query restriction, reserved name, transport or renderer-only workaround is needed. Reuse the present collision-qualification approach for emitted captions while preserving ordinary noncolliding captions, source values, deterministic order/ranking and the nineteen-plus-one overflow rule. Do not sum different source series to avoid duplicate keys.

Focused closure: extend the existing Validated portable rendering case with the above two-y/two-group result and assert four separate lines, unique attributable legend/tooltip/accessible captions and exact values 1/2/3/4 before overflow. Keep R2 authored other/qualification and 5/20/21 tests. A pure producer assertion can supplement this mounted case; no live-server or new harness is required.
