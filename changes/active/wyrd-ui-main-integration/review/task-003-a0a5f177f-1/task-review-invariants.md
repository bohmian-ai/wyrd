## Material proposal INV-003-10 — authored grouping identity is lossy before overflow

**Classification:** INCORRECT. **Suggested new stable ID if independently validated:** FIND-003-10. **Obligation:** REQ-025 admits one or more numeric y columns and an optional text series, folding only above twenty; REQ-030 preserves normalized values and renders truthful complete Charts. **Location:** `packages/ui/src/lib/plot.ts:36-45`, especially line 42; consumer `components/Chart.svelte:43,209,233,256-270`.

**Accepted producer domain.** ChartInputSchema permits arbitrary nonempty column names, including spaces, quotes, punctuation and text equal to qualification captions; y has one or more such names. shapeChart accepts first-matching Timestamp/Date x descriptors, numeric Int/UInt/Float/Decimal y descriptors and optional Utf8/LargeUtf8/Utf8View series descriptors. It does not reject nullable series. A complete actual result can therefore contain arbitrary text strings or null in that series column, numeric values (including existing string encoding for 64-bit/decimal) or null in y, and supported temporal x values. The loop ignores null y and invalid parsed x, uses epoch milliseconds for point grouping, and otherwise combines each selected y with its series value. Without a series column, y names are already the grouping identity. With one, both the raw series value and y binding are needed; concatenating display text is not injective over this accepted domain. Repeated identical bindings remain the same binding; this proposal does not invent new semantics for duplicate authored y declarations or change existing same-tuple/same-instant summing.

**Reachable path and independent evidence.** Both executors preserve these positional values. loadChart/shapeChart mark the following complete typed result populated. With y `["tokens", "input tokens"]`, series column `model`, and one instant, two result rows are:

```text
model = "model input", tokens = 1, input tokens = 10
model = "model",       tokens = 2, input tokens = 20
```

The approved cross-product contains four distinct authored groups. timeSeries constructs the same caption `model input tokens` for `(model input, tokens)` and `(model, input tokens)`, then adds 1 and 20 in the same Map before any overflow logic runs. An independent read-only mise Node probe imported the already-built source-aligned producer and public shapeChart, confirmed populated, and returned:

```json
[{"label":"model input tokens","points":[{"x":1792454400000,"y":21}]},{"label":"model input input tokens","points":[{"x":1792454400000,"y":10}]},{"label":"model tokens","points":[{"x":1792454400000,"y":2}]}]
```

A second independent probe with one y, nullable Utf8 series, and rows `(null,1)` and `("null",2)` is also accepted populated and produces one line labelled `null` with value 3. This is the same lossy identity source (`String(row[si])`), not a second per-consumer finding. Arbitrary alternative delimiters or a fixed null sentinel cannot cover the full string/null domain.

**Consumers and consequence.** Only Chart calls timeSeries in production. The plot, tooltip, legend and accessible name all consume its already-corrupted output; three each loops also key on label. Direct Chart consumers, WyrdView via in-process executor, remote BFF/custom app and MCP App artifact all converge here. There is no later normalization writer or server identity bug. Distinct valid observed metrics silently become a false summed metric, and the producer undercounts groups for the twenty-series threshold. Current R2 tests use one y per textual series, so collision avoidance in the overflow caption cannot detect this.

**Smallest correction boundary.** Keep the existing timeSeries owner, first-match selectors, same-group same-instant sum, ordering/ranking, threshold and overflow behavior. Preserve series value type/null and y binding as an injective private group identity before summation; conventional JSON serialization of the typed pair or an equivalent nested map fits the existing Map-based owner without dependencies or a new exported contract. Generate final captions at that same producer with enough collision qualification to distinguish every returned authored group and synthetic aggregate across the full accepted domain; retain ordinary unambiguous authored captions and the existing recognizable other aggregate. This also keeps the current keyed plot/tooltip/legend valid and makes accessible attribution truthful. Treat a delimiter substitution, null sentinel, renderer-only key change, hidden/rejected data or merging two groups as insufficient. No new transport, public Series ID contract, schema restriction, chart framework or query rewrite is required.

**Focused testable closure.** Extend the existing portable rendering scenario with the two accepted examples above. Assert four independently attributable lines/values for the multi-y case and two for null/string-null; mount/focus Chart and verify plot count, legend, tooltip and accessible captions remain distinguishable through rerender. Include authored qualification-like text to prevent a fixed caption replacement from passing. Preserve existing 5/20/21 threshold, aggregate totals, authored other/qualification, duplicate-descriptor, signed and null-y assertions. Reuse the current exact `mise exec -- pnpm --dir crates/wyrd/wyrd-server/wyrd-ui test src/lib/ui-library.test.ts -t '^TASK-003: Validated portable rendering$'` command and existing package check/build; no new live journey or broad aggregate is necessary for this pure shaping defect.
