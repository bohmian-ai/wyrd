## Material proposed finding

### MNT-003-08 — a valid series named `other` collides with the generated fold identity

**Classification:** INCORRECT. **Location:** `packages/ui/src/lib/plot.ts:47-58`, consumed by `components/Chart.svelte` keyed line, tooltip and legend loops (line loop around 230, tooltip at 256, legend at 263).

**Governing obligation:** REQ-025 permits a text series column and folds only above twenty; TASK-003 completes Chart for every host. The maintainer guide requires typed contracts/owners a maintainer can safely change and tests of caller-visible outcomes. No schema reserves the text `other`.

`timeSeries` keys original data by its authored label, sorts twenty-one entries, preserves nineteen entries, then appends a synthetic entry whose label is always `other`. If a real `other` series is among the retained nineteen, the result has two identical labels. Chart treats label as its keyed iteration identity in all three sibling consumers. This violates the keyed-list uniqueness contract, causing a development renderer duplicate-key error and leaving production keyed updates with ambiguous identity. The supported data cannot reliably render through any host. A maintainer changing aggregation currently must understand that a display caption doubles as renderer identity across three separate loops.

**Independent source-aligned reproduction:** executed a read-only `mise exec -- node --input-type=module -e ...` from the UI workspace, importing existing built `packages/ui/dist/plot.js`. Built and source bodies agree. With one timestamp and twenty-one distinct text series (`s0..s19` valued 1..20, plus `other` valued 21), the returned labels are `["other","s19",...,"s2","other"]`; returned `other` points have separate values 21 and 3. No source, fixture or harness was written. This is produced from an ordinary validated numeric/text query result, independent of SQL parsing or executor behavior. Existing 21-series test uses only `m1..m21`, so it cannot reveal the collision.

**Smallest testable correction:** retain the existing `timeSeries` aggregation and all values; stop using a user-controlled display label as an assumed unique keyed identity for the generated overflow entry. These three stateless list renderings can use ordinary unkeyed iteration (or their unique positional index), preserving both authored and aggregate values without adding a public identity field, reserved input name, per-host workaround or another aggregation owner. Apply the correction to all three sibling consumers together. If labels are also clarified, do not remove/merge a retained original series merely to hide the duplicate key.

**Focused closure proof:** add the above 21-series case with the authored `other` retained, mount Chart, focus its tooltip, and assert both retained value 21 and folded value 3 remain rendered without duplicate-key failure. Replace/update that mounted result so identity handling is exercised beyond initial construction. Retain existing 5/20/21 and fold-total assertions. No live server, new library, harness, schema or release suite is needed for this correction.
