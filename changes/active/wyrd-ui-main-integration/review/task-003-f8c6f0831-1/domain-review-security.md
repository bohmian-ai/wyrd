## Existing owner and sibling-consumer assessment

The existing `BrowserSession.api` and shared client HTTP authenticated transport already own cookie forwarding and credential handling; the added `client()` projects those capabilities into SDK consumers rather than introducing a UI auth client/cache. Shipped BFF holds request scope; custom app intentionally holds its own server credential; MCP executor uses the existing authenticated host connection. These authorities are separate host contexts, not interchangeable tenant selectors. Session mutations and their inbound-origin enforcement are unchanged by this read endpoint.

Existing server bounded collection already supplied the projection and ceilings. Extracting `JsonResultBuilder` shares that policy with native SDK collection while preserving server stream settlement and SDK validated stream lifecycle; the UI does not acquire a query service. `chartParams` is the common planning owner used by direct loaders, `loadPanel`, local/MCP renderer and HTTP consumers. Its lexical scan selects bind arity only, so it neither replaces the server parser nor changes its admission/read-only rules. There is no portable existing tokenizer to reuse identified in the reviewed owners; the local scanner does not introduce a dependency, transport or public SQL parser.
