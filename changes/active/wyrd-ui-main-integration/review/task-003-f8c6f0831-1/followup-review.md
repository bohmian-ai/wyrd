## BEH-1: valid null observations reach an active brush

**Follow-up source ID: FUP-BEH-1; classification: INCORRECT.** Supports BEH-1 without broadening it into loader/schema rejection.

REQ-030 requires retained null query values, compatible chart rendering, typed safe actions, and a view whose time-series brush updates the shared range. TASK-003 scenarios 1 and 3 own complete chart states/interactions and safe action handoff. A typed numeric column remains a compatible numeric column when its observed values are null.

The producer-to-consumer trace is:

1. A real admitted table has a timestamp x column: `crates/vala/vala-bifrost-redux/src/tables/traces/spans.rs:77` declares `start_time_unix_nano` as `signal::OTLP_INSTANT`; the existing table tests use `TimestampNanosecondArray` for it. Thus the behavior report's bounded query selecting that column and `CAST(NULL AS DOUBLE)` is a conventional typed timestamp/numeric result over an authorized `vala.*` table. The example app's existing bounded SQL already selects this timestamp and the same `$1/$2` range. Add `ORDER BY 1` when using this example to meet the authored timeseries ordering contract; ordering does not affect the all-null path.
2. The shared actual projection, `crates/shared/wyrd-queue/src/json_result.rs::accept_batch:149–181`, explicitly writes `JsonValue::Null` for a null slot. The Node query branch collects the SDK stream, and the shared query result contract retains positional rows and nullable type metadata. This is supported production data, not malformed props invented solely by a unit test.
3. `packages/ui/src/lib/loaders.ts::shapeChart:171–199` checks x/y Arrow column types, not y presence. A nonempty timestamp/Float64 result with every y null passes and becomes `state: 'populated'`. `loadChart` and `loadPanel` preserve that state. No server or component-input schema forbids this result.
4. `packages/ui/src/lib/plot.ts::timeSeries:35–47` skips each null numeric observation. With every y null, its `lines` map stays empty; returned lines and points are empty. This skipping preserves truthful null handling and is not itself the defect.

At lines 219–241, rendering depends on the populated state and timeseries type; it still renders the SVG and its pointer handlers. `onpointerdown` creates a brush whenever `onaction` exists. 6. At `Chart.svelte::release:99–105`, a drag of at least six SVG units passes the only geometry-related gate. Interpolation with the undefined bounds yields NaN; `new Date(NaN).toISOString()` throws before `onaction` can be invoked. 7. This is active in required hosts. `WyrdView.svelte:330–332` always passes a per-panel callback to Chart, even when the host has supplied no navigation callback. The example direct-components page omits it and therefore does not create a brush; that limits that one consumer, not the shared view hosts.

The exact consequence is an uncaught pointer-event conversion error and failed range interaction for a successful null-only result. The evidence does not establish process termination, durable corruption, or all-host failure, and none is claimed.

The correction boundary is the existing Chart geometry-to-range conversion. Its owner must refuse conversion/emission when its drawable x domain is absent or cannot produce a finite increasing range. A consumer check belongs here because Chart itself produces the invalid arithmetic and also accepts typed direct props independently of the shared loader. Do not reject supported nullable result schemas, synthesize zero numeric observations, replace query success with denial, add a parser, or require unrelated WyrdView layout changes. Keep host validation as the separate trust boundary it already owns.

Existing tests cover normal brush reloads at `ui-library.test.ts:507–520` and series identity values named/null at `:154–175`; those do not cover null y values removing all geometry. The focused regression should feed a successful typed timestamp/nullable-numeric null-only result through the shared loader and rendered Chart/WyrdView, exercise a meaningful drag, and prove no throw or malformed range emission. Replacing it with drawable points should retain the existing valid brush/reload behavior. This requires no live server or new harness.

## SYS-1: request-local construction limits, but does not remove, rejected initialization poisoning

**Follow-up source ID: FUP-SYS-1; classification: REGRESSION/INCORRECT adaptation.** Supports SYS-1 specifically for a retained public Node executor. No automatic reconnect feature is required.

The specification's REQ-030 Executors section expressly exports a Node executor built from a `WyrdClient` for a user's own server. `contract.ts::Executor` exposes `run(requests, signal)` with positional responses and transport-aware cancellation; it does not define one-shot use or disposal after error. Repeated caller-initiated loading is ordinary public consumption. The live foundation test itself retains `sdk = nodeExecutor(client)` at `ui-library.integration.test.ts:139` for multiple reads. A host can retain this public executor for successive loads without a new API or a new product decision.

The trace of recoverable initialization into permanent adapter state is:

1. `packages/ui/src/lib/node.ts:16–19` stores both connection promises using nullish assignment. After rejection, the promise remains defined. Every subsequent operation sharing that handle awaits the same rejection; there is no path that invokes connect again.
2. `Cards.connect` at `sdks/wyrd-sdk-ts/wyrd/src/index.ts:1670` calls native `cards()`, then `nativeHandle` projects an error to a thrown SDK error. `sdks/wyrd-sdk-ts/native/src/cards.rs:68–84` calls Rust `Cards::connect_with`; `crates/shared/wyrd-client/src/cards/handle.rs:193` calls `client.connected().await?`.
3. `crates/shared/wyrd-client/src/client.rs::connected:131–137` uses the existing access-token owner for non-session credentials. `auth.rs::bearer:851–883` takes the credential cache lock, reuses a fresh token if present, otherwise exchanges. `exchange_and_store:956–965` performs the fallible exchange before storing. On transport error it returns with no poisoned cache entry. A later fresh SDK Cards connect can retry the exchange using the same client once the service recovers.
4. `Bifrost.connect` at SDK `index.ts:1098–1106` calls native `connect_bifrost`; native `src/client.rs:200–220` calls Rust `Bifrost::connect_with`. `bifrost/facade.rs:148–160` performs credential connection and, for a custom-app client, `assemble:248–266` attempts the gRPC transport connection. An initial auth or ingest-channel outage can reject. Calling the same SDK connect again would perform a fresh attempt; its failure has not made the original client terminal.
5. The Node executor prevents that next fresh attempt. Cards get/list share the poisoned Cards promise; Bifrost query/list/describe share the poisoned Bifrost promise. The execution-status branch connects separately and is not disabled by either cache. The error remains a structured failed read through `run`; there is no data fabrication or cross-tenant access.
6. All identified production calls in this repository are request-local: `src/routes/t/[tenantKey]/ui/load/+server.ts:24–25` builds a new executor for the request, while `examples/ui-app/src/executor.ts:9` is a factory used by page and endpoint loads. These specific hosts can recover on a later request because they abandon the failed instance. Accordingly, a claim that the shipped BFF is permanently disabled would be unsupported. The required reusable package export remains affected when a user's server retains its executor, including a view/loader owner using successive `run` calls.

This is a bounded new adapter-cache failure: first-connect failure changes future calls from fresh SDK attempts into replay of one historic error. Recovery requires executor recreation/restart despite the same underlying client being usable again. Nothing in the task authorizes that new lifetime constraint; eliminating it needs no stronger dependency availability promise.

The smallest correction is at `nodeExecutor`'s initialization cache producer: retain no failed initialization as the reusable handle, while preserving existing SDK credential/transport ownership and successful/in-flight sharing as appropriate. Apply the invariant to both caches; no caller-by-caller retry guards, automatic retry/backoff, new connection service, SDK auth changes, or BFF lifetime change are justified. A focused mock test can make first initialization return the existing structured SDK failure, then make a subsequent initialization succeed, asserting successive reads on the same executor reach the SDK again. Exercise both cache owners and preserve the existing cancellation cases. Healthy successful-connect tests do not cover this transition.
