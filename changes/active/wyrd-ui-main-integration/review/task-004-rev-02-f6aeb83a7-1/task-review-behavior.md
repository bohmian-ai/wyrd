### B-03 — INCORRECT: metric identity and summaries silently mix evidence

**Authority.** Task Metrics precision paragraph explicitly prohibits generic duplicate-point summation/series folding as metric aggregation; REQ-017/039 and inherited R1 require compatible series with truthful Latest/Max/Mean.

**Locations/producer-to-consumer trace.** `observe.ts:311–315` keys series by optional stringified grouping value plus kind/unit/temporality/monotonicity. It omits point/resource/scope attributes and even service when no grouping is selected. Canonical metrics schema contains these recorded fields (`crates/vala/vala-bifrost-redux/src/tables/metrics/points.rs:119,139–153`). `metricPanels:350` feeds raw rows bearing that caption into Chart. `plot.ts:38–47` sums every duplicate timestamp per caption; lines 52–63 sum overflow into “other” beyond 20 series. Chart legend derives summary values from those transformed points, while `metricPanels:356–360` groups raw rows under that same incomplete label. Contrary to the implementation narrative, actual generic plot code sums duplicates; it does not discard all but one. Additionally max/mean use COALESCE(integer aggregate, double aggregate): same-series samples int=1 and double=100 return max=1 and mean=1 rather than 100 and 50.5. Latest may come from the double row, producing an internally inconsistent summary. Optional group uses COALESCE to literal `not set`, merging SQL NULL with actual string `not set` and loses typed identities.

**Reachable consequence.** Two gauge attribute sets at one instant, values 1 and 2, become one plotted value 3 while exact raw-row mean is 1.5. Untagged resource instances merge by default. A legitimate >20-series metric gains an implicit summed series. Mixed numeric sample representation is supported by OTLP gauge/sum; int/double is not a trustworthy separate identity. These corrupt interpretation of the actual metric under ordinary supported input.

**Smallest correction.** At existing shared Metrics planner/shaper owner, keep a stable typed recorded series identity (metric descriptor/kind/unit/temporality/monotonicity plus recorded resource/scope/point dimensions) separate from its human caption, and reuse it consistently for chart and selectable exact summary. Do not use caption concatenation as identity. For unaggregated points preserve independent series; metric shaping must bypass generic duplicate-sum/overflow folding, while preserving generic Chart's separately approved query-series behavior for other consumers. Any supported grouping/aggregation must be explicit and computed consistently over compatible points; unsupported aggregation remains unavailable. Derive exact summary values over both scalar representations using existing SQL/result capabilities, not COALESCE between disjoint aggregates. Maintain exact text display and mark approximate chart geometry. Respect existing sensitive payload authorization rather than bypassing it to obtain identity.

**Burden/proof.** A shared Metrics correction is necessary; splitting by kind/unit alone or changing only the legend cannot prevent invalid series production. No new transport or generic analytics framework is justified. Test same timestamp/different attrs and resources, typed null/string group collision, mixed int/double samples, >20 series, missing/zero, and unsafe scalar integers. Assert exact SQL results and legend/summary identity and visibility agreement; no sum/folding occurs unless an explicit valid aggregation was selected. Keep generic authored-query plot regressions green.
