### MAINT-005-1 — INCORRECT: shared YAML presentation rewrites authored multiline values

- **Changed location:** `crates/wyrd/wyrd-server/wyrd-ui/packages/ui/src/lib/format.ts:103–104`, `fmtYaml`'s multiline `inline` branch.
- **Obligation:** TASK-005 requires the selected raw Card/spec YAML and native Prompt body to reflect the authored form, preserving native extension fields; architecture's Prompt contract preserves that form. The maintainer guide requires outcome tests and clear, locally owned rules. This serializer is the shared owner used by CardFacts YAML, native PromptMessages and VersionDiff.
- **Source-proven path:** CardFacts calls `fmtYaml(card)` at line 34; PromptMessages calls `fmtYaml(spec.body)` at line 37 and settings at line 51; VersionDiff's `show` formats non-string changed fields through it. Every multiline string not beginning with whitespace enters the literal-block branch. Its `.trimEnd()` removes authored trailing spaces from each line, and the chosen `|` clip chomping cannot retain multiple final newlines.
- **Reproduction:** Read candidate source directly with `mise exec -- node --input-type=module`, import `packages/ui/src/lib/format.ts`, and evaluate `fmtYaml({system: "a  \\nb\\n\\n"})` using real newline escapes. Parse the result with existing Python PyYAML under `mise exec -- python3`. Actual source execution yielded input `{'system': 'a  \\nb\\n\\n'}` and decoded result `{'system': 'a\\nb\\n'}`; equality was false. No source/test file was changed for this check.
- **Observable consequence/materiality:** A valid authored Prompt's whitespace is lost in its advertised raw YAML/native body. A native-body version change affecting those characters is recognized by `diffPrompts` but both body sides can then display the same formatted value. This undermines exact-version inspection/comparison, an explicit task outcome; it is not a demand for arbitrary YAML features.
- **Concrete maintenance cost:** The custom literal-block branch makes callers depend on subtle YAML indentation/chomping rules. Its test at `ui-library.test.ts:2073` and native-body test at line 2129 derive the expectation from the same formatter, so they cannot detect altered data.
- **Smallest testable correction:** Fix this once in the formatter. Use the existing JSON-string scalar path for multiline strings whose whitespace cannot be preserved by the current literal representation (JSON double-quoted scalars are valid YAML), or preserve their spaces and chomping correctly locally. No new serializer framework, dependency, cache, loader or caller guard is needed. Preserve block layout for currently correct ordinary multiline text. Add focused expected-value/round-trip cases for trailing spaces and multiple final newlines, plus one native-body comparison rendering proving distinguishable authored values remain distinguishable.
