## Deployed path and affected capabilities

The production UI uses adapter-node (`wyrd-ui/svelte.config.js`). An authenticated request goes through `src/hooks.server.ts` BrowserSession resolution, then the tenant/layout/page loads. Observe layout owns the list/facets/overview/metric reads; the page independently owns selected trace/span/log reads. Both use the existing session-bound nodeExecutor, whose Bifrost path creates/collects a native stream. No durable state or background job was added here.

In official images, Node BFF, Rust server and nginx are siblings in one container. `architecture/operations/deployment-and-release.md:239–245` and `docker/official/extras/entrypoint.sh:25–49` establish that any child exiting terminates the others. Thus a BFF process crash also removes unrelated HTTP/MCP/gRPC capabilities on that replica until its external deployment restarts it. This matters beyond one drawer.

## SYS-005-1 — REGRESSION: streamed drawer cancellation can terminate the shared BFF

**Location:** `crates/wyrd/wyrd-server/wyrd-ui/src/routes/t/[tenantKey]/observe/+page.server.ts:28–33`.

**Violated boundary:** previously awaited request errors must remain request-local; the spec's cancellation requirement does not permit bringing unrelated capabilities down. The change exposes a new promise rejection window before the Svelte catch blocks or SvelteKit serializer observe these reads.

**Producer → consumer evidence:**

1. `nodeExecutor.run` deliberately rejects on aborted signals (`packages/ui/src/lib/node.ts:73,77`); Bifrost collection checks the signal at lines 44 and 49. This is a supported interruption path, not malformed user data.
2. The changed Observe route returns raw `loadPanel(...)` promises for data requests (both the log branch and trace/span branch), with no immediate rejection handler. Direct SSR still awaits them safely.
3. Installed SvelteKit `src/runtime/server/data/index.js:100–127` awaits all route/layout data before calling `data_serializer.add_node`. Observe layout itself awaits multiple dependent reads (`observe/+layout.server.ts:48–59`); when entering Observe, changing list state, or invalidating its layout, this supplies a genuine asynchronous window while the selected-record promise is already running.
4. `src/runtime/server/page/load_data.js:177–190` returns the object without observing its nested promises. The first rejection handler is installed by `src/runtime/server/page/data_serializer.js` inside the Promise reducer (approximately lines 159–184), after that window. The framework's auto-catch for event.fetch does not apply: this route calls the native SDK through nodeExecutor instead.
5. The Svelte page's await/catch only handles promises delivered to the browser. It cannot catch server rejection before serialization. If a drawer read rejects from request cancellation while another layout read is still pending, Node sees an unhandled rejection first. An aborted stream waiting for initial native connection may not settle synchronously with a sibling already collecting, so cancellation does not require every layout promise to finish before this window closes.

**Executed focused reproduction:** imported the existing built Observe page module from `.svelte-kit/output/server/entries/pages/t/_tenantKey_/observe/_page.server.ts.js`, called `load` with valid trace `0123456789abcdef0123456789abcdef`, `isDataRequest: true`, a session client stub, and `request.signal: AbortSignal.abort()`. Delayed observation for 25 ms to represent another pending layout load. A temporary process listener recorded `{"streamed":true,"unhandledBeforeSerialization":["AbortError"]}`. Repeating without the listener exited with status **1**, `DOMException [AbortError]`, Node **v26.2.0** (the same version pinned by official Dockerfiles). No repo file was created for the reproduction. The client stub is never used for IO because nodeExecutor throws before dispatch. This proves the returned promise's process behavior; it is not a full authenticated HTTP interruption test or a claim of having crashed the running development stack.

**Observable consequence / materiality:** interrupted navigation can escape the per-request/component boundary and terminate the shared Node process. In official containers the supervisor then stops Rust and nginx too. Recovery requires container/process replacement and affects unrelated requests on that replica. Stable WyrdError outcomes normally resolve and do not trigger this, but abort is expressly supported and must not have this system consequence.

**Smallest testable correction:** immediately mark each intentionally streamed promise's rejection observed before returning it, while preserving its original settlement for the framework and Svelte error view; reuse native Promise catch behavior. Cover log, waterfall and optional record branches at this owner. Do not add a process-level swallowing hook, retries, another loader/transport, or weaken nodeExecutor cancellation. A focused delayed-observation test should exercise cancellation before serializer attachment and assert no unhandled rejection, plus retain the same rejection/visible error for the consumer. Existing direct-SSR awaiting and independent list reads must remain intact.
