## Proposed finding I027-R4-01 — REGRESSION

**Violated obligation:** REQ-030's public WyrdView host and REQ-036/AC-015's narrow rendering and authored-document authority. Reloading/replacing a document must render its authored panels. The task's non-goal against reader add/remove controls does not ban a host passing a different accepted document; replacement/reset is an explicit existing lifetime supported by this renderer and prior remediation constraints.

**Exact location:** `packages/ui/src/lib/WyrdView.svelte:137-138`, narrow `ordered` comparator. Producers are `parsed:56`, synchronous `placements:129-134`, and post-effect `panels` replacement at `:83-89,236-255`.

**Reachable path and cause:** Mount a valid view with at least two old panel IDs at width 500; then replace `doc` with another valid view having two different IDs. `parsed` and `placements` already describe the new document, while `panels` still holds the previous generation until the ordinary loading effect calls start. Narrow ordered immediately sorts these old panel records using `placements.get(a.id)!` / `placements.get(b.id)!`. The assertions erase only TypeScript checks; both lookups are undefined and `p.y` throws before the new loaded panel generation can render. The same source has no corresponding dereference in desktop order, and `boxStyle` explicitly handles a missing placement. Stale asynchronous settlement protections do not solve this synchronous presentation-generation mismatch.

**Independent read-only runtime evidence:** Executed the actual candidate WyrdView and imported local dependencies, compiled entirely in memory with installed `svelte/compiler` 5.57.2, TypeScript transpileModule and vm SourceTextModule. Used native installed Svelte browser runtime, jsdom, clientWidth=500, and an ordinary Svelte reactive props object. Both documents contain two schema-valid Chart stat inputs (`sql:'select 1'`) and bounded layouts `{x:0,y:0,w:12,h:4}` / `{x:0,y:4,w:12,h:4}`. The shared loader resolves ordinary empty props. After mount and flush, output was `initial [ 'old', 'old2' ]`. Assigning a new valid document with IDs new/new2 and flushing produced `TypeError: Cannot read properties of undefined (reading 'y')`, stack at actual WyrdView ordered comparator and Svelte update_derived/batch traversal. No application file, test, generated artifact or probe script was written. Initial harness attempts failed on compiler import shape and module-link setup; correcting the in-memory harness enabled the actual-source reproduction. This is a mounted candidate failure, not a separate reimplementation of the comparator.

**Observable consequence:** A supported narrow custom host replacing its document throws during the render update rather than showing the new view. The candidate's check/test/build and existing narrow test do not cover this transition. Gallery/example have stable panel IDs and AppBridge remounts, so those callers mask the public shared-owner regression.

**Sibling callers / writers examined:** All layout readers share the same placement Map. Local edits change layouts without changing IDs and do not trigger panel reloads. Reactive input/range changes keep IDs in existing tests. Gallery/example echo documents with unchanged panel IDs. AppBridge destroys the whole renderer for a new result. Public mountView has no update method. Public WyrdView export supports direct-Svelte changed doc props, which is the reachable failing consumer. Only start writes the loaded panel collection; settle updates props and ignores aborted controllers. No host-side fix, reset signature change or executor change belongs here.

**Smallest testable correction boundary:** Keep the existing WyrdView ordering/projection owner and current placement Map. Narrow rendering must only order loaded panel records with a placement in the current accepted authored document; discard obsolete-generation records from that projection until start supplies the current records, then retain the required `(y,x)` order. Current Map membership already expresses this invariant; no new generation store, parser, framework, host protocol, placeholder layout, guessed coordinate, or load-lifetime redesign is needed. This guard belongs at the renderer's ordering boundary because it combines two separately timed views of one authored document; changing shared data loading to synchronous rendering work would broaden the correction and risk layout-only no-reload behavior. Preserve existing start/abort/settle, no feedback requirement, reset/capture cleanup, fixed geometry, arbitrary IDs and loaded props semantics.

**Focused closure proof:** Extend the existing Narrow views scenario with a real document transition at width 500: begin with two ordinary IDs, replace with a different valid two-panel document (include reversed authored x order for the new pair), flush, and assert no thrown error, only new IDs, correct `(y,x)` sequence, retained h and absent controls. Also exercise host removal/renaming through the same public reactive-document facility if chosen within that same case; these share the ID-domain mismatch. A pending old load must remain unable to resurrect an obsolete panel under existing abort rules. Reuse existing component test/measurement facilities; no new harness or dependency is needed. Keep grid/edit/reset/cancel regression cases green and run UI check/build for renderer changes. No schema/codegen/backend/journey aggregate is needed for this bounded correction.
