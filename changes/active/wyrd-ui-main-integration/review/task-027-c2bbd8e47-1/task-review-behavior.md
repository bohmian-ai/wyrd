## Proposed FIND-027-4 — inherited object keys become authored layouts

Classification: **INCORRECT**. Violated obligations: REQ-036/AC-015 valid authored layout positioning, complete valid document callbacks and untouched-panel preservation; REQ-030 accepts any nonempty unique panel id.

Primary source: `packages/ui/src/lib/WyrdView.svelte:96,107,113,152-155`. Sibling source: transient height record and lookup at 116/120. Contract producer: `schemas.ts:197-199,216-220`. Observable consumers: `layout.ts:36-38`, WyrdView boxStyle/current and callback host feedback.

Reachable scenario: a valid view contains a panel with id `constructor`, `toString` or `__proto__`, with an ordinary valid explicit layout, plus another editable panel. These names pass PanelSchema. On the initial render `kept` is `{}`, so `kept['constructor']` is the inherited Object constructor and wins over `panel.layout` at line 113. `place` spreads that function into `{auto:false}` without x/y/w/h; boxStyle generates invalid grid coordinates and dimensions, and following placement can receive NaN bottoms. This breaks read-only documents before any editing. After editing a different panel, `{...kept, [draft.id]:...}` still has Object.prototype; line 155 mistakes the inherited function/object for a completed sibling edit and overwrites the untouched sibling layout. A feedback host then receives a document that fails its own layout contract (or serializing a function-valued layout silently omits it). The measurement record has the same own-entry assumption and must be included in the correction boundary.

Independent read-only reproduction used the pinned Node toolchain to import the actual candidate schemas and geometry. An input with id `constructor`, layout `{x:0,y:0,w:6,h:4}`, and an ordinary sibling validates successfully. Evaluating the renderer's actual selection expression `kept[p.id] ?? p.layout` and calling the actual `place` produces the first placement `{auto:false}` rather than its authored coordinates. `typeof kept.constructor` is `function`. Evaluating the actual callback overlay with an untouched inherited-key sibling similarly replaces its valid layout with that function (JSON output omits the function-valued property). No synthetic load or package build was involved.

Producer/caller inventory: `kept` has only initialization, new-document reset and commit replacement writers; its geometry and whole-document reads share this cause. `heights` is initialized locally and written by the offsetHeight binding, then consumed by placement. `placements` already uses a Map and correctly supports arbitrary IDs; PanelView lookup uses equality and is not the cause. All WyrdView consumers (direct component, mountView, gallery, example, MCP artifact) inherit the same fault. No host correction can restore an id's layout before the renderer chooses the inherited value.

Required smallest outcome: retain the existing WyrdView owner and make its id-keyed layout and height lookups distinguish own entries from inherited Object properties for every initialization/reset/commit state. Standard `Object.hasOwn` checks at those lookups, or one consistently prototype-free/native-map representation through all writers, suffice; no reserved-name restriction, new validator, host merge, dependency, framework or API is warranted. Leave schema IDs unchanged. Use the same corrected own-entry semantics for callback overlays so untouched panels retain their authored layout or absence of layout.

Focused proof: render valid placed and unplaced panels named `constructor`, `toString` and `__proto__` alongside an ordinary sibling; assert finite expected placement and successful editing; edit the ordinary sibling, assert exactly one callback, untouched inherited-key panels unchanged, and `validateView(callback)` succeeds. Include non-echoing completion then echo without lost edits or reload. This is one shared-key cause, not separate findings per caller or spelling. Existing ordinary-id tests do not exercise it.
