# Focused follow-up: confidential OAuth client and encrypted session cookies

Result: **RESOLVED**. Subject: base `8651b96fd0c049ab5e63b0606c98326af1fc8848`, candidate `843484f6cceba1f48139349f66794966221c5d37`. This follow-up resolves the authority/source mismatch only; it does not repeat discovery of other findings or certify either complete task.

## Resolution

The security review accurately describes both the authority and actual implementation. The confidential-client and encrypted-cookie properties **are absent in the baseline and candidate**. The behavior review's phrase “confidential-client owners retained” is factually incorrect. Its more limited claim that existing session behavior is retained is correct. The standards report's claim that tokens remain out of page data is supported, but does not establish encrypted cookies or client authentication. These statements concern different guarantees and cannot be reconciled as an unconditional REQ-006 PASS.

This is not an introduced authentication regression. It is inherited implementation drift explicitly carried into an approved requirement whose premise (“the configured confidential OAuth client”, preserve “HttpOnly/encrypted cookie behavior”) does not match main. Because REQ-006 names the properties, baseline inheritance alone cannot turn them into passing acceptance or erase the authority conflict. Conversely, this transport/removal task does not authorize an adjacent client-registration and secret-lifecycle redesign merely by asking to retain nonexistent behavior.

The appropriate route for this discrepancy is **SPEC_REVISION_REQUIRED**, rather than a bounded transport remediation: establish the missing security prerequisite and its ownership/scope under the existing stronger security/design authority. Do not silently revise the spec to bless the public/plaintext-cookie implementation. A human-approved scope/dependency correction can name the prerequisite; changing the stronger security posture itself would require its own explicit approval. This follow-up does not select new secret delivery, keyring, rotation or replica ownership contracts.
