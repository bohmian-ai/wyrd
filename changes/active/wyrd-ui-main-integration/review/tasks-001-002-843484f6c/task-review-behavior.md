## Proposed finding

### BEH-001 — Cached server-only releases bypass the new UI completeness requirement

- Task: TASK-001. Classification: **INCORRECT**. Violated obligations: REQ-002, REQ-003 recovery guidance, AC-001; task Scenario 1 requires incomplete UI never to replace a working install and requires consumer closure.
- Changed enforcement site: `crates/wyrd/wyrd-cli/src/server/install.rs:445` (`extract` UI predicate). Missed sibling paths: `ServerInstaller::install` at lines 228–249 and `installed` at lines 190–197. Consumer: `DevArgs::run` at lines 101–104 and `DevServer::check_ui` at lines 229–236. Public installer caller: `src/server/mod.rs` Install dispatch.
- Producer-to-consumer evidence: prior releases used this same versions directory but bundled no UI. `install()` still treats an existing `versions/<latest>/wyrd-server` as sufficient to skip download/extract, and then activates that directory unconditionally. Thus the new predicate is unreachable for cached versions. `installed()` likewise returns a server-only directory, so `server dev` selects it, then `check_ui` tells the caller to run `wyrd server install`; running that command selects the same cache and cannot repair the missing UI.
- Reachable failure: retain a usable active version A, with server-only cached version B (a pre-change installation or a cached release whose UI has been removed), and make the release service list B as newest compatible. Running Install returns success and changes current to B without fetching or validating any B UI. `server dev` then refuses the missing production UI. No malformed external request or speculative future feature is needed.
- Observable consequence: an incomplete cached package can replace a working application installation, and the prescribed recovery command repeats successful activation of the same unusable package. Downloaded-missing-UI coverage does not exercise this branch.
- Existing alternative and smallest correction boundary: keep the existing `ServerInstaller` staging/signature/activation workflow. Apply its UI-completeness decision before **every** activation, including reuse of cached versions, and make installed-release selection consistent with that decision. Incomplete cache content must never be activated; repair/replacement must go through the same verified staging owner, retaining the previous current installation until the replacement is valid. Do not add another installer, lifecycle owner, Node bundle, domain client or downstream-only check. System-Node runtime compatibility remains the launch owner's responsibility as specified by the task.
- Focused closure proof: extend the existing `server_install` fixture owner to retain a good active A and a cached server-only B. Assert the new Install operation does not activate incomplete B and preserves A on any failed verified replacement; prove successful verified UI replacement/reuse is runnable according to the same payload contract. Also cover `server dev` selecting/recovering an incomplete active cache without falsely directing the user to a no-op install. Reuse the existing exact Rust integration target `mise exec -- cargo nextest run --locked -p wyrd-cli --test cli -E 'test(=server_install::server_install_preserves_previous_on_failure)'` when adding the activation case there; use the corresponding exact selector if a separate focused scenario is added. This review did not modify fixtures to manufacture a new passing test.
