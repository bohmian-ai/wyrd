# Agent Runtime

`Agent` and `Workflow` are the local authoring and run surfaces for Skald.
Wyrd stores declarations as cards; user code runs the implementation.

## Agent

An `Agent` is a single flat runtime struct with envelope metadata, a resolved
prompt, runtime-local tools, callbacks, session memory, and run configuration.

`agent.run(input, *, session_id=None)` drives the bounded model/tool loop
through the process provider registry. Provider requests and responses stay in
typed provider-native wrappers.

## Workflow

A `Workflow` stores `Vec<WorkflowStep>`. Each step has an `action` and
`depends_on`. The shipped S13 action is `WorkflowAction::Agent(AgentRef)`.
The internal `DagExecutor` schedules the graph; users call `Workflow.run`.

`Workflow.run(input) -> WorkflowRun` returns per-step outcomes, events, final
step id, accumulated structured-output parameters, and terminal text.

## Cross-Step Parameters

When a prompt declares structured output, `AgentRun.structured_output` is
merged into `WorkflowRun.parameters`. Downstream prompts resolve variables in
this order: upstream parameters, then workflow input.

## Observer

Observers are workflow-scoped instrumentation. Attach them through
`Workflow(observers=[...])`, `Workflow.sequential(..., observers=[...])`, or
`Workflow.parallel(..., observers=[...])`.

Callbacks mutate inline behavior. Observers watch lifecycle events. See
[Observer](/concepts/observer/).

## Cascade Registration

Named child agents in a workflow produce cascade entries for registry-owned
durable registration. Local workflow execution uses inline resolved specs and
does not require registration. See
[Cascade Registration](/concepts/cascade-registration/).
