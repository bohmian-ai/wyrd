# Cards

<Aside title="TL;DR" data-variant="wyrd">
A Card is the shared envelope for any Wyrd-governed asset. Same outer shape across all 18 kinds; the typed Spec carries kind-specific fields.
</Aside>

<dl class="wyrd-defs">
  <dt data-kind="model">Identity</dt>
  <dd>`metadata.space`, `metadata.name`, `metadata.version`, optional `uid`, and the top-level `kind`.</dd>

  <dt>Payload</dt>
  <dd>A typed Spec validated against the schema for the card's kind.</dd>

  <dt>Metadata</dt>
  <dd>Labels for indexed classification and annotations for descriptive context.</dd>

  <dt>Status</dt>
  <dd>Server-managed lifecycle state. Local card holders may serialize `null` before registration.</dd>
</dl>

A Card should answer four questions without a side conversation: what is this,
which typed Spec describes it, what other Cards does it depend on, and which
rules apply when it is used.

<Aside title="What this isn't" data-variant="not">
A Card is **not** a file-system artifact, an ORM row, or a git blob. Local card
objects can write local files, but durable registration is owned by registry or
client surfaces.
</Aside>

## Shape

```yaml
apiVersion: wyrd/v1
metadata:
  space: default
  name: customer-churn
  version: "0.1.0"
  labels:
    domain: customer
  annotations:
    example.com/source: local notebook
kind: Data
spec:
  interface:
    kind: Pandas
relationships: []
status: null
```

The envelope is stable. `kind` selects the typed `spec`. `CardRef` values inside
specs connect Cards. Server-derived `relationships` explain those connections.
Server-managed `status` tracks lifecycle.

## Lifecycle

Card objects are local holders. For example, Python `DataCard.save(path)`
materializes local data files and writes `card.json`; `DataCard.load(path)`
hydrates local data through the held interface. That local workflow does not
register the Card, upload artifacts, or create an `ArtifactCard`.

Durable registration belongs to registry and client surfaces. Storage owns
durable bytes. `ArtifactCard` records durable artifact metadata, and specs link
to artifacts through `CardRef`.
