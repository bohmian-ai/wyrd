# Cards

<Aside title="TL;DR" data-variant="wyrd">
A Card is the durable record for any Wyrd-governed asset. Same envelope across all 18 kinds; the typed Spec carries kind-specific fields.
</Aside>

<dl class="wyrd-defs">
  <dt data-kind="model">Identity</dt>
  <dd>kind, name, owner, version — stable across the lifetime of the asset.</dd>

  <dt>Payload</dt>
  <dd>A typed Spec validated against the schema for the card's kind.</dd>

  <dt>Status</dt>
  <dd>Where this version sits in its lifecycle (draft, released, retired).</dd>

  <dt>References</dt>
  <dd>Explicit links to other Cards that this one depends on at runtime.</dd>
</dl>

A Card should answer four questions without a side conversation: what is this, which typed Spec describes it, what other records does it depend on, and which rules apply when it is used.

<Aside title="What this isn't" data-variant="not">
A Card is **not** a file-system artifact, an ORM row, or a git blob. It is a typed, versioned record the registry owns end-to-end.
</Aside>
