# Cascade Registration

When you register a card that composes other named cards, Wyrd registers the
children transactionally before committing the parent. A workflow can therefore
carry named `Agent` children without leaving dangling references in durable
storage.

## Composition Rule

Authoring is local. You compose workflows from `Agent` values. Anonymous agents
stay inline. Named agents with a version produce cascade entries so the registry
can register or relate them before the parent workflow is committed.

| You pass | Intent | Cascade effect |
|---|---|---|
| Anonymous `Agent` | Inline only. | No cascade entry. |
| Named `Agent` with version | Child card. | `CardRef` appended and registered. |

The workflow spec stores enough inline data for local execution. The cascade
manifest is the server-facing view of which child cards belong with the parent.

## Register

On `client.cards.register(workflow_card)`, the server walks
`cascade_children`, registers children without `uid`, records relationships for
children with `uid`, and commits the parent. Failure rolls back the submission
with `WYRD_REGISTRATION_500_CASCADE_ROLLBACK`.

Local `Workflow.run(...)` does not require registry state.
