# Observer

`Observer` is a Python base class you subclass to receive lifecycle events from
workflow runs. All methods have no-op defaults.

<Aside type="note">
For a step-by-step setup, see [Instrument with Observers](/guides/instrument-with-observers/)
and [Instrument with OTel](/guides/instrument-with-otel/). This page covers the lifecycle reference.
</Aside>

Install observers only on workflows:

```python
from wyrd import Observer, Workflow

class RunLogger(Observer):
    def on_workflow_start(self, run_id, workflow_id, step_count):
        print(f"start {workflow_id}")

wf = Workflow.sequential("research", planner, writer, observers=[RunLogger()])
wf.run({"topic": "Rust"})
```

There is no global Python install path and no per-run observer parameter.

## Why Workflow Level

The Workflow owns the run id, DAG scheduling, step dependencies, fan-out, fan-in,
and final result. Observers attach there so every child Agent event belongs to
one workflow event stream.

An Agent owns only its local model loop: prompt rendering, tool calls,
callbacks, session memory, and finish reason. Agent-level observers would split
multi-step runs into separate streams without one owner for parent-child order,
dependency timing, or final workflow status. Wrap a solo Agent in a one-step
Workflow when it needs lifecycle events.

## Callbacks Vs Observers

| You want to | Use |
|---|---|
| Replace requests, transform responses, or abort inline behavior | Agent callbacks |
| Count tokens, emit traces, audit events, or log lifecycle | Workflow observers |

Callbacks can return replacement values. Observers watch; their return values
are ignored.

## Multiple Observers

`observers=` is always a list. Order is preserved.

```python
wf = Workflow.sequential("research", planner, writer,
                         observers=[OtelObserver(), TokenCounter()])
```

## OTel

`OtelObserver` is just an observer. Add it to `observers=` when you want spans.
It uses the Python OpenTelemetry SDK and the tracer provider already configured
by your application.

```python
from wyrd import OtelObserver, Workflow

wf = Workflow.sequential("research", planner, writer,
                         observers=[OtelObserver()])
```

Span shape:

```text
workflow.run/research
├── agent.run/planner
│   └── model.call/openai
└── agent.run/writer
    └── model.call/openai
```

## Custom Observer

```python
from wyrd import Observer

class MetricsObserver(Observer):
    def on_model_call(self, run_id, agent_id, iteration, provider, model, request):
        if provider == "openai":
            metrics.histogram("prompt_messages", len(request.openai().messages))

    def on_model_result(self, run_id, agent_id, iteration,
                        finish_reason, synthetic, response):
        if synthetic:
            return
        try:
            usage = response.openai().usage
        except Exception:
            return
        if usage:
            metrics.histogram("tokens_out", usage.completion_tokens)
```

## Solo Agents

A standalone `agent.run(...)` emits no observer events. Wrap it:

```python
solo = Workflow.sequential("solo", agent, observers=[MetricsObserver()])
solo.run("input")
```

## Lifecycle Reference

| Method | When |
|---|---|
| `on_workflow_start(run_id, workflow_id, step_count)` | Before DAG scheduling. |
| `on_agent_start(run_id, parent_run_id, agent_id, input, session_id)` | Child agent starts. |
| `on_iteration(run_id, agent_id, index)` | Agent loop iteration starts. |
| `on_model_call(run_id, agent_id, iteration, provider, model, request: ProviderRequest)` | Provider request dispatch. |
| `on_model_result(run_id, agent_id, iteration, finish_reason, synthetic, response: ProviderResponse)` | Provider response received. |
| `on_tool_call(run_id, agent_id, iteration, call_id, tool_name)` | Tool invocation starts. |
| `on_tool_result(run_id, agent_id, iteration, call_id, ok)` | Tool invocation completes. |
| `on_agent_finish(run_id, agent_id, finish_reason, iterations, duration_ms)` | Agent completes. |
| `on_agent_error(run_id, agent_id, code, message)` | Agent fails. |
| `on_workflow_finish(run_id, workflow_id, duration_ms)` | Workflow completes. |

`synthetic=True` means the response came from callback abort/error synthesis.
Check it before calling provider-specific response accessors.
