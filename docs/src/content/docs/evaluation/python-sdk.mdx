# Python SDK

## `run_eval` signature

`wyrd.eval.run_eval` is a thin protocol client. It opens a run on a Wyrd
server, loops on the server's next directive, calls the supplied Python
callbacks, and returns when the server emits `RunComplete`.

```python
from collections.abc import Callable
from typing import Literal, TypedDict


class ConversationTurn(TypedDict):
    role: Literal["User", "Agent"]
    content: str


class AgentTurnResponse(TypedDict, total=False):
    response: str
    records: list[dict]


class RunSummary(TypedDict):
    run_id: str
    server_url: str


def run_eval(
    server_url: str,
    eval_ref: str,
    agent_fn: Callable[[str, list[ConversationTurn]], AgentTurnResponse | str],
    *,
    simulated_user_fn: Callable[[list[ConversationTurn]], str] | None = None,
    simulated_user: Literal["server", "client"] = "server",
    request_timeout_secs: int = 60,
) -> RunSummary: ...
```

## Quickstart

```python
from wyrd.eval import run_eval


def agent_fn(message, history):
    return f"received: {message}"


summary = run_eval("http://127.0.0.1:8080", "team/support-eval@1.0.0", agent_fn)
print(summary["run_id"])
```

The callable runs in the caller's Python process. It can return a plain string
or `{"response": "...", "records": [...]}` when the agent emits eval records
for mechanic-view tasks.

## Simulated-user modes

| Mode | Python caller behavior | Notes |
|---|---|---|
| `server` | Provide only `agent_fn` | Server supplies non-scripted user turns, usually through a configured persona |
| `client` | Provide `agent_fn` and `simulated_user_fn` | Caller supplies the next user turn from local Python code |

Scripted scenario turns are server-side scenario data. They do not require a
third Python mode.

## Errors

The Python client raises `WyrdError` for validation, transport, malformed
protocol responses, and callback failures. The stable `code`, `message`,
`details`, and `remediation` fields come from the shared Wyrd error catalog.

```python
from wyrd import WyrdError
from wyrd.eval import run_eval

try:
    run_eval("not a url", "team/support-eval@1.0.0", lambda message, history: message)
except WyrdError as error:
    print(error.code)
    print(error.remediation)
```

Auth failures, missing routes, malformed directives, and callback exceptions
are distinguished by the Wyrd error metadata rather than eval-specific Python
exception classes in v1.

## What v1 does not ship

- `fetch_results(run_id)`: the v1 server protocol has no results-fetch route.
  `RunSummary` carries `run_id` and `server_url`; results remain server-side.
- `local=True`: embedded local execution is available through
  [`wyrd eval run --local`](/evaluation/running-evals/), not through the Python
  protocol client.
- Retries with jitter: the client is single-attempt so wire-shape and callback
  failures remain visible.
- Subprocess agents: Python supplies an in-process callable. Use the CLI
  `--agent-url` flow when the agent is hosted as a local HTTP process.
