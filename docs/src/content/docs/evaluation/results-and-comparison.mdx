## EvalResults

`EvalResults` is the artifact produced at the end of a local eval run. It contains run identity, per-scenario results, per-subject rollups, run-level metrics, and an optional pass-gate verdict.

### Reading task results

Each entry in `subjects.<key>.task_results.<task_id>` is a list of `AssertionResult` rows — one per record the task ran against.

`AssertionResult` fields:

| Field | Description |
|---|---|
| `task_id` | Which task produced this result |
| `passed` | `true` / `false` |
| `actual` | The extracted value (affected by `context_capture`) |
| `expected` | The declared expected value |
| `operator` | The comparison that ran |
| `message` | Human-readable failure reason when `passed: false` |
| `stage` | Topological stage index |
| `started_at` | UTC timestamp |
| `duration_ms` | Execution time |

### Scenario pass logic

A scenario passes when:
- Mechanic view: all `AssertionResult` rows are `passed: true`, **and**
- Passenger view: all scenario task summaries are `passed: true`

A scenario with zero mechanic results and zero passenger tasks is `scenario_passed: false`. Empty results are not a pass.

## Pass gates

`EvalSpec.pass_gate` applies once after all records are aggregated.

### `overall_pass_rate`

```yaml
pass_gate:
  kind: overall_pass_rate
  threshold: 0.9
```

`passed_tasks / total_tasks >= threshold`. Counts every `AssertionResult` row across all subjects and tasks.

### `per_judge_pass_rate`

```yaml
pass_gate:
  kind: per_judge_pass_rate
  threshold: 0.85
```

The minimum per-task pass rate across all subjects must be `>= threshold`. Catches the case where a single task has poor quality even if the overall rate looks good.

### `all_pass`

```yaml
pass_gate:
  kind: all_pass
```

Every task across every record must pass. Zero tolerance. Use for high-stakes gates where any failure is a blocking regression.

## Exit codes

| Code | Meaning |
|---|---|
| `0` | Run completed. Gate passed or no gate declared. |
| `1` | Run failed (load error, engine error, transport failure). |
| `2` | Run completed. Gate declared and failed. Requires `--fail-on-gate` (default on). |

## Comparison

Save a `EvalResults` JSON file as a baseline, then pass it to subsequent runs with `--baseline`. The CLI writes `comparison.json` alongside `results.json`.

```bash
# Save a baseline
wyrd eval run ... --out .wyrd/eval/baseline
cp .wyrd/eval/baseline/results.json baselines/support-eval@1.0.0.json

# Run against the baseline
wyrd eval run ... \
  --baseline baselines/support-eval@1.0.0.json \
  --out .wyrd/eval/candidate
```

### Four-quadrant classification

Each subject and task gets classified:

| Classification | Meaning |
|---|---|
| `stable_pass` | Both baseline and candidate pass the cutoff |
| `stable_fail` | Both baseline and candidate fail the cutoff |
| `regression` | Candidate drops below baseline by more than the threshold |
| `improvement` | Candidate rises above baseline by more than the threshold |

### comparison.json layout

```json
{
  "baseline_run_id": "018f5f54-0000-7000-8000-000000000001",
  "candidate_run_id": "018f5f54-0000-7000-8000-000000000010",
  "subjects": {
    "agent::my-team::support-agent::1.0.0": {
      "aggregate": {
        "baseline_pass_rate": 0.95,
        "candidate_pass_rate": 0.833,
        "delta": -0.117,
        "flag": "regression"
      },
      "task_deltas": {
        "helpfulness": {
          "baseline_pass_rate": 1.0,
          "candidate_pass_rate": 0.667,
          "delta": -0.333,
          "flag": "regression"
        }
      }
    }
  },
  "scenarios": {
    "refund_status": {
      "baseline_passed": true,
      "candidate_passed": false,
      "flag": "regression"
    }
  },
  "system": {
    "baseline_pass_rate": 0.95,
    "candidate_pass_rate": 0.833,
    "delta": -0.117,
    "flag": "regression"
  },
  "regressed_subjects": ["agent::my-team::support-agent::1.0.0"],
  "improved_subjects": []
}
```

Subjects or scenarios present on only one side are listed explicitly — they are not folded into pass-rate deltas.

### Using comparison in CI

The comparison artifact tells you what changed. Block the release or not based on your policy.

```bash
#!/bin/bash
wyrd eval run \
  --eval eval-cards/support-eval.yaml \
  --scenarios data/scenarios/support-smoke.json \
  --local \
  --agent-url http://127.0.0.1:9000/agent \
  --baseline baselines/support-eval@1.0.0.json \
  --fail-on-gate

# $? is 0 (pass gate satisfied) or 2 (pass gate failed)
if [ $? -eq 2 ]; then
  echo "Pass gate failed. Check .wyrd/eval/latest/results.json"
  exit 1
fi

# Additional regression check
REGRESSIONS=$(jq '.regressed_subjects | length' .wyrd/eval/latest/comparison.json)
if [ "$REGRESSIONS" -gt 0 ]; then
  echo "$REGRESSIONS subject(s) regressed. Check comparison.json"
  exit 1
fi
```
