# Build an Agent

An Agent runs a bounded loop over a Prompt with tools, callbacks, and session memory. Provider and model live on the Prompt; the Agent owns execution policy. Observers attach to Workflows, not Agents.

## Tools

Tools are runtime-local callables. Python uses the `@tool` decorator. Rust uses `ToolDef::function(...)` or an `AgentTool` implementation. `agent.as_tool()` delegates a bounded Agent run to a parent Agent.

## Callbacks

Callbacks mutate inline behavior. They can replace a request, transform a response, or abort. Observers watch lifecycle events and ignore return values. Agent hooks include `before_agent_callback`, `after_agent_callback`, `before_model_callback`, `after_model_callback`, `before_tool_callback`, and `after_tool_callback`. `before_model_callback` receives `ProviderRequest`; `after_model_callback` receives `ProviderResponse`.

```rust
use skald_agent::{AfterModelFn, BeforeModelFn};
use skald_spec::{ProviderRequest, ProviderResponse};

let before: BeforeModelFn = std::sync::Arc::new(|request: &ProviderRequest| {
    tracing::debug!(?request, "provider request");
    Ok(None)
});
let after: AfterModelFn = std::sync::Arc::new(|response: &ProviderResponse| {
    tracing::debug!(?response, "provider response");
    Ok(None)
});
let agent = Agent::new(prompt).before_model(before).after_model(after);
```

## Session Memory

Session memory stores conversation turns by `session_id`. Supply the backend on the Agent, then pass the id for each run that should share history.

<Tabs>
  <TabItem label="Python">

```python
agent = Agent(name="support", prompt=prompt, session=memory)
first = agent.run("Hello", session_id="case-123")
second = agent.run("Continue", session_id="case-123")
```

  </TabItem>
  <TabItem label="Rust">

```rust
let agent = Agent::new(prompt).with_session(memory);
let first = agent.run("Hello").await?;
let second = agent.run_with_session("Continue", "case-123").await?;
```

  </TabItem>
</Tabs>

## AgentRun Fields

| Field | Meaning |
|---|---|
| `output` | Final assistant text. |
| `finish_reason` | Terminal reason for the bounded loop. |
| `iterations` | Number of model-loop iterations. |
| `tokens_in` | Provider input tokens when reported. |
| `tokens_out` | Provider output tokens when reported. |
| `conversation` | Conversation transcript captured during the run. |
| `error` | Structured Wyrd error when the run ended with failure. |
| `structured_output` | JSON object parsed from declared structured output. |
| `parsed` | Python typed object when `output_type` was supplied. |
| `provider_response` | Typed provider response wrapper from the terminal model call. |

Use this guide as the run-reading guide. The [Agent card reference](/cards/agent/) stays focused on fields.

## Tool Delegation: `agent.as_tool()`

Use `agent.as_tool()` when a parent Agent should call another Agent through the tool loop.

<Tabs>
  <TabItem label="Python">

```python
researcher_tool = researcher.as_tool(description="Research a topic.")
writer = Agent(name="writer", prompt=writer_prompt, tools=[researcher_tool])
```

  </TabItem>
  <TabItem label="Rust">

```rust
let delegate = AgentDelegateTool::from_agent(agent, providers);
let parent = Agent::new(prompt).with_tool(delegate);
```

  </TabItem>
</Tabs>
