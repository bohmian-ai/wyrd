# Instrument with Observers

Observers subscribe to workflow lifecycle events. Callbacks mutate inline behavior; observers watch.

## Observers Vs Callbacks

| You want to | Use |
|---|---|
| Replace requests, transform responses, or abort inline behavior | Agent callbacks |
| Count tokens, emit traces, audit events, or log lifecycle | Workflow observers |

Callbacks can return replacement values. Observers watch; their return values are ignored.

## Where Observers Attach

Python attaches observers with `Workflow(observers=[...])` or `Workflow.sequential(..., observers=[...])`. There is no global Python observer, no Agent-level observer list, and no per-run observer argument. To observe one Agent, wrap it with `Workflow.sequential("solo", agent, observers=[...])`.

Rust attaches observers per workflow with `Workflow::with_observers(vec![...])` or process-wide with `wyrd_observe::set_global(Arc::new(...))`. Both paths compose through `wyrd_observe::current()`.

## Why Workflow Level

The Workflow is the execution boundary that owns the run id, DAG scheduling, step dependencies, fan-out, fan-in, and final result. Observing there gives one event stream for the full run and keeps child Agent events linked to the same `run_id`.

An Agent owns its local model loop: prompt rendering, tool calls, callbacks, session memory, and finish reason. If observers attached to Agents directly, a multi-step workflow would produce separate event streams with no single owner for parent-child ordering, dependency timing, or final workflow status. Wrap a solo Agent in a one-step Workflow when it needs lifecycle events.

## Multiple Observers

Pass observers in order: `observers=[OtelObserver(), counter]`. Wyrd preserves order and fans each event out to every observer.

## `run_id` Semantics

`run_id` is unique per workflow run. Child Agent events carry the same `run_id` and their own `agent_id`. A solo `agent.run()` outside a workflow emits no observer events.

## The `synthetic` Flag On `on_model_result`

When a callback aborts or synthesizes a response, `synthetic=True`. Provider-specific accessors may fail for synthetic responses. Guard before reading provider fields:

```python
if synthetic:
    return
```
