# Instrument with OTel

`OtelObserver` emits OpenTelemetry spans for workflow runs, Agent runs, and model calls.

```text
workflow.run/<name>
├── agent.run/<agent>
│   └── model.call/<provider>
└── agent.run/<agent>
    └── model.call/<provider>
```

Python and Rust use independent OpenTelemetry SDKs. A workflow with a Python `OtelObserver` emits Python spans; a workflow with a Rust `OtelObserver` emits Rust spans. Span names match. SDK state does not bridge across languages.

## Where To Call SDK Init

Set the tracer provider before the first observer fires. Put SDK init in application startup. Do not put it inside a library or inside Wyrd.

## Span Sampling And Redaction

Spans carry Agent ids, provider names, model names, and timing. They do not carry message bodies. Configure sample rate on the tracer provider. When Vala archives spans, redaction belongs to the Vala archive sink.

## Troubleshooting

<Aside type="caution">

- No spans appear: check that the tracer provider was set before the workflow ran.
- Spans appear without parent linkage: use the same observer instance for the workflow run.
- Python and Rust spans do not link together: expected. They use separate SDKs.

</Aside>
