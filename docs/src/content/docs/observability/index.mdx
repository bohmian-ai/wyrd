# Observability

Wyrd observability connects runtime behavior back to cards and runs. The goal is not just metrics; it is explainable state that can drive evaluation, drift review, alerting, and remediation.

Observation records should preserve the asset identity, run identity when available, timestamp, signal type, and enough context to decide what to do next.
