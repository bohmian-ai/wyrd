# Delegation

Delegation lets one Wyrd principal request a token for a Service or Agent card
while preserving the actor chain in the JWT `act` claim and in request audit
context.

## Agent card-bound delegation

```http
POST /auth/token
Content-Type: application/json

{
  "grant_type": "urn:ietf:params:oauth:grant-type:token-exchange",
  "subject_token": "<caller's JWT>",
  "subject_token_type": "urn:ietf:params:oauth:token-type:access_token",
  "requested_subject": {
    "kind": "card_ref",
    "card_ref": {
      "space": "prod",
      "kind": "Agent",
      "name": "claude-code",
      "version": "1.0.0"
    }
  }
}
```

## Service card-bound delegation

```http
POST /auth/token
Content-Type: application/json

{
  "grant_type": "urn:ietf:params:oauth:grant-type:token-exchange",
  "subject_token": "<caller's JWT>",
  "subject_token_type": "urn:ietf:params:oauth:token-type:access_token",
  "requested_subject": {
    "kind": "card_ref",
    "card_ref": {
      "space": "prod",
      "kind": "Service",
      "name": "billing",
      "version": "1.0.0"
    }
  }
}
```

## Principal id form

Use the bare UUID form only when the caller already has the target principal id:

```http
POST /auth/token
Content-Type: application/json

{
  "grant_type": "urn:ietf:params:oauth:grant-type:token-exchange",
  "subject_token": "<caller's JWT>",
  "subject_token_type": "urn:ietf:params:oauth:token-type:access_token",
  "requested_subject": {
    "kind": "principal_id",
    "id": "9b6c8e84-3c2a-4f5e-b2d1-0f47a1c2e8d3"
  }
}
```

Principal ids are plain UUIDs. The kind discriminator lives on
`PrincipalKind`, not inside the id string.

## Response

```json
{
  "access_token": "eyJ0eXAiOiJKV1QiLCJhbGciOi...",
  "refresh_token": "eyJ0eXAiOiJKV1QiLCJhbGciOi...",
  "token_type": "Bearer",
  "expires_at": "2026-06-15T16:45:00Z"
}
```

The target `card_ref` is encoded inside the JWT `principal.card_ref` claim.
Clients that need it decode the JWT claim; they do not read a separate response
field.

## Rules

Delegation requires `Permission { Delegation, Issue }`, which is granted by the
`runtime_admin` builtin role.

The maximum delegation depth is five. Issuance refuses deeper chains and
verification rejects deeper chains. PR 5.3 does not support delegating to
Users; target principals must be Service or Agent identities in the caller's
tenant.

Wyrd does not produce or consume a separate identity header for delegation.
Caller identity lives in the delegated JWT carried by `X-Wyrd-Access-Token`.
