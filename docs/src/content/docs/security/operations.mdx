# Operations

PR 5.3 lands before production Wyrd auth data exists. Operators running it
against a populated database must treat rollout as a destructive cutover and
snapshot first.

## Migration rollout

The auth schema is folded into the existing migration train. After snapshotting
local data, reset and migrate:

```bash
mise run db:reset
mise run db:migrate
```

Verify the auth tables:

```bash
psql "$WYRD_DATABASE_URL" -c '\d wyrd.auth_users'
psql "$WYRD_DATABASE_URL" -c '\d wyrd.auth_service_accounts'
psql "$WYRD_DATABASE_URL" -c '\d wyrd.auth_refresh_tokens'
```

`auth_users.id` must be UUID-backed. `auth_service_accounts` must include
principal kind, card kind, and card UID columns. `auth_refresh_tokens` must be
principal-generic and include a revoked-reason column.

## Audit durability

Credential issuance and token exchange write audit rows transactionally with
the credential or refresh-token row. If the audit write fails, the transaction
rolls back and plaintext is not returned. The public response is
`WYRD_AUDIT_503_UNAVAILABLE`.

Fire-and-forget auth audit is forbidden. This grep must return no matches:

```bash
rg -n 'fire-and-forget|emit_async' crates/wyrd/wyrd-server/src/auth/
```

## Preview gate

`/auth/issue-key` and token exchange depend on service-account rows that the
apply-side Card Registry plane will populate. Until that lands, handlers are
behind `AppState.allow_preview_auth`.

Debug and test builds default the gate open. Release builds must keep it
closed unless a later production mount explicitly supports it. When closed, the
handlers return `WYRD_AUTH_503_PREVIEW_DISABLED` before database I/O.

## Ambiguous 5xx recovery

`/auth/issue-key` and token exchange are not idempotent in PR 5.3. Clients must
not automatically retry 5xx responses on those routes.

For an ambiguous failure, list credentials for the target principal, revoke
duplicates, and then issue a fresh credential. SDK retry middleware should
exclude these routes.

## Request ids

`Wyrd-Request-Id` is minted at the first trusted Wyrd boundary. Production
deployments should ignore inbound request-id headers from untrusted networks.
Only enable upstream propagation when a trusted upstream list is configured and
the mesh integration has shipped.
