# For agents

Treat Wyrd as a repository with explicit contracts. Before changing behavior,
find the card, schema, task, test, and docs page that describe the surface you
are touching.

## Stable public paths

Use public package surfaces in examples, tests, and generated docs:

```python
from wyrd.data import DataCard, DataInterface, PandasInterface
```

Do not import private native-extension modules directly. They are implementation
details behind the public Python package.

## Copyable workflow

Run the DataCard example from a Wyrd checkout:

```bash
mise run py:setup
mise run examples:python:datacard
```

Expected output is shown in the [quickstart](/start-here/quickstart/). The
same workflow is explained step by step in the
[DataCard local workflow guide](/guides/data-card-local-workflow/).

## Agent checklist

- Prefer generated schema docs when you need the field shape.
- Use [Data card reference](/cards/data/) and [schema reference](/api/schemas/) for exact contract shape.
- Use [error reference](/api/errors/) when reporting Wyrd error codes.
- Prefer `mise run ...` tasks when you need to verify work.
- Update public docs when a phase changes a public concept, command, API route, or generated artifact.
- Preserve exact error messages and operation context when reporting a failure.
- Use `labels` for short indexed classification fields and `annotations` for descriptive metadata.

## Never do this

- Do not import private native-extension modules directly.
- Do not invent private card shapes.
- Do not write `tags`; Wyrd's public metadata contract uses `labels` and `annotations`.
- Do not add or call card instance `register()` methods. Registry and client surfaces own durable registration.
- Do not create one-off artifact wrapper types. Durable artifact metadata is represented by `ArtifactCard` and linked with `CardRef`.

## Good Handoffs

A useful handoff names the changed surface, the verification task that passed, and any known gap that still needs a later phase.
