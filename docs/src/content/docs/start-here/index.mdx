# Start here

Pick the path below that matches how you work with Wyrd.

## Data scientist / ML engineer

You use Wyrd to register models, prompts, datasets, and evals as versioned Cards and move them from local experimentation into governed production. Start with [what Wyrd is](./what-is-wyrd/) to understand the Card model, then read the [register a card guide](/guides/register-card/) for the first hands-on step.

## AI engineer / prompt or agent builder

You work with PromptCards, ToolCards, AgentCards, and the MCP surface. Start with [what Wyrd is](./what-is-wyrd/), then see [agents and MCP](/agents/mcp/) for how to consume Wyrd through MCP tools and how structured errors are designed for agent use.

## Platform engineer

You use Wyrd to establish Card inventory, policy, audit, and deployment boundaries for your organization. Start with [what Wyrd is](./what-is-wyrd/) for the full framing, then read [ServiceCard](/cards/service/), [PolicyCard](/cards/policy/), and [AuditCard](/cards/audit/) to understand the governance surface.

## Agent

You consume Card schemas to understand types, use MCP tools to read and write Cards, parse structured errors to know what to fix, and follow task workflows defined in the guides. Wyrd does not run your code. See [use Wyrd through MCP](/agents/mcp/) and [error remediation](/agents/error-remediation/) for the primary agent-facing contracts.

## Engineering leader

Wyrd connects Security, Infra, Data Science, and Observability through a single Card-based substrate. Read [what Wyrd is](./what-is-wyrd/) for the full cross-cutting framing and the rationale for why point tools do not solve this alone.
