Tech specs document Wyrd subsystems at the level of detail a human or AI
engineer needs to implement, review, or operate them. Each spec covers:

- Scope and permanent locks
- Component topology and ownership boundaries
- End-to-end flow diagrams
- Wire contracts and state machines
- Error mapping and failure modes

<Aside title="Audience" data-variant="wyrd">
Server engineers, ML platform operators, and AI agents working on Wyrd
itself. Not a getting-started surface — see [Quickstart](/start-here/quickstart/)
for that.
</Aside>

## Conventions

- **Permanent locks** (`L#`) are invariants enforced by CI greps. Removing one is a breaking-change PR.
- **Wire types** live in `wyrd-spec` (PyO3-free) and derive `JsonSchema` + `ToSchema`.
- **Errors** cross the wire as `WyrdError` problem+json. Subsystem catalogs lift into it via `From<Wyrd*Error> for WyrdError`.
- **Sequence diagrams** are written in Mermaid. They render directly on GitHub; the docsite renders them once a Mermaid integration is added.
