# HTTP transport

The HTTP transport is the fallback for environments where gRPC is blocked
by network policy, egress proxies, or platform constraints. It uses the
same `SecretRef` and `TlsConfig` security primitives as the gRPC variant.

The Wyrd server appends ingest routes (`/api/v1/observations`,
`/api/v1/records`, etc.) to `base_url` at call time. Do not include a
trailing path.

## Configuration

| Field | Type | Default | Notes |
|---|---|---|---|
| `base_url` | `String` | `"http://localhost:50050"` | Validated non-empty. Routes are appended at call time. |
| `timeout_ms` | `u64` | `30000` | Per-request timeout. Validated `>= 1`. |
| `tls` | `Option<TlsConfig>` | `None` | See [Secrets and TLS](/transports/secrets-and-tls/). |
| `auth` | `Option<SecretRef>` | `None` | Sent as the `Authorization` header. Resolves at request time. |
| `compression` | `bool` | `false` | Gzip the request body. The server must accept `Content-Encoding: gzip`. |

## Feature gating

HTTP is gated on the `transport-http` Cargo feature in `wyrd-client`. The
default `wyrd-client` build has it on. If you build the crate with
`--no-default-features` and only `transport-grpc`, constructing a runtime
client from `TransportConfig::Http(_)` returns
[`WYRD_CLIENT_400_TRANSPORT_FEATURE_DISABLED`](/transports/troubleshooting/#feature-disabled).
