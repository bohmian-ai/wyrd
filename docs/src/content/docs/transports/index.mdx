# Transports

`wyrd-client` ships every observation, span, eval record, and agent trace to
the Wyrd server through a transport. The transport is the wire layer; the
[queue policy](/transports/queue-policy/) decides when to flush. Both are
configured before the client opens a socket.

## Pick a transport

| Transport | When to use | Notes |
|---|---|---|
| **gRPC** (default) | Production. Low overhead, streaming-friendly, mutual TLS. | Speaks `tonic` on the server. Pulls in `transport-grpc` Cargo feature; on by default. |
| **HTTP** | gRPC-restricted networks (legacy proxies, some egress policies). | `reqwest` under the hood. Optional gzip on the request body. |
| **Mock** | Tests. In-memory loopback that records every flushed envelope. | Always compiled in; no feature flag. Supports deterministic flush-failure injection. |

Queue-backed transports (Kafka, RabbitMQ, Redis) are not part of the
current `TransportConfig` enum. They return as a coherent follow-on plan
when consumers genuinely need queue publication.

## Public imports

```rust
use wyrd_client::transport::{
    GrpcConfig, HttpConfig, MockConfig, QueueConfig, TransportConfig,
};
use wyrd_spec::security::{SecretRef, TlsConfig};
```

The Python examples in this section use JSON-compatible dictionaries that
match the Rust serde shape. The typed Python constructor surface will live
under `wyrd.client` when the Python wrapper lands; there is no top-level
`wyrd.TransportConfig` alias and no `wyrd.vala` namespace.

## Defaults

`TransportConfig::default()` returns `Grpc(GrpcConfig::default())`. The
default `GrpcConfig` points at `http://localhost:50051` -- fine for a
local Wyrd server, never for production. Override the endpoint before
shipping the client anywhere.
