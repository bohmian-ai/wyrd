# Secrets and TLS

Every transport's `auth` field and every `TlsConfig` certificate field
takes a `SecretRef`, not a string. `SecretRef` decouples configuration
from credential values: the config carries a pointer (env var name, file
path, vault key); the Wyrd auth shell resolves it at connect time.

This is non-negotiable. Plaintext credentials never reach disk under
Wyrd, and serialized configs are safe to commit.

## `SecretRef` variants

| Variant | Wire form | Use |
|---|---|---|
| `Env` | `{"source":"env","name":"WYRD_API_KEY"}` | CI, simple containers, env-injected secrets. |
| `File` | `{"source":"file","path":"/var/run/secrets/wyrd/api-key"}` | Kubernetes Secret volume mounts. |
| `Vault` | `{"source":"vault","key":"secret/data/wyrd/api"}` | HashiCorp Vault, AWS Secrets Manager, Google Secret Manager. Backend selection lives in the auth shell config. |
| `Inline` (test only) | `{"source":"inline","value":"..."}` | Tests only. Not compiled into production builds. Rejected by `serde` outside the `test-utils` feature. |

`Inline` is gated at the Rust type level; production schemas do not
include it. If you see `unknown variant 'inline'` at runtime, the build is
correctly excluding the variant -- supply an `Env`, `File`, or `Vault`
reference instead.

## `TlsConfig` fields

| Field | Type | Notes |
|---|---|---|
| `ca_cert` | `Option<SecretRef>` | Override the system CA pool. PEM-encoded. |
| `client_cert` | `Option<SecretRef>` | mTLS client certificate. Must be paired with `client_key`. |
| `client_key` | `Option<SecretRef>` | mTLS client private key. |
| `server_name_override` | `Option<String>` | SNI override when the server certificate CN does not match the address in `endpoint`. |
| `insecure_skip_verify` | `bool` | Disable peer verification. **Local development only.** |

## What `wyrd_auth::resolve` does

The Wyrd auth shell (`wyrd_auth::resolve(secret_ref) -> SecretString`)
runs at connect time:

- `Env`: reads `std::env::var(name)`, strips whitespace.
- `File`: reads the file, strips trailing newline.
- `Vault`: calls the configured backend.
- `Inline`: returns the value (test builds only; refused in production).

Resolution errors map to the client runtime's public auth failure at the
boundary once the runtime client constructor lands.

## Where credentials must NOT go

- `headers` on any webhook config -- that map is plaintext-only and
  validated against a secret-shaped-name denylist. Credential headers go
  in `secret_headers` (server-internal config; not constructed from the
  Python client).
- Labels and annotations on cards. Wyrd validates these for common
  secret-looking values and refuses them.
- Commit messages, CI logs, error messages. `Debug` impls on
  `InlineSecret` redact the value; `SecretRef` `Debug` redacts the
  payload variant.
